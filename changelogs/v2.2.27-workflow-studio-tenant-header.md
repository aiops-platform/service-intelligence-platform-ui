# v2.2.27 — Workflow Studio 不带租户头，读的是 `local` 租户的旧流程

**日期**: 2026-09-21

**问题/背景**: 「我在 workflow studio 界面查看两个 workflow 的配置信息没有看到
ticket-done 节点。」

---

## 根因：同名不同 id，看着对、内容错

`js/app.js` 的 Workflow Studio 段用的是自己的 `WS_API_BASE` + **裸 `fetch`**：

```js
var WS_API_BASE = localStorage.getItem('workflowBaseUrl') || 'http://localhost:8000';
fetch(WS_API_BASE + '/workflows')   // ← 没有 X-Tenant-ID
```

后端 `get_tenant_context` 在 dev 模式（未配 `AGENTFLOW_JWT_SECRET`）下**从请求头取租户，
缺省 `local`**。于是 Studio 读的是租户 `local` 的 workflow：

```
不带租户头   →  seed-scenario1-quotation-print-fail / seed-scenario2-bug-fix   （09-18 的种子，没有 ticket-done）
X-Tenant-ID: otr →  79b62b4404bb / 93eed1138e7a                                （刚改过的，有 ticket-done）
```

**两边同名不同 id** —— 列表标题一模一样，点开才发现是旧副本。这是最误导的一种形态：
不是"什么都没有"，而是"有，但是旧的"。

## 这个坑本仓已经踩过一次

`initProblems` 里有整整一段注释记着同一件事：

> 本页此前的 agentflow 调用**全都不带这个头**，run 会落到 agentflow 的 dev 缺省租户 local，
> 而那里没有任何 MCP 绑定 → agent 拿不到工具。故统一收口到 `agentflowFetch`。

但那次收口只做在 **Problem Center 那一段的作用域内**（`agentflowFetch` 定义在
`initProblems()` 里），别的段用不上，于是各写各的 —— Workflow Studio 就这么漏了。

---

## 改动

### 1. 把 base / 租户 / fetch **上提到模块级**（唯一出处）

```js
var AGENTFLOW_BASE = localStorage.getItem('bugSolveBaseUrl')
    || localStorage.getItem('workflowBaseUrl') || 'http://localhost:8000';
var AGENTFLOW_TENANT = localStorage.getItem('agentflowTenantId') || 'otr';

function agentflowFetch(path, options) { … }   // 统一补 X-Tenant-ID、统一 JSON.stringify(body)
```

租户 key 与 Vue 侧 `src/api/config.js` 的 `resolveTenant()` 取同一个
（`agentflowTenantId`），两边不会各认一个。

### 2. `initProblems` 删掉自己的三份声明，改用共用的

保留它那段解释性注释（改成指向新位置），历史缘由不能丢。

### 3. Workflow Studio 的 5 处 fetch 改用 `agentflowFetch`

`loadWorkflows` / `preview` / `save` / `edit` / `remove`，删掉 `WS_API_BASE`。

---

## 影响范围

| 场景 | 预期 | 实际 | 状态 |
|------|------|------|------|
| Studio 列表的 id | 是 otr 的 | `79b62b4404bb` / `93eed1138e7a` | OK |
| Edit 后图上 | 有 ticket-done | true | OK |
| Edit 后 YAML | 有 ticket-done | true | OK |
| Problem Center | 行为不变 | 仍走同一份 helper | OK |
| `js/app.js` 语法 | 通过 | `node --check` ✓ | OK |
| 生产构建 | 通过 | `npm run build` ✓ | OK |

## ⚠️ 没有修的部分（同类，已确认仍然存在）

还有三段 legacy 用着自己的 base、也没有租户头：

| 段 | 影响的页面 | 是否已迁 Vue |
|---|---|---|
| `AGENT_API_BASE` | Agents | ✅ 已迁 → 该段实际不再渲染 |
| `BS_API_BASE` | Bug Solve | ✅ 已迁 → 同上 |
| `MCP_API_BASE` | **MCP Servers** | ❌ 仍是 legacy → **会显示 local 的数据** |
| `AGC_API_BASE` | **Agent Configs** | ❌ 仍是 legacy → **同上** |

后两段是用户可见的，同一个 bug、同一个症状。**本次没动**：它们各有 5 处 fetch，
且调用形态与 Studio 不完全一样（有的已经在外面 `JSON.stringify`，改的时候要连带
把 stringify 收进 helper，改错会**双重编码**）。要修的话建议单独一轮，逐个站点核对。
