# v2.5.2 — 审批按钮上移到窗口顶部；放开 180px 上限，「diff」终于看得见

**日期**: 2026-09-22

**问题/背景**: 「待审批页面审批按钮要在窗口上部，窗口跟节点详情窗口一样，跟流程窗口下沿对齐。审批内容需要清晰展现」

---

## 病根：内容**渲染了但看不见**

先用 CDP 量了一遍，发现的不是"排版不好看"，而是**最该看的字段根本不在屏幕上**：

```
.bs-upstream .bs-payload   max-height: 180px   overflow-y: auto   ← 内层滚动盒
  explanation      可见
  files_changed    可见
  diff             在盒内第 190px 处  →  **不可见**
面板下方剩余空白:  102px                     ← 一边藏内容，一边空着
```

那 180px 上限是 v2.2.28 加的 —— 当时审批卡是**上下堆叠**在面板里的，不封顶会把面板
撑到 2435px。但 v2.3.3 把审批改成**整高页签**之后，滚动已经上移到 `.bs-panel-approvals`，
这条上限就只剩副作用：**套出第二层滚动，把 diff 藏起来**。

审批人看不到 diff 就点「通过」—— 这个页面等于没起作用。

## 三处改动

### 1. `src/views/runs/RunDetailView.vue` — 按钮移到标题之下、载荷之前

```html
<div class="bs-approval-head">…</div>
<div class="bs-approval-actions">通过 / 驳回</div>   ← 从卡片末尾挪到开头
<div v-if="p.upstream" class="bs-upstreams">…</div>
```

### 2. `css/styles.css` — 按钮改为**吸顶**

```css
#page-run-detail .bs-approval-actions, #page-bug-solve .bs-approval-actions {
    position: sticky;
    top: 0;          /* 原为 bottom: 0 */
    padding: 6px 0;  /* 原为 padding-top: 6px */
    background: #fffbeb;   /* 吸顶时盖住从下面滚过去的载荷 */
}
```

⚠️ **两处必须一起改**：只挪位置不加 sticky，滚下去照样够不着；只加 sticky 不挪位置，
按钮停在卡片底部，仍是"翻到底才看得到"。原注释写的是「钉在卡片底部」，现在描述的是意图。

### 3. `css/styles.css` — 审批页签里放开 180px 上限

```css
#page-run-detail .bs-panel-approvals .bs-upstream .bs-payload {
    max-height: none;
    overflow-y: visible;
}
```

**按页面 id 限定，不动共用规则**：`.bs-upstream .bs-payload` 给 Bug Solve 留着 ——
那边不是滚动容器（详情在图下方、本就 `max-height: none`），停用会把整页拉长。

## 影响范围

| 场景 | 预期 | 实际（CDP 实测） | 状态 |
|------|------|------|------|
| **diff 可见性** | 在屏幕上 | `diff可见: false` → **true** | OK |
| 载荷盒 | 不再是内层滚动盒 | `maxHeight: none` / `overflowY: visible` / `scrollable: false` | OK |
| 按钮位置 | 在载荷**之前** | 按钮 528–564，载荷 597+ | OK |
| 面板 | 内容超出时由面板滚 | 剩余空白 102 → **−33**（转为滚动） | OK |
| 6 张待审批卡 | 可滚、不溢出、不被压扁 | maxScroll 609，卡片高 162，`panelOverflows: false` | OK |
| 徽标持久性 | 切走仍在 | 「审批 1」在「节点详情」下仍可见 | OK |
| 面板高度 | 与图等高 | `h == 620 == --bs-graph-h` | OK |
| Bug Solve 审批卡 | 不受 180px 改动影响 | 规则按页面 id 限定 | OK |
| legacy（`.bs-approval-actions`） | 不受影响 | 规则本身未改，覆盖仍是两个 Vue 页面 | OK |
| 生产构建 | 通过 | `npm run build` ✓ | OK |

## 验证方式

用 CDP 注入一条**带 diff 的**待审批数据（`Page.addScriptToEvaluateOnNewDocument` 里
patch `window.fetch`），**只动浏览器、后端零改动**。改前改后各量一次同一组指标，
而不是凭截图肉眼看 —— 「diff 渲染了但不可见」这种正是肉眼容易放过的。

> 顺带记一条环境经验：CDP 的 `Fetch.enable` 请求拦截在全量请求下会死锁
> （事件量大时 `recv` 取不到自己的响应）；换成注入 patch `window.fetch` 的脚本可靠得多。
