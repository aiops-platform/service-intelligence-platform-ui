# v2.2.14 — 修正：悬停提示要的是 **agent 的描述**，不是节点自己的

**日期**: 2026-09-20

**问题**: v2.2.13 我把"描述"理解成了**节点在 YAML 里写的 `description`**，
新造了一套（还改了两个 seed workflow 的 38 个节点）。用户要的是 **Agents 页
红圈里那句** —— 即 **agent 的描述**：

```
metrics-analyst → 分析 Prometheus 指标定位异常（CPU/内存/磁盘/延迟/错误率）
```

来源是后端 `agents/registry.py:48` 的 `AGENT_DESCRIPTIONS`，
经 `GET /agents` 暴露（可被租户 `agent_configs.description` 覆盖）。

---

## 改动明细

### 1. `src/components/graph/nodeTip.js` — 第三参 `agentDesc` (36)

**两者都保留，因为是不同维度**：

| | 说什么 | 例 |
|---|---|---|
| `desc`（agent） | 这类活是干什么的 | 「分析 Prometheus 指标定位异常」 |
| `nodeDesc`（YAML） | 这一处具体做什么 | 「按候选服务与时间窗查应用日志」 |

### 2. `src/components/graph/useGraphCanvas.js` — 渲染两段 (355)

两段都是**独立段落**（不是 label/value 行，可能较长）；**空的不渲染**，不留空白条。

### 3. `css/styles.css` — `.bs-node-tip-desc2` (6279)

节点自述：次一级、斜体、更淡。

### 4. `src/views/runs/RunDetailView.vue` (42) / `src/views/bug-solve/BugSolveView.vue` (61)

各在 `onMounted` 里取一次 `GET /agents`，建 `agent → 描述` 映射。
**只取一次**——图上的节点指向固定几个 agent，没必要跟着轮询反复拉。
取不到就留空，**不影响提示其余字段**。

## 踩坑记录

### 我把"描述"理解错了

用户说「节点在创建时给的 description」，我理解成了"workflow 作者在 YAML 节点上写的"，
于是新加 `Node.description` 字段 + 给 38 个 seed 节点补文案。
用户澄清后才明白指的是 **agent 的描述**。

**前一轮不算白做**（节点自述是另一个有用的维度，且 `Node.description`
此前确实是"YAML 里写了会被静默忽略"的缺口），但**主描述应当是 agent 的**。

### 新加的 `agentDesc` 块被放在了使用它的函数之后

自动插入时把 `const agentDesc = ref({})` 放到了 `nodeTip` 定义**之后**。
能跑（函数是后调用的），但读起来别扭——已前移。
