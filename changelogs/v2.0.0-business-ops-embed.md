# v2.0.0 — Business Ops 域接入概览页

**日期**: 2026-09-15

**需求背景**: 本仓的 **Business Ops** 域一直只有一条侧边栏（Ticket Workspace →
Approval Center / Agent Tasks），**没有自己的页面** —— 顶栏点它落到 `approval-center`。

而部署站 `https://sip-platform.web.app/business-ops/` 上有一个完整的 Business Ops 概览页
（panel `2/9 · BUSINESS OPS`，与本仓 `biz-ops.panel` 逐字相同）：journey health 三张卡、
六条 journey 的可排序 XLA 表、14 周 × 7 天的 incident pressure 热力图、右侧 340px 的 inspector。

用户要求：**顶栏点 Business Ops 直接展示这个概览页；老的侧边栏对应的页面暂时不要了。**

---

## 结论先说：内嵌，并把 Business Ops 变成「空壳域」

沿用 Constellation 已有的先例（见 `changelogs/v2.0.0-constellation-embed.md`）：
把能跑的页面搬进来、只做必要适配，用 Vue 重写等于重写整个 Next.js 页面。

结构上让 `biz-ops` 与 `constellation` **完全同构**：`sidebar: null` ⇒ 落进 `EMPTY_DOMAINS`
⇒ 走自己的路由 `/biz-ops`，不挂侧边栏。

> 不挂侧边栏还有个布局原因：那页**右侧自带 340px 的 inspector**，再来一条外层侧边栏
> 会把中间的表格挤没。

### 三个关键发现（都是实测，不是推断）

**1. 内层页面的 h1 由 pathname 决定 —— 路径选错会静默变成 "SIP"**

内层用 `usePathname()` 查面板表（`0wuztp2.9oz~8.js` 的 `panelByRoute`，由
`0pfw3-ib1qee0.js` 的 `PanelContainer` 消费）：

```js
{ id:"business-ops", index:2, label:"Business Ops", route:"/business-ops", … }

// PanelContainer 里：
let c = usePathname(), d = panelByRoute(c)
… children: d?.label ?? "SIP"
```

路径对不上时 `d` 是 undefined，而代码写的是 `d?.label ?? "SIP"` —— **不报错、不白屏**，
只是 h1 从「Business Ops」悄悄变成「SIP」。

所以产出文件**必须**叫 `public/business-ops/index.html`，iframe **必须**打 `/business-ops/`
（`panelByRoute` 会剥掉尾部斜杠）。这条路径不能改。

**2. Vite 不解析 public/ 里的目录索引**

实测（同一台 dev server，同一时刻）：

| 请求 | 结果 |
|---|---|
| `/business-ops/index.html` | 200，Next 离线页（10,210 字节） |
| `/business-ops/` | 200，**Vue 应用的 index.html**（388 字节） |

Vite 用 sirv 伺服 public/，但「目录 + 尾斜杠」不解析成 `index.html`，直接落到 SPA 兜底。
后果是 iframe 里**渲染出 Vue 应用自己**（自己套自己）。

生产不需要管这个 —— nginx 的 `try_files $uri $uri/ /index.html` 本来就解析目录索引。

**3. 下载的那份 html 又是 DOM 快照，启动不了 React**

与 Constellation 同一个坑：Chrome「网页，完整」保存的是**运行时 DOM 快照**（73,654 字节），
而服务器原始外壳只有 9,942 字节。拿前者当入口 → React 根本不启动、页面点不动。

`_files/` 里的 JS/CSS 是好的，坏的只是那份 HTML。**必须用服务器原始 HTML 作外壳。**

## 改动明细

### 1. `tools/make-offline-page.py` — 支持多页面

**原因**: 原来写死只构建 Constellation（`PAGE_NAME`、`STRIP_CSS`、`SITE + "/"`）。
Business Ops 是第二个页面，共用同一套 Next 外壳和同一批 chunk。

- 新增 `PAGES` 注册表（line 129-145）：每个页面的 `site_path` / 产出路径 / 缓存子目录
- 新增 `--page {constellation|business-ops}`（默认 `constellation`，**行为不变**）
- `refresh_vendor` / `load_vendor` / `build` 改为按页面取参
- `build` 的 `chunk_srcs` 从单个目录改成**列表**，且 `main()` 里铺的是**所有页面**的
  并集（分享池 + 每个页面的独有 chunk）—— 不是只铺当前页的

> 最后这条是被一个真 bug 逼出来的：两个页面共用 `public/_next/`，而构建先 `rmtree`
> 清空。只铺当前页的资源时，「先建 business-ops、再单独重建 constellation」会把
> business-ops 那 3 个独有 chunk 永久抹掉，**且构建输出完全正常、不报任何错**，
> 直到打开 Business Ops 才发现 404。

```python
PAGES = {
    "constellation": {"out": ("constellation-app.html",), "vendor_sub": "", …},
    "business-ops":  {"out": ("business-ops", "index.html"), "vendor_sub": "business-ops", …},
}
```

> `--refresh` 现在会**跳过分享池里已有的同名 chunk** —— 实测两个页面的 30/31 个资源
> 逐字节相同（md5 对比），再存一份没意义。

### 2. `public/business-ops/index.html` + `public/_next/static/chunks/` ×3 — 新增

脚本产出，**入库**（与 Constellation 同理：「克隆下来 `npm run dev` 就能用」的关键）。

新增的 3 个 chunk 是 Business Ops 独有的：
`0pfw3-ib1qee0.js`(10K，`PanelContainer`) / `100pim9o6kpoy.js`(161K，业务数据) /
`00tsl~72wvlrr.js`(40K，`BusinessOps` 组件)。其余 14 个与 Constellation 共用。

### 3. `tools/vendor/business-ops/` — 新增

`server.html`（服务器原始外壳）+ `chunks/`（上面那 3 个）。
**这是为了让 Business Ops 不依赖用户下载的目录** —— 那个目录最终要删掉，
所以构建输入必须落到仓库里。字体仍共用 `vendor/media/`。

### 4. `src/components/NextEmbed.vue` — 新增，抽共享组件

**原因**: `ConstellationView.vue` 里那段「iframe + 加载遮罩 + 轮询/超时兜底」有 25 行
**踩过坑的时序逻辑**。复制一份等于以后要把那个 bug 修两遍。

props: `src` / `title` / `label`。

### 5. `src/views/business-ops/BusinessOpsView.vue` — 新增

薄壳，一行 `<NextEmbed src="/business-ops/" … />`。文件头记了「路径为什么必须是
`/business-ops/`」的原委。

### 6. `src/views/constellation/ConstellationView.vue` — 改用共享组件 (line 1-25)

从 100 行缩到 25 行。保留了它自己的「为什么不用 Vue 重写」那段历史（三次失败尝试），
共享机制的部分改为指向 `NextEmbed.vue`。

### 7. `src/router/nav.js` — `biz-ops` 摘掉侧边栏 (line 64-83)

```js
-    landing: 'approval-center',
     …
-    sidebar: { id: 'sidebar-biz-ops', … groups: [ Ticket Workspace … ] },
+    sidebar: null,
```

`sidebar: null` ⇒ 自动落进 `EMPTY_DOMAINS` ⇒ 顶栏点击走 `/biz-ops`（`App.vue:100` 的
`item.sidebar ? /landing : /key` 分支）。

> 摘掉后 `approval-center` / `agent-tasks` 两个 slug 不再由 `flattenItems()` 产出，
> **没有路由可达**。但那两个 legacy 面板仍在 `js/app.js` 与 `legacy-panels.html` 里，
> `PANEL_ID` 里的条目也保留（旧代码可能仍传 `page-approval-center` 过来）。
> 要恢复：把 sidebar 放回来 + 从 `DOMAIN_COMPONENTS` 摘掉 `biz-ops`。

### 8. `src/router/index.js` — 登记域组件 (line 77-80)

```js
 const DOMAIN_COMPONENTS = {
   constellation: () => import('@/views/constellation/ConstellationView.vue'),
+  'biz-ops': () => import('@/views/business-ops/BusinessOpsView.vue'),
 }
```

⚠️ 这里跟的是**域的 key**（`biz-ops`），不是 slug。

**不用**动 `MIGRATED` / `VIEW_COMPONENTS` —— index.js:68-70 已写明那条「两处必须同时改」
的规矩只针对**侧边栏叶子**；空壳域走 `emptyDomainRoutes` 这条独立分支，登记一次即可。

### 9. `vite.config.js` — 补目录索引插件 (line 44-90)

新增 `sipEmbedPageIndex()`，`configureServer` + `configurePreviewServer` 各挂一次
（preview 不继承 server 的中间件，仓里 `proxy` 也是为同样的原因配了两遍）。

dev 读 `public/`、preview 读 `dist/`（`configResolved` 里才拿得到这两个值）。
文件不存在时 `next()` 交给 SPA 兜底，**不吞请求**。

### 10. `css/styles.css` — 只改注释 (line 7357)

`/* Constellation Embed */` → `/* Next.js Embed */`，并注明两个域共用、类名保留 `cs-` 前缀。

**类名一个没动** —— 样式表也是类名的消费方，改一处漏一处就是静默掉样式
（本仓在 `#bsZoomFit` 上踩过同一个坑，见 CLAUDE.md）。

## 踩坑记录

| 坑 | 现象 | 根因 | 处置 |
|---|---|---|---|
| 拿下载的 html 当入口 | 页面看着对、**点不动** | Chrome 保存的是运行时 DOM 快照，React 从未启动（与 Constellation 同因，已第二次踩） | 用 `curl` 取服务器原始外壳 |
| 产出文件叫 `business-ops-app.html` | h1 显示 **"SIP"** 而不是 "Business Ops"，**零报错** | `panelByRoute(usePathname())` 落空 → `d?.label ?? "SIP"` | 产出改叫 `business-ops/index.html`，iframe 打 `/business-ops/` |
| Vite 伺服 `/business-ops/` | iframe 里**渲染出 Vue 应用自己** | sirv 不解析 public/ 的目录索引，落到 SPA 兜底 | 加 `sipEmbedPageIndex` 插件（dev + preview） |
| `Path \| None` 注解 | `TypeError: unsupported operand type(s) for \|` | 本机 Python 3.9，`X \| None` 要 3.10+ | 去掉该注解 |
| 首次 headless 验 Constellation | 报 WebGL 创建失败 | `--disable-gpu` 的 headless 建不出 WebGL 上下文，**不是回归** | 换 `--enable-unsafe-swiftshader` 复测通过 |
| **单独重建 Constellation** | Business Ops 的 3 个 chunk **被抹掉**，页面 404，而构建输出**一切正常、零报错** | 两个页面共用 `public/_next/`，构建先清空、却只铺当前页的资源 | 改成每次铺**所有页面**的并集（见改动明细第 1 条）；构建会打印来源数 |
| 误判 `/approval-center` 成了死链 | 以为摘掉 Business Ops 侧边栏后它该重定向 | 它**同时也是 Service Ops 侧边栏的项**（nav.js:100），仍然有效 | 非问题。真正失去路由的只有 `agent-tasks` |

## 怎么用

```bash
npm run dev            # 顶栏点 Business Ops（内嵌在 Vue 应用里）

# 重建离线页（默认不联网）
python3 tools/make-offline-page.py                     # Constellation
python3 tools/make-offline-page.py --page business-ops # Business Ops
python3 tools/make-offline-page.py --page business-ops --refresh   # 站点更新后（唯一联网操作）
```

> 两个页面**共用 `public/_next/`**：每次构建先清空、再把**所有页面**的资源铺满
> （分享池 + 每个页面的独有 chunk），所以重建哪一个都不会拆掉另一个。

## 遗留 / 已知代价

- **`extract_business_view/` 可以删了** —— 需要的 3 个 chunk 与外壳已落到
  `public/` 与 `tools/vendor/business-ops/`，构建不再依赖它。本仓未代删，交给你。
- **Business Ops 域没有侧边栏了**，`approval-center` / `agent-tasks` 暂时不可达。
  恢复方法见改动明细第 7 条。
- **Constellation 的 h1 仍是 "SIP"**（同一个 `panelByRoute` 机制）—— 它的 route 是 `/`，
  而 `/` 被 Vue 应用占着，没法像 Business Ops 这样对齐路径。**这是本次改动之前就有的**，
  未动。
- `public/business-ops/` 这个路径名与部署站的路由对齐，是被 `panelByRoute` 逼出来的；
  本仓的 Vue 路由是 `/biz-ops`，两者不同名、不冲突。
