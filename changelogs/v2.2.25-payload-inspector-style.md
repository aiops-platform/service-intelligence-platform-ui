## 改动明细

### 1. `src/components/graph/NodePayload.vue` — 模板重排

- 字段从「键左值右」改为**标签在上、值在下**（参考图的排法）；
- **标量数组 → 胶囊**（`ruled_out: [network, dependency, …]` 原来竖排四行）；
- **对象数组 → 每项一张卡**（`hypotheses[]` 原来和标量混在一个列表里）；
- 数字/布尔加 `.bs-num` 等宽类。

### 2. `css/styles.css` — 重写 `.bs-payload*`

类名全部用 `bs-payload-*` / `bs-field*` / `bs-chip` / `bs-card`。
**`.bs-content` 与 `.bs-detail` 都没动** —— legacy `js/app.js` 也在用它们
（同 `.bs-canvas` 那条规矩）。

### 3. ⚠️ 顺带修掉「看不到其它字段」的真正原因

排查时发现 `.bs-detail` 带 `max-height: 300px; overflow-y: auto`：

```
可视高 299px，内容高 952px   →  9 个字段只露得出 2 个，其余要在一个嵌套滚动区里翻
```

上一版（v2.2.23）我以为「按字段展示 + 折叠」就解决了「只显示了一个输入」，
**但那只解决了"被长值顶出去"，没解决"被容器截断"** —— 两个原因叠加，
只修一个还是看不全。

修法是按页面 id 限定（`.bs-detail` 与 legacy 共用，不能直接改）：

```css
#page-run-detail .bs-detail,
#page-bug-solve .bs-detail { max-height: none; overflow: visible; }
```

不限高也不会失控：长字符串默认折叠到 4 行。

## 追加：右侧详情面板与图**等高**（下沿对齐）

用户要求「输入/输出内容窗口的下边沿跟流程节点展示的窗口下沿对齐」。

两个页面的布局**不一样**，所以分别处理：

- **Run 详情**：详情在**右侧栏**（`.bs-panel`），与图并排 → 需要等高
- **Bug Solve**：详情在**图下方**（`.bs-main` 内）→ 本来就在流里，没有对齐问题

实现（Run 详情）：

```css
:root { --bs-graph-h: clamp(360px, 62vh, 820px); }   /* 图高抽成变量 */
.bs-graph-fit { height: var(--bs-graph-h); }
#page-run-detail .bs-panel { height: var(--bs-graph-h); }   /* 等高 */
#page-run-detail .bs-detail {
    flex: 1 1 auto;
    min-height: 0;        /* 不可省：flex 子项默认下限是内容高度，不写会顶破上面的 height */
    max-height: none;
    overflow-y: auto;
}
```

两个刻意的选择：

- **高度抽成 `--bs-graph-h` 单一真源**：对齐的前提是两处用同一个值，
  各写一份的话改了一处另一处会静默错位。
- **用 `height` 而不是 `max-height`**：内容比图短时，只给上限的话面板会缩到内容高，
  下沿又对不齐了。等高才是"对齐"的充要条件。

实测：`图下沿 1037 == 面板下沿 1037 == 内容区下沿 1037，差 0`；图高 620 == 面板高 620。
