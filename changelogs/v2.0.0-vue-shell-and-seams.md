# v2.0.0 — Vue 化第 2 步：双世界接缝 + 外壳落地

**日期**: 2026-09-11

**需求背景**: 承接 `v2.0.0-vue-scaffold.md`（S1 搭 Vite 骨架）。本步做**最关键的一步**：
让 Vue 外壳与旧 `js/app.js` 在同一文档内安全共存，并把外壳（header / 侧边栏 / footer）渲染出来。

改造前 `index.html` 的 shell 与 17 个视图面板同处一棵 DOM，`js/app.js` 用**全文档**查询驱动它们。
一旦 Vue 也渲染同类名的节点（必须同类名，才能复用 `styles.css`），旧 handler 就会误伤 Vue 的 DOM。
本步引入 `legacyRoot()` 作用域根 + 9 处接缝把两者切开。

---

## 改动明细

### 1. `js/app.js:13-21` — 新增 `legacyRoot()` 作用域根

**原因**: 共存的地基。所有「全文档」查询都必须收进 legacy 子树。

```js
function legacyRoot() {
    return window.__SIP_LEGACY_ROOT || document;
}
```

独立打开旧 `index.html` 时 `__SIP_LEGACY_ROOT` 未定义 → 回退 `document`，行为与改造前完全一致。

### 2. `js/app.js` — 8 处全文档查询作用域化（行 64 / 103 / 591 / 600 / 2181 / 2213 / 2259 / 2270）

| 行号（改后） | 函数 | 选择器 |
|---|---|---|
| 64 | `showPage` | `.page-panel` |
| 103 | `initSidebar` | `.sidebar` |
| 591 / 600 | `initNavigation` | `.nav-item` / `.sidebar` |
| **2181** | **`initFilterChips`** | `.filter-chip` |
| **2213** | **`initTableSorting`** | `th` |
| **2259** | **`initButtonGroup`** | `.btn-group .btn` |
| **2270** | **`initRowClick`** | `tbody tr` |

加粗的四个是**通用初始化器**（不属于任何单个视图），也是真正的雷：`initTableSorting` 会
`appendChild` 重排 `tbody`，绑到 Vue 的行上会让 vdom 与真实 DOM 失步，症状随机难复现。


### 8. `js/app.js:84-98` — 接缝 S9（**计划稿写 8 处，实施时发现第 9 处**）

5 个无侧边栏的「空壳」域（Constellation / Architecture / FinOps / Security Ops / Value Pool）
在改造前走 `initNavigation` 的 else 分支：隐藏所有侧边栏 → `showPage('page-service-ops')`
→ **把该页的 `.page-title` 改成域名、清空 `.page-desc`**。这两个节点在 `#page-service-ops` 内、
归 app.js 所有，故由本文件提供受控入口，而不是让 Vue 直接改 legacy DOM：

```js
window.__SIP_SET_DOMAIN_HEADER = function (title, desc) {
    var root = legacyRoot();
    var t = root.querySelector('#page-service-ops .page-title');
    var d = root.querySelector('#page-service-ops .page-desc');
    …
};
```

**顺带修掉一个潜伏 bug**：改造前用的是 `document.querySelector('.page-title')`（取**全文档首个**匹配）。
外壳归 Vue 后，若 Vue 先渲染出带 `.page-title` 的视图，这里就会误取 Vue 的标题。现在显式限定在
`#page-service-ops` 内。

### 9. `src/legacy/bridge.js` — 新增（73 行）

装载旧世界：设 `__SIP_LEGACY_ROOT` → 设 `__SIP_DEFER_LEGACY_INIT` → 以 **classic script**
加载 `/js/app.js`（不能走 ESM，那是个 IIFE）→ 显式调 `__SIP_LEGACY_INIT()`。

`ensureLegacyBooted()` 是**幂等 memoized promise**（失败时重置以允许重试），保证只装载一次 ——
重复装载会让 17 个 init 再跑一遍 fetch、8 个 `setInterval` 再起一遍。

### 10. `src/router/nav.js` — 新增（234 行）

导航唯一真源。把改造前散在 `index.html` 的 `data-*` + `app.js:61-124` 的**一长串 if-else** 收敛成数据：

- `PANEL_ID`：slug → legacy panel id（**只有两处真不一致**：`knowledge-reflow-log`→`page-reflow-log`、
  `agent-registry`→`page-agents`，其余加 `page-` 前缀即可）
- `NAV`：9 个顶部域 + 各自侧边栏（支持一层嵌套：Service Ops › Observability › APM）
- `landing`：每个有侧边栏的域落地到哪个 slug（对齐改造前各 sidebar 里预置 `.active` 的那个叶子）
- `flattenItems` / `navKeyOf` 供路由表与高亮使用

### 11. `src/App.vue` + 4 个 shell 组件 — 新增

`AppHeader.vue`(48) / `AppSidebar.vue`(27) / `SidebarGroup.vue`(51，递归支持嵌套分组) /
`AppFooter.vue`(29) / `LegacyPanels.vue`(28) / `App.vue`(103)。

DOM 结构与 class **逐字对齐**改造前的 `index.html:11-38 / 41-151 / 2189-2205`，
因此 `styles.css` 一字未改即可复用（含 `.sidebar.visible { display:block }` 的显示机制、
`.expanded`/`.collapsed` 的折叠语义）。

`LegacyPanels.vue` 的 `v-html` 绑定**冻结常量**（不是 ref/computed）—— 硬约束：一旦 Vue 重渲染
这棵子树，app.js 绑好的监听器与已渲染内容会全部被冲掉。

## 踩坑记录

### 坑 1：`.page-title` 的 `document.querySelector` 会取错（S9 的由来）

计划稿只列了 8 处接缝，实施时读 `initNavigation` 才发现第 9 处：它用
`document.querySelector('.page-title')` 取**全文档首个**匹配。改造前没问题（Service Ops 面板
在 DOM 最前），外壳归 Vue 后一旦 Vue 先渲染出带 `.page-title` 的节点就会取错。已改为
`legacyRoot().querySelector('#page-service-ops .page-title')`。

### 坑 2：`npm i --no-save playwright` 后浏览器版本不匹配

本机 `~/Library/Caches/ms-playwright` 有 `chromium-1228`，但新装的 playwright 要 `chromium_headless_shell-1243`，
`launch()` 直接报 "Executable doesn't exist"。解法是让它用本机已有的 Chrome：

```js
chromium.launch({ executablePath: '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' })
```

（playwright 是 `--no-save` 安装的，未进 `package.json`，仅用于本次验证。）
