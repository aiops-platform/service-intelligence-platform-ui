# v1.17.0 — View analysis 重构：主弹框左流程/右输入输出，DAG 收敛到 Flow Diagram 二级弹框

**日期**: 2026-09-07

**问题/背景**: v1.16.0 把 View analysis 改成左右分栏（左=执行流程，右=画布+详情）后，用户仍不满意：DAG 画布巨大，挤在主弹框里
导致布局局促、右侧既要放图又要放详情，空间互相挤压。经确认交互：
1. **主弹框不再内嵌流程图**（流程图画布先隐藏/抽离）；
2. **主弹框改为左右结构**：左侧 = Execution Flow（待审批置顶 + 全量节点步骤列表），右侧 = 点击流程节点后展示该节点
   **输入/输出**（Output / Prompt），自动跟随 running 节点时右侧实时翻新；
3. **概要条（Run ID/Status/Step/Tokens/Cost）右端新增「Flow Diagram」按钮** → 打开一个**独立二级宽弹框（~1200px）专门展示 DAG 流程图**
   （整块画布 + 缩放/平移/Fit + 底部状态图例），Esc/点遮罩关闭回到主弹框；
4. **按钮带执行态圆点**：随 run 状态翻色（running/waiting 呼吸动画、success 绿、failed 红…），指示当前是否正在执行。

文案英文（与 Problem Center 其余 UI 一致）。纯前端 SIP（`index.html` / `js/app.js` / `css/styles.css` + changelog）。

**方案**: 复用 v1.15/v1.16 的全部逻辑（轮询/审批/节点详情/canvas 工厂/`pcRunCanvas` 实例 id 不变），只做**结构迁移**：把
`pcRunZoom/pcRunGraph/pcRunHint/pcRunZoomControls` 画布 DOM 从主弹框移到新二级弹框；`createGraphCanvas` 仍以这些 id 绑定，
第三个 canvas 实例不变。主弹框右栏由「画布+详情」换成纯「详情」列。

## 改动明细

### 1. `index.html`
- 概要条 `pcRunStats` 末尾（Cost 之后）加右对齐的 Flow Diagram 入口（index.html:2094-2100）：
  ```html
  <!-- 右端：Flow Diagram 入口（执行态圆点指示 run 状态；running/waiting 呼吸动画） -->
  <div class="bs-stat pcrun-flowaction">
      <button type="button" class="pcrun-flowbtn" id="pcRunFlowBtn" data-state="" title="Open the execution flow diagram">
          <span class="pcrun-flowdot is-idle"></span>
          <span class="pcrun-flowbtn-label">Flow Diagram</span>
      </button>
  </div>
  ```
- 主弹框右栏由 `.bs-main.pcrun-main`（内含 `bs-canvas.pcrun-canvas` 画布 + `.bs-detail`）**换成纯详情列**（index.html:2116-2119）：
  ```html
  <!-- 右栏：点左栏流程步骤 → 展示该节点输入/输出（DAG 图在独立 Flow Diagram 二级弹框） -->
  <section class="pcrun-detailcol">
      <div class="bs-detail" id="pcRunDetail"></div>
  </section>
  ```
- 新增**独立二级宽弹框 `#pcRunGraphOverlay`**（index.html:2126-2156）：header（`#pcRunGraphTitle`/`#pcRunGraphClose`）+
  `.pcrg-body`（`bs-canvas.pcrg-canvas`：`pcRunHint`/`pcRunZoom`/`pcRunGraph`/`pcRunArrow`/`pcRunZoomControls` 画布）
  + `.pcrg-legend` 状态图例（Running/Done/Failed/Waiting/Skipped/Approval + 操作提示）。画布 id 沿用原主弹框那套，canvas 实例零改动。

### 2. `css/styles.css`
- 主弹框收窄：`#pcRunOverlay .ap-modal` 由 1200px → `max-width:920px`（大图已抽离）（styles.css:4942-4946）。
- 概要条右端按钮（styles.css:5077-5121）：`.pcrun-flowaction`（`margin-left:auto`，横向居中）、`.pcrun-flowbtn`（浅蓝 pill，
  悬停加深）、`.pcrun-flowdot` 圆点 + 状态类（`.is-idle/.is-pending/.is-done/.is-running/.is-waiting/.is-failed/.is-cancelled`，
  running/waiting 用 `@keyframes pcrun-dot-pulse` 呼吸），及 `#pcRunFlowBtn[data-state=…]` 边框/底色联动。
- 右栏详情列（styles.css:5124-5132）：`.pcrun-detailcol { flex:1 1 auto; min-width:0; min-height:0; display:flex; }`，
  `.pcrun-detailcol .bs-detail` 填满整栏（`flex:1; min-height:0; max-height:none; border+radius; padding; overflow:auto`）。
- Flow Diagram 二级弹框（styles.css:5135-5185）：`#pcRunGraphOverlay`（居中）；`.ap-modal` `max-width:1200px` +
  `height:calc(100vh - 80px)`；`.pcrg-body` flex 列、`overflow:hidden`；`.pcrg-canvas`/`#pcRunGraphOverlay .bs-zoom` `flex:1;
  min-height:0`；`.pcrg-legend`（`::before` 色块对应节点状态色，approval 虚线框）。节点选中环样式作用域由 `#pcRunOverlay` 改到
  `#pcRunGraphOverlay`（图只在二级弹框出现）。

### 3. `js/app.js`（initProblems 内 run viewer 块）
- `applyRunView()`：概要条 Status badge 更新后追加 `pcSetFlowBtnState(status)`（按钮执行态圆点翻色）。
  尾部**重排**为：auto 选中 running → 渲染右栏详情 → 渲染审批 → **仅当 Flow Diagram 弹框打开才 `pcRunCanvas.render` +
  `pcMarkGraphSel`**（隐藏时跳过渲染，避免 display:none 下 fitGraph 取 0 尺寸）→ `renderRunSteps()` → 终态停轮询。
- `renderRunDetail()` 空文案由 "Click a node in the graph…" 改为 "Select a step to view its input/output."（主弹框不再有图）。
- 新增（renderRunSteps 之后、closeProblemRun 之前）：
  - `pcRunGraphIsOpen()`：二级弹框 `.open` 判定；
  - `pcSetFlowBtnState(status)`：`pcrun-flowdot` 状态类 + `#pcRunFlowBtn` `data-state`/title；
  - `openRunGraph()`：标题 `Flow Diagram - {record_id}`、`.open` 后再画（先 open 再 render 保 fit 有尺寸）→ `renderRunGraphNow()`；
  - `renderRunGraphNow()`：有 `pcRunGraph` 则 `pcRunCanvas.render(pcRunGraph, pcRunStatusMap())` + `pcMarkGraphSel()`；无则保持 hint；
  - `closeRunGraph()`：移除 `.open`。
- `openProblemRun()`：打开前先 `closeRunGraph()`（残留收起），meta 复位后 `pcSetFlowBtnState('')`（圆点回 idle）。
- `closeProblemRun()`：追加 `closeRunGraph()` + `pcSetFlowBtnState('')`。
- 生命周期接线：`#pcRunFlowBtn` click→`openRunGraph`；`#pcRunGraphClose` click→`closeRunGraph`；图弹框 backdrop 点击→`closeRunGraph`；
  **Escape 链：图弹框放最前**，先关 Flow Diagram，再关主弹框 → analyze → detail。

| 场景 | 预期 | 实际 | 状态 |
|------|------|------|------|
| 打开 View analysis | 主弹框(920px) = 概要条 + 左执行流程/右输入输出，无大图 | `.pcrun-split` 左 `.pcrun-flow-col`(300px) 右 `.pcrun-detailcol` | OK |
| 概要条右端 | Flow Diagram 按钮 + 执行态圆点 | `.pcrun-flowaction` margin-left:auto 靠右；`pcSetFlowBtnState` 随 status 翻色 | OK |
| run 执行中 | 按钮圆点呼吸 + 按钮蓝色高亮；右侧自动展示 running 节点输入输出 | `.is-running` + `pcrun-dot-pulse`；`applyRunView` auto → `renderRunDetail` | OK |
| 点左栏步骤 | 右栏展示该节点 Output/Prompt | `pcSelectNode` → `renderRunDetail(nid)`；tab 委托不变 | OK |
