# v2.2.11 — 修复：流程图显示空白（图区没有高度上限，fit 是假的）

**日期**: 2026-09-20

**问题**: Run Detail 页的 workflow 图**看不到 / 显示一大片空白**。

**根因**: 图区**整条布局链都没有高度约束**，所以 `.bs-zoom` 被 SVG 撑到全高，
`fitGraph` 里 `ch / gh ≡ 1` —— **fit 永远不会缩小**，等于没生效。

实测（18 节点的图，viewBox 780×1506）：

```
.bs-body   { display:flex; align-items:flex-start }         ← 无高度
.bs-main   { flex:1; display:flex; flex-direction:column }  ← 无高度
.bs-canvas { display:flex; flex-direction:column }          ← 无高度
.bs-zoom   { min-height:300px; overflow:hidden }            ← 只有下限，无上限

→ .bs-zoom 高 1506 = gh  → ch/gh = 1
→ zoom 只受宽度限制（cw=323 → 0.414）
→ panY = (1506 − 1506×0.414)/2 = 441px  ← 内容被垂直居中到超高盒子里
→ 外层 overflow:hidden 一裁，可见区域大半是空的
```

**为什么以前不显形**：页面有滚轮缩放 / 拖拽平移，用户能自己把图拖到眼前。
v2.2.8 改成"固定 fit、去掉缩放"之后，**这个既存缺陷才变成致命伤**——
fit 成了唯一的显示方式，而它根本没在 fit。

---

## 改动明细

### 1. `src/components/graph/GraphCanvas.vue` — 根元素加 `bs-graph-fit`

**原因**: 需要给图区一个受限高度。

⚠️ **不能直接改 `.bs-canvas`**——它与 `src/legacy/legacy-panels.html` 共用
（legacy 的 Flow Diagram 弹框用的是 `class="bs-canvas pcrg-canvas"`）。
故新增一个只属于本组件的修饰类。

### 2. `css/styles.css` — `.bs-graph-fit` 高度 + `.bs-zoom` 允许收缩 (6092 附近)

```css
.bs-graph-fit {
    height: clamp(360px, 62vh, 820px);
}
.bs-graph-fit .bs-zoom {
    flex: 1 1 auto;
    min-height: 0;   /* 允许收缩到内容以下，否则 flex 子项的下限仍是内容高度 */
}
```

`min-height: 0` 是必须的：flex 子项默认 `min-height: auto`，
即使给了父级高度、子项也不会缩到内容高度以下。

**修法参照 legacy 侧的既有做法**（`#pcRunGraphOverlay .bs-zoom { flex: 1 1 auto; min-height: 0 }`）
—— 同一件事 legacy 早就解决了，Vue 侧一直缺。

## 踩坑记录

### 现象具有误导性

看到"空白"的第一反应是"渲染挂了 / JS 报错"，但：

- 控制台**无我方异常**（只有 legacy `js/app.js` 的旧 fetch 报错，与本图无关）
- 渲染台里引擎**完全正常**（18 节点、无异常）

真正的线索是 dump 出来的 **`transform: translate(0px, 441px) scale(0.414)`**：
`panY = 441` 说明容器比内容高得多，内容被垂直居中到了一个正在被裁剪的盒子里。

**教训**：图"看不见"不一定是没渲染——先看**变换矩阵**，比看截图猜快得多。

### 样式类要分清谁在用

`.bs-canvas` 名字看着像组件私有，实际 `legacy-panels.html` 也在用。
本仓已记录过这个坑（"样式表也是类名的消费方"），所以这次先 grep 了三个类的
使用方再动手，选择新增修饰类而不是改共用类。
