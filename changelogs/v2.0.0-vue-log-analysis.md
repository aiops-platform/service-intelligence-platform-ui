# v2.0.0 — Vue 化第 6 步：Log Analysis 视图迁移

**日期**: 2026-09-11

**需求背景**: 承接 `v2.0.0-vue-alert-detail-modal.md`（S5）。把 `page-log-analysis`
（原 `index.html:1113-1193` 面板 + `app.js` 的 `initLogAnalysis`，约 189 行）迁到 Vue。
这是**第一个真正落地的业务视图** —— 迁完后 `<RouterView>` 分支才第一次有内容。

---

## 改动明细

### 1. `src/views/log-analysis/LogAnalysisView.vue` — 新增

DOM 与 class 逐字沿用原面板，继续复用 `styles.css`。与改造前的三处差异（都是刻意的）：

| 改造前 | 现在 |
|---|---|
| `tbody.innerHTML = html` 拼串，渲染后逐个 `addEventListener` | `v-for` 渲染 `rows`，`@click` 直接绑 `openDetail` |
| `document.getElementById('laServiceFilter').value = x` 反写 | `:value="service"` + `@change` |
| `_pageRefreshers['page-log-analysis']` + `sessionStorage.navContext` | `watch(route.query.serviceName)` + `onActivated` |

**恒 10 行是易丢细节**，已保留：`rows` 计算属性补 null 到 10 个，模板对 null 渲染
`<tr class="alert-empty-row"><td colspan="7">&nbsp;</td></tr>` —— 改造前是
`for (var i=0;i<10;i++)`，作用是保持表格高度稳定、切换筛选时不跳动。

### 2. `src/views/log-analysis/useLogAnalysis.js` — 新增

把改造前闭包里的 `currentPage` / `currentService` / `currentSeverity` /
`currentStatus` / `allAlerts` 升成 ref。KPI 与列表是**两条独立请求**（改造前亦然），
KPI 失败静默 —— 保持原样，没有"顺手"改成一起失败。

### 3. `src/utils/format.js` — 新增

`escapeHtml`（从 renderAnalysis 提出来共用）+ `truncateText`（摘要列截 60 字符 + `...[truncated]`）。

### 4. `src/utils/time.js` — `formatTime` 空值返回 `'-'`

原实现返回 `'-'`（不是 `'N/A'`），与 `initLogAnalysis` 内的同名函数对齐。

### 5. `src/router/index.js` — 加 `VIEW_COMPONENTS` 表

```js
const VIEW_COMPONENTS = { 'log-analysis': () => import('@/views/log-analysis/LogAnalysisView.vue') }
component: VIEW_COMPONENTS[item.slug] || LegacyPanelHost
```

**键必须同时在 `nav.js` 的 `MIGRATED` 集合里** —— `meta.legacy` 由后者决定，两者不一致
会出现「组件渲染了但 legacy 面板没隐藏」的双显。已加注释提示。

### 6. `src/App.vue` — `<RouterView>` 套 `<KeepAlive>`

对应改造前"所有面板常驻 DOM、切页保留筛选状态"的行为；也是 `onActivated` 生效的前提。

## 影响范围

用桩后端（4 个端点：`log-alert` / `alert-summary` / `app-indicator/services` /
`log-alert/{id}/analysis`），返回 3 条告警覆盖 CRITICAL/WARNING/INFO 与
OPEN/ACKNOWLEDGED/RESOLVED 各态。

| 场景 | 预期 | 实际 | 状态 |
|------|------|------|------|
| 路由 `/log-analysis` | 渲染 Vue 视图 | 视图存在，**legacy 宿主已隐藏** | OK |
| **表格恒 10 行** | 3 真实 + 7 空行 | 3 + 7 = 10 | OK |
| KPI 五项 | 3/3/1/1/1 | 一致 | OK |
| 服务下拉 | All + 3 个服务 | 4 项 | OK |
| 摘要截断 | 60 字符 + `...[truncated]`，`title` 存全文 | 74 字符含标记；`title` 92 字符 | OK |
| severity/status 类名 | `severity-critical` / `status-open` | 一致 | OK |
| Total 计数 | 3 | 3 | OK |
| 点 CRITICAL 筛选 | 只请求 severity=CRITICAL，该 chip active，All 取消 active | `page=0&size=10&severity=CRITICAL`；1 行；active 正确切换 | OK |
| 行内 Detail | 打开详情模态 | 模态打开，标题 `Agent Analysis - 结算接口异常` | OK |
| 页面错误 | 0 | **0** | OK |

**时间列显示 `2026/09/10 18:30:00`（输入是 `10:30:00+08:00`）** —— 这是**改造前就有的行为**，
不是本次引入：原 `formatTime` 先把时区后缀正则剥掉、再补 `Z` 当作 UTC，最后用
`toLocaleString('zh-CN', {timeZone:'Asia/Shanghai'})` 转回上海，等于对带时区的输入多加了一次
+8 偏移。本次**逐字保留**（计划稿要求"不要顺手简化"），如果确认是后端契约问题应单独修。

**未覆盖 / 下一步**：仍是桩后端验证 —— 真实 sip-aiops（`:8080`）本机未运行，
「后端真实数据形状与渲染假设是否一致」要等接上真后端。翻页字段 `page` 保留了但无 UI 绑定
（改造前 `currentPage` 恒为 0），与原行为一致。
