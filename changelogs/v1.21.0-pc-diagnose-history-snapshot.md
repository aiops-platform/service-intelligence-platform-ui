# v1.21.0 — feat: 「历史计划」升级为**整轮诊断快照**：决策那一刻抓一份，拒绝/忽略/误报三态都存

**日期**: 2026-09-10

**需求背景**: v1.20.0 已交付审批链路（拒绝/忽略/误报）+ 弹窗最下边的「历史计划」，但历史条目**只存了被拒那一版方案的
`steps` + 拒因**。用户看完第一轮、拒绝之后，历史里只剩"那一版计划"——**第一轮的根因 / 总结 / 其他方案 / 分析链路全没了**。

用户诉求（原话）：

> "对于我第一轮分析完后，我拒绝后，那个历史能不能展示**第一轮所有信息**。而不是第一轮的计划。"

**结论：不能只靠"存得更多"解决，必须在"决策那一刻"先抓一份快照。** 两个硬约束决定了实现方式：

| # | 约束 | 证据 | 推论 |
|---|------|------|------|
| 1 | **spike 侧必丢** | `aidiag/diag/runner.py:117-121` —— 每次重跑都把 `raw_reply` / `tasks` / `tool_calls` / `conclusion` / `remediation` 全部清空 | 第一轮的结论在 spike 侧**不可恢复** → 必须在"动手之前"抓 `GET {diagnose_base}/status/{sid}`，落到 APM `problem_record.evidence`（唯一持久真源） |
| 2 | **列表是 5s 轮询 + `limit=500`** | `js/app.js` 的 `refresh()`（`/v1/problems?limit=500`）+ 5s `setInterval`；APM `list_problems` 逐条回传完整 `evidence` | 快照直接塞进 evidence 会让每 5 秒一次的轮询包体膨胀 → **快照必须从列表响应里剥掉**，只在详情 `GET /{id}` 与只读端点 `GET /{id}/diagnose/decisions` 返回全量 |

**用户已拍板**：粒度 = **全量快照**（根因 + 总结 + 全部方案 + 分析链路含工具调用/证据链/原始 JSON）；
范围 = **拒绝 / 忽略 / 误报三种都存**（会话过期抓不到 → 降级显示，不报错）。

**跨三仓改动**：UI（本仓）→ APM（`aiops-apm-anomaly-detector`）→ spike（`aiops-agent-orchestration-spike`，**零代码改动**）。

---

## 改动明细

### 1. spike — **零代码改动**，仅补文档

`GET /status/{session_id}` 返回的 `SessionStore.snapshot()` 已含所需全部字段
（`tasks` / `tool_calls` / `conclusion` / `remediation_status` / `remediation_option` / 时间戳），无需加接口、无需加持久化。

`docs/TRACE_CODE_DESIGN.md` §3.2 末尾补一条：**APM 在决策那一刻先取一份 `/status` 快照做历史留档**
（三态都取、best-effort、抓不到降级），并写明 `runner.py:117-121` 是"必须抓在动作之前"的原因。

### 2. APM `src/aiops_apm/router/problems.py`

**(a) 新增出站 GET 助手 `_spike_get(request, path)`** —— 逐字镜像既有 `_spike_post`
（`settings.diagnose_base_url` + `OutboundGateway.validate_url` + `app.state.http_client`，
`httpx.HTTPError` → 502）。

**(b) 新增 best-effort 快照抓取 `_fetch_snapshot(request, session_id) -> dict | None`**

> 决策（拒绝/忽略/误报）是**带下游副作用**的动作（重跑 / 关单 / FPR 回写），抓快照只为历史留档——
> 网络抖动、会话已过期（404）、上游 5xx 都**不该让"关单"失败**。故吞掉所有异常，任何失败返回 `None`。

**(c) 体积护栏 `_bounded_snapshot(snap) -> dict`**（保证单次病态长输出撑不爆 MySQL JSON 行）

- 恒做：`conclusion.evidence[].supporting_text` 每项截到 **4000** 字符（唯一无界字段）；
- 若 `json.dumps` 后仍 **> 128KB** → 丢掉 `tool_calls`（保 `conclusion` / `tasks` 等），
  工具调用是最大头且可弃。

**(d) 决策端点 `decide_problem_diagnosis`** —— 两处顺序调整，其余分支逻辑一字未动：

- `recorded` 初始化字典加 `"snapshot": None`（保持条目形状统一）；
- **入参校验前置**：`reject` 的空 feedback 校验提到抓快照**之前**——避免为注定 400 的请求白出站一次；
- **在守卫之后（`sid` 已取出）、三种分支之前**插快照抓取：

  ```python
  snap = await _fetch_snapshot(request, sid)
  if snap is not None:
      recorded["snapshot"] = _bounded_snapshot(snap)
  ```

  必须在 `/remediate`、`/approve`、`/dismiss` **之前**——因为拒绝会立刻在后台重跑并推平整轮现场。

**(e) 列表剥离 `_strip_decision_snapshots(rec)`** —— `list_problems` 返回前，把每条记录里
`type == "diagnose_decision"` 的条目**浅拷贝并去掉 `snapshot`**（不改原记录）。
`diagnose_session` 等其他 evidence 原样保留。

**(f) 模块 docstring + 决策端点 docstring + `DiagnoseDecisionBody` 上方注释**：写清快照的来由、
必须抓在动作之前的原因（含 spike file:line）、以及"只在详情与 `/diagnose/decisions` 返回、列表剥离"的策略。

### 3. APM 测试

**`tests/test_problem_diagnose_decision_api.py`**（13 例 → 21 例）：

- 新增 `_status_snap()`（构造 `GET /status/{sid}` 200 的整轮快照）与 `_dismiss_ok()` 助手；
- 每条决策用例的 `CapturingHttp` 响应序列**最前面多插一个 `/status` 响应**；
- 断言**出站顺序**：
  - reject → `GET /status` → `POST /remediate` → `POST /approve`；
  - ignore / false_positive → `GET /status` → `POST /dismiss`；
- 断言落库的 `evidence[].snapshot`（含 `conclusion.root_cause`、`conclusion.summary`、`tasks`、`tool_calls`）；
- 新增 **`/status` 抓不到不阻断决策**：
  - reject：`/status` 404 → 仍 200、`snapshot is None`、降级路径仍靠 `steps`；
  - ignore：`/status` 与 `/dismiss` 同走 404 → 仍能关单、`snapshot is None`；
- 新增 **列表剥离**用例：列表响应里 `diagnose_decision` **无 `snapshot` 键**，同记录详情 `GET /{id}` **有**，
  `/diagnose/decisions` **有**；`_strip_decision_snapshots` 不改写源记录（纯函数用例）；
- 新增体积护栏纯函数用例：`supporting_text` 截到 4000；超 128KB 时丢 `tool_calls` 但保 `conclusion` / `tasks`。

### 4. UI `js/app.js`

- **抽出 `dgxConclusion(c)`**（**纯重构，零行为变化**）：把 `renderDiagnosis` 内联的
  「根因卡片（含置信度 / deployed / base / 已修复于 / base_note）+ 总结卡片」搬进新函数，
  `renderDiagnosis` 改为调用它——**live 与历史快照从此共用同一套结论渲染**。
- **`dgxFixOptions(opts, opts_)` 新增「平铺模式」** `{ flat: true, highlight: N }`：
  不渲染分页签，**所有互斥方案依次铺开**（各带 `方案N · 标题` 头），`highlight`（1-based）那一个
  标 `本轮被拒` 中文胶囊 + `.is-rejected` 左边框高亮。
  **live 路径不传 `opts_` → 行为零变化**（`dgxOptSel` 分页签逻辑原样保留，平铺分支不碰该全局）。
  理由：互斥关系在"当时"已由用户裁决，历史里再把 2 选 1 藏进分页签就看不出被拒的是哪一版。
- **`dgxChain(snap, openFlag, hist)`**：加后两参（缺省 `openFlag = dgxChainOpen`，保持 live 轮询重渲染不塌）；
  `hist=true` 时多加 `.dgx-chain--hist` 类。
- **toggle 捕获处理器**加一条早退：`if (t.classList.contains('dgx-chain--hist')) return;`
  —— 防止历史条目的链路开合**污染 live 的 `dgxChainOpen`**（否则看一次历史，下一个 5s 轮询会把 live 链路也展开）。
- **新增 `dgxHistSnapshot(snap, rejectIdx)`**：历史条目里的"整轮"渲染 =
  状态头（复用 `DGX_STATUS_LABEL` 中文胶囊 + 来源 / session / 耗时，同 `renderDiagnosis` 头部规矩）
  → `dgxConclusion(c)` → `dgxFixOptions(opts, {flat:true, highlight:rejectIdx})` → `dgxChain(snap, false, true)`。
  全部经 `dgxEsc`。
- **改 `dgxPlanHistory()`** 条目 body 顺序：
  1. **拒因**（`feedback`，保留现有渲染）；
  2. `it.snapshot` 存在 → `dgxHistSnapshot(it.snapshot, it.option_index)`；
     **否则降级**为现有渲染（`it.steps` via `dgxOptionBody`）+ 一行灰字「该轮快照不可用（诊断会话已过期）。」；
  3. 驳回次数页脚（保留）。
  - summary 仍是 `#N 方案X · option_title` + 决策胶囊 + 时间（**不动**）。
  - `steps` **继续存**（快照里虽也有，但"被拒的那一版"以 `steps` 为权威，且是降级路径的唯一来源）。

## 未覆盖项 / 后续

- **浏览器实测未做（诚实声明）**：历史条目的真实点击链路未在浏览器里跑过。理由：那会真实消耗 LLM 重跑诊断，
  且会改动真实演示单（`PR-20260907-1003`）的状态。逻辑由 APM 21 例单测覆盖 + node 渲染走查覆盖。
  **建议用户自跑**：`PR-20260907-1003` 点「拒绝」→ 重跑完成后，展开历史条目应看到第一轮的
  根因 / 总结 / 两个方案（被拒的那个标「本轮被拒」）/ 分析链路；另验 spike 重启（会话过期）后点「忽略」
  → 仍能关单，历史条目降级显示 + 「该轮快照不可用」。
- **历史快照是一次性留档，不随第二轮变化**：抓的就是决策那一刻的 `/status`。若第二轮产出新结论，
  它只出现在 live 视图；再拒绝一次才会再留一条历史——这是"逐版留档"的本意，不是缺陷。
- **`session.raw_reply` 不在快照里**：`SessionStore.snapshot()` 本就不返回它（模型原始回复），
  历史里能拿到的是**结构化**的结论/任务/工具调用/证据链。若将来需要原始回复，得改 spike 的 `snapshot()`。
- **表格行的 `Ignore` 按钮命名坑（已知不动，沿用 v1.20.0 结论）**：`js/app.js` 表格行的 `Ignore` 语义上就是"误报"
  （发 `/resolve {false_positive:true}`），与弹窗内的「忽略」（`state=closed`）同名不同义。
  已与用户确认：**先放那，后续改到那块流程时再一并处理**。
- 三仓改动**均未 commit**。
