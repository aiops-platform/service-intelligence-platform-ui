# v2.0.0 — Vue 化第 4 步：路由接管导航

**日期**: 2026-09-11

**需求背景**: 承接 `v2.0.0-vue-api-layer.md`（S3）。S2 的外壳导航是**直连**的（点侧边栏直接调
`__SIP_SHOW_PAGE`），URL 不变化、刷新回首页、跨页下钻靠 `sessionStorage` 传参。
本步接入 Vue Router：URL 成为唯一真源，可分享、可刷新、可前进后退。

---

## 改动明细

### 1. `src/router/index.js` — 新增

**路由表**（扁平，不做嵌套 —— shell 只渲染一次，视图都是叶子）：

- `/` → 重定向到 `/service-ops`
- `flattenItems()` 产出的每个叶子 → `/<slug>`，`meta` 带 `panelId` / `legacy` / `label`
- **`STANDALONE_PAGES`**：`service-ops`（域概览页，**不在任何侧边栏里**，见坑 1）
- **`emptyDomainRoutes`**：5 个空壳域各自的 `/constellation`、`/finops` …（见坑 2）
- `/:pathMatch(.*)*` → 兜底落到默认页（改造前任何未知入口也都落到 Service Ops）

**历史别名**：`/agents` → `agent-registry`、`/reflow-log` → `knowledge-reflow-log`，
由 `SLUG_ALIASES` 生成 `alias` 字段，旧链接不会 404。

**切页守卫**（替代改造前 `showPage()` 的调用点）：

```js
router.afterEach(async (to) => {
  if (!to.meta.legacy) return
  await ensureLegacyBooted()
  window.__SIP_SHOW_PAGE?.(to.meta.panelId)
})
```

旧世界的 10 处 `_pageRefreshers` 注册**原样保留生效** —— 它们挂在 `showPage` 内部，
这里只要把 panelId 递过去即可，**不需要改那 10 处**。

**接缝 S3 的落点** `installLegacyBridge()`：把旧代码的 `navigateToPage(pageId, context)`
接到路由上，`context` 变成 URL query：

```js
window.__SIP_NAVIGATE = (pageId, context) =>
  router.push({ path: `/${slugOf(pageId)}`, query: context || {} })
```

### 2. `src/router/nav.js` — 补 `resolveSlug()` / `slugFromPanelId()`

路由参数、旧代码传来的 `page-xxx`、历史别名（`agents`）都要能吃进同一个入口并归一到规范 slug。

### 3. `src/App.vue` — 改为完全由路由派生

```js
const activeSlug = computed(() => resolveSlug(route.path.slice(1)) || DEFAULT_SLUG)
const activeKey  = computed(() => route.meta.domainKey ?? navKeyOf(activeSlug.value) ?? 'service-ops')
```

不再有任何"当前选中的域"的组件内状态。`<LegacyPanels v-show="isLegacyRoute">` 与
`<RouterView v-if="!isLegacyRoute">` 并存 —— 后者在 S6/S7 两个视图迁移后才有内容。

### 4. `src/main.js` — 挂载前先 `installLegacyBridge()`

必须在 mount 之前装好 —— 未迁移的视图可能在首屏就触发跨页下钻。

## 踩坑记录

### 坑 1：无限重定向（`Maximum call stack size exceeded`）

首版路由表只由 `flattenItems()` 产出。但 **`service-ops`（域概览页）不在任何侧边栏分组里** ——
它只能由默认值和顶部导航落过来。于是 `/service-ops` 匹配不到任何路由 → 落到 catch-all →
重定向回 `/service-ops` → **无限循环，整个应用白屏**（`#app` 内容为空，`.nav-item` 数为 0）。

修法：显式补 `STANDALONE_PAGES`。这个 bug 说明「路由表从导航树派生」有一个隐含假设 ——
**导航树 ⊇ 页面集合**，而本仓恰好不成立（概览页不在导航里）。

### 坑 2：组件内覆盖状态与 URL 两套真源打架

空壳域（Constellation / FinOps / …）点进去要落到 service-ops 概览，但顶部高亮与 footer
文案要停在被点的域上。首版用一个 `domainOverride` ref 覆盖，配 `watch(activeSlug)` 在正常
导航时清掉。结果点 FinOps 时：`domainOverride='finops'` → `router.push('/service-ops')` →
watcher 触发把它清成 `null` → 高亮域变回 `service-ops`。

**症状是会"半对"**：页面标题正确显示 `FinOps`（接缝 S9 已执行），但侧边栏没有隐藏
（旧版走 `hideAllSidebars()`，应显示 0 个）。这种"一半对"的错位比全错更难发现。

修法：**给空壳域各自一条路由**（`/finops` → 面板仍指向 `page-service-ops`，`meta.domainKey='finops'`），
高亮/footer/标题全部由路由派生，删掉覆盖状态。顺带让这些域可分享、可刷新。

同时补了**标题还原**：离开空壳域时把 service-ops 的原始标题写回（首次进入时留底），
否则标题会一直停在最后点过的域名上。
