# v2.2.20 — "待审批"从 In Progress 里拆出来；详情弹窗的 run 行改用派生状态

**日期**: 2026-09-20

**问题/背景**: 承接 v2.2.19。有人问「如果是等待审批，在列表页面是什么状态？」——
一查，答案是 `running`。这和 halted 被算成 success 是**同一类错误**：
把一个"不动了、在等人"的状态藏进了"进行中"。

而且 `waiting_approval` 比 halted 更该被看见 —— **它是唯一一个卡在用户手里、
只有用户能推进的状态**。藏在 In Progress 里，等于让审批躺在队列里没人知道。

---

## 改动明细

### 1. `src/views/tickets/useTickets.js` — 从 `RUN_ACTIVE` 里摘掉 `waiting_approval`

```js
// before
const RUN_ACTIVE = new Set(['running', 'pending', 'queued', 'paused', 'waiting_approval'])

// after
/**
 * run **确实在往前走**的状态。
 * ⚠️ `waiting_approval` **不在**这里：它不动了，在等人。
 */
const RUN_ACTIVE = new Set(['running', 'pending', 'queued'])
```

判定顺序也有讲究，必须**排在 `RUN_ACTIVE` 之前**：

```js
if (r.outcome === 'halted') return NEEDS_INFO
if (r.status === WAITING_APPROVAL) return WAITING_APPROVAL   // ← 新增
if (RUN_ACTIVE.has(r.status)) return 'running'
```

### 2. 展示值直接复用 `waiting_approval`，不新造枚举

`.alert-tag.status-waiting_approval`（琥珀 `#d97706`）**早就有**（工单详情里的
run 列表在用），"待审批"也是本仓既有措辞（Bug Solve 页的 `stepLabel`）。
新造一个 `pending_approval` 只会让同一个状态有两个名字。

### 3. `STATUS_FILTERS` + `counts` + KPI 卡片（6 列 → 7 列）

### 4. `TicketsView.vue` 详情弹窗的 run 行改用 `runStatusOf(r)`

这一处**原先直接用 `r.status`** —— 于是停在 halt 节点的 run 在弹窗里显示 `success`，
而同一张工单在列表列里显示"缺少必要信息"，**自相矛盾**。

## 影响范围

| 场景 | 预期 | 实际 | 状态 |
|------|------|------|------|
| `waiting_approval` | 显示"待审批"，不是 running | 待审批 | OK |
| `running`/`pending`/`queued` | 仍显示 running | running | OK |
| 停在 halt | 缺少必要信息 | 缺少必要信息 | OK |
| `success`/`failed` | resolved / failed | 一致 | OK |
| 筛选 chip | 有"待审批"，且与列表条数一致 | 有；counts 与 visible 同源 | OK |
| KPI 卡片 7 列 | 不挤压、不裁切 | 各 211px，`scrollWidth == clientWidth` | OK |
| 详情弹窗 run 行 | 与列表列不矛盾 | 改用 `runStatusOf` | OK |
| 生产构建 | 通过 | `npm run build` ✓ | OK |

## 未处理（同类问题）

- **`paused` 仍显示成 running。** pause 是**人按的**（`POST /runs/{id}/pause`），
  所以"已暂停"和"进行中"混在一起也有同样的误导，只是这个状态在演示里大概率不出现。
  要拆的话照本办法：从 `RUN_ACTIVE` 摘掉 + 一个 chip + 一张卡。
- **`new` 之外的状态在 KPI 卡里没有**（`new` 有）。目前只做了两个"等人"的状态。
