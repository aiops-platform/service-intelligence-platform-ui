# v2.2.9 — workflow 图：同一节点的多条出入边合并为共享主干

**日期**: 2026-09-20

**需求/背景**: 承接 v2.2.8 —— 对**同一节点**的多条出边（或入边）做**合并处理**，
减少线条数量。

v2.2.8 把同一节点的多条边**均分**到该边沿（下沿/上沿各占一段），
于是扇出 7 条的节点底部拖着 **7 条线头**，看着就是一束毛边；入边同理（7 条线汇入顶部 7 个点）。

---

## 改动明细

### 1. `src/components/graph/useGraphCanvas.js` — 去掉锚点均分，改为每节点一根主干 (148)

**原因**: 线头太多。

```js
// before：每条边各自在节点下沿/上沿分配一个锚点
const anchorX = (p, idx, total) => p.x + (NODE_W * (idx + 1)) / (total + 1)

// after：同一节点全部走底部中心，实测就是"合并"
const cxOf = (nid) => pos[nid].x + NODE_W / 2
```

### 2. `src/components/graph/useGraphCanvas.js` — 主干各画一次 + 分支另画

**原因**: 主干若每条边各画一遍，等于 N 条线段完全重叠——**视觉上是合并了，
但 DOM 里是重复的**，且几何检查器会当成 N 条独立线。

```js
// 主干：每个有出/入边的节点各一根，只画一次（箭头在入主干上）
if (hasOut[n.id]) html += `<path d="M ${cx} ${p.y + NODE_H} V ${p.y + NODE_H + halfGap}"/>`
if (hasIn[n.id])  html += `<path d="M ${cx} ${p.y - halfGap} V ${p.y}" marker-end="..."/>`

// 分支：主干末端 → 目标上方的入主干起点
html += `<path d="${edgePath(e.from, e.to, cxOf(e.from), cxOf(e.to))}"/>`
```

### 3. `src/components/graph/useGraphCanvas.js` — `edgePath` 改为「主干末端 → 入主干起点」 (212)

**原因**: 首末竖段已由主干承担，分支只需负责中间部分。

**关键性质**：相邻层时主干末端与入主干起点**恰好重合**
（`yOut == yIn`，都是层间空档中线），分支退化成一条横线 ——
竖段全部由两根主干承担，这是最省线的形态。

---

## 踩坑记录

### 计数的口径要分清

改完 DOM 里的 `<path>` 数**反而从 32 涨到 65**（主干 33 + 分支 32）。

「减少线条数量」减少的是**视觉上的线头**（节点上下从"一束"变成"一根"），
**不是 DOM 节点数**。分支各自通往不同目标，那部分省不掉；主干取代的是原先各自独立的竖段。

验证时用的几何检查器第一版正则写成 `<path class="bs-edge" d="`，
只匹配到主干（分支是 `class` 后跟 `fill` 再跟 `d`），**数少了还不报错**——
改成 `<path class="bs-edge"[^>]*\sd="` 才是全部 65 条。
