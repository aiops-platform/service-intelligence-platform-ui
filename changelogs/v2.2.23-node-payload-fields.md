# v2.2.23 — 节点入参/输出按字段展示，长值可折叠

**日期**: 2026-09-21

**需求/背景**: 用户指出两件事 ——
「一个流程节点有多个输入，现在只显示了一个输入，其它没有显示。」
「流程节点的输入输出不要直接输出 json 格式，将 json 内容按字段正常展示。」

第二句是第一句的解法。

---

## 根因：`<pre>{{ JSON.stringify(...) }}</pre>` 等于没展示

实测 `run_d8f3a5c560` 的 `rca` 节点：

```
{
  "code": "目标服务来源：…（1063 字）",
  "logs": "…", "trace": "…", "infra": "…", "metrics": "…", …
}
```

**后端没问题** —— `rca` 声明 9 个入参，落库的 9 个都在
（`code/know/logs/infra/trace/metrics/end_time/start_time/scope_primary`）。
问题是 `code` 一个值就占满整个面板，其余 8 个被顶到几百像素之外。

> 排查记录：一开始我以为是后端的 join/params 问题，先打了 API 才确认
> **9 个 key 都在** —— 那就是纯渲染问题。**先看数据再看 UI**，别反过来猜。

这不是排版瑕疵，是**误导**：读的人会以为这个节点只收到一个输入。
而"这个节点收到了什么"恰恰是排查 workflow 时最常看的东西。

## 改动明细

### 1. `src/components/graph/NodePayload.vue`（新增，递归）

两件事一起做，**缺一不可**：

1. **一行一字段**（键在左、值在右），不再是一个 JSON 大块；
2. **长值默认折叠**（> 200 字符或 > 4 行），点「展开（N 字符）」看全文。

只做 ① 不够：一行一字段之后，那个 1063 字的值依然占满屏幕，其余字段照样看不见。
实测折叠把面板从 **1720px 压到 612px** —— 9 个字段一屏看全。

其余规则：

- 对象 → 递归（左侧一道细线标层级）；数组项 → `#1 #2` 编号；
- 数组里的长字符串**同样折叠**（`notable[].error_message` 就是这种）；
- `null`/`undefined` → `—`（灰斜体），空数组/空对象 → 「（空）」。
  **不显示成空字符串**：那分不清"没有这个字段"与"字段是空串"。

### 2. 三处 `<pre>` 全部替换

| 位置 | 原样 |
|---|---|
| Run 详情 · 节点详情 | `<pre>{{ JSON.stringify(...) }}</pre>` |
| Run 详情 · 待审批的 upstream | 同上 |
| Bug Solve · 节点详情 | 同上 |

配套：`useRunDetail.js` / `useBugSolveRun.js` 的 `detail` 计算属性**改为传对象本身**
（原先在这里 `JSON.stringify`，再由 `<pre>` 直出）。`(无输出)` / `(执行中…)`
这两种"不是数据"的情况改用独立的 `isRunning` 标志 + 文案 div。

### 3. `css/styles.css` — `.bs-payload*`（14 条规则）

键列固定 96px + 右对齐：值从同一条竖线开始，扫读时不用左右找。
折叠用 `-webkit-line-clamp: 4`。

## 踩坑记录：Vue 的 `v-for` 在数组上第二个参数是**下标**

第一版写成：

```html
<div v-for="(v, k) in entries" :key="k">   <!-- entries = Object.entries(obj) -->
```

`entries` 是**数组**，于是 Vue 把 `k` 当**下标**、`v` 拿到 `[key, value]` 整对。
结果是页面上 9 行齐全、看着挺像回事，但**键名列全是 `0/1/2…`**、
值列把"键名+值"当数组又展开了一遍。

**肉眼只觉得"有点怪"，是 CDP 打印 DOM 才看清的**（`title="0"` / 内部是
`bs-payload-arr` 而非 `bs-payload-clamp`）。改成显式的 `{ k, v }` 数组。

教训：这类"渲染出来了但渲染错了"的问题，**看截图/看文字都可能骗过去**，
把 DOM 打出来看结构才作数。
