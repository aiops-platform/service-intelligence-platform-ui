# v2.6.3 — 修表头排序：占位行撞 `undefined` 抛异常导致整体失效；数字列判据不再写死列号

**日期**: 2026-09-22

> 本文行号为**改动后**的文件。

**问题**: 「点这个表任意表头排序都会抛 `TypeError` …… 异常发生在 `sort` 比较器里，
后面的重排根本没执行，于是**排序整体失效**（只要行数不是 10 的倍数就复现）」——
改 Diagnosis Center 列表列数时顺带发现并修掉。这是**既有缺陷**（`git stash` 回到改动前同样复现），
不是本次加列引入的。

两个根因叠在一起，且**都不报错到用户看得见的地方**：

1. **占位行参与排序**。凑高度的行是「整行一个跨列格」
   （`<tr class="alert-empty-row"><td colspan="N">&nbsp;</td></tr>`），只有 1 个子格。
   跟数据行一起排时 `a.children[colIndex]` 对它取到 `undefined` → 抛 TypeError。
   致命之处在于**异常发生在 `Array.sort` 的比较器内部**：`sort` 抛了就往下走不了，
   紧随其后的 `rows.forEach(appendChild)`（真正的重排）**整段不执行**。
   现场表现是「点表头没反应」，只有控制台留一条报错 —— 看起来像"这张表不支持排序"。
2. **数字列的判据是写死的列号 `[0, 4, 5, 6]`**。那份名单是给某一页的
   `# / Incidents / Bot % / Risk` 配的，换一页就错位。在 Diagnosis Center 上：
   First Seen 恰好落在 6 → `parseFloat("2026/09/22 12:54:22") === 2026`，整列相等
   → **点了纹丝不动**；而 Severity/State 落在"数字"分支上更是纯属瞎排。

修完之后这两个症状都没了（见下方实测）。

## 改动明细

### `js/app.js:2534-2620` — 重写 `initTableSorting()` 的比较与分流逻辑

**为什么动这个共用函数**: 它是 `legacyRoot()` 下**所有** legacy 表格共用的表头排序
（`init()` 里对每个 `th` 绑一次），缺陷在函数本身，不在某一张表。

```js
// before —— 拿全部 tr 一起排，且按写死的列号决定走不走数字分支
var rows = Array.from(tbody.querySelectorAll('tr'));
rows.sort(function (a, b) {
    var aVal = a.children[colIndex].textContent.trim();   // ← 占位行在这里抛 undefined
    var bVal = b.children[colIndex].textContent.trim();
    if ([0, 4, 5, 6].indexOf(colIndex) !== -1) {          // ← 换个页面就错位
        var aNum = parseFloat(aVal.replace(/[,%]/g, '')) || 0;
        ...
    }
    ...
});
rows.forEach(function (row) { return tbody.appendChild(row); });   // ← 抛了就永远到不了

// after —— 先按结构把占位行摘出来，再逐列判定是不是数字列
var dataRows = [], fillerRows = [];
Array.from(tbody.querySelectorAll('tr')).forEach(function (row) {
    var only = row.children.length === 1 ? row.children[0] : null;
    ((only && only.colSpan > 1) ? fillerRows : dataRows).push(row);   // 整行一个跨列格 = 占位行
});
var cellText = function (row) {                                       // 缺格给空串，绝不抛
    var cell = row.children[colIndex];
    return cell ? cell.textContent.trim() : '';
};
var leadingNum = function (v) {                                       // 「数字 + 后缀」拆开看
    var m = /^[+-]?[\d,]+(\.\d+)?/.exec(v);
    return m ? { n: parseFloat(m[0].replace(/,/g, '')) || 0, rest: v.slice(m[0].length) } : null;
};
var parsedCells = dataRows.map(cellText).map(leadingNum);
var head = parsedCells[0];
var numeric = !!head && parsedCells.every(function (p) { return p && p.rest === head.rest; });
...
dataRows.concat(fillerRows).forEach(function (row) { return tbody.appendChild(row); });  // 占位行回表尾
```

三个决定的理由：

- **占位行的判据用「整行只有一个跨列格」，不比对表头格数**。分组表头那种多行 `thead`
  会让"表头格数"与数据行格数对不上，把数据行误判成占位行 —— 那又是一次静默失效。
- **占位行排在最后**（`dataRows.concat(fillerRows)`）：它们本就是垫底补白的，位置无所谓，
  但不能被排到数据行中间去。
- **数字列判据 = 整列都是「一个数字 + 同一个后缀」**。后缀相同这一条是关键：
  - `'120s' / '9s' / '60s'`（带单位）→ 数字序 9s < 60s < 120s ✓
  - `'95%' / '3%' / '12%'` → 数字序 ✓（字符串序会给出 12% < 3% < 95%，是错的）
  - `'1,234' / '9,876' / '500'` → 数字序 ✓（千分位先剥掉）
  - `'2026/09/22 12:54:22'` 这类**以数字开头**的日期 → 后缀各不相同 → 回落字符串序
    （定宽 `YYYY/MM/DD HH:MM:SS` 的字典序正好是时间序）✓
  - 有值时有时无（如 `'120s' / '9s' / '-'`）→ 回落字符串序，不抛 ✓

## 踩坑记录

1. **第一版判据（"整列都是纯数字"）把带单位的值判成了字符串，反而把原本正确的列改错**。
   写死的 `[0,4,5,6]` 虽然换页就错位，但在 Monitor Targets 上 `Interval` 恰好落在 5，
   于是 `'120s'/'9s'/'60s'` 一直是按数字排的（`parseFloat` 剥掉单位）——我的第一版用
   `^[+-]?[\d,]+(\.\d+)?%?$` 严格匹配，把带 `s` 的那些判进字符串分支，
   排序结果从 `9s,60s,120s` 变成 `120s,60s,9s`：**一次静默的行为倒退**。
   改成「数字 + 同一个后缀」后，带单位列走数字、日期列走字符串，两者都对。
   ——教训：改一个"判据类"的公共函数，要拿**每一页的真实值形态**回测，不能只测自己那页。

2. **测排序容易被"上一条用例的排序方向"串味**。`initTableSorting` 的方向靠 `th` 上的
   `sorted-asc`/`sorted-desc` 类记忆：同一条用例里连点两次是"升→降"，但**跨用例复用同一个页面**
   时，第一次点击会接着上一次的方向继续翻，于是"首次点击"读出来的顺序是反的，
   很容易误判成"分支选错了"。第一轮矩阵测试就是这么被误导的（三种分支的解释都能对上，
   反而看不出问题）。**每个用例重新 `Page.navigate`** 才看得准 —— 输出里那句
   `初始类=""` 就是这个前提的自检。

3. **两个已知但本次未做**（都摆在这儿，要做说一声）：
   - **排序会被 5s 轮询冲掉**：Diagnosis Center 每 5s 静默 `refresh()` → `renderTable()`
     按后端顺序整段重建 tbody，DOM 级排序**最多存活 5s**。实测：点 Ticket 升序后排成
     `-,-,-,-,-,-,INC-…001,INC-…001,INC-…002`，6.5s 后回到后端顺序（`survived = false`）。
     要留住排序，得把排序状态提到 `initProblems` 的模块级、在 `renderTable()` 里对
     `filteredProblems()` 排完再分页（顺带能让排序作用于**全部 500 条**而不是当前这一页 ——
     现在只有当前页的 10 行在 DOM 里）。
   - **`escapeHtml` 不转义引号**（`js/app.js:24`，用 `div.innerHTML` 实现，文本节点里引号合法）。
     当它被用在**属性值**里就出事：`title="' + escapeHtml(title) + '"` 遇到标题含 `"`
     会被撑破，实测 Problem 列 `title` 属性实际值只剩 `Cannot invoke `（后半截成了另外几个
     伪属性），于是「hover 看全量标题」这个功能对这类标题失效（单元格文本不受影响）。
     修法是让 `escapeHtml` 一并转义 `"`/`'`，但它有约百处调用方，影响面比这次两个 changelog
     都大，故未擅动。
