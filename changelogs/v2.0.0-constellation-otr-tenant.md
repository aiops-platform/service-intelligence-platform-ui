# v2.0.0 — Constellation 新增 `otr` 租户（内容复制 `mb-retail`）

**日期**: 2026-09-16

**问题/背景**: `otr` 是 agentflow 侧统一使用的租户名（`src/api/config.js` 的
`DEFAULT_TENANT = 'otr'`，后端 `--tenant otr`），但 Constellation 内嵌的那套 Next.js
应用里**没有这个租户**——它只有 11 个（`retail` / `mb-retail` / `banking` / …）。
两边租户名不一致，看同一份数据要换名字。**需要 `otr` 能看到与 `mb-retail` 完全一样的数据与页面。**

---

## 排查过程中的一个反直觉结论（先记下来）

**`?tenant=xxx` 加在 SIP 父页面上是无效的。**

```
src/views/constellation/ConstellationView.vue   <NextEmbed src="/constellation-app.html" />   ← 字面量，不转发查询串
src/components/NextEmbed.vue:49,92              src 是普通字符串 prop，直接 :src="src" 绑到 iframe
```

iframe **不继承父页面的查询串**，它只读自己的 `window.location.search`。所以

```
http://localhost:5173/constellation?tenant=mb-retail      ← ❌ 无效
http://localhost:5173/constellation-app.html?tenant=mb-retail   ← ✅ 有效（直接开 iframe 的 URL）
```

激活租户的判定逻辑（从 bundle 里抠出来的原文）：

```js
let e = new URLSearchParams(window.location.search).get("tenant");
if (e && e in tg) { localStorage.setItem("sip-active-tenant", e); return e }
let t = window.localStorage.getItem("sip-active-tenant");
if (t && t in tg) return t
return "retail"        // 兜底
```

**三种切换方式**（同源，localStorage 共享）：① 直接开 `/constellation-app.html?tenant=otr`；
② 控制台 `localStorage.setItem('sip-active-tenant','otr'); location.reload()`；
③ 图内切换器（三击 `>accenture` 或 `Shift+S`）。

## 改动明细

### 1. `tools/tenant-data/otr.json` — 新增覆盖文件

**原因**: 走**已有的加租户流程**（`tools/tenant_data.py`），不手改 bundle。
`tenant-data/` 是覆盖目录，文件名即租户 id；`apply` 时把该目录下所有 json 写回 bundle。
`mb-retail.json` 已在该目录——同事加 mb-retail 时用的就是这条流程。

```bash
cp tenant-data/mb-retail.json tenant-data/otr.json
```

**只改 6 个身份字段，内容一字不动**：

| 路径 | before | after |
|---|---|---|
| `tenant.id` | `"mb-retail"` | `"otr"` |
| `tenant.name` | `"MB Retail"` | `"OTR"` |
| `tenant.demoTitle` | `"… · MB Retail"` | `"… · OTR"` |
| `tenant.client.displayName` | `"MB Retail"` | `"OTR"` |
| `tenant.client.ticker` | `"MBR"` | `"OTR"` |
| `snapshot.source.db` | `"design:mb-retail@1"` | `"design:otr@1"` |

**不动**：`snapshot.apps`(50) / `portfolios`(11) / `journeys`(2) / `portfolioEdges` / `facts` /
`brand`（品牌色 `#00adef` 保留）。改动前后对 `apps+portfolios+journeys+edges+facts`
取 sha256 校验，**指纹一致**（`fb8328f2…`）——这是"只改身份字段"的机器证明。

### 2. `public/_next/static/chunks/0wuztp2.9oz~8.js` — `apply` 写回

**原因**: 租户数据住在该 chunk 的模块 89784（`t.exports = JSON.parse('{...}')`）。

```bash
cd tools && python3 tenant_data.py check     # ✓ mb-retail.json (50 apps) / ✓ otr.json (50 apps)
cd tools && python3 tenant_data.py apply     # 覆盖租户：mb-retail / 新增租户：otr
```

`write_bundle` **原地改写**（只动 JSON 字符串那一段，其余字节保留）。
文件 4,580,289 → **4,623,929** 字节。

### 3. `public/_next/static/chunks/0aed4f89z1emu.js` — 切换器清单追加 `otr`（line 末）

**原因**: 租户切换器的下拉列表**不在数据 bundle 里**，而是硬编码在这个 chunk：

```js
[…,{"id":"mb-retail","label":"MB Retail","industry":"Automotive Retail","client":"MB Retail"}]
                                                                                     ↑ 在这里追加
     {"id":"otr","label":"OTR","industry":"Automotive Retail","client":"OTR"}
```

**不做这步 `?tenant=otr` 也能工作**（激活判定读的是数据模块的 `ALL_TENANTS`），
只是下拉里不列出 OTR。

插入锚点 `"client":"MB Retail"}]` 在文件里**只出现一次**，插入后 38,034 → 38,107 字节。

### 4. `public/_next/static/chunks/0wuztp2.9oz~8.js` — 兜底租户 `retail` → `otr`

**原因**: 本项目**统一用 `otr`**（与 agentflow 侧 `X-Tenant-ID` / `--tenant otr` 一致），
并把它设为**默认租户**——不传参数、localStorage 无值时打开就是 OTR。

```js
// 激活判定的兜底（该 chunk 内唯一一处）
…}catch{}return"retail"}()   →   …}catch{}return"otr"}()
```

等长替换不成立（`retail` 6 字符 vs `otr` 3），文件 4,623,912 → **4,623,909** 字节（−3）。
`return"retail"` 在**全部 chunk 里只出现一次**，替换前做了唯一性断言。

### 5. `tools/README.md` — 「切换租户」一节重写

**原因**: 原文档写的兜底是 `retail`、租户数写「10 个」，都已过时；且**缺 DevTools 方法**。
新增/更正：

- 解析顺序里的兜底改为 `otr`，并注明「统一用 otr」
- **新增「用 Chrome DevTools 改 localStorage 切租户」整节**（Application → Storage →
  Local Storage → `sip-active-tenant`；或 Console 一行 `localStorage.setItem(...); location.reload()`），
  含**为什么必须刷新**（激活判定在模块初始化时跑一次，不是响应式）
- **新增「`?tenant=` 必须加在 iframe 自己的 URL 上」警告**（父页面上静默失效的说明，
  标注「已知行为，暂不修」）
- 图内切换器的三种触发方式；租户清单 10 → **12**，标出默认项

## 踩坑记录

1. **一开始把 `?tenant=` 加在父页面**验证，结论是"数据没更新"——**方向错了**。
   真因是 iframe 不继承父页面查询串（见上）。这个坑值得单独修，见"未做"。
2. **正则误判租户清单**：旧条目是 `{id:"..."`（无引号），同事加的 mb-retail 是
   `{"id":"..."`（有引号）。用 `\{"id":"` 搜只能匹配到 1 条，一度以为"清单里只有 mb-retail"。
3. **`dist/` 是旧产物**（`dist/_next/...` 4,532,678 vs `public/...` 4,580,289 字节）。
   `:4173` 没在跑所以不影响；**用 `npm run preview` 前必须 `npm run build`**，否则旧数据。

| 场景 | 预期 | 实际 | 状态 |

| `0aed4f89z1emu.js` 语法 | 页面能渲染（该 chunk 参与 zod 校验） | `node --check` 通过 + `eval` 解析出 12 条 | OK |
| `0wuztp2.9oz~8.js` 语法 | 同上 | `node --check` 通过 | OK |
| 13 个静态资源 | 磁盘与 dev server 逐字节一致 | 13/13 一致 | OK |

**注意**：曾经切过别的租户的浏览器，`localStorage["sip-active-tenant"]` 里有旧值，

（或用 DevTools 把它改成 `otr`）。
