# v1.4.6 — 列表末列加英文列名 "Actions" + 删除改用 SIP 风格确认弹窗

**日期**: 2026-08-27

**问题/背景**: Monitor Targets 列表最后一列是操作按钮，但表头为空，缺少英文列名；且删除目标时使用浏览器原生 `window.confirm` 确认框，与 SIP 整体风格不搭。需求：表头加英文列名 **Actions**；删除确认改为适配前端样式的确认弹窗（SIP 风格，替代原生 confirm）。

---

## 改动明细

### 1. `index.html` — 列表表头末列加 "Actions"

**原因**: 操作列无列名。改动点：把 Monitor Targets 列表最后一行表头由空 `<th></th>` 改为 `<th>Actions</th>`。

### 2. `index.html` — 新增通用 Confirm Modal 结构

**原因**: 复用既有 `.ap-modal` 组件体系，新增 `#confirmModalOverlay`（`max-width: 420px` 窄卡片），标题「Confirm」+ 关闭按钮，正文 `#confirmModalMsg`，底部 `Cancel`（`.btn.btn-secondary`）+ `Confirm`（`.btn.btn-danger`）。

```html
<!-- Confirm Modal（通用确认弹窗，适配 SIP 风格） -->
<div class="ap-modal-overlay" id="confirmModalOverlay">
    <div class="ap-modal" style="max-width: 420px;">
        <div class="ap-modal-header">
            <h3 id="confirmModalTitle">Confirm</h3>
            <button class="ap-modal-close" id="confirmModalClose">&times;</button>
        </div>
        <div class="ap-modal-body">
            <p class="apm-confirm-msg" id="confirmModalMsg"></p>
            <div class="apm-confirm-actions">
                <button class="btn btn-secondary" id="confirmModalCancel">Cancel</button>
                <button class="btn btn-danger" id="confirmModalOk">Confirm</button>
            </div>
        </div>
    </div>
</div>
```

### 3. `css/styles.css` — 新增危险按钮与确认弹窗样式

- `.btn-danger`（红底白字，hover 降透明度）——通用危险操作按钮。
- `.apm-confirm-msg`（正文消息，`word-break: break-word` 防超长 ID 溢出）。
- `.apm-confirm-actions`（底部操作按钮右对齐 + `gap`）。

### 4. `js/app.js` — `confirmDialog`/`closeConfirm`/`runConfirm` 助手 + 事件接线 + 替换原生 confirm

**原因**: 通用确认弹窗逻辑：`confirmDialog(message, onConfirm)` 写入 `#confirmModalMsg` 并打开遮罩；`runConfirm()` 取出回调执行后关闭；`closeConfirm()` 关闭并清回调。事件接线：

- `#confirmModalOk` → `runConfirm`
- `#confirmModalCancel` / `#confirmModalClose` / 遮罩点击 → `closeConfirm`

删除分支由原生 confirm 改为：

```js
// before
if (!window.confirm('Delete monitor target ' + id + '? (soft delete, enabled=0)')) return;
// after
confirmDialog('Delete monitor target ' + id + '? (soft delete, enabled=0)', function () {
    apmApi('/v1/monitors/' + encodeURIComponent(id), { method: 'DELETE' })
        .then(function () { window._showToast('Deleted ' + id, 'success'); refreshList(); })
        .catch(function (err) { window._showToast('Delete failed: ' + err.message, 'error'); });
});
```

### 5. `js/app.js` — `showPage()` 同步关闭 Confirm Modal

**原因**: Confirm Modal 同样是 `position: fixed` 遮罩（z-index 10000），切页时若不关闭会残留盖住其他页面（与 `apmModalOverlay` 同款处理）。在 `showPage()` 里追加 `confirmModalOverlay` 的 `open` 移除。

---

## 踩坑记录

- **ID 三处必须一致**：`index.html` 的 `confirmModalOverlay` / `confirmModalMsg` / `confirmModalOk` / `confirmModalCancel` / `confirmModalClose` 必须与 `js/app.js` 事件接线逐一对应，少一个按钮 ID 会导致点击无响应（无报错）。
- **`runConfirm` 先取回调再关闭**：`closeConfirm()` 会清 `_confirmCb`，所以 `runConfirm` 必须先 `var cb = _confirmCb` 再 `closeConfirm()`，否则回调丢失。
- **Confirm Modal 复用 `.ap-modal` 但需窄宽度**：`.ap-modal` 基类 `max-width: 860px`，确认弹窗用行内 `style="max-width: 420px"` 覆盖，不引入额外 CSS 类。
