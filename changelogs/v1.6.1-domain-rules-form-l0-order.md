# v1.6.1 — Domain Rules 表单改为按漏斗顺序（L0 → L1 → L2 → L3）组织

**日期**: 2026-08-28

**问题/背景**: Domain Rules 的 New/Edit 弹出框里，规则区块顺序是 **DETECTORS → SUPPRESSORS → CORRELATION/VERIFY**，与检测漏斗的执行顺序相反（漏斗是 L0 抑制 → L1 检测 → L2 关联 → L3 验证），操作时容易在「抑制器放哪、检测器放哪」之间来回跳。本次把表单区块顺序调整为 **SUPPRESSORS (L0) → DETECTORS (L1) → CORRELATION (L2) → VERIFY (L3)**，让「添加/修改规则」这一动作按漏斗从 L0 到 L3 一路排下来。

---

## 改动明细

### 1. `index.html` — 域配置模态框区块重排 + 拆分 CORRELATION/VERIFY (index.html:1262-1308)

**原因**: 表单区块顺序需与漏斗 L0→L3 一致；原 CORRELATION/VERIFY 合并在一个区块，与「L2/L3 两个步骤」的认知不一致，拆成两个独立区块。

- SUPPRESSORS 区块**移到最前**并标注 `(L0)`（原在 DETECTORS 之后）。
- DETECTORS 区块排第二并标注 `(L1)`。
- 原「CORRELATION / VERIFY」合并区块拆为两个：`CORRELATION (L2)`（`dcMetricLogWindow`/`dcChangeWindow`）+ `VERIFY (L3)`（`dcPersistenceRounds`/`dcFpThreshold`/`dcMinSamples`）。
- 所有 input id（`dcSuppressors`/`dcDetectors`/`dcMetricLogWindow` 等）与按钮 id 保持不变，JS 渲染/收集代码无需改动。

```html
<!-- before：DETECTORS → SUPPRESSORS → CORRELATION/VERIFY（合并） -->
<div class="dc-section"><div class="dc-section-title">DETECTORS</div>...</div>
<div class="dc-section"><div class="dc-section-title">SUPPRESSORS</div>...</div>
<div class="dc-section"><div class="dc-section-title">CORRELATION / VERIFY</div>...</div>

<!-- after：SUPPRESSORS (L0) → DETECTORS (L1) → CORRELATION (L2) → VERIFY (L3） -->
<div class="dc-section"><div class="dc-section-title">SUPPRESSORS (L0)</div>...</div>
<div class="dc-section"><div class="dc-section-title">DETECTORS (L1)</div>...</div>
<div class="dc-section"><div class="dc-section-title">CORRELATION (L2)</div>...</div>
<div class="dc-section"><div class="dc-section-title">VERIFY (L3)</div>...</div>
```

### 2. `js/app.js` — `collect()` 载荷键序与表单一致 (js/app.js:4335-4350)

**原因**: 提交给 `PUT /v1/config/{domain}` 的 JSON 键顺序改为与表单展示顺序一致（L0→L3）。后端 pydantic 解析不依赖键序，此处仅保持读写两侧一致、便于对照排查。

```js
// before：detectors → suppressors → correlation → verify
return { detectors: ..., suppressors: ..., correlation: {...}, verify: {...} };
// after：suppressors → detectors → correlation → verify
return { suppressors: ..., detectors: ..., correlation: {...}, verify: {...} };
```

## 踩坑记录

- **只动 DOM 顺序，不动 JS 逻辑**：渲染（`renderDetectors`/`renderSuppressors`）、新增卡片（`addEmptyCard`）、收集（`collectDetectors`/`collectSuppressors`）、重置（`resetForm`/`newDomain`）、重编号（`renumberCards`）全部按容器 id（`dcDetectors`/`dcSuppressors`）操作，与区块在 DOM 中的先后无关，因此重排只改 `index.html` 一处 + `collect()` 键序即可。
- **区块标题加 `(L0)`/`(L1)`/`(L2)`/`(L3)` 标注**：直接对应漏斗步骤，避免后续维护者再对着 `domain-config-tutorial.md` 的 4 块映射去数。
