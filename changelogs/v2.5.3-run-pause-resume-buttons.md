# v2.5.3 — Run 详情加「暂停 / 恢复」，并让「已无执行者」看得见

**日期**: 2026-09-22

**需求/背景**: 「增加一个暂停流程的按钮，然后再加一个恢复按钮，通过这种方式重启流程。当流程正常完成或者 halt 之后，不能重启流程。」

---

## 解决的是什么

一条 run **卡在 `running` 却早已没有执行者**（Worker 崩溃/被杀）时，界面上和"正在跑"**长得一模一样** —— 只有"这条怎么半天没动"这种猜测。而它实际上：

- 不能被重新触发（后端接单 CAS 只从 `queued` 接）
- 不能被 resume（CAS 只从 `paused` / `waiting_approval` 接）
- 重启 Worker 也视而不见

**只能直接改库**（`UPDATE runs SET status='paused'`）—— 实测救过两条。

现在后端有了**执行租约**（Worker 执行期间持一个带 TTL 的键并续期，见
`multi-agent-workflow` 的 `d8ba814` / `5d0791d`），于是"有没有执行者"第一次可判定。

## 改动

### 1. `src/api/agentflow.js` — `runApi.pause` / `runApi.resume`

```js
pause:  (id) => agentflow.post(`/runs/${id}/pause`),
resume: (id) => agentflow.post(`/runs/${id}/resume`),
```

### 2. `src/views/runs/useRunDetail.js` — 三态存活判据 + 两个动作

```js
const executorAlive = computed(() =>
  run.value?.executor_alive === undefined ? null : run.value.executor_alive)
const looksStranded = computed(
  () => status.value === 'running' && executorAlive.value === false)
```

⚠️ **`executorAlive` 是三态**：`true` / `false` / `null`（判不了）。
`null` **绝不能**当 `false` 用 —— 那会在后端抖一下的时候把真在跑的 run 说成僵尸。
（`undefined` 归一成 `null`：后端没升级时字段不存在，也是"判不了"。）

`pause()` 会把后端的 `forced` 翻译成人话，两者对使用者意义不同：

| 后端 | 含义 | 提示 |
|---|---|---|
| `forced: false` | 跑完这个节点就停 | 「已请求暂停，当前节点跑完即停。」 |
| `forced: true` | **它其实早停了**，直接置的 paused | 「这条 run 已无执行者…点恢复可从断点续跑。」 |

### 3. `src/views/runs/RunDetailView.vue` — 按钮与提示

```html
<span v-if="looksStranded" class="alert-tag status-rejected">已无执行者</span>
<button v-if="status === 'running'" @click="pause">暂停</button>
<button v-if="status === 'paused'"  @click="resume">恢复</button>
<button v-if="running"              @click="stop">停止</button>
```

**「完成 / halt 之后不能重启」由后端保证**，前端不做额外判断：终态的 CAS 拦得住
（halt 的 run 是 `status=success` + `outcome=halted`，同在终态里）。前端只按
`status` 显示按钮 —— 终态时两个按钮都不出现。

---

## 影响范围

| 场景 | 预期 | 实际（CDP 实测） | 状态 |
|------|------|------|------|
| `running` + 有执行者 | 只显「暂停/停止」 | 按钮=暂停/停止/返回，无提示 | OK |
| `running` + **无执行者** | 显「已无执行者」+「暂停」 | 标签=`进行中` `已无执行者` | OK |
| `running` + **未知(null)** | **不显**僵尸提示 | 僵尸提示=False | OK |
| `paused` | 显「恢复」 | 按钮=恢复/返回，状态=`已暂停` | OK |
| 终态（success/failed/cancelled） | 两个按钮都不出现 | `status` 判据 | OK |
| 生产构建 | 通过 | `npm run build` ✓ | OK |

**真实数据验证**（不是造的）：那条卡了 4 天的 `run_dfa3801aee` ——
`GET` 返回 `status=running` + `executor_alive=false`，界面显示「进行中 / 已无执行者」；
后端 `POST /pause` 返回 `forced: true` 并把状态置为 `paused`。

## 验证方式

CDP 注入 patch `window.fetch` 造出 `running` + `executor_alive` 三态各一份，
**只动浏览器、后端零改动**，改前改后量同一组 DOM 指标。

> 三态那条是刻意单独验的：只测 `false` → 报僵尸、`true` → 不报，无法证明 `null` 没被
> 当成 `false`。而"未知被当成没有"正是会把真在跑的 run 判成僵尸的那个错误。

## 依赖

后端需提供 `GET /runs/{id}` 的 `executor_alive` 与 `POST /pause` 的 `forced`
（`multi-agent-workflow` `d8ba814`）。**后端未升级时**：字段不存在 → `executorAlive`
恒为 `null` → 僵尸提示不出现（保守，不会误报），暂停/恢复按钮照常可用。
