# v1.4.5 — Save 成功后关弹窗 + 列表按 created_at 时间倒序（后端排序）

**日期**: 2026-08-27

**问题/背景**: Monitor Targets 弹窗内点 Save 成功后，仅弹成功 toast 并刷新列表，**弹窗保持打开**（表单停留在 Editing 态）；且列表顺序依赖后端返回（InMemory 按插入序、MySQL 无 ORDER BY），新创建的 target 不保证在列表最上方。需求：保存成功后**关闭弹窗** + 成功提示 + 刷新列表且**新记录在最上（时间倒序）**；时间倒序由**后端查询 SQL 按 `created_at` 完成**，前端不做排序。

---

## 改动明细

### 1. `js/app.js` — `saveTarget()` 成功后关闭弹窗 (line 3815-3818)

**原因**: `.then` 里原来的 `currentTarget`/`setFormState` 簿记改为直接取 `savedId`，弹成功 toast 后 `closeModal()` 关弹窗并 `refreshList()`。`currentTarget` 保留无碍：下次 New 会走 `resetForm(true)`（内部 `currentTarget = null`），Edit 会走 `fillForm(t)` 重填。

```js
// before
if (data && data.target_id) { currentTarget = Object.assign({}, body, data); } else if (isEdit && currentTarget) { ... }
setFormState(currentTarget && currentTarget.target_id);
window._showToast(...);
refreshList();
// after
var savedId = (data && data.target_id) || (isEdit && currentTarget ? currentTarget.target_id : '');
window._showToast(isEdit ? 'Updated ' + savedId : 'Created ' + savedId, 'success');
closeModal();
refreshList();
```

### 2. 后端 `aiops-apm-anomaly-detector/src/aiops_apm/storage/monitor_targets.py` — 列表按 `created_at DESC` 排序

**原因**: 时间倒序下沉到存储层查询，前端不再自己排。改动点：

- `_PUBLIC_FIELDS` 增加 `"created_at"`，`_public()`（MySQL tuple 分支）增加 `"created_at": row[8]` —— `monitor_target` 表 V1 已有 `created_at DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3)` 列，无需迁移。
- **MySQL `list()`**：SELECT 补 `created_at` 列，加 `ORDER BY created_at DESC, id DESC`（`id` 兜底，保证同一毫秒内创建顺序也稳定）。
- **InMemory `create()`**：行内加 `"created_at": datetime.now(timezone.utc)`；`list()` 改为按 `(created_at, id)` 倒序后转 `_public`。
- MySQL `get()` / `load_all_targets()` 的 SELECT 同步补 `created_at`（`_public` 按 tuple 索引取第 9 列，漏加会越界）。

```python
# before（MySQL list）
SELECT target_id, service, signal_type, source_type, domain, source_config, schedule, enabled
FROM monitor_target WHERE tenant_id=%s
# after
SELECT target_id, service, signal_type, source_type, domain, source_config, schedule, enabled, created_at
FROM monitor_target WHERE tenant_id=%s ...
ORDER BY created_at DESC, id DESC
```

### 3. `js/app.js` — `refreshList()` 移除前端排序 (line 3876-3883)

**原因**: 后端已按 `created_at DESC` 返回，前端直接按序渲染；删除此前加的 `targetSeq()` 辅助函数与 `targets.sort(...)`。

```js
targets = (data && data.items) || [];   // 后端已排序，新创建的排最前
renderList();
```

## 踩坑记录

- **`created_at` 列 V1 已存在**：`monitor_target` 表 V1:82 定义 `created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)`，本次仅把该字段对外暴露并用于排序，**无新迁移**。
- **`_PUBLIC_FIELDS` 属存储层字段集**（非 M1 冻结的 models/fingerprint/plugins 契约），追加 `created_at` 为向后兼容的加字段；前端 `fillForm` 忽略未知字段，不受影响。
- **MySQL SELECT 列序必须与 `_public` tuple 索引对齐**：`_public` 取 `row[8]` 为 `created_at`，所有喂 `_public` 的 SELECT（list/get/load_all_targets）都必须补第 9 列，否则 tuple 索引越界。
- **同毫秒创建兜底**：MySQL 用 `ORDER BY created_at DESC, id DESC`；InMemory 用 `(created_at, id)` 元组倒序，均保证稳定排序。
