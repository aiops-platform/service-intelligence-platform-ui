# v1.11.2 — MCP Server 配置页：保存门控（必须先「测试连接」成功）+ 列表可用性 + 全部刷新

**日期**: 2026-09-03

**问题/背景**: v1.11.1（Monitor Targets 风格 + New 弹窗）后，保存流程原先设计为「Save 按钮内部
自动试连、失败即阻止」。用户走查后认为该流程「显得不是很好」，明确要求改成 **测试门控**：

> 新增或更新时，一旦修改/添加信息后 Save Server 按钮就**不可点击**；只有点「测试连接」且**测试成功**
> 后，才允许保存；按钮下方加提示/提醒。

由此最终形态：**Save = 需先通过一次针对当前表单配置的「测试连接」**，任何字段改动即把 Save 重新锁回、
要求重测；测试/保存中按钮禁用防重复；按钮下方常驻提示条实时反映状态（灰=需测试 / 琥珀=测试中 /
绿=可保存 / 红=测试失败无法保存）。

> 主要改动在 SIP 前端（`index.html` / `js/app.js` / `css/styles.css`）；后端仅沿用 v1.11.2 前置改动里
> 的 `multi-agent-workflow/agentflow/agents/mcp_manager.py` 一行错误文案可读性修复（`_exc_message` 递归
> 解开 `ExceptionGroup` → 失败提示露出真实根因如 `All connection attempts failed`），无行为变更、
> 后端测试不受影响。本版本另含上一轮已确认保留的两项列表增强：**tools=null 行可用性置灰** + **Probe All 全部刷新**。

## 改动明细

### 1. `index.html`
- Save Server 按钮改为 `.btn-secondary`（与「测试连接」同款配色，可点击时视觉一致；不再用黑色实心
  btn-primary）+ `disabled` 初值（index.html:1679，弹窗底部 `.apm-form-actions` 内）。
- 按钮行下方新增提示条 `#mcpSaveHint`（index.html:1683）：
  `请先点「测试连接」，测试成功后才能保存。`（`.mcp-save-hint`，JS 动态改文案/配色）。
- 页头 Probe All 按钮（`#mcpProbeAllBtn`，index.html:1560，Refresh 左侧）沿用上一轮。

### 2. `js/app.js` — `initMcpServers()`（init 于 app.js:5993）
- **状态**：新增 `tested`（当前表单是否已通过测试，Save 唯一解锁条件）(app.js:6002)、`testing`
  （测试请求进行中）、`dirtyWhileTesting`（测试期间表单被改动 → 该次结果作废）(app.js:6003-6004)。
- **门控辅助** (app.js:6328-6358)：
  - `MCP_FIELD_IDS`：11 个配置字段 id 名单（name/transport/stdio 三件套/http 三件套/enabled/
    enable_tools/disable_tools）。
  - `syncSaveBtn()`：`disabled = saving || testing || !tested`。
  - `setSaveHint(kind,msg)`：`.mcp-save-hint` + `-lock/-ok/-fail/-running` 配色。
  - `invalidateTest()`：任一字段改动 → `tested=false` + `currentTools=null` + 清结果区 +
    提示重测 + 锁回 Save；若恰在测试中，置 `dirtyWhileTesting=true`，该次结果落地时作废。
- **`testConnection()` 重写** (app.js:6361)：测试按钮进 `testing…` 态并禁用；成功 → `tested=true` +
  `renderTools`（capture=true → currentTools=tools 随保存落快照）+ 绿条「测试连接成功…可以保存了」；
  失败 → `tested=false` + 结果区红条 + 红条「测试连接失败，无法保存…」；`dirtyWhileTesting` 时结果
  作废锁回。finally 恢复按钮 + `syncSaveBtn()`。
- **`save()` 改为纯 POST/PUT** (app.js:6410)：`if (saving || !tested) return;` —— 不再内部试连。
  成功 toast + closeModal + 刷新列表；失败 `showError('保存失败：…')` 停在弹窗。
- **开弹窗即锁**：`fillForm()`(Edit) (app.js:6296) / `resetForm()`(New/Reset) (app.js:6320) 均置
  `tested=false` + 对应 lock 提示 + `syncSaveBtn()`。Edit 仍先展示已存 tools 快照（`renderCachedTools`）。
- **字段改动委托**：模态框 `#mcpModalOverlay` 上 `input`/`change` 冒泡监听，命中 `MCP_FIELD_IDS` 任一即
  `invalidateTest()`（bindEvents 尾部，app.js:6575 附近）；transport `<select>` 的原 change 处理器只留
  `setTransportUi()`，门控交给同一委托统一处理。
- **保留（上轮已确认）**：`fmtTs()` (app.js:6217)；`renderList()` tools=null → 灰显
  `not probed / failed` + `updated_at` 小字 (app.js:6249)；`probeAll()`「全部刷新」 (app.js:6487)。

### 3. `css/styles.css` — 追加提示条配色（文件尾）
- `.mcp-save-hint`（灰小字）/ `-ok`（绿）/ `-fail`（红）/ `-running`（琥珀）。
- Save 门控视觉：`#mcpSaveBtn:disabled` 置灰（浅灰底 + 灰字 + `cursor:not-allowed`）——可点击时因按钮

### 4. 后端一行可读性（沿用，跨仓库 `multi-agent-workflow/agentflow/agents/mcp_manager.py`）
- `test_connection` 失败文案经 `_exc_message` 递归取 `ExceptionGroup` 首子异常，露出根因；仅文案。

## 备注
- 门控为**统一规则**：任何字段改动（含仅勾/取消「Enabled」、改动 enable/disable 名单）都会使 Save
  锁回，需重新测试通过才能保存；要「先存一个暂时起不来服务的配置」将无法保存（可后续加「跳过测试
  强制保存」开关，本次未做）。
- 编辑态先展示的是 DB 里已存 tools 快照（非 live），仅作离线可读参考，不会解锁 Save。
- 测试成功即把本次 live tools 存入 `currentTools`，随 POST/PUT 提交为 tools 快照 → update 必然写入
  当前真实工具列表，不再保留可能过期的旧快照。
- SIP 仓库内 v1.9.0 / v1.10.0 / v1.11.0 / v1.11.1 / 本 v1.11.2 改动仍处于「未提交待查验」状态。
