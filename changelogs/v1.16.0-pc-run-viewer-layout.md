# v1.16.0 — View analysis 弹框改为左右分栏：左=执行流程要点，右=流程图

**日期**: 2026-09-07

**问题/背景**: v1.15.0 的 `pcRunOverlay`（View analysis 实时查看器）是自上而下的**纵向堆叠**布局（概要条 → 画布 → 审批 →
详情全在一条竖轴上），用户觉得页面布局不佳：DAG 画布本身又高又宽，详情/审批只能挤在下方，弹框高度下全部内容都要纵向滚动。
经确认交互：**改为左右分栏** —— 左侧一栏集中呈现整个执行流程的**要点**（待审批置顶 + 全量节点步骤列表），右侧保留**流程图**
（DAG 画布自适应占高），选中节点的详情面板从独立区块下移**并入右栏画布下方**。概要条（Run ID/Status/Step/Tokens/Cost）保持通栏横跨两栏。

**方案**: 纯前端 SIP（`index.html` / `js/app.js` / `css/styles.css` + changelog），**零改动已实现逻辑**——只动结构/样式/数据映射，
轮询、审批、节点详情渲染、canvas 工厂全部沿用 v1.15.0。复用既有 `.bs-*` 全局样式与 `createGraphCanvas` 工厂（第三实例不变）。

---

## 改动明细

### 1. `index.html` — `pcRunOverlay` body 由纵向堆叠改为左右分栏 (index.html:2086-2131)

**原因**: 把「执行流程要点」从隐性信息提升为**左栏常驻步骤列表**，DAG 图与详情归并到右栏，避免弹框高度内全部内容纵向滚动。

        <div class="bs-stat"><span class="bs-stat-label">Cost</span><span class="bs-stat-value" id="pcRunCost">0.0</span></div>
    </div>
    <!-- 左右分栏：左=执行流程要点，右=流程图 -->
    <div class="pcrun-split">
        <!-- 左栏：待审批（置顶，无则整段隐藏）+ 执行流程步骤列表 -->

            </div>
            <div class="pcrun-steps" id="pcRunSteps"></div>
        </aside>
        <!-- 右栏：DAG 画布（自适应）+ 选中节点详情（固定底部） -->

- `.bs-zoom-controls` 仍是 `.bs-zoom` 的**兄弟节点**（不在其内）——`createGraphCanvas` 对 `.bs-zoom` 施加 transform，控件不能嵌套，
  否则会随图缩放/平移。
- marker/defs 结构照抄 Bug Solve `#bsArrow`，不变。

### 2. `css/styles.css` — `#pcRunOverlay` 作用域布局改为左右分栏 (styles.css:4951-5110)

**原因**: 纵向堆叠的 `.pcrun-body{overflow-y:auto}` 改为**禁止弹框自身纵向滚动**（`overflow:hidden`），内部两层结构消化高度：
`.pcrun-split` 横向分栏，左右两栏各自 `min-height:0` + 内部滚动，保证任一栏超高时只在栏内滚、不整页滚。
全部以 `#pcRunOverlay` / `.pcrun-*` 限定，不动全局 `.bs-*`。

```css
.pcrun-body { flex:1; min-height:0; display:flex; flex-direction:column; gap:10px; overflow:hidden; }
.pcrun-split { flex:1 1 auto; min-height:0; display:flex; gap:14px; align-items:stretch; }

/* 左栏固定 300px */
.pcrun-flow-col { flex:0 0 300px; width:300px; … display:flex; flex-direction:column; gap:8px;
                  border-right:1px solid var(--border-color); padding-right:12px; min-height:0; }
.pcrun-approvals { flex:0 0 auto; max-height:40%; overflow-y:auto; }   /* 待审批置顶，最多占左栏 40% 高，保证步骤列表可达 */
.pcrun-steps     { flex:1 1 auto; min-height:0; overflow-y:auto; … }    /* 步骤列表占满左栏余下 */

/* 右栏：画布自适应占高 + 详情固定底部 */
.pcrun-main { flex:1 1 auto; min-width:0; min-height:0; }
#pcRunOverlay .pcrun-canvas { flex:1 1 auto; min-height:0; }
#pcRunOverlay .bs-zoom      { flex:1 1 auto; min-height:0; }
#pcRunOverlay .bs-detail    { flex:0 0 auto; max-height:220px; }
```

**步骤列表样式**（`#pcRunOverlay` 作用域，与画布节点同状态语义）：每行 = 序号圆点（按状态着色，绿=done/蓝=running/红=failed·
rejected/橙=waiting·cancelled/灰=skipped·pending）+ 节点(agent) 等宽名 + tokens + `bs-badge` 状态徽章；`running` 行浅蓝描边、
`pcrun-sel` 选中行高亮，hover 提亮——行可点，与画布节点选中双向联动。

### 3. `js/app.js` — 步骤列表渲染 / 双向选中联动 / 生命周期接线 (app.js:4300-4422)

**原因**: 左栏列表本身不存在于 v1.15.0，需新增「节点数据 → 步骤行」渲染与「图点 ↔ 步骤点」选中同步；其余逻辑（轮询/审批/详情/
close）原样保留，只把各调用点串进新结构。

**新增辅助（initProblems 内）**:
```js
// 状态 → 步骤序号圆点着色类
function pcStepStateClass(st) { …'done':'st-done','running':'st-running','failed':'st-failed','cancelled':'st-cancelled',
                                    'rejected':'st-rejected','waiting_approval':'st-waiting','skipped':'st-skipped'…
                                    return m[st] || 'st-pending'; }
// 节点数据 → {nid:status} 映射（画布渲染与步骤列表共用）
function pcRunStatusMap() { … }
// renderGraph 每次整段重建 innerHTML，需在其后按 pcRunSel 重新叠加选中环
function pcMarkGraphSel() { svg.querySelectorAll('g[data-node]') → toggle bs-node-selected by pcRunSel }
// 选中节点（图点击 / 左栏步骤点击共用）：停 autoFollow、标选中环、刷详情与步骤列表
function pcSelectNode(nid) { if (nid) pcRunAuto = false; pcRunSel = nid; pcMarkGraphSel(); renderRunDetail(nid); renderRunSteps(); }
// 左栏步骤列表：按 DAG 定义顺序列全部节点；行 = 序号 + 节点(agent) + tokens + bs-badge
function renderRunSteps() { … empty → 'Waiting for run data…' … }
```

**改动点**:
- `onNodeClick`（原停 autoFollow + 渲染详情）改为统一走 `pcSelectNode(nid)`（画布点 ↔ 步骤点同步）；
- `openProblemRun()`：`pcRunCanvas.reset()` 后追加 `renderRunSteps()`（清旧 + 显示占位「Waiting for run data…」）；
- `applyRunView(data)`：状态徽章/step 概要更新逻辑不变；`pcRunCanvas.render` 后追加
  `pcMarkGraphSel()`（图重建 innerHTML 后按 `pcRunSel` 补选中环）+ `renderRunSteps()`；autoFollow 选中的 running 节点
  同时落到步骤行；
- `closeProblemRun()`：追加 `pcRunAuto = true` 复位 + 清空 `#pcRunSteps`。

**生命周期接线（第 6 区块内，审批委托之后）**:
```js
var pcRunStepsEl = getEl('pcRunSteps');
if (pcRunStepsEl) pcRunStepsEl.addEventListener('click', function (e) {
    var t = e.target;
    var btn = t && t.closest ? t.closest('[data-nid]') : null;
    if (btn) pcSelectNode(btn.getAttribute('data-nid'));
});
```

## 影响范围

| 场景 | 预期 | 实际 | 状态 |
|------|------|------|------|
| 打开 View analysis | 概要条通栏，下方左右分栏；左=步骤列表，右=流程图 | `pcrun-split` flex 分栏；左栏 `pcrun-flow-col` 300px，右栏 `pcrun-main` 自适应 | OK |
| 左栏步骤列表 | 按 DAG 定义顺序列出全部节点，带序号/agent/tokens/状态徽章 | `renderRunSteps()` 消费 `pcRunGraph.nodes`（缺则退化 `pcRunData` keys） | OK |
| 待审批 | 置顶于左栏，无则整段隐藏 | `pcRunApprovalSection` display 切换；最多占左栏 40% 高内滚 | OK |
| running / waiting_approval | 概要 Step 显示当前执行节点，步骤行同步高亮 | `applyRunView` autoFollow running → `pcRunSel` → 步骤行 + 画布同亮 | OK |
| 点图 / 点步骤行 | 双向选中联动：环 + 行高亮同步，下方详情刷新 | 统一 `pcSelectNode(nid)`；图点击走 `onNodeClick`，行点击走 `#pcRunSteps` 委托 | OK |
| 详情 Output/Prompt | 在右栏画布下方固定底部高度内 tab 切换 | `#pcRunOverlay .bs-detail` max-height 220px，tab 委托不变 | OK |
| 关弹框（Escape / × / 遮罩） | 清 timer、复位 autoFollow、清步骤列表 | `closeProblemRun()` 追加复位 | OK |
| 弹框超高 | 只在栏内滚动，不整页滚 | body `overflow:hidden`；左右栏各自 `min-height:0` + 内部 `overflow-y:auto` | OK |
| Bug Solve / Detail 弹框 | 布局与样式不受影响 | 全部新规则以 `#pcRunOverlay`/`.pcrun-*` 限定，未改全局 `.bs-*` | OK |

- 静态校验：`node --check js/app.js` 通过；`pcRunSteps`/`pcRunStepCount`/`pcRunApprovalSection`/`pcRunApprovals` id 与
  app.js `getEl` 引用一一对应（脚本核对无缺失）；CSS `.pcrun-*`/`.st-*` 类与 `renderRunSteps` 输出匹配。
- 逻辑零改动：轮询、审批、节点详情渲染、canvas 工厂沿用 v1.15.0，只动结构/样式/数据映射 + 新增步骤列表与选中联动。
- **浏览器 E2E 未跑**（遵循用户「改好了和我说就行」惯例）。建议走查：开 View analysis 看左右分栏布局；跑一个带并行/审批的
  workflow，观察步骤行状态随轮询翻色、待审批卡置顶；点图节点 ↔ 点步骤行双向联动、详情 tab 切换；超高时左右栏内部滚动不整页滚。
