# v2.6.11 — APM Monitor Targets 表单支持 ES 查询字段（ES Query Fields JSON 编辑器）

**日期**: 2026-09-23

**问题/背景**: 后端 `monitor_target.source_config` 新增了 `level_field` + `levels`（ES 侧按日志级别过滤，
把 INFO 洪峰挡在查询之外），但 APM Monitor Targets 页面的表单里没有任何 ES 查询键的输入项，
用户**看不到也无法编辑**自己的配置。

更严重的是这不只是「看不见」：`readForm()` 是**从零重建** `source_config`（`var sc = { url: url }`），
只写它认识的键，然后 `PUT /v1/monitors/{id}`（后端是**整体替换**，不是 merge）。所以任何一次从 UI
编辑 ELK 端点再保存，都会**静默抹掉** `time_field`/`service_field`/`level_field`/`levels` —— 端点退化成
非 ES 源：后端 `_build_body` 返回 `None`，采集器改走 URL 参数、没有时间窗，每轮重采最新一页、
水位线永远推不动（后端实测过这类静默失效的完整链路，见后端仓库 `docs/logs/M9.md`）。

**形态选择**：最初实现成四个独立命名输入框，评审后改为**一个 JSON 编辑器**。理由：与页面既有的
`Params (JSON)` / `Headers (JSON)` / `Time Params (JSON)` 习惯一致；这四个键本来是一家人，一个 JSON
能表达「ES 模式：有 / 无」；且后端将来加键不必再改前端。

## 改动明细

### 1. `src/legacy/legacy-panels.html` — 表单新增一个 JSON 编辑器 (line 1699-1702)

**原因**: 表单是**静态 HTML + 逐个 id 手写**，没有字段元数据表；不渲染就没有输入项。

```html
<!-- 插在 `Time Params` 之后、`Timezone` 之前 —— 都是源侧查询/时间语义的键，聚在一起 -->
<div class="apm-field apm-field-wide">
    <label for="apmEsQuery">ES Query Fields (JSON) <span class="apm-hint">ES 源查询开关，只进 POST body；需 .keyword 后缀、大小写精确；其余键原样透传</span></label>
    <textarea id="apmEsQuery" rows="4" placeholder='{"time_field": "@timestamp", "service_field": "app.service.keyword", "level_field": "app.level.keyword", "levels": ["ERROR"]}'></textarea>
</div>
```

沿用既有 class（`.apm-field` / `.apm-field-wide` / `.apm-hint`），**未新造 class**（`css/styles.css`
全局且不重写）。`placeholder` 给一份**可直接用的完整示例**，`apm-hint` 里写明 `.keyword` 后缀与
大小写要求 —— 这两点最容易配错且配错不会报错。

### 2. `js/app.js` — 新增「表单字段契约」两张键表 (line 6856-6863)

**原因**: 表单把 `source_config` 分成两半，必须有一处明确声明边界，否则键会在往返中丢失。

```js
var NAMED_KEYS = ['url', 'rows_path', 'signature_frames', 'window_sec', 'timezone',
                  'field_mapping', 'headers', 'params', 'time_params'];
var ES_QUERY_KEYS = ['time_field', 'service_field', 'level_field', 'levels'];
```

`readForm` 与 `fillForm` 用**同一对表** —— 这替换了初版里那层「保留未知键」的安全网：未知键不再
只是「保命但看不见」，而是被回填进 JSON 编辑器，**可见、可改、可删**。少一个机制，且没有隐形状态。

### 3. `js/app.js` — `readForm()` 解析 + 校验 + 合并 (line 6878-6897)

```js
// before → after
-var sc = { url: url };
+var esQuery = parseJson('apmEsQuery', false);
+// 注意 typeof null === 'object'，故 null 要单独挡掉
+if (!esQuery || Array.isArray(esQuery) || typeof esQuery !== 'object') {
+    throw new Error('ES Query Fields must be a JSON object');
+}
+// 键名写错不会有任何后端报错（source_config 写入侧不校验未知键，采集器也忽略它们），
+// 所以这里显式预警。**仍然照存**：后端新加的键不必等前端发版就能用。
+Object.keys(esQuery).forEach(function (k) {
+    if (ES_QUERY_KEYS.indexOf(k) === -1) {
+        window._showToast('未知键 "' + k + '" 不是已知的 ES 查询字段，将原样透传', 'error');
+    }
+});
+// levels 必须是数组：写成 "ERROR" 会被后端按字符序列当多个值，实测匹配 0 条。
+if (esQuery.levels !== undefined && !Array.isArray(esQuery.levels)) {
+    throw new Error('levels 必须是数组，如 ["ERROR"]');
+}
+
+var sc = {};
+Object.keys(esQuery).forEach(function (k) { sc[k] = esQuery[k]; });

```

校验分两级：**结构性错误**（不是对象 / `levels` 非数组）→ 抛错拦住保存；**未知键** → toast 预警
但照常保存（保留扩展性，不让前端成为后端加键的瓶颈）。编辑器留空 = 这四个键全部删除。

### 4. `js/app.js` — `fillForm()` 回填 (line 6938-6946)

```js
// ES Query Fields：四个 ES 查询开关 + 表单没别的输入框承载的键。
// 后者必须一起回填，否则后端新加的键会在界面上"消失"，用户改完一保存就被抹掉
// —— 与 readForm 里的 NAMED_KEYS/ES_QUERY_KEYS 是同一对约定，改一处要改两处。
var esObj = {};
Object.keys(sc).forEach(function (k) {
    if (ES_QUERY_KEYS.indexOf(k) !== -1 || NAMED_KEYS.indexOf(k) === -1) esObj[k] = sc[k];
});
getEl('apmEsQuery').value = Object.keys(esObj).length ? JSON.stringify(esObj, null, 2) : '';
```

### 5. `js/app.js` — `resetForm()` New 分支清空 (line 6975)

一行 `getEl('apmEsQuery').value = '';`（初版的四个清空合并成一处）。

### 6. `src/legacy/legacy-panels.html` — 修掉 `Params` 的错误占位符 (line 1690-1693)

**原因**: 占位符原本是 `{"level": "error"}` —— 正在教用户把级别过滤塞进 **URL 查询串**，而这是实测
死路：ES 对未识别参数返回 400 `unrecognized parameter`；换成 `q` 则会**整体覆盖** body 的 query，
静默丢掉水位线窗口与服务隔离。

```html
-<label for="apmParams">Params (JSON)</label>
-<textarea id="apmParams" rows="3" placeholder='{"level": "error"}'></textarea>
+<label for="apmParams">Params (JSON) <span class="apm-hint">URL 查询串 · 仅放源认识的键</span></label>
+<textarea id="apmParams" rows="3" placeholder='{"pretty": "true"}'></textarea>
```

### 7. 后端仓库 `docs/plans/UI-monitors-implementation-plan.md` — 同步修正 (line 76, 175)

同一份错误指引在该文档出现两处（`source_config` 键表 + §8.2 设计注意），已改为指向
`level_field` + `levels`。

## 踩坑记录

1. **`readForm()` 是「重建」而不是「补丁」** —— 这是本次问题的真正根源：表单看不见的键不是「显示为空」，
   而是**保存即删除**。改动 2/3/4 共同保证「凡 source_config 里有的键，要么有命名输入框，要么出现在
   JSON 编辑器里」，不存在第三种状态。
2. **改了三个地方才算加完一个字段** —— HTML 标记、`readForm`、`fillForm`、`resetForm`，没有中心化
   字段表，漏一处就静默失效（漏 `readForm` → 改了存不上；漏 `fillForm` → 编辑时看不见）。
3. **命名输入框 vs JSON 编辑器的取舍**：命名输入框可发现性好、键名不可能写错；JSON 编辑器一致、
   可扩展、能一次性看全。最终选了 JSON 编辑器，代价是「键名可能写错」—— 用两级校验补偿
   （未知键 toast、`levels` 非数组拦住）。**未做**键名白名单硬拦，是为了不让前端成为后端加键的瓶颈。
4. **dev server 下遗留世界是断的（既有问题，非本次引入）**：`legacy-panels.html:112` 的
   `Bot < 50%` 里的裸 `<` 让 Vite 的 parse5 报 `invalid-first-character-of-tag-name`，
   `/src/legacy/legacy-panels.html?raw` 直接 **500** → `bridge.js` 的静态 import 失败 → 整个遗留
   世界（15 个未迁移视图，含本页）在 dev 下无法装载。该内容由 `3e7e6a1`（v2.0.0 Vite 骨架，2026-09-11）
   引入，**在跑了两天的 :5173 与新起的实例上都复现**。生产 `npm run build` 路径不受影响（rollup 不走该
   HTML transform），所以本次验证走 build + preview。修复只需把 `<` 写成 `&lt;`，**本次未动**（超出范围）。
