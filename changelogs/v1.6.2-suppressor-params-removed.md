# v1.6.2 — Domain Rules 表单：Suppressor 卡片去掉 Params（内置抑制器不消费 params）

**日期**: 2026-08-28

**问题/背景**: Domain Rules 的 SUPPRESSORS (L0) 区块每张卡片都渲染了 `Params:` 区 + `+ Add Param` 按钮，但内置抑制器（`blacklist` / `maintenance_window`）的 `check()` 根本不读 `params`——实际匹配条目（service+level / service+时间窗口）存在独立的 `suppress_blacklist` / `maintenance_window` 表里（`domain_config` 只写「开哪个插件」）。对指标和日志的采集都一样，表单里的 Params 填了也不会生效（无害但误导）。本次把 Suppressor 卡片的 Params 相关 UI 与收集逻辑移除，只保留 `Name` 下拉；Detector 卡片的 Params 保持不变（`signature_aggregate`/`static_threshold` 等真的需要）。

---

## 改动明细

### 1. `js/app.js` — `renderSuppressors()`：卡片不再渲染 Params 区块 (app.js:4216-4233)

**原因**: 抑制器只选插件名；内置插件不消费 params，条目在独立表。移除后 Edit 回填只显示 `Name` 下拉。

```js
// before：Name 字段后跟着 Params 区块 + Add Param 按钮
card.innerHTML =
    '<div class="rule-card-head">...Suppressor N...Delete</div>' +
    '<div class="rule-card-fields"><label class="rule-field">Name ' + pluginSelect('dc-name', pluginSuppressors, s.name) + '</label></div>' +
    '<div class="rule-params">' +
        '<div class="rule-params-title">Params:</div>' +
        '<div class="kv-rows">' + (kvHtmlFromParams(s.params) || '<div class="kv-empty">No params</div>') + '</div>' +
        '<button type="button" class="btn btn-outline kv-add">+ Add Param</button>' +
    '</div>';

// after：只剩 Name 下拉
card.innerHTML =
    '<div class="rule-card-head">...Suppressor N...Delete</div>' +
    '<div class="rule-card-fields"><label class="rule-field">Name ' + pluginSelect('dc-name', pluginSuppressors, s.name) + '</label></div>';
```

### 2. `js/app.js` — `addEmptyCard()`：Params 区块按 `isDetector` 条件渲染 (app.js:4235-4262)

**原因**: `addEmptyCard` 同时服务 Detector / Suppressor 两种卡片，原来 Params 区块无条件追加。改为只有 Detector 卡片带 Params（`+ Add Param`），Suppressor 卡片不渲染。

```js
// before：Params 区块无条件追加
'</div>' +
'<div class="rule-params">' +
    '<div class="rule-params-title">Params:</div>' +
    '<div class="kv-rows"><div class="kv-empty">No params</div></div>' +
    '<button type="button" class="btn btn-outline kv-add">+ Add Param</button>' +
'</div>';

// after：仅 Detector 渲染 Params，Suppressor 空字符串
'</div>' +
(isDetector
    ? '<div class="rule-params">' +
        '<div class="rule-params-title">Params:</div>' +
        '<div class="kv-rows"><div class="kv-empty">No params</div></div>' +
        '<button type="button" class="btn btn-outline kv-add">+ Add Param</button>' +
      '</div>'
    : '');
```

### 3. `js/app.js` — `collectSuppressors()`：不再收集 params (app.js:4319-4331)

**原因**: UI 已无 params 输入，收集逻辑同步简化，提交的 JSON 只含 `{"name": "blacklist"}` / `{"name": "maintenance_window"}`。内置插件忽略 params，去掉不改变行为；此前 seed（`domains.yaml`）的 suppressor 也本就是无 params 的。

```js
// before
var s = { name: name };
var params = collectParams(card);
if (Object.keys(params).length) s.params = params;
out.push(s);

// after
out.push({ name: name });
```

## 踩坑记录

- **只动 Suppressor，不动 Detector**：`collectParams` / `kvHtmlFromParams` / `kv-add` 事件委托（`wireCardContainer`）继续服务于 Detector 卡片，Detector 的 `static_threshold.threshold`、`signature_aggregate.min_count` 等 params 照常可用，未受影响。
- **历史配置数据兼容**：若此前 config 里 suppressor 带过 params（内置插件本来也不读），Edit 回填不再显示、Save 后会被丢弃——对内置抑制器无功能影响，属预期清理。将来若引入真正消费 params 的自定义 suppressor，再恢复该区块即可（本次注释已标明）。
- **`node --check js/app.js`** 通过，无语法错误。
