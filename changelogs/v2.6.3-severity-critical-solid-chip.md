# v2.6.3 — critical 与 high 拉开档次：critical 改实心，high 保持浅底

**日期**: 2026-09-22

**问题**: 「critical 和 high 区分一下」——v2.6.2 把 `P1` 归一到 `critical` 之后，
Ticket Inbox 上 `CRITICAL` 与 `HIGH` 两格**看起来差不多**。

---

## 症状：背景完全相同，只差一档色阶

改前实测（CDP 取计算样式）：

```
severity-high      bg rgb(254, 242, 242)   color rgb(239, 68, 68)   无边框
severity-critical  bg rgb(254, 242, 242)   color rgb(220, 38, 38)   无边框
                   ^^^^^^^^^^^^^^^^^^^^^ 背景一模一样
```

`#ef4444`（red-500）与 `#dc2626`（red-600）是**同一支红的相邻两档**，
铺在同一块 `#fef2f2` 粉底上，实测分不出来 —— 只剩细微的字色差。

## 判据：最严重那一档不该只靠"色阶的一格之差"

改法是**换形态**而不是再压一档色阶：

```css
.alert-tag.severity-critical { background: #dc2626; color: #fff; }   /* 实心 + 白字 */
```

- `critical` = **实心底 + 白字**，`high` / `medium` / `low` 仍是**浅底 + 彩字** ——
  形成"只有最严重那个是实心"的递进，一眼能定位。
- **实心与浅底是两种形态，不是同一个色相的两格** —— 即使打印成灰度、或对红色不敏感，
  也能分开。这是相对"再加深一点"更抗退化的做法。
- 只改这一条；`high` 那 13 行**一字未动**（有回归测试钉住，见下）。

## 验证

**改前 → 改后**（同一组 DOM 指标）：

| 签名 | 改前 | 改后 |
|---|---|---|
| `HIGH \| severity-high \| rgb(254,242,242)` | ×13 | **×13（不变）** |
| `MEDIUM \| severity-medium \| rgb(255,251,235)` | ×2 | **×2（不变）** |
| `- \| (none)` | ×12 | **×12（不变）** |
| critical 那一格 | `P1` 全透明 | **`CRITICAL` `severity-critical` `rgb(220,38,38)` + 白字** |

- 整列 28 行的签名逐条比对，**除 critical 那格外全部一致**（无回归）。
- **截图人工确认**：实心红的一格在一列浅底 `HIGH` 里一眼可见，且不显得突兀。
- `npm run build` 通过。

## ⚠️ 影响面（与 v2.6.2 同一处未验证项）

`css/styles.css` 是**双世界共享**，`.severity-critical` 同时服务 legacy
`js/app.js` 的告警表（`SEVERITIES = ['warning','high','critical']`）。
所以那边若有 `critical` 的告警，也会从浅底变实心。

其数据源 `http://localhost:8080/api/sip-aiops/app-alert` 是**真后端、非 mock**，
**本机未运行 → 无法枚举实际取值**，故这一条仍记为**未验证**，不声称安全。

选在共享表里改（而不是只给工单页加专属类）是为了与 v2.6.2 的处理一致：
**同一个语义在应用里只该有一种长相**，否则又是"同一字段两套样式"。
