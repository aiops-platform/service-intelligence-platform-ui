# v2.2.17 — 修复：悬停提示跟着轮询刷新闪烁

**日期**: 2026-09-20

**问题**: 节点悬停提示弹出后，**跟着后台刷新节奏一闪一闪**。

**根因**: `renderGraph` 里那行 `hideTip()`：

```js
svgEl.innerHTML = html
hideTip()   // 「提示行内元素已被重建，留着会指向已卸载的节点」
```

清理的理由本身没错，但**只清了不重建**。宿主是**轮询驱动**的（每几秒 `render()` 一次），
而**鼠标不动就不会再触发 `mouseover`** —— 于是提示收起后一直不回来，
要用户动一下鼠标才重新计时 1.5s。表现为"跟着刷新闪"。

**与 `flowNode` 是同一族**：v2.2.10 给流动高亮加过重放，提示这次漏了。

---

## 改动明细

### `src/components/graph/useGraphCanvas.js`

1. 新增 `tipNode`（当前**显示着**提示的节点）(63)
2. `hideTip()` 清它、`showTip()` 记它 (369 / 382)
3. `renderGraph` 末尾**重放** (325)：

```js
const tipToRestore = tipNode
svgEl.innerHTML = html
if (tipToRestore) {
  // ⚠️ 必须重新 querySelector 拿**新**的 <g> —— 旧的已随 innerHTML 卸载
  const gEl = svgEl.querySelector(`[data-node="…"]`)
  if (gEl) showTip(tipToRestore, gEl)
  else hideTip()   // 节点没了（换了图）→ 收起
}
```

`showTip` 本来就用 `getBoundingClientRect()` 现算位置，所以重放会自动落到新元素上。

---

## 踩坑记录：探针自己报了个假阳性

第一版探针把 `<g>` 元素**在刷新前**就抓在变量里，刷新后拿**已脱离 DOM 的旧元素**
去 `dispatchEvent(mouseout)`——事件**冒泡不到容器上的委托监听器**，
于是显示"移开后=block"，看着像"移开也收不起来"。

改成每次都 `querySelector` 重抓后：`移开后=none` ✓

**判据**：用 `innerHTML` 重写 DOM 的组件，探针里**不能缓存元素引用**。

| 场景 | 预期 | 实际 | 状态 |
|------|------|------|------|
