### 2. `tools/make-offline-page.py` — ★ 产出加 JS 语法校验 (line 459)

**原因（本次最值得记的一处）**: `tenant_copy.py` 的补丁是**在字符层面改 chunk** 的。
拼错一个字符照样写出文件、照样「产出校验通过」，而浏览器那边是**整页白屏**。
实测就是被这个咬到的 —— 见下面「踩坑 A」。

```python
     bad_syntax = []
     if shutil.which("node"):
         for js in sorted((out_dir / "_next" / "static" / "chunks").glob("*.js")):
             r = subprocess.run(["node", "--check", str(js)], capture_output=True, text=True)
             if r.returncode != 0:
                 msg = next((l.strip() for l in r.stderr.split("\n")
                             if l.startswith("SyntaxError")), None)
                 bad_syntax.append((js.name, msg or r.stderr.strip().split("\n")[-1]))
     else:
         bad_syntax = None      # 没有 node 就明说「跳过」，不假装查过
```

失败时**非零退出**，消息里带上 `SyntaxError` 原文与「多半是 tenant_copy.py 里某个补丁拼错了」。

> 反向验证过：往临时 vendor 副本注入 `let X=1,let S=[` 后构建 → 退出码 1、报出
> `SyntaxError: Unexpected strict mode reserved word`。

### 5. `tools/tenant_copy.py` — FinOps 的 agent ticker (line 1022-1152)

**原因**: ticker 那 8 条里有 3 个 app 名、1 个组合名和一个金额，全是 best-buy 的；
金额还与同屏 KPI 直接打架。

| | 修复前 | 修复后（默认租户 otr） |
|---|---|---|
| KPI（按租户算） | `Total estate burn $1.6M` | 同左 |
| ticker | `estate burn projected $13.4M next month` | `estate burn $1.6M monthly · hidden legacy $388K of it` |
| ticker | `flagged Manhattan WMS …` | `flagged CRM Campaign · run cost $41K/mo · 19% in hidden legacy tax` |

**与 Security Ops 那条补丁的关键区别**（记下来，免得下次一刀切）：
那一页的 case 列表是 KPI 计数的**数据源**且同屏 KPI 标着 REAL —— 功能性的不一致。
这一页的 ticker 自带 tooltip `"Synthetic-but-believable FinOps activity ticker ·
scripted for the demo"`，是页面**公开声明的剧本文案**，且不喂任何 KPI。
**仍然改了** —— 同一块屏幕上 $1.6M 与 $13.4M 并列，观感上就是错的。

**改法上刻意克制**：只换名称与金额（外加两个有精确来源的百分比 `hiddenShare` /
`legacyShare`），**没有数据来源的趋势词去掉而不是编一个**：

```
  +18% MoM        → 去掉，换成真实的 run cost/mo
  trending +12%   → 去掉，换成真实的 run cost/mo
  candidate flagged Retire → 去掉（该 app 未必在 6R 的 Retire 名单里）
```

三条纯叙事/通用文案（阈值 60%、4 条决策、0.84 confidence）**原样不动**。

**为什么写成运行期派生**：金额与百分比都由 `x(app)` / `f()` 在 JS 里算出来，
改写器的文本替换（只作用于渲染后的文本节点）够不着。补丁插入一段求值序 `__FS`，
产出本租户的 top-3 高成本 app、top-1 组合与成本聚合，再让 5 条文案引用它。

作用域已核：`n.snapshot.*` / `x()` / `f()` / `b()`（金额格式化，函数声明会提升）
都与插入点同作用域且定义更早；`let S=[` 之前在 offset 6054，而 `let P=f()` 在 22794 ——
所以**必须**在这里自己算一次（`f()` 带 memo，后面 `let P=f()` 直接命中缓存，无副作用）。
三个取值器都带兜底，租户 app 数不足时回落而不是抛异常。

## 踩坑记录

### A. ★ chunk 补丁拼错一个字符 → 整页白屏，而构建一切正常

把 `__FS` 并进原来那条 `let S=[…]` 时，我保留了锚点开头的 `let `：

```js
let __FS=(function(){…})(),let S=[{…}]
//                          ^^^ let 出现在声明列表里
// SyntaxError: Unexpected strict mode reserved word  → 内嵌页整页白屏
```

构建的「产出校验」只查**文件存在性**（HTML 引用的 `/_next/…` 在不在），
语法错误完全查不到；而内嵌页的 JS 全在一个 chunk 里，解析失败等于整页不启动。
**是我自己另跑 `node --check` 才发现的**。已修（插入时吃掉锚点的 `let `），
并把语法校验做进构建（见改动 2），反向验证过它会拦。

### B. 不加 `EMBED_PAGES` 就去看 `/finops/`，会渲染出**别的页面**

接完前四步、还没做 Vue 接线的中间态，我打开 `/finops/` 看到的是 **Service Ops 的内容**
（KPI 是事故数 / MTTR / TOP APPS BY INCIDENT PRESSURE），但 **h1 显示「FinOps」**——

因为 `/finops/` 没被插件拦下 → 落进 SPA 兜底 → vue-router 走 `emptyDomainRoutes` 的
**空壳语义**：渲染 service-ops 概览面板，再由接缝 S9 把标题改写成域名。

**h1 是对的，内容是别人的** —— 比「白屏」更容易误判成「接上了」。
教训：三处成对**做完再看页面**，别在中间态验收。

### C. 自检脚本的 ⚠ 要看，但脚本不是全覆盖（Security Ops 那轮的延续）

`check-embed-wiring.py` 对本页报了 3 条 ⚠，逐条判断后**有意保留**（见下）。
而更有价值的是这一轮**新加的 appKey 校验**直接给出 ✓ —— 本页没有 Security Ops 那种
写死的 `appKey`（那 5 个只在 best-buy 存在的值），一眼就确认了。

### 10. `.claude/skills/sip-embed-page/scripts/check-embed-wiring.py` — 文本扫描也改扫产出

**原因**: 上一轮（v2.4.0）给 appKey 校验选的是**产出目录**，而文本扫描还留在 `vendor/` ——
两处不一致时，**已被构建期补丁改掉的串仍会被报成 ⚠**。本轮就撞上了：
补丁把 `Selling portfolio · run cost trending +12% · 5 apps driving the spike`
改成租户的组合名之后，脚本照样报它。

改成与 appKey 校验同一判据（扫 `public/_next/`，按该页独有 chunk 名过滤；
没构建过则退回 `vendor/`）。**这不会漏掉改写器管的那些串** —— 改写是**运行时**
在渲染后的文本节点上做的，产出 chunk 里仍是原文。

效果：finops 的 ⚠ 从 3 条降到 2 条（剩下两条见下），其余页不变，全量仍是 0 ✗。
