# v2.2.10 — Business Ops：点 journey 名字改为下钻（与行尾 › 一致）

**日期**: 2026-09-20

> 本文行号指**本次改动后**的当前文件。`public/` 下的 chunk 是压缩产物、整个文件一行（无换行），
> 所以只能给「第 1 行」+ 字符串锚点。

**需求/背景**: Business Ops 概览页（顶部筛选框选 **Enterprise** 时）有一张 journey 表。
表里一行有三个点击面，其中「名字」和「行尾 ›」干的是两件事，而需求是**让名字也走 › 那条路**：

| 点击目标 | 改动前 | 改动后 |
|---|---|---|
| **journey 名字** | 冒泡到整行 → **只选中**（右侧出现 journey inspector），顶部筛选框仍停在 `Enterprise` | **下钻**：顶部筛选框切到该 journey，下方面板整体切成该 journey 的视图（KPI 卡片 + portfolio 表） |
| 行内数字（XLA / Apps / Inc/d / Bot %） | 选中 → 右侧 inspector | **不变** |
| 行尾 `›` 箭头 | 下钻 | **不变** |

理由：名字是整行里最宽、最自然的点击目标，而它此前是「什么都不跳」的那一个。

## 改动明细

### 1. `tools/tenant_copy.py:337-395` — 新增 `patch_journey_name_drill()`

**原因**: 页面源码不在本仓（内嵌的 Next.js 应用，见 `src/views/business-ops/BusinessOpsView.vue`），
但本仓**已在维护它的编译产物** —— `tenant_copy.py` 里已有 5 个同类补丁。本次照
`patch_ask_sip()`（`:305`）的写法加第 6 个：幂等 + `count != 1` 静默跳过 + `surrogateescape` 读写。

行组件 `w()` 本来就收到了 `onDrill` 回调（行尾 `›` 用的就是它），所以改法是把行尾那一套
**原样搬到名字上** —— 不新增状态、不新增回调：

```js
// 名字那个 div —— 改前
(0,t.jsxs)("div",{children:[(0,t.jsx)("div",{style:{…},children:e.isCrossJourney?"Cross-Journey":e.domain.label})

// 改后：+ onClick + title（+ cursor，与行尾 › 的写法逐字一致）
(0,t.jsxs)("div",{onClick:e=>{e.stopPropagation(),i()},title:"Drill into "+e.domain.label,
             style:{cursor:"pointer"},children:[(0,t.jsx)("div",{style:{…},children:…})
```

- `i` 即 `onDrill`；箭头参数 `e` 遮蔽行 prop `e`，只在箭头体内生效；
- `title` 在对象字面量里求值（渲染作用域，此时 `e` 仍是行 prop），文案与行尾 `›` 逐字一致，
  所以 **cross-journey 行不需要额外分支**（实测该行 title = `Drill into Cross-Journey`）。

**为什么改 JS 而不是像租户文案那样做 DOM 改写**: 下钻要用**该行的 domain id**
（`onDrill` 内部按 id 调 `findDomain`）。DOM 层要复现只能拿名字文本去顶部筛选框里找同名按钮
再 `.click()` —— 那等于把「文案」当成「标识」，改标签/换语言就断。这里要接的是事件不是文案，
DOM 改写没有优势。

### 2. `tools/make-offline-page.py:334-336` — 注册

**原因**: 与其余 5 个补丁同一处注册，成功时打一行日志（照既有格式）。

### 3. `public/_next/static/chunks/00tsl~72wvlrr.js` — 重建产物

## 踩坑记录

1. **★ 重建会把默认租户从 `otr` 冲回 `retail`（既有 bug，本次未修）**

   `cf01394`（bo.gong）把激活判定的兜底 `return"retail"` 改成 `return"otr"`，但那是**手改构建产物**
   —— 没做成补丁。所以 `python3 make-offline-page.py` 一跑，这 3 个字节就被 vendor 源覆盖回去，
   而**构建输出一切正常、不报错**：打开页面只是默认租户变成了 retail。

   本次因为「补丁必须重建才生效」而踩到：重建后 `git status` 多出两个文件，逐个比对才定位到
   这 3 字节。处理方式是**把这两个产物回退到 HEAD**，让本次 diff 只含该改的那一行。

   > **根治建议（未做，另开一次改动）**：把默认租户也做成 `tenant_copy.py` 里的一个补丁
   > （`return"retail"` → `return"<目标租户>"`，带唯一性断言），或给构建脚本加
   > `--default-tenant` 参数。否则**任何人重建一次，默认租户就悄悄回退**。
   > 顺带一提，`business-ops/index.html` 的 `__SIPCOPY__` 目前也比数据 chunk 少一个 `otr` 条目
   > （同一次重建的产物差异），即 HEAD 上这两份产物本身就不一致。

2. **锚点必须带上 `children:e.isCrossJourney?…` 才唯一**。同一个 style 前缀
   （`fontFamily:"var(--font-display)",fontSize:13,…lineHeight:1.2`）在组件 `A()`（组合行）里还有一份，
   只匹配前缀会命中 2 处 —— 而本补丁的约定是「不唯一就静默跳过」，那样会**看起来打了、其实没打**。
   落地前对 vendor 源与产物各断言了一次 `count == 1`。

3. **`title` 里的 `e` 是渲染作用域的**，箭头参数 `e` 只在箭头体内遮蔽。若把 `title` 写成
   `e=>e.domain.label` 之类就会拿到事件对象。写的时候容易顺手写成箭头体内引用。

4. **探针别认错元素**：`"N portfolios in X · click to inspect"` 属于**下方面板**（组件 `F`），
   不是右侧 inspector。第一版探针用它判断「inspector 出现了」，导致「点行内数字」一栏误判成
   「没反应」。inspector 的稳定特征是 `⊙ Inspector` 眉标 + `button[aria-label="Close inspector"]`。

5. **headless 无 WebGL 会把 Constellation 误报成坏页**：不加软渲染时页面显示
   「This page couldn't load」并抛 `Error: Error creating WebGL context.` —— 看着像回归，其实是环境。
   用 `--enable-unsafe-swiftshader --use-angle=swiftshader` 复跑即正常（canvas/scene 都在）。

6. **静态 diff 验证不了「接线」**。`node --check` 只能证明语法，证明不了「点下去会不会走对分支」
   —— 本次三类点击的差异（选中 / 下钻 / 无反应）在静态检查里长得一模一样，必须真点。
