# v2.3.0 — Architecture 域接入部署站的 Architecture 面板（内嵌），并修掉改写器与数据兜底租户不一致

**日期**: 2026-09-21

**需求/背景**: 「复刻 https://sip-platform.web.app/architecture/ 这个网页到我的前端项目中，
并且在 Architecture 的菜单栏下展示」。

改造前 Architecture 是**空壳域**：`NAV` 里 `sidebar: null`，点顶栏落到 service-ops 概览，
再由接缝 S9 把那页标题改写成域名 —— 也就是说这一栏背后没有自己的页面。

沿用已跑通三次的内嵌路线（Constellation / Business Ops / Service Ops），不重写。
理由与那三次相同，记录在 `ConstellationView.vue` 与 `changelogs/v2.0.0-constellation-embed.md`：
那是另一套 Next.js 应用的一整页，而本页的核心是 **cytoscape 现场跑的 22 节点布局**
（4 层边着色 + 点选上下钻 + inspector 联动），Vue 重写等于重写整个页面。

---

## 改动明细

### 1. `tools/make-offline-page.py` — 加第 4 个页面 (line 165)

**原因**: 离线副本的入口表，产出必须落在 `/architecture/index.html`。

```python
# 四个页面。产出都进 public/
     "architecture": {
         "site_path": "/architecture/",
         # ⚠️ 面板表里是 `route:"/architecture"`，对不上时内层 h1 静默变成 "SIP"
         "out": ("architecture", "index.html"),
         "vendor_sub": "architecture",
         "shared_chunks": True,
     },
```

顺带补齐文件头那份**已经过期**的页面清单（原先只列 constellation / business-ops，
service-ops 加进来时没同步）。

### 2. `tools/tenant_copy.py` — Architecture 的三条租户文案 (line 81-88, 194-201)

**原因**: 该页有三处**写死的 data-sicg 数字**，页面其余部分（KPI 四格、6R 分布、
Tech stack、Wave plan）都读 snapshot、本来就按租户算 —— 只有这三处不跟着变，
切到别的租户会出现「标题说 893 apps / 22 portfolios，正下方的 KPI 说 50 apps / 11 portfolios」。

```python
"arch_desc": "893 apps · 22 portfolios · 6 journeys · the estate as one canvas. …",
"arch_sub":  "22 portfolios · click any node to inspect · KPIs / 6R / journeys filter the graph",
"arch_aria": "Estate graph · 22 portfolios with edge layers",     # 属性，走 aria-label 白名单
```

字面量在页面自己的 chunk `01d8-2wl~-f7r.js`（`PanelContainer` 的 description 与
Estate graph 小节），不在 server.html 的 RSC payload 里 —— 但改写器只认**渲染后的
DOM 文本 / 属性**，源码在哪儿都无所谓。

三个数缺一不可：只换一部分会拼出「50 apps · 22 portfolios · 2 journeys」这种自相矛盾的
句子，比不换更糟，所以整条一起产出。

### 3. `tools/tenant_copy.py` — 改写器兜底租户改用 `DT_DEFAULT` (line 956, 1042) ★

**原因（这是本次唯一一处**既存 bug**，且不在原需求范围内）**：
那个兜底有**两个消费方**，而它们被改成了不同的值：

```js
// 内嵌页取数（bundle，patch_default_tenant 已把 retail 改成 otr）
?tenant=<id> → localStorage["sip-active-tenant"] → 兜底 "otr"

// 本文件的改写器（一直是 retail）
if (t && MAP[t]) return t;  …  return 'retail';   →   return '__DT_DEFAULT__';
```

于是**「没设过租户」这个最常见的情况下数据按 otr 渲染、文案按 retail 改写**。
实测（headless，`/architecture`，未设 localStorage）：

| | 修复前 | 修复后 |
|---|---|---|
| 标题（改写器） | `282 apps · 9 portfolios · 6 journeys` | `50 apps · 11 portfolios · 2 journeys` |
| KPI（snapshot） | `50` apps / `11` portfolios / `2` journeys | 同左 |

站点自带的兜底**两处都是 retail**，所以原样搬过来时看不出问题；`patch_default_tenant`
（`cf01394`）把数据那侧改成 otr 之后，就只剩改写器没跟上。

占位符 `__DT_DEFAULT__` 由 `inject()` 填成 `DT_DEFAULT` —— 单一真源，不再有第二个字面量。

### 4. `vite.config.js` — `EMBED_PAGES` 加 `/architecture` (line 69)

**原因**: 与 Service Ops 同一套处理。本页 Vue 路由与内嵌页路径**同名**，
插件只拦**带尾斜杠**的请求，`/architecture` 留给 SPA：

```
/architecture/  → 内嵌页（iframe 打的就是它）
/architecture   → SPA（否则硬刷新会拿到裸的内嵌页，没有 AppHeader / 侧边栏）
```

（Business Ops 那边不同名 —— 路由叫 `/biz-ops`、内嵌页在 `/business-ops/`，所以从不打架。）

### 5. `src/views/architecture/ArchitectureView.vue` — 新增

复用 `NextEmbed.vue`，`src="/architecture/"`。文件头写清了三件事：为什么内嵌、
路径为什么不能改（面板表里 `route:"/architecture"`）、以及与 Vue 路由同名时的三处成对处置。

### 6. `src/router/index.js` — `DOMAIN_COMPONENTS` 登记 (line 144)

```js
const DOMAIN_COMPONENTS = {
  constellation: () => import('@/views/constellation/ConstellationView.vue'),
  'biz-ops':      () => import('@/views/business-ops/BusinessOpsView.vue'),
  architecture:   () => import('@/views/architecture/ArchitectureView.vue'),   // ← 新增
}
```

空壳域不走 `MIGRATED` / `VIEW_COMPONENTS` 那一套，**只在这里登记一次**。
`meta.legacy` 由 `!own` 派生，组件渲染了 legacy 面板就隐藏 —— 两处不一致会出现双显。

### 7. `README.md` (line 64) — nginx 补一条同源规则

```nginx
location = /architecture { try_files /index.html =404; }
```

**原因**: `dist/architecture/index.html` 存在时，通用 `try_files $uri $uri/ /index.html`
会把 `/architecture` 经 `$uri/` 解成那个目录索引，**吐出裸的内嵌页**。
dev/preview 由 `sipEmbedPageIndex` 兜住，生产只能靠这条。

### 8. 文档同步（`CLAUDE.md` / `src/components/NextEmbed.vue` / `src/router/nav.js`）

- `CLAUDE.md`：内嵌页一节「三个域」→「四个域」；补两条踩坑（同名内嵌页三处成对、
  改写器兜底租户必须与 `patch_default_tenant` 同值）；当前版本号 `v2.0.0` → `v2.3.0`
  （原先已经落后于 `changelogs/` 里的 `v2.2.25`）。
- `nav.js`：`EMPTY_DOMAINS` 与顶部注释里「空壳域」的措辞按现状修正 ——
  **没有侧边栏 ≠ 没有自己的页面**，这 5 个里已有 3 个接了内嵌页。

## 踩坑记录

### ⚠️ 重建 `public/` 会顺手把三份**过期**的 HTML 刷新

`tools/make-offline-page.py` 每次重建都从 bundle 现算 `__SIPCOPY__`，所以「只重建
architecture」在 git 上却动了另外三个页面。逐个核对过差异，归因清楚：

| 差异 | 性质 |
|---|---|
| 三页各 +3 条 arch 文案 | 新增键，全局共享一份 map —— 预期内 |
| 三页的 otr 租户从**无**到有（23 条） | **修好了一处既存遗漏**：`cf01394` 给 bundle 加了 otr 租户（`tenant-data/otr.json` → `apply_overrides`），但**没有重跑三个页面的 HTML**，所以那三份产物里 otr 一条文案都没有 —— 切到 otr 时文案停在 retail 的措辞 |
| 改写器兜底 `retail` → `otr` | 第 3 条的修复，见上 |

结论：**没有**手改过的产物被冲掉（差异 100% 可归因）。这正是 `CLAUDE.md` 那条
「提交前先看 `git status` / diff」要防的事 —— 构建输出「一切正常、不报错」。

### headless 里 Constellation 白屏 ≠ 本次改坏

验证时 `/constellation` 在 headless 下是 Next 自己的错误页（`<html id="__next_error__">`），
一度像是被重建弄坏了。**对照实验**：把 `HEAD` 版那一份 `constellation-app.html`
单独伺服，**同样报错** —— 说明与本次改动无关。

真因是 headless 默认拿不到 WebGL，而那张图是 three.js 的。加
`--enable-unsafe-swiftshader` 后正常渲染（顺带确认 otr 的文案这次是**对的**：
「The OTR operational fabric · 50 apps across 11 portfolios + 2 journeys」）。
