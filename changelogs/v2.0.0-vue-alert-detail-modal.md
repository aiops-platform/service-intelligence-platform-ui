## 改动明细

### 1. 实测范围比计划稿大：403 行 → **~515 行 / 4 个函数**

计划稿按"403 行的 `renderAlertAnalysisContent`"估算，实测还要连带三个函数：

| 函数 | 行数 | 作用 |
|---|---|---|
| `renderAlertAnalysisContent` | 406 | 主体：hero / AI 摘要 / 影响评估 / 建议动作 / 诊断时间线 / 原始详情 / Agent 执行日志 |
| `renderToolExecution` | 24 | 单次工具调用卡片 |
| `renderToolResult` | 44 | 按工具名分派结果渲染 |
| `renderLogQueryResult` | 41 | 日志查询结果条目 |

**内联处理器也更多**：计划稿说 3 处 `window._showToast`，实际共 **9 处** ——
3 处 `_showToast` + 3 处匿名 IIFE（思考链展开、工具参数展开、堆栈展开）
+ 2 处 `_toggleCollapsible` + 1 处 `_toggleEvidence`。

### 2. `src/components/alert-detail/renderAnalysis.js` — 新增（~560 行）

四个渲染函数逐段移植，`container.innerHTML = html` 改为 `return html`。

**两条约束写在文件头注释里**：

1. **`escapeHtml` 不能省** —— 产物经 `v-html` 注入，而 `v-html` **不做转义**。
   改造前这里对每处插值都调了 `escapeHtml`，移植时逐处保留。
2. **不再有 `onclick`** —— 那类处理器在 `v-html` 注入的 HTML 里**不会被 Vue 编译、也不会执行**
   （这就是"整段 v-html 搬过去会让按钮全废"的原因）。全部改成 `data-action` 属性：

```diff
- '<button class="action-btn primary" onclick="window._showToast(\'Copied: X\',\'info\')">'
+ '<button class="action-btn primary" data-action="toast" data-type="info" data-msg="Copied: X">'
```

顺带修掉一个隐患：改造前 `renderToolExecution` / `renderLogQueryResult` 用
`Math.random().toString(36).substr(2,8)` 生成元素 id，多次渲染有撞号风险且不可复现；
改为模块级递增计数器。

### 3. `src/components/AlertDetailModal.vue` — 新增

DOM 逐字沿用原 `index.html:2035-2045`（`.ap-modal-overlay` / `.ap-modal` / `#alertDetailTitle` /
`#alertDetailContent`），继续复用 `styles.css`。

核心是**一个委托监听器**处理全部 9 类交互：

```js
function onClick(e) {
  const el = e.target.closest('[data-action]')
  if (!el) return
  switch (el.dataset.action) {
    case 'toast':               showToast(msg, type); break
    case 'toggle-evidence':     /* 切 .visible + 按钮文案 + timeline .show-details */ break
    case 'toggle-collapsible':  /* aria-expanded + .expanded + content .open */ break
    case 'toggle-think-step':   /* .think-step 的 .expanded */ break
    case 'toggle-args':         /* target 的 .open */ break
    case 'toggle-stack':        /* target 的 .open + 按钮文案 */ break
  }
}
```

**不需要 Vue 的响应式**：这块内容是一次生成、之后不再变的静态 DOM（每次打开按 API 数据
重算一份），拆成 8 个组件只会把同一批条件分散到 8 个文件、更难比对。故按"单组件 + 事件委托"
处理（该取舍已与需求方确认）。

### 4. `src/composables/useAlertDetail.js` — 新增

模块级单例状态（不是 per-component）：模态被两个视图共用，全文档只应有一个实例
—— 这也正是改造前 `#alertDetailOverlay` 靠 id 唯一性保证的事。沿用改造前的参数化设计
（`apiPrefix ∈ 'log-alert' | 'metric-alert'`），并保留原判定链：响应是
`{success, data:{success, data:{…}}}`，api 层只剥一层，这里再判内层 `.success` 后取 `.data`。

### 5. `src/utils/time.js` — 新增

`formatTimeAgo`（改造前是 app.js 的模块级函数，模态与列表共用）+ `formatTime`（S6 用）。
`formatTime` 的时区处理逐字保留：**先正则剥掉自带的时区后缀再补 `Z`**，否则会偏。

### 6. `src/App.vue` — 挂载模态 + 暴露接缝 S4

```js
window.__SIP_OPEN_ALERT_DETAIL = (apiPrefix, alert) => openAlertDetail(apiPrefix, alert)
```

## 踩坑记录

### playwright 的点击可点击性检查会误报

第一轮用 `locator.click()` 点折叠触发器，报 `intercepts pointer events` 并超时，
一度以为是覆盖层把按钮挡住了。改用 `evaluate(() => el.click())` 直接触发后：
`{w:908, h:39, expanded:true, open:true}` —— **按钮尺寸正常、处理器正常触发**。
原因是该按钮在滚动容器的可视区外，playwright 的可操作性检查（要求元素稳定可点）判定失败。

后续交互验证统一改用 JS 触发，避免把"工具的限制"误判成"代码的 bug"。
（真实用户滚动后点击是正常的。）
