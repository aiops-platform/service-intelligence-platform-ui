# v2.2.13 — 悬停提示里加上节点创建时给的 description

**日期**: 2026-09-20

**需求/背景**: 承接 v2.2.12 —— 悬停提示除了 agent/status/耗时/tokens/cost，
还要显示**节点创建时给的 `description`**。

---

## 改动明细

### 1. `src/components/graph/nodeTip.js` — 返回值加 `desc` (35)

**原因**: 节点说明要显示。

```js
// before
return { title: g.id || '—', rows }

// after
return { title: g.id || '—', desc: g.description || '', rows }
```

### 2. `src/components/graph/useGraphCanvas.js` — 渲染 desc 段落 (355)

**原因**: 同上。

**以独立段落呈现，不是 `label: value` 行**——它是对节点的一句话解释，可能较长；
塞进行里会把 key 列挤没。空 `desc` 时**整段不渲染**（不留空白条）。

**照样用 `textContent`**：description 是数据（YAML 里人写的），拼 HTML 就是注入口子。

### 3. `css/styles.css` — `.bs-node-tip-desc` (6271)

标题下方、字段上方，虚线下边框分隔。

## ⚠️ 一个绕不开的限制（读这条再排查"为什么没显示"）

run 的图是从 **snapshot** 重建的，而 snapshot 在 run 创建时就**冻结**了：

| | 能看到 description 吗 |
|---|---|
| 已有的 run | ❌ **永远不能**——快照里就没有这个字段 |
| 新建的 run（流程图已更新） | ✅ |

所以验证时要**新建一次 run**，不要拿历史 run 试。
另外种子改动**只对新建租户生效**（空表才播）；已开通租户要 `PUT /workflows/{wid}`。
