# v2.2.6 — Service Ops 侧边栏隐藏 Metrics Analysis / Log Analysis

**日期**: 2026-09-18

**问题/背景**: 需求 ——「把 Service Ops 中导航栏里的 Metrics Analysis 和 Log Analysis
这俩页面隐藏掉」。与 2026-09-17 隐藏 Ticket Workspace 的 Approval Center / L1 Automation、
以及 Value Pool 域同类：**只摘导航，不删页面**。

---

## 改动明细

### 1. `src/router/nav.js` — observability 分组摘掉两个叶子 (line 116-148)

**原因**: 侧边栏由 `NAV` 直接渲染（`AppHeader.vue` / `SidebarGroup.vue`），路由表由
`flattenItems()` 从同一份 `NAV` 派生（`src/router/index.js:161`）。所以**只动这一处**，
菜单项与路由会同时消失，不需要在别处再摘一次。

```diff
         {
+          /*
+           * 原先这里还有 Metrics Analysis 与 Log Analysis 两个叶子。按用户要求
+           * 「隐藏掉」，已于 2026-09-18 从本数组摘除 —— 与上面 Ticket Workspace
+           * 那次同一条路子：**只摘导航，不删页面**。
+           * ...（恢复方法见注释本身）
+           */
           key: 'observability',
           label: 'Observability',
           items: [
             { slug: 'smart-inspection', label: 'Smart Inspection' },
-            { slug: 'metrics-analysis', label: 'Metrics Analysis' },
-            { slug: 'log-analysis', label: 'Log Analysis' },
             { slug: 'problems', label: 'Problem Center' },
           ],
```

**一个字节都没动的东西**（恢复时不用碰）：

| 位置 | 内容 |
|---|---|
| `src/legacy/legacy-panels.html` | `#page-metrics-analysis`（:885）整个面板 |
| `js/app.js` | `initMetricsAnalysis()`、`_pageRefreshers['page-metrics-analysis']`（:3475）、`_pageRefreshers['page-log-analysis']`（:3664）、`initNavigation` 的两个分支（:153-156） |
| `src/router/nav.js` | `MIGRATED` 里的 `log-analysis`（:9）、`PANEL_ID` 的两条映射（:28-29） |
| `src/router/index.js` | `VIEW_COMPONENTS` 的 `log-analysis` 懒加载（:19） |
| `src/views/log-analysis/` | `LogAnalysisView.vue` 全套 |

> `log-analysis` 与 `metrics-analysis` 的性质不同，这点在恢复时才有意义：
> 前者是**已迁到 Vue 的视图**，后者是 **legacy 面板**。`MIGRATED` 与 `VIEW_COMPONENTS`
> 里那两条现在暂时没有消费方（叶子不产出 → 没有路由 → 组件不会被加载），但**刻意保留**
> —— 它们是「已迁移」的唯一登记口，且两处必须成对，摘掉反而要在恢复时重新拼回来。

**踩坑记录 / 需要记住的副作用**：这次与上两次隐藏有一处实质区别 ——
**Metrics Analysis 不是只有菜单能到**。Smart Inspection 表格里的 Alert Count 徽标点下去会
`navigateToPage('metrics-analysis', ...)`（`js/app.js:2124`），经接缝 S3 变成
`router.push('/metrics-analysis')`。叶子摘掉后这条 URL 不再存在，于是那个徽标会**静默落进
catch-all 重定向回 `/service-ops`**。这正是「隐藏即可直达」语义的应有效果（同 README 里
Value Pool / Approval Center 两节所记），但它是**一处仍在页面上的交互**，所以特别记在这里，
以免日后被当成 bug 排查。

> 另一个徽标（Log Anomalies 列）不受影响 —— 该列数据源已下线、恒为 `-`，渲染出的
> class 是 `null-alert` 而非 `has-alerts`，`js/app.js:2113` 的 `closest('.si-alert-badge.has-alerts')`
> 本来就选不中它，那条 `log-analysis` 下钻早已到不了。

**没有**新增 `hidden` 标志位 —— 理由同 README 里 Value Pool 那节的注解：加标志位等于给
「可见性」引入第三套语义，而「从 `NAV` 摘掉」本身已经同时表达了「菜单不显示」与「路由不存在」。

**恢复方式**：把这两行放回 `nav.js` 的 `observability.items` 即可：

```js
{ slug: 'metrics-analysis', label: 'Metrics Analysis' },
{ slug: 'log-analysis', label: 'Log Analysis' },
```
