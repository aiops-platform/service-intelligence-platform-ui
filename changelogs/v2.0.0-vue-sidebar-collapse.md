# v2.0.0 — Service Ops 侧边栏可收起（附：修好断掉的外壳高度链）

**日期**: 2026-09-16

**需求背景**: Service Ops 页面左侧常驻一条 220px 导航栏，把右边的 KPI 卡片区和
Applications 表格挤窄了。要求做成**默认可收起** —— 收起后左边缘留一个朝右的箭头把手，
点一下展开。

排查过程中发现需求之外的一个既有 bug（用户确认后一并修）：**Service Ops 页面底部被截断
且无法滚动**，Applications 表格的后几行永远看不到。

---

## 结论先说

两件事分开看：

1. **侧边栏收起**：靠 `v-if` 卸载整个 `<aside>` 实现，**不动 `.sidebar` 的 220px 宽度**。
   该宽度被 `js/app.js` 的 `hideAllSidebars()` 和独立打开的
   `engineering-ops-standalone.html` 共用，改它等于波及旧世界。
   能力开关做成 `nav.js` 的域字段 `collapsible`，仅 Service Ops 打开。

2. **底部截断**：根因是 Vue 改造在 `<body>` 和 `.app-body` 之间插入了 `#app`，
   而 `#app` 在本仓样式表里**一条规则都没有**。修法是给 `#app` 补上布局规则 ——
   纯新增，不改任何既有选择器。

> 第二条是全站性的，不只 Service Ops。修之前所有长页面都中招。

### 高度链是怎么断的

```
body(100vh, flex column, overflow:hidden)
  └ #app          ← 无规则 = display:block + 自动高度，flex:1 无处生效
    └ .app-body   flex:1 —— 父级不是 flex 容器，悬空
      └ main      flex:1 + overflow-y:auto —— 高度恒等于内容高，等于不滚
```

改造前 `.app-body` 是 `<body>` 的直接 flex 子项，`flex:1` 生效、`main` 有确定高度、
`overflow-y:auto` 正常滚动。Vue 插入 `#app` 后这条链断了，最后 `body` 的
`overflow:hidden` 把超出视口的内容直接裁掉。

⚠️ 注意 `body { overflow: hidden }` 会按 CSS 规范**传播到视口**（body 自身计算为 visible），
所以表现是「**连滚动条都没有**」，而不是「有滚动条但滚不动」——
这也解释了为什么它一直没被当成 bug 报出来。

本仓其实早就记录过这条断链：`css/styles.css:7369-7378`（Next.js Embed 一节），
当初 Constellation 就是因为绕不开它才用了 `position: fixed`。

## 改动明细

### 1. `css/styles.css` — 新增 `#app` 规则 (line 40-64)

**原因**: 补上高度链缺的那一环。**纯新增** —— `#app` 此前零规则
（改动前 `grep -n "#app"` 只命中 7372 行注释里的一处）。

```css
+ #app {
+     display: flex;
+     flex-direction: column;
+     flex: 1;
+     min-height: 0;
+     overflow: hidden;
+ }
```

**`min-height: 0` 不可省**：flex 子项的 `min-height` 默认是 `auto`（即内容高），
不给 0 的话 `#app` 依然会被长内容撑开、拒绝收缩到 100vh，等于没修。
这是本次唯一一处「看着多余、删了就静默失效」的声明。

修完后：`#app` = 100vh → `.app-body` flex:1 生效 → `main` 拿到确定高度 → 恢复滚动，
且 `main` 的 `padding-bottom: 40px`（本就是给 fixed footer 让位的）终于有意义。

### 2. `css/styles.css` — 新增 `.sidebar-grip` (line 369-420)

**原因**: 收起后左边缘需要一个抓手。插在侧边栏块末尾、`/* Main Container */` 之前。

```css
+ .sidebar-grip {
+     display: flex;
+     align-items: center;
+     justify-content: center;
+     width: 12px;
+     min-width: 12px;
+     flex-shrink: 0;
+     border: 0;      /* <button> 的 UA 默认样式重置 */
+     padding: 0;
+     background: var(--bg-white);
+     cursor: pointer;
+     transition: background-color 0.15s;
+ }
+ .sidebar-grip:hover { background-color: #f3f4f6; }
+ .sidebar-grip:focus-visible { outline: 2px solid var(--accent-purple); outline-offset: -2px; }
+
+ /* 朝右 —— 收起态，点击展开 */
+ .sidebar-grip::before {
+     content: '';
+     display: block;
+     width: 0; height: 0;
+     border-top: 4px solid transparent;
+     border-bottom: 4px solid transparent;
+     border-left: 5px solid var(--text-tertiary);
+ }
+ /* 展开后翻转朝左 —— 点击收起 */
+ .sidebar-grip.expanded::before {
+     border-left: 0;
+     border-right: 5px solid var(--text-tertiary);
+ }
```

三个刻意的选择：

- **不碰 `.sidebar` / `.sidebar.visible`**（`styles.css:257-269`）—— 收起靠 `v-if`，不靠 width。
- **把手不带 border**：`.sidebar` 自带 `border-right`（`styles.css:262`），展开时两者相邻，
  再加一条就是双线。
- **状态类名用 `.expanded`** 而非 `is-expanded` —— 与仓库既有词汇一致
  （`.sidebar-item.has-children.expanded`，`styles.css:343`；全仓 `is-expanded` 零命中）。
  既有的 `.expanded` 全是复合选择器，漏不到 `.sidebar-grip` 上。

### 3. `src/router/nav.js` — 域能力开关 (line 88-89)

```js
  key: 'service-ops',
  label: 'Service Ops',
  landing: 'service-ops',
+ /** 该域的侧边栏可收起、且默认收起。消费方见 src/App.vue 的 sidebarCollapsible。 */
+ collapsible: true,
  dot: '#10b981',
```

**原因**: 仓里已有「用数据字段表达域行为」的先例（`sidebar: null` ⇒ 落进 `EMPTY_DOMAINS`）。
做成域字段而不是在 App.vue 里硬编码域名字符串 —— 以后要给 eng-ops / agents 开这个能力
就是一行数据。

### 4. `src/App.vue` — 状态与把手 (line 41-60, 135-153)

**script**:

```js
+ const collapsed = ref(true)   // 默认收起

+ // 域判定用 navKeyOf(activeSlug) 而**不是** activeKey
+ const slugDomainKey = computed(() => navKeyOf(activeSlug.value))
+ const sidebarCollapsible = computed(
+   () => !!activeSidebar.value && !!NAV.find((n) => n.key === slugDomainKey.value)?.collapsible,
+ )
+ const showSidebar = computed(
+   () => !!activeSidebar.value && !(sidebarCollapsible.value && collapsed.value),
+ )
```

**为什么不用 `activeKey`**：它带 `?? 'service-ops'` 兜底（`App.vue:35`），会让**域外路由**
误命中 Service Ops —— 典型是 `/runs/:runId`（`router/index.js:26-33` 的 `EXTRA_ROUTES`），
它的 `activeSlug` 是字面量 `runs/<id>`，`navKeyOf` 返回 `null`，正好把把手挡在域外。
而 `navKeyOf` 对 `/service-ops` 本身返回 `'service-ops'`（`nav.js:267` 的 `DEFAULT_SLUG` 分支），
两种路径都对。

**template**（`.app-body` 内、`AppSidebar` 与 `main` 之间）:

```html
- <AppSidebar :sidebar="activeSidebar" :active-slug="activeSlug" />
+ <AppSidebar v-if="showSidebar" :sidebar="activeSidebar" :active-slug="activeSlug" />
+
+ <button v-if="sidebarCollapsible" type="button" class="sidebar-grip"
+   :class="{ expanded: !collapsed }"
+   :aria-expanded="String(!collapsed)" :aria-controls="activeSidebar.id"
+   :title="collapsed ? '展开导航' : '收起导航'"
+   @click="collapsed = !collapsed"></button>
```

**为什么把手放在 App.vue 而不是 AppSidebar 内部**：收起时那个组件整个被卸载，
把手必须留在外面才存在得了。

**为什么用真 `<button>` 而非 `div[role=button]`**：默认收起意味着键盘用户若够不到它，
就**完全没有任何路径**打开该域的导航。真按钮自带 Tab/Enter/Space，与仓库既有的展开控件
写法一致（`components/alert-detail/renderAnalysis.js:528` 用的就是带 `aria-expanded` 的 button）。

**状态为什么不需要 localStorage**：`ref` 活在 App 实例里，而 App 全局只挂载一次
（`main.js:14`），`router.push` 不重挂 —— 所以 SPA 内切页天然保留、刷新页面自然回到
默认收起。这正是需求要的语义。

## 踩坑记录

| 坑 | 现象 | 根因 | 处置 |
|---|---|---|---|
| **把手位置依赖高度链** | 若按原设计让把手随 `.app-body` 内容高度 stretch，内容一高箭头就跑到屏幕外；而默认又是**收起**，等于导航彻底打不开、刷新也救不回来 | `#app` 无规则导致 `.app-body` 高度等于内容高（不是视口高） | 先修 `#app`，把手才是视口高的。实测 1440×500 短视口下箭头中心仍在可视带内 |
| **把手不能用 `position: absolute`** | 会被裁掉 | `main` 是 `overflow-y:auto`（`styles.css:376`），绝对定位子元素会被它裁；本仓在 `.cs-embed` 上踩过同一个坑（`styles.css:7380-7382`：absolute + 高度对了，但 main 只有 60px，照样裁） | 用**在流 flex 子项**。副作用是好的：位置固定，展开/收起时不跳动 |
| **`min-height: 0` 看着多余** | 不加则 `#app` 仍被内容撑开，**改了跟没改一样、且不报错** | flex 子项 `min-height` 默认 `auto` = 内容高 | 已在 `styles.css` 就地写明，防止后人"清理冗余声明"时删掉 |
| **body 的 overflow 会传播到视口** | 表现是「连滚动条都没有」，不是「有滚动条但滚不动」 | CSS 规范：body 的 overflow 传播到视口后 body 自身计算为 visible | 非问题，但它是这个 bug 藏了这么久的原因，记录备查 |
| **宽度变化没有通知通道** | 收起会让 `main` 宽度变 220px，而 `window.resize` **不触发**（视口没变）、仓里也没有 `ResizeObserver` | 纯 CSS 布局变化对 JS 不可见 | 今天全站无影响（见下表验证）。**但第一个用 `clientWidth` 自适应宽度的 Service Ops 视图会踩这个坑** —— 届时改成 `provide('sidebarCollapsed', collapsed)`（对齐 `App.vue` 既有的 `provide('expandedGroups')` 惯例）即可，本次**不预先加**（没有消费方的抽象） |

> 另一条**差点踩**的：`.sidebar-grip` 一开始写的是 `is-expanded`。仓库既有词汇是
> `.expanded`，已统一。
