# v2.0.0 — 服务概览页筛选框去掉空的 `JOURNEY 3~6` chip

**日期**: 2026-09-16

**问题/背景**: 用 MB Retail 租户（只有 2 条 journey）看服务概览页时，**顶部筛选框**里多出
4 个空 chip：

```
SALES CUSTOMER JOURNEY · 28   CUSTOMER SERVER JOURNEY · 22
JOURNEY 3 · 0   JOURNEY 4 · 0   JOURNEY 5 · 0   JOURNEY 6 · 0   ← 这 4 个
```

要求把这几个拿掉 —— 暂时没有对应内容。

---

## 结论先说：与 journey 表是**同一个根因的第二处现场**

`changelogs/v2.0.0-business-ops-journey-slots.md` 记过一次同类问题：页面把 journey 槽位
**写死成 6 个**，原有 10 个租户恰好都是 6 条 journey 所以从没暴露；租户不足 6 条时，
多出来的槽位在 `snapshot.journeys` 里查不到，就退回字面量 `` `Journey ${n}` ``。

当时只修了 **Business Ops 的 journey 表**（`0pfw3-ib1qee0.js`）。本次发现
**服务概览页的筛选框**（`0t1fyt7wcotiz.js`）有一份形状完全相同的硬编码：

```js
function u(e){ let r=t.snapshot.journeys.find(t=>t.id===`journey:${e}`); return r?.label ?? `Journey ${e}` }
let p=[1,2,3,4,5,6].map(e=>c(u(e)…))      // ← 同样写死 6 个槽位
```

两处只是 minify 后的变量名不同。所以不新增函数，**把既有的 `patch_journey_slots` 改成表驱动**。

---

## 改动明细

### 1. `tools/tenant_copy.py` — `patch_journey_slots` 改为表驱动 (line 209-259)

```python
JOURNEY_SLOTS = [
    ("Business Ops journey 表", "0pfw3-ib1qee0.js",
     "let h=[1,2,3,4,5,6].map(",
     "let h=e.snapshot.journeys.map((_,i)=>i+1).map("),
    ("服务概览页筛选框", "0t1fyt7wcotiz.js",
     "let p=[1,2,3,4,5,6].map(e=>c(u(e)",
     "let p=t.snapshot.journeys.map((_,i)=>i+1).map(e=>c(u(e)"),
]
```

**返回值从 `bool` 改成 `list`**（已修补的标签列表），调用方据此逐个打印 —— 比原来的
`if … : print(…)` 更能看出到底修了几处、修的是哪处。

原有那处的 `FIND`/`REPL` 字符串**一字未改**，只是搬进了表里；幂等与「不唯一就静默跳过」
两条语义都保留（每一项独立判断）。

> 注意两处的模块绑定名不同：Business Ops 那边是 `e.snapshot`，服务概览页这边是
> `t.snapshot`（同一文件内 `t.snapshot` 出现 17 次，绑定有效）。

### 2. `tools/make-offline-page.py` — 调用点跟进 (line 320-323)

```python
- if tenant_copy.patch_journey_slots(chunks_dir):
-     print("  journey 表行数：6（写死）→ 按 snapshot.journeys 自适应")
+ for where in tenant_copy.patch_journey_slots(chunks_dir):
+     print(f"  journey 槽位：6（写死）→ 按 snapshot.journeys 自适应 · {where}")
```

### 3. `public/_next/static/chunks/0t1fyt7wcotiz.js` — 构建产物随之更新

与另两处 patch 同理：产物入库，重建时被改写。

## 踩坑记录

| 坑 | 现象 | 根因 | 处置 |
|---|---|---|---|
| **一开始以为要「删掉几个 chip」** | 想在筛选组件里砍掉后 4 项 | 那 4 项不是「多画的」，而是硬编码槽位查不到数据后退回的字面量 | 改成按 `snapshot.journeys` 自适应 —— 租户有几条就渲染几条，对任何租户都成立 |
| 拿默认租户复现不出来 | 未设租户时 6 个 chip 都正常、都有计数 | 默认的 Acme Retail 恰好是 6 条 journey，槽位刚好填满 | 必须**切到 `mb-retail`**（`localStorage['sip-active-tenant']`）才能复现 |
| 改完看不到效果 | 磁盘已是新代码，页面 chip 没变 | 浏览器缓存了 chunk | CDP 里 `Network.clearBrowserCache` + `setCacheDisabled` |
