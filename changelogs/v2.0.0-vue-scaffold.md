**日期**: 2026-09-11

**需求背景**: 本仓现为纯静态站点（无 package.json / 无构建 / 无 lint），`js/app.js` 已涨到 8777 行
单文件、`index.html` 2210 行含 17 个视图面板，51 个版本里 63% 是补丁版。计划用 Vue 3 重写外壳 +

## 改动明细

### 1. `index.html` — 2210 行整体替换为薄入口（原文件 → 11 行）

**原因**: Vite 要求项目根的 `index.html` 作为唯一入口。原文件同时承担了 shell（header/sidebar/footer）、
17 个视图面板、13 个模态框三类内容，必须拆开才能让 Vue 接管 shell。

```diff
- <link rel="stylesheet" href="css/styles.css">
- <header class="flex items-center"> … 9 个 .nav-item … </header>
- <div class="app-body"> … 4 个 <aside class="sidebar"> … </div>
- <main id="main-content"> … 17 个 <div id="page-*" class="page-panel"> … 13 个模态 … </main>
- <footer> … </footer>
- <script src="js/app.js"></script>
- <div class="toast-container" id="toastContainer"></div>
+ <div id="app"></div>
+ <script type="module" src="/src/main.js"></script>
```

### 2. `src/legacy/legacy-panels.html` — 新增（1868 行）

**原因**: 15 个未迁移视图 + 12 个共享模态需要一个持久 DOM 宿主，由旧 `app.js` 继续拥有。
逐字从原 `index.html` 抽取，**不做任何格式化或改写**（class 名、缩进、内联 `style` 全部保持原样），
这样 `styles.css` 不需要任何配合改动。

抽取命令（可复现）：

```bash
sed -n '154,1112p;1194,1484p;1557,2034p;2046,2185p' index.html > src/legacy/legacy-panels.html
```

### 3. `vite.config.js` — 新增

**原因**: 三件事 —— 跨域（dev proxy）、`@` 别名、以及 `js/app.js` 的进出。

- **dev proxy**（跨域方案的核心）：浏览器请求 `http://localhost:5173/api/sip-aiops/...`，由 Vite
  服务端转发到 `:8080`，浏览器视角同源 → **无 CORS、无 preflight**。agentflow 挂在根路径
  （`/workflows`、`/runs/{id}`），故加 `rewrite` 剥掉 `/agentflow` 前缀。

  ```js
  '/api/sip-aiops': { target: 'http://localhost:8080', changeOrigin: true },
  '/agentflow':     { target: 'http://localhost:8000', changeOrigin: true,
                      rewrite: (p) => p.replace(/^\/agentflow/, '') },
  ```

- **`js/app.js` 的伺服与复制**：它从仓库根被原样保留（未迁移视图仍需），但不是 ESM、也不在
  `public/` 下，所以拆成两个插件分别处理 dev 与 build（见下节踩坑）。

### 4. `package.json` / `jsconfig.json` / `.env.example` — 新增

依赖压到最小：runtime 只有 `vue` + `vue-router`，devDeps 只有 `vite` + `@vitejs/plugin-vue`。
不装 Pinia（现有 8777 行里几乎无跨模块共享状态）、不装 axios（用原生 fetch 封装）、不装 TS。

### 5. `src/main.js` / `src/App.vue` — 新增（S1 占位）

`main.js` 挂载应用并全局引入 `../css/styles.css`；`App.vue` 本步仅占位，真 shell 在 S2 落地。

## 踩坑记录

### 坑 1：`apply: 'build'` 把 dev 中间件一起关掉了（已修）

第一版把「dev 伺服 app.js」和「build 复制 app.js」写在**同一个插件对象**里，并加了 `apply: 'build'`。
结果 `apply` 作用于整个插件，`configureServer` 在 dev 下**根本不执行** —— 中间件没生效，
Vite 用默认逻辑给这个 470KB 的文件追加了约 **2.4MB 的 inline sourcemap**（`/js/app.js` 返回 2,896,494 字节）。

功能上无损（IIFE 语义不变，只是白传 2.4MB），但 dev 下每次加载都付这个代价。改成两个插件各自限定 `apply`：

```js
function sipLegacyDevServe() { return { name: '…-dev-serve', apply: 'serve', configureServer(…) } }
function sipLegacyBuildCopy() { return { name: '…-build-copy', apply: 'build', closeBundle(…) } }
```

修后 `/js/app.js` 与本地文件 **sha256 完全一致**（`1971b646…`，470,211 字节）。

### 坑 2：`git check-ignore` 对已跟踪路径返回「未忽略」

补完 `.gitignore` 后用 `git check-ignore -v node_modules dist .idea/misc.xml` 验证，三条全报"未忽略"，
一度以为模式写错。实际原因是 **`.idea/` 当时还在索引里（已跟踪文件优先于 ignore 规则）**，
而 `node_modules`/`dist` 当时还不存在。加 `--no-index` 后三条全部正确命中：

```
$ git check-ignore -v --no-index .idea/misc.xml
.gitignore:10:.idea/	.idea/misc.xml
```

最终用「造 probe 文件再看 `git status`」的方式实证（三个 `probe.txt` 均未出现）。

### 坑 3：esbuild 的 postinstall 被 npx 拦住

`npm install` 报告 `esbuild@0.25.12 (postinstall: node install.js)` 被 allowScripts 策略阻止。
实测**不影响**：平台二进制由可选依赖包 `@esbuild/darwin-arm64` 提供
（`node_modules/@esbuild/darwin-arm64/bin/esbuild` 存在），`vite build` 正常通过。故未去放开脚本白名单。
