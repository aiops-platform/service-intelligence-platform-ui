# v1.3.0 — APM Monitors 监控端点配置页

**日期**: 2026-08-27

**问题/背景**: 后端 `aiops-apm-anomaly-detector` M0–M7 已完成，监控端点相关 API（`/v1/monitors` CRUD + `/{id}/test` + `/{id}/run`）已全部就绪，但无前端页面。需要图形化配置 monitor_target（3.2 对象配置①）：列表 / 新建 / 编辑 / 连通测试 / 手动单跑，单页面布局，配好（enabled + interval_sec + domain=application）即由后端调度器自动定时跑。

---

## 改动明细

### 1. `index.html` — Observability 分组下新增 APM Monitors 侧边栏子项 (line 103-105 后)

**原因**: 提供进入 APM Monitors 页面的导航入口。

```html
<div class="sidebar-item" data-page="apm-monitors">
    <span class="sidebar-label">APM Monitors</span>
</div>
```

### 2. `index.html` — 新增 APM Monitors 页面区块 (line 1150 后，Log Analysis 与模态框之间)

**原因**: 单页面布局，按后端 `/v1/monitors` 契约：顶部 Monitor Target Form（新建/编辑复用，含 `window_sec`/`time_params` 方案 B 字段）+ Test/Run Result 折叠区 + 底部 Targets 列表（搜索 / signal_type 筛选 / New 按钮）。

### 3. `js/app.js` — 侧边栏/顶栏路由接入 `page-apm-monitors` (line 93、571)

**原因**: 点击 sidebar 子项与顶栏 Service Ops 导航能切换到新页面。

```js
} else if (page === 'apm-monitors') {
    showPage('page-apm-monitors');
}
```

### 4. `js/app.js` — 新增 `initApmMonitors()` 模块 (line 3656 前)

**原因**: 对接后端 `/v1/monitors` API：
- 统一 `apmApi()` fetch 封装（带 `X-Tenant-Id`，可选 `Authorization: Bearer`；`APM_BASE_URL` 默认 `http://localhost:7070`，可用 localStorage `apmBaseUrl`/`apmTenantId`/`apmApiKey` 覆盖）
- 表单读写 `readForm()`/`fillForm()`/`resetForm()`（含 `window_sec`/`time_params` 滚动窗口字段、`signature_frames` log-only）
- `applyTemplate()` 模板下拉一键填 field_mapping（Prometheus / Flat row / ELK log）
- `saveTarget()` POST/PUT、`connectivityTest()` POST `/{id}/test`、`manualRun()` POST `/{id}/run` 结果渲染
- 列表 `refreshList()`/`renderList()` 渲染 + 搜索 + signal_type 筛选 + 行内 Edit/Test/Run/Delete
- 注册 `_pageRefreshers['page-apm-monitors']`，切回本页自动刷新；`init()` 中注册 `initApmMonitors()`

### 5. `css/styles.css` — APM 表单/结果/徽章样式 (文件末尾追加)

**原因**: 复用既有设计令牌，补齐表单卡片（`.apm-form-card`/`.apm-field`）、结果区（`.apm-result`/`.apm-signal-row`）、enabled 徽章（`.apm-badge`）、error toast（`.toast-msg.error`）。
