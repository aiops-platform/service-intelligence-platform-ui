# v2.0.0 — Vue 化第 3 步：统一 API 层 + 跨域收口

**日期**: 2026-09-11

**需求背景**: 承接 `v2.0.0-vue-shell-and-seams.md`（S2 外壳落地）。本步把后端调用从
「散落 12 处硬编码 base + 49 处裸 fetch + 3 份复制粘贴的封装」收敛成一层，并把跨域从
「前端硬编码绝对 URL、依赖后端开 CORS」改为「相对路径 + proxy」——**这是跨域问题的解法本身**。

---

## 改动明细

### 1. `src/api/config.js` — 新增：base 解析（替代 12 处硬编码）

三级回退：**localStorage > `VITE_*` 环境变量 > 相对路径默认值**。

```js
const DEFAULTS = { sipAiops: '/api/sip-aiops', agentflow: '/agentflow' }
```

两个设计点：

- **localStorage key 沿用旧名**（`bugSolveBaseUrl` / `workflowBaseUrl` / `agentsBaseUrl` /
  `mcpBaseUrl` / `agentConfigBaseUrl` / `apmBaseUrl`）—— 改造前从 console 设过的值继续生效，
  不打断既有习惯。
- **补上 `setBase()`** —— 改造前**全文件没有任何 `localStorage.setItem`**，那些「可用
  localStorage 覆盖」的注释实际无法从前端触达，只能靠外部注入。现在有了写入口，
  dev 下还挂了 `window.__sipApi` 便于 console 调试。

### 2. `src/api/http.js` — 新增：唯一的 fetch 封装

替代 49 处裸 fetch 与 3 份 `apmApi` 副本。包含：

- **query 拼接**：跳过 `undefined`/`null`/`''`（对齐改造前 `if (currentService)` 的条件拼接语义），
  数组展开成重复 key
- **超时**：`AbortController`，默认 15s（旧版无超时，请求会一直挂着）
- **`ApiError`**：带 `status` / `url` / `method` / `body`，错误信息取 `detail || message || error`
- **信封剥离**：`{success, data}` 只剥**一层**

```js
const unwrapEnvelope = (body) =>
  body && typeof body === 'object' && 'success' in body ? body.data : body
```

> 只剥一层是刻意的：analysis 接口返回 `{success, data:{success, data:{…}}}`，
> 剥两层会让调用方拿不到内层的 `.success`。与改造前 app.js:2269 的写法保持一致。

### 3. `src/api/sipAiops.js` / `src/api/agentflow.js` — 新增：端点模块

只列本方案两个视图（log-analysis / bug-solve）需要的端点，不预先写没人调的代码。

`agentflow` 的 base 是 `/agentflow` 而非根路径 —— agentflow 的路由挂在根
（`/workflows`、`/runs/{id}`），前缀由 dev proxy 的 `rewrite` 或生产 nginx 剥掉。

`logAlertApi.analysis()` 特意在注释里标明「只剥一层」的原因，避免后人"顺手修正"。

### 4. `src/composables/usePolling.js` — 新增

替代改造前 8 处裸 `setInterval` + `page.style.display !== 'none'` 守卫。统一处理：
`onUnmounted` 必停、keep-alive 下 `onDeactivated` 停 / `onActivated` 恢复、
`document.hidden` 跳过本轮（**修掉改造前"标签页在后台仍 2 秒一轮"的浪费**）、
`enabled()` 谓词（如"仅在 run 运行中轮询"）。

### 5. `src/composables/useToast.js` — 新增

复用旧世界的 DOM 契约（`#toastContainer` + `.toast-msg/.toast-info/.toast-success/.toast-error`）。
**刻意不定义 `window._showToast`** —— 那个由 `js/app.js` 定义并服务旧视图，两边都定义会互相覆盖。

### 6. `.env.example` — 说明两个 `VITE_*` 变量仅在「不配代理、要直连」时才需要填

## 影响范围

| 场景 | 预期 | 实际 | 状态 |
|------|------|------|------|
| `grep -rn 'localhost:' src/` | 零命中（注释除外） | 仅 2 处注释提及改造前状况，无实际硬编码 | OK |
| `npm run build` | 编译通过 | 通过 | OK |
| **sip-aiops 代理** | `:5173/api/sip-aiops/...` 转发到 `:8080` | 起桩后端实测：经代理与直连返回**逐字节相同**，且路径原样保留 | OK |
| **agentflow 代理 + rewrite** | `:5173/agentflow/workflows` → `:8000/workflows` | 对**真实运行的控制面**实测：经代理与直连结果一致（`[]`，HTTP 200） | OK |
| **rewrite 确实在剥前缀** | 不剥会 404 | `:8000/agentflow/workflows` → **HTTP 404**（对照证明） | OK |
| 浏览器无 CORS 预检 | 同源，无 `OPTIONS` | dev proxy 下浏览器视角同源 | OK |

**未覆盖 / 下一步**：本步只建立 API 层，**尚无调用方**——两个视图（log-analysis / bug-solve）
在 S6/S7 才接上去。因此本步的端点定义要到那时才算端到端验证过。APM(`:7070`)/KB 不在本次范围，
相关端点的 base 也一并留空（待其视图迁移时再补 `createClient`）。
