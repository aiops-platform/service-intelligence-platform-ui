# v2.2.28 — 审批卡"卡里套卡" + 撑爆面板；空字符串渲染成空白

**日期**: 2026-09-21

**问题/背景**: 「审批样式乱了」。复现对象 `run_668981c0a7`（停在 `approve-plan`）。

三处叠在一起，**都是我前面几轮改出来的**：

```
面板 h=620（我加的"与图等高"）   scrollH=2492   ← 内容溢出 4 倍
审批卡 h=2435                                  ← 撑爆面板
节点详情 top=2479 h=13                          ← 被挤到面板外，只剩 13px
```

---

## ① 卡里套卡（四层）

`<pre>{{ JSON.stringify(out) }}</pre>` 换成 `<NodePayload>` 之后，审批卡里出现了
**白底卡嵌琥珀卡**：

```
.bs-approval-card（琥珀底 + 橙左边框）
  └ .bs-upstream
      └ .bs-payload-top   ← 我加的白卡，为"白底面板"设计的，这里纯属套娃
          └ .bs-payload-nested → .bs-card（又一个灰底卡）
```

**修法**：给 `NodePayload` 加 `bare` prop —— 顶层不套白卡。嵌进**别人已有边框的卡**
里时用（审批卡就是），节点详情面板保持默认（那儿底是白的，白卡给内容一个边界）。

## ② 审批卡 2435px，撑破固定高的面板

`.bs-upstream pre { max-height: 120px; overflow-y: auto }` —— **原设计里上游载荷本来
就有高度上限、内部滚动**。换成 NodePayload 后（不再是 `<pre>`）**那条规则不再命中**，
载荷于是无上限增长。

而 `.bs-panel` 我上一轮刚改成**固定高**（与图等高），于是面板顶不住、内容溢出，
把节点详情挤到只剩 13px。

**修法**：

```css
.bs-upstream .bs-payload { max-height: 180px; overflow-y: auto; }
```

这条只匹配新组件（legacy 那边是 `<pre>`，没有 `.bs-payload`），所以**不用按页面限定**。

实测：审批卡 **2435px → 296px**，落进 `.bs-approvals` 的 320px 盒子；
详情回到面板内（bottom = 620 = 面板下沿）。

### 顺带：按钮钉在卡底

上游载荷再长也不该把「通过 / 驳回」滚出视野 —— 否则要翻到底才能点到主操作。
`#page-run-detail / #page-bug-solve .bs-approval-actions { position: sticky; bottom: 0 }`
（`.bs-approval-actions` 与 legacy 共用，故按页面 id 限定）。

### 还有一处漏用

CSS 里 `.bs-approvals`（`max-height: 320px; overflow-y: auto`）**定义了却没被 Vue
模板用** —— 标题和卡片原先直接挂在 `.bs-panel` 上。已改用该容器（它与 legacy 的
`#pcRunApprovals` 共用，**规则不动**）。

## ③ 空字符串渲染成一片空白

`comment` = `''` 时，`fmt('')` 返回空串 → 渲染成一个 **0 高度的 span**：
屏幕上什么都没有，看上去和"系统没返回这个字段"一模一样 ——
而这正是组件头部那条约定警告过的（"分不清『没有这个字段』与『字段是空串』"），
**第一版的实现反了**。

现在三种"空"各有其形：

| 值 | 渲染 |
|---|---|
| `null` / `undefined` | `—`（灰斜体）—— 没有这个值 |
| `''` / 纯空白 | `（空字符串）`（灰斜体）—— 有字段，值是空的 |
| `[]` / `{}` | `（空）` |
