# v2.0.0 — 站点根路径落地到 Constellation

**日期**: 2026-09-15

**问题/背景**: 打开 `http://localhost:5173` 落地到 `service-ops` 概览页。
需求是首屏直接展示 Constellation（`http://localhost:5173/constellation`）。

---

## 改动明细

### 1. `src/router/index.js` — 新增 `LANDING_PATH` 常量 (line 55-65)

**原因**: 落地页与 `DEFAULT_SLUG` 是**两个不同的语义**，不能共用一个常量。

- `DEFAULT_SLUG`（`service-ops`）是「**没有页面可落**时的兜底」：catch-all 路由、
  空壳域的 `panelId`、`__SIP_NAVIGATE` 空参，都指它；
- 落地页只是「**打开站点先看哪一页**」。

直接改 `DEFAULT_SLUG` 会把兜底一起改掉 —— 未知入口（`/typo`）会跟着跳到空壳域
`/constellation`，而按改造前的语义它应当落 Service Ops 概览。故引入独立常量：

```js
// before: 无此常量
// after:
const LANDING_PATH = '/constellation'
```

### 2. `src/router/index.js` — 根路径 redirect 改用 `LANDING_PATH` (line 121)

**原因**: 需求本身。只动根路径这一条，catch-all 保持不动。

```js
// before
{ path: '/', redirect: `/${DEFAULT_SLUG}` },
// after
{ path: '/', redirect: LANDING_PATH },
```

`/constellation` 是既有路由（由 `emptyDomainRoutes` 从 `EMPTY_DOMAINS` 生成，
`DOMAIN_COMPONENTS.constellation` 已挂 `ConstellationView.vue`），无需新增路由。

---

## 踩坑记录

### 落地到空壳域会不会踩 S9 标题改写？

`/constellation` 带 `meta.domainKey`，`App.vue` 的 `syncDomainHeader()` 会经接缝 S9
把 **legacy service-ops 概览页**的标题改写成域名（那两个节点归 legacy 所有）。
若首屏就落在空壳域，需要确认原始标题**先被留底、再被改写**，否则之后进
`/service-ops` 会把「Constellation」当成原始标题还原。

核对结论：**不会**，链条是安全的 ——

1. `LegacyPanels` 用 `v-show`（不是 `v-if`），首屏即挂载 → `onMounted` 跑
   `ensureLegacyBooted()`，旧世界仍在整个应用的最开始完成装载；
2. `onLegacyBooted()` 内部顺序是 `captureOriginalHeader()` → `syncDomainHeader()`，
   留底在改写之前；
3. `watch(() => route.fullPath, syncDomainHeader)` **没有 immediate**，首屏不触发，
   只在后续跳转时改写。

### 为什么不动 catch-all

用户需求只覆盖根路径。`/:pathMatch(.*)*` 保持 `→ DEFAULT_SLUG`，维持
「未知入口落 Service Ops」的改造前语义。若后续也要改成 Constellation，改 line 126 即可。

## 影响范围

| 场景 | 预期 | 实际 | 状态 |
|------|------|------|------|
| 访问 `http://localhost:5173/` | 跳 `/constellation` 并渲染星座图 | 跳 `/constellation` | OK |
| 访问 `/constellation` 直接进入 | 渲染星座图，顶栏高亮 Constellation | 同左（既有路由未改动） | OK |
| 访问 `/service-ops` | 仍是 Service Ops 概览页，标题未被污染 | 标题留底早于改写 | OK |
| 访问未知路径 `/typo` | 仍落 `/service-ops`（兜底不变） | 同左 | OK |
| 空壳域 `/finops` 等 | 行为不变 | 同左 | OK |
| 旧代码跨页下钻无参 | 仍落 `service-ops`（`DEFAULT_SLUG` 未改） | 同左 | OK |

验证方式：

- `npx vite build` 通过，无警告；
- `node -e` 校验 `EMPTY_DOMAINS` 确实产出 `/constellation` 路由；
- 运行中的 dev server（:5173）经 HMR 已加载新模块，
  `curl /src/router/index.js` 可见 `{ path: '/', redirect: LANDING_PATH }`。
