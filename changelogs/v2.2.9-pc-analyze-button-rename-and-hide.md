# v2.2.9 — Problem Center：按钮改名 Analyze，发起后隐藏并让位给 View diagnosis；Analyze 路径文案改英文

**日期**: 2026-09-20

> 本文行号指**本次改动后**的当前文件（v2.2.8 的改动尚未提交，用 HEAD 行号会对不上）。

**需求/背景**: 上一版（v2.2.8）下线了原来那个需要人工选 workflow 的 **Analyze** 按钮，
列表里只剩中文标签的 **「分析new」**。本次做两件事：

1. 把它**改名为 Analyze**（与 Detail / Ignore / View diagnosis 等英文按钮统一），并调整它的生命周期。
2. 把 **Analyze 这条路径上的用户可见文案改成英文**——按钮是英文却弹中文 toast，读起来别扭。

| | 改动前 | 改动后 |
|---|---|---|
| 标签 | `分析new` | **`Analyze`** |
| 已发起分析后 | **置灰不可点**（`disabled` + `title="Analysis already started"`） | **隐藏**，由 `View diagnosis` 接替 |
| 后续操作入口 | 置灰的按钮 + View diagnosis 并存 | 只剩 `View diagnosis` |
| toast / 报错 | `分析已启动` / `分析失败:` / `未找到流程…` | **`Analyze started` / `Analyze failed:` / `workflow … not found`** |

即：**Analyze 与 View diagnosis 互斥**——都只看 `diag`（是否已绑定 agent_run / diagnose_session）。

> 命名说明：v2.2.8 删掉的是「选 workflow 再分析」那个旧 Analyze，本次把**保留下来的**这条
> 分析链路（`startDiagnose` → `problem-log-diagnose`）正式命名为 Analyze，是同一个名字的
> **接替**而非回退。

## 改动明细

### 1. `js/app.js:4275` — 按钮改名 + 未发起时才渲染

**原因**: 改名并把「置灰」改为「不渲染」。

```js
// before：pending/in_progress 一律渲染，已发起则 disabled
((st === 'pending' || st === 'in_progress')
  ? '<button class="btn-alert-detail pc-diag-btn" ... data-act="diagnose"'
    + (diag ? ' disabled title="Analysis already started"' : '')
    + '>分析new</button>'
  : '')

// after：加 !diag，去掉 disabled/title，标签改 Analyze
((st === 'pending' || st === 'in_progress') && !diag
  ? '<button class="btn-alert-detail pc-diag-btn" ... data-act="diagnose">Analyze</button>'
  : '')
```

按钮的 `class` / `data-act="diagnose"` / `data-id` 均未变，**`startDiagnose()` 与事件委托无需改动**。

### 2. `css/styles.css:4956-4971` — 删除 `.pc-diag-btn` 的 `:disabled` 样式（9 行）

### 4. `js/app.js` — Analyze 路径的用户可见文案改英文

**原因**: 按钮已改英文，但点下去弹的是中文 toast；同表其它动作用的是英文
（`'Ignored ' + rec.record_id`、`'Ignore failed: '`、`'Load problems failed: '`），中文反而是孤例。

```js
// startDiagnose()：两条 toast
- window._showToast('分析已启动' + (rid ? ' · ' + rid : ''), 'success');
+ window._showToast('Analyze started' + (rid ? ' · ' + rid : ''), 'success');
- window._showToast('分析失败: ' + (err && err.message ? err.message : 'network error'), 'error');
+ window._showToast('Analyze failed: ' + (err && err.message ? err.message : 'network error'), 'error');
```

```js
// resolveLogDiagnoseWorkflowId()：两条报错。它们经 err.message 进上面那条 toast，
// 只改前缀会让用户看到「Analyze failed: 未找到流程 …」这种半中半英，故一并改。
- new Error('workflow 解析中，请稍后重试')
+ new Error('workflow lookup already in progress, please retry')

- throw new Error('未找到流程 ' + LOG_DIAGNOSE_WF_NAME +
-     '（先在 multi-agent-workflow 跑 scripts/seed_problem_log_diagnose.py --tenant ' + AGENTFLOW_TENANT + '）');
+ throw new Error('workflow ' + LOG_DIAGNOSE_WF_NAME + ' not found' +
+     ' (seed it first: run scripts/seed_problem_log_diagnose.py in multi-agent-workflow' +
+     ' with --tenant ' + AGENTFLOW_TENANT + ')');
```

> 第二条原样保留了**可执行的提示**（脚本名 + `--tenant` + 租户值），只换成英文表述，
> 没有臆造 `cd` 路径之类的原始信息里没有的内容。

### 5. 有意**不改**的部分（说明理由）

诊断内容弹窗（`View diagnosis` → `.dgx-*`）**整套是中文 UI**，本次保持原样：

- 审批按钮：`拒绝 · 重新分析` / `忽略` / `误报` / `提交拒绝并重新分析` / `取消`
- 反馈框 placeholder：`请给出要修改的地方，诊断将带着这条建议重新分析…`
- 状态胶囊：`分析中/已完成/失败/已通过/需人工处理/已忽略`（源码里明确写着「**绝不把原始枚举印给用户**」）
- toast：`请先填写修改建议` / `驳回已达上限 …` / `已标记误报并关闭问题单` 等

这是**自成一套的中文子界面**，只翻译其中的 toast 反而会让它内部不一致。列表行按钮
（Detail / Analyze / View diagnosis / Ignore）走英文，弹窗内部走中文——各自内部自洽。
若要把整个弹窗也英文化，是另一个独立改动。

## 踩坑记录

1. **「置灰」改成「隐藏」会让 `:disabled` 样式变成死代码**。改模板时容易只动那一行，
   把 CSS 留在原地——它不会报错、也不会有人发现，直到下次有人往这个按钮上加 `disabled`
   才可能被误导。本次一并删掉了。
2. **行号口径**：v2.2.8 的改动尚未提交，所以本文不用 HEAD 行号（那会指到 v2.2.8 改动前的状态），
   统一用**改动后的当前行号**，并在此注明。
3. **报错文案要连「被谁展示」一起看**。`resolveLogDiagnoseWorkflowId` 的两条 Error 不是直接弹给用户的，
   而是经 `err.message` 拼进 `'Analyze failed: '` 这条 toast——只改 toast 前缀，用户会看到
   「Analyze failed: 未找到流程 …」的半中半英。改文案时顺着 `err.message` 往上找了一层才改全。
