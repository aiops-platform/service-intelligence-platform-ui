# v1.10.0 — Bug Solve「Bug 解决」页面

**日期**: 2026-09-01

**问题/背景**: 需要「Bug 解决」能力——选已保存流程 → 粘贴 Ticket JSON → 开始 run → 轮询状态 → 审批卡片（通过/驳回）→ 节点状态图 → 点节点看输出/输入详情。原 agentflow-ui 的 BugSolve 页调用 `agentflow` 后端；本次在 SIP 实现同款页面，后端改用 `multi-agent-workflow` 服务（控制面新增 UI 兼容层，见「后端配套」章节）。

**用户确认**: ① token/cost 在 API 模式（mock 无 LLM）下**诚实返回 0**，不伪造；② 菜单放在 **Agent Fleet 子列表**（面包屑 `Agents › Agent Fleet › Bug Solve`）。

### 3. `js/app.js` — 抽出共享图 canvas `createGraphCanvas(opts)` (app.js:5181)

**原因**: Workflow Studio 与 Bug Solve 都要「SVG Kahn 分层布局 + CSS transform 缩放/平移（滚轮/拖拽/+/−/Fit）」。把 Workflow Studio 已验证的实现参数化为共享 helper，消除复制粘贴。

`createGraphCanvas(opts)` 参数：元素 ID（`hintId/zoomId/svgId/controlsId/zoomInId/zoomOutId/zoomFitId`）、`controlsCls`（拖拽判定排除的控件类）、`markerId`、`nodeCls/edgeCls`（基础类名，rect 用 `{nodeCls}-rect`、text 用 `{nodeCls}-text`）、`nodeStyle(n, status) -> {cls, label}`、`onNodeClick(nid)`（节点点击事件委托）。返回 `{render(graph, statusMap), reset()}`。内部绑定滚轮/拖拽/+/−/Fit 事件。

### 4. `js/app.js` — 重构 `initWorkflowStudio()` 委托共享 canvas

**原因**: 消除重复实现。原内联的 zoom 状态（`zoom/panX/panY/clampZoom/applyTransform/zoomBy/fitGraph`）、Kahn 布局 `renderGraph`、`resetForm` 的缩放重置、`bindEvents` 里的滚轮/拖拽/缩放按钮绑定，全部改为 `var canvas = createGraphCanvas({ws 元素 ID, nodeStyle: approval 紫色高亮})`；`renderGraph(data.graph)` → `canvas.render(data.graph)`；`resetForm` 里 `svg/hint/ctrl/zoom/applyTransform` → `canvas.reset()`；`bindEvents` 删除缩放事件块（共享 canvas 已绑定）。行为不变（E2E 回归验证）。

### 5. `js/app.js` — 新增 `initBugSolve()` 模块 (app.js:5589)

**原因**: 实现 Bug Solve 页全部交互，仿 `initAgentRegistry()` 模式（ES5、局部 `getEl/setText`、`localStorage` 可覆盖后端地址）。

`initBugSolve()` 内部：
- `BS_API_BASE = localStorage.getItem('bugSolveBaseUrl') || localStorage.getItem('workflowBaseUrl') || 'http://localhost:8000'` — 后端地址可配置（沿用 workflowBaseUrl，可单独覆盖 bugSolveBaseUrl）
- `canvas = createGraphCanvas({bs 元素 ID, nodeStyle: 按状态着色 + approval 虚线圈})`，`onNodeClick` → `selectNode`
- `loadWorkflows()` → `GET /workflows` → `renderWorkflowOptions()` 填充下拉；`onWorkflowChange` → 选流程后 `GET /workflows/{id}` 预渲染静态图（未运行前展示全图）
- `start()` → 校验流程 + `parseTicket()`（非法 JSON 报错）→ `POST /run {workflow_id, ticket}` → 记录 runId → `poll()`（`setInterval` 2s）
- `poll()` → `GET /runs/{id}` → `applyRun`：更新 stats（`total_tokens/total_cost`，mock 诚实为 0）、`pendingApprovals`、由 `run.nodes` 建 `status[nid]` 映射 → `canvas.render(run.graph, statusMap)` → `renderApprovals()` + `renderDetail(selectedNode)`（若选中）；status ∈ (success/failed/cancelled) 停轮询
- `stop()` → `POST /runs/{id}/stop` → 本地置 cancelled
- `approve/reject(nodeId)` → `POST /runs/{id}/approve|reject body {node_id}` → 本地从 pendingApprovals 移除（下一轮询兜底）
- `renderApprovals()` → 审批卡片：node_id + trigger badge（无 trigger 兜底「人工审批」）+ 上游输出 JSON 块 + 通过(绿)/驳回(红) 按钮（事件委托）
- `renderDetail(nid)` → 状态 badge + tokens/cost + tab「输出 Output」/「输入 Prompt」（`params` JSON），tab 切换事件委托
- `resetRun()` → 清 stats/审批/详情、停轮询、恢复按钮；`_pageRefreshers['page-bug-solve'] = loadWorkflows`（切回本页自动刷新）

## 接入真实 agent（对齐参考 agentflow 的 AgentRuntime 注入，可选）

**背景**: 参考实现 `agentflow/agentflow/server.py:231` 每个 `POST /run` **无条件** `runtime = OpenCodeAdapter()` 注入 `DAGExecutor`（执行接缝叫 `runtime`/`AgentRuntime`，永远真实、无 mock）。本服务的执行接缝是 `node_runner`（`dag_executor.py:46`），此前 API `init()` 从不传 → 回退 `_default_runner`（睡 0.01s 返回 `{"node":id,"ok":true}`），Bug Solve 页全绿、无 agent。

**本次改动**（`multi-agent-workflow` 仓库，等价注入）：
- `agentflow/agents/runner.py`（新建）— `AgentNodeRunner`：按 `node.agent` 分发，`build_toolkit(use_mock=True)` + `build_agent` + `run_agent`（AgentScope → DeepSeek，`trace-analyst` max_iters=12）；`node.agent` 为空（审批节点不会走到）返回结构化占位。
- `agentflow/api/app.py` `init()` — **检测到 `DEEPSEEK_API_KEY` 即注入** `RunService(store, node_runner=AgentNodeRunner(build_model(settings)))`，等价参考的 `_build_executor(runtime)`；无 Key 保持默认 mock（不引入配置开关字段，按参考「真实默认 + 无 Key 兜底 mock」）。
- `tests/test_run_api.py` — 新增 `test_agent_node_runner_scripted`：`AgentNodeRunner` + `ScriptedJsonModel`（无 Key 确定性回退）走通 `POST /run` → `GET /runs`，断言 triage 输出来自 agent（`{"summary": "diagnosed"}`）。

**启用方式**：只要带 Key 起 API 即真跑 agent，无需额外参数：
```bash
source ../spike/.env            # 提供 DEEPSEEK_API_KEY
make api                        # init() 检测到 Key → 注入真实 node_runner
# 不带 Key 起 = mock（页面全绿、token/cost 诚实 0），不影响演示
```

**影响**: agent 模式下每个节点真实调 DeepSeek（5-30s/节点，bug-fix-pipeline 全链路约 1-3 分钟），token/cost 为真实计费值；数据源仍是 mock（`build_toolkit(use_mock=True)`），真实 testbed 数据源后续可换 `RealDataSourceAdapter`。

## 真实 token/cost 计量（agent 模式）

**问题**: 上一节注入真实 agent 后，Bug Solve 页节点执行真实 LLM，但 stats 的 token/cost 仍是 0——因为 AgentScope 的 token 计量在模型响应里（`ChatResponse.usage` / `StructuredResponse.usage`），而模型调用发生在 Agent 内部 react 循环，`node_runner` 接缝收不到。

**本次改动**（`multi-agent-workflow` 仓库，链路打通后页面自动显示真实计量）：

- `agents/runner.py` — 新增 `UsageTrackingModel`（`ChatModelBase` 子类）：包装内层模型，拦截 `__call__`（含 streaming 逐 chunk 累加）/ `generate_structured_output`，累加 `ChatUsage.input_tokens/output_tokens`；其余属性/方法（`count_tokens`/`context_size` 等）经 `__getattr__` 委托内层。顶部定义 DeepSeek 费率常量 `_PRICE_INPUT_PER_M=0.07` / `_PRICE_OUTPUT_PER_M=0.28`（$ / 百万 token，deepseek-v4-flash 未公开单独费率，取 DeepSeek 标准费率，可按账单调整）。
- `AgentNodeRunner` — 内层模型包一层 `UsageTrackingModel`；每节点跑完 `last_usage = {"tokens": in+out, "cost": ...}`；mock 模型（ScriptedJsonModel）无 usage → 0/0.0（诚实不伪造）。
- `executor/dag_executor.py` `_exec_node` — 节点完成后 `getattr(node_runner, "last_usage", None)` 若非空，把 `tokens/cost` 并入节点 checkpoint 再持久化；`_default_runner` 无 `last_usage` → 保持无计量（mock 聚合 GET 诚实 0）。
- `tests/test_run_api.py` — 新增 `test_usage_metering_flows_to_aggregate`（`_UsageStubModel` 每次调用带 ChatUsage，无 Key 确定性回退）：断言聚合 GET 的 `total_tokens>0` / `total_cost>0` / 节点 tokens>0，且输出仍来自 agent。

**实测**（本地 `source ../spike/.env` + `make api`，bug-fix-with-approval 全链路）：triage 1225 tokens → rca 10895 → metrics 6271 → … 审批前累计 **total_tokens=29037、total_cost=$0.003865**；审批通过后 commit/test/review 继续累积，最终 **total_tokens=31238、total_cost=$0.004355**；审批节点（无 agent）诚实 0。
