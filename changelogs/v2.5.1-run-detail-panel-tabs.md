# v2.5.1 — Run 详情右侧拆成「节点详情 / 审批」两个页签，待审批给持久徽标

**日期**: 2026-09-21

> 版本号从 v2.3.3 改为 **v2.5.1**：本分支同时段另有一份 `v2.3.3-escalate-generates-ticket.md`
> （合并 `origin/vue` 时发现），且远端已推进到 v2.5.0。文件名不同所以 git 不报冲突，
> 但**两个 v2.3.3 并存**，故取当前最大号 +1。

**问题/背景**: 右侧面板里「待审批」和「节点详情」原本是**上下堆叠**的，两块互相挤：
审批卡的上游载荷一长，节点详情就被压到只剩十几像素（v2.2.28 修过一次，靠给载荷加
180px 上限勉强共存）。同时后端 `GET /runs/{id}` **只返回 `pending_approvals`** ——
批过之后那次审批从界面上彻底消失，谁批的、为什么驳回，事后一概查不到。

需求有两部分：
1. 两块拆成可切换的页签；
2. **有待审批时页签上给明显提示，切走也要有提示**。

## 改动明细

### 1. `src/views/runs/useRunDetail.js` — 面板页签状态 (+71)

**原因**: 页签与「自动跳转」的开关状态要有唯一出处。

```js
const panelTab = ref('detail')
const tabTouched = ref(false)   // 用户自己切过就不再替他跳
let autoJumped = false          // 每个 run 只自动跳一次
```

三条约定，都写在代码注释里：

- **默认落"节点详情"**，但待审批出现时**自动跳到审批页签** —— 待审批是阻塞态
  （run 停在那儿等人），不跳的话用户得先注意到徽标。
- **只跳一次，且用户切过就不跳**。否则「正在看某个节点」被后台出现的审批拽走，
  比不跳更烦人。徽标在任何页签下都在，不跳也不会漏。
- **`selectNode` 也算"用户动过面板"**（点节点 = 要看它的详情，顺带切回详情页签）。
  它是对**节点**表达意图，但对面板的效果就是"别替我跳了"。

复位放在 `load()` 里判 `runId` 变化，**不放 `start()`** —— `start` 还会被 `onActivated`
调用（keep-alive 回到本页），那时重置会把用户选的页签抹掉。

```js
const approvals = computed(() => {          // 待办排最前
  const rank = { WAITING_APPROVAL: 0, REJECTED: 1, TIMED_OUT: 1, APPROVED: 2 }
  return [...(run.value?.approvals || [])].sort(...)
})
```

页签要回答的第一个问题是「还欠着什么」，不是「以前批过什么」，所以按状态分档而不是
按库里的 `node_id` 顺序原样铺开。

### 2. `src/views/runs/RunDetailView.vue` — 页签化 (+78/-46)

**原因**: 两块的容器从「`.bs-panel` 下并列」改成「页签 + 各占满面板」。

```html
<div class="bs-panel-tabs">
  <button class="bs-panel-tab" :class="{ active: panelTab === 'detail' }" ...>节点详情</button>
  <button class="bs-panel-tab" :class="{ active: panelTab === 'approvals' }" ...>
    审批
    <span v-if="pendingApprovals.length" class="bs-panel-tab-badge">{{ pendingApprovals.length }}</span>
  </button>
</div>
```

**徽标挂在页签按钮上**，不是挂在卡片区里 —— 这就是"切走也看得见"的实现方式。

用 `v-show` 而非 `v-if`：保住节点详情的展开状态与滚动位置。

### 3. `src/utils/runStatus.js` — 审批状态文案 (+11)

**原因**: 判据只写一份（本仓约定）。`GET /runs/{id}` 的 `approvals[].status` 是后端常量
**大写**原值，与上面那些小写档位不是一回事：

```js
WAITING_APPROVAL: '待审批', APPROVED: '已通过',
REJECTED: '已驳回',          TIMED_OUT: '审批超时',
```

⚠️ 别"顺手统一大小写"：查不到时兜底是**原样透出**（约定 1），界面上会直接印出
`WAITING_APPROVAL` —— 不报错、只是难看。

### 4. `css/styles.css` — 新类，不动共用类 (+105)

`.bs-tabs` / `.bs-tab` 是 **legacy 的 Flow Diagram 弹框**在用的（`js/app.js:8352`），
按本仓规矩共用类不改，故全部新开：`.bs-panel-tabs` / `.bs-panel-tab` /
`.bs-panel-tab-badge` / `.bs-approval-history*` / `.bs-approval-none`。

徽标用**红底 + 呼吸动画**而不是一个灰数字 —— 它代表的是阻塞态。带
`prefers-reduced-motion` 关掉动画（动效是"提醒"不是"信息"，徽标本身已经把话说全）。

滚动**上移到页签容器**：`.bs-approvals` 自带的 `max-height: 320; overflow-y: auto`
在页签里会变成"滚动区套滚动区"，滚轮停在内层时看着像卡住。该类与 legacy
`#pcRunApprovals` 共用，故**按页面 id 限定覆盖**，不动它本身的规则。

## 踩坑记录

### ① 一条"删掉的"规则：我读错了样式链，还给它写了假注释

给 `.bs-panel-approvals > *` 加了 `flex: 0 0 auto`，注释里写「实测：30 张子卡片内容
实高 4935px，而容器报 296px 且 scrollHeight == clientHeight」—— 断言得斩钉截铁。

**那是误读**：`.bs-upstreams` 只有 212px，因为上游载荷**本就被 180px 上限 + 内部滚动
封顶**（v2.2.28 加的）。那 4935px 在**设计好的滚动盒里**，不是被裁掉。

反向验证（把规则退回 `flex-shrink: 1`）在 3 张、6 张卡的场景下**布局逐项相同** ——
flex 项的默认 `min-height: auto` 已经提供了"不低于内容最小高度"的保护。规则是冗余的，
已删除。

**教训**：注释里的"实测"必须是**量出来的**，不是从布局数字里推断出来的。这次差点把一条
错误结论固化进样式表，而它长得和真结论一模一样。

### ② CDP 的 `Fetch.enable` 拦截在全量请求下会死锁

用 `urlPattern: "*"` 拦响应改写，事件量一大 `send` 的 recv 循环就再取不到自己的响应
（60s 超时）。改用 `Page.addScriptToEvaluateOnNewDocument` 注入一段 patch `window.fetch`
的脚本 —— 同样只动浏览器、后端零改动，但完全可靠。

## 依赖

后端需 `GET /runs/{id}` 提供 `approvals` 字段（见 `multi-agent-workflow` `54e021d`）。
后端未升级时该字段为 `undefined` → `approvals` 计算为空数组 → 历史区不渲染，
页签与徽标照常工作。
