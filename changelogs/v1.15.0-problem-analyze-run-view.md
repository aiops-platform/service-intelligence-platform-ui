# v1.15.0 — Problem Center View analysis：宽弹框实时查看 agentflow run 分析过程

**日期**: 2026-09-07

**问题/背景**: v1.14.0 起点 Analyze 后问题变为 `in_progress`，但 Problem Center 里**没有入口查看这次分析的过程/流程**——行上只有
Detail，Detail 只是把 evidence（含 `agent_run {run_id,…}`）当整条 JSON 平铺，run_id 不可点。用户希望像 Bug Solve 页那样看到
分析的实时流程（DAG 节点执行、状态、输出、待审批）。经确认交互：**in_progress 行上新增「View analysis」按钮 → 打开 ~1200px 宽弹框，
内嵌 agentflow run 实时查看器**（DAG 画布 + 节点状态/输出，2s 轮询刷新；带通过/驳回）。

**方案**: 纯前端 SIP（`index.html` / `js/app.js` / `css/styles.css` + changelog），复用 Bug Solve 页的整套 `.bs-*` 样式与
`createGraphCanvas` 工厂（id 全参数化，已 ws/bs 两个实例，这是第三个，id 唯一无冲突）和 run 轮询/渲染/审批逻辑作蓝本，零造轮子。
run_id 来源即行 evidence 里 `mark_in_progress` 追加的 `agent_run` 条目（record_id → run_id 的桥，列表接口已解码 evidence），
**无需后端新接口**。不做自动弹查看器（analyze 成功 → 行变 in_progress → 用户点 View analysis）；resolve 行历史 run 查看留作扩展。

### 5. `js/app.js` — `initProblems()` 内新增 run viewer 逻辑 (app.js:4044-4309)

**原因**: 复用 Bug Solve 的轮询/渲染/审批整套逻辑作移植蓝本（applyRun/renderDetail/renderApprovals/resetRun），弹框文案英文。
- 状态变量 `pcRunRec/pcRunId/pcRunTimer/pcRunSel/pcRunTab/pcRunData/pcRunGraph/pcRunAuto`（4049-4058）；
- `pcRunStatusClass(st)`：节点状态 → `bs-node-status-*` 着色类，与 Bug Solve statusClass 同映射（4059）；
- `pcRunCanvas = createGraphCanvas({...})`（4074）：**第三个 canvas 实例**，DOM 常驻、init 时实例化一次、事件只绑一次，
  `nodeStyle` 对 `kind==='approval'` 追加 `bs-node-approval`（虚线描边），`onNodeClick` 手动选中节点并停 autoFollow；
- `findAgentRun(rec)`（4090）：`(rec.evidence||[])` 里取**末条** `type==='agent_run' && run_id`；
- `openProblemRun(rec)`（4100）：无 run 则 toast `No agent analysis run found for {id}`；先 `.open` 弹框**再拉数据**
  （display:none 时 fit 取 0 尺寸）→ `fetchRunNow()+startRunPolling()`；
- `startRunPolling/stopRunPolling`（4131/4136）：2s `setInterval(fetchRunNow, 2000)`；
- `fetchRunNow()`（4140）：`GET {AGENTFLOW_BASE}/runs/{run_id}`，**首拉失败明确 toast**、后续轮询失败静默（避免刷屏）；
- `applyRunView(data)`（4159）：`data.run_id !== pcRunId` 忽略 → 更新 status badge/step/tokens/cost → 沿用最近一次 graph
  （`if (data.graph) pcRunGraph = data.graph; render(data.graph||pcRunGraph,…)`，轮询缺 graph 不清空画布）→ approvals →
  autoFollow running 节点 → 终态 `success/failed/cancelled` 停轮询；
- `renderRunDetail(nid)`（4213）：`.bs-detail-head` + badge + Output/Prompt tab，running 显示 `(running…)`；
- `renderRunApprovals(approvals)`（4246）：`.bs-approval-card`，Approve/Reject 英文按钮，无则隐藏整段；
- `runApproval(action, nodeId)`（4283）：`POST /runs/{pcRunId}/approve|/reject` body `{node_id}`，成功后 `fetchRunNow()` 刷图；
- `closeProblemRun()`（4299）：清 timer（关弹框必清，否则后台持续轮询）、置空状态、移除 `.open`。

```js
// findAgentRun：行 evidence → 最新 agent_run 的 run_id（record_id → run_id 的桥）
function findAgentRun(rec) {
    var ev = (rec && rec.evidence) || [];
    var runs = [];
    for (var i = 0; i < ev.length; i++) {
        var e = ev[i];
        if (e && e.type === 'agent_run' && e.run_id) runs.push(e);
    }
    return runs.length ? runs[runs.length - 1] : null;
}

function openProblemRun(rec) {
    stopRunPolling();
    var ar = findAgentRun(rec);
    if (!ar) { window._showToast('No agent analysis run found for ' + (rec && rec.record_id ? rec.record_id : 'record'), 'error'); return; }
    pcRunRec = rec;
    pcRunId = ar.run_id;
    pcRunData = null; pcRunGraph = null; pcRunSel = null; pcRunAuto = true;
    var title = getEl('pcRunTitle');
    if (title) title.textContent = 'Analysis Process - ' + (rec && rec.record_id ? rec.record_id : '');
    setPcRunText('pcRunId', ar.run_id);
    setPcRunText('pcRunStep', '—'); setPcRunText('pcRunTokens', '0'); setPcRunText('pcRunCost', '0.0');
    var statusEl = getEl('pcRunStatus');
    if (statusEl) { statusEl.textContent = '—'; statusEl.className = 'bs-badge'; }
    var sec = getEl('pcRunApprovalSection');
    if (sec) sec.style.display = 'none';
    renderRunDetail(null);
    var overlay = getEl('pcRunOverlay');
    if (overlay) overlay.classList.add('open'); // 先 .open 再拉数据，fit 才能取到尺寸
    pcRunCanvas.reset();
    fetchRunNow();
    startRunPolling();
}
```

`AGENTFLOW_BASE`（app.js:3624，`bugSolveBaseUrl > workflowBaseUrl > http://localhost:8000`）在 `initProblems` 内已定义，与
Bug Solve 解析规则一致，此处复用，无新增。

### 6. `js/app.js` — Run Viewer 弹框生命周期接线 (app.js:4399-4436)

**原因**: 关闭按钮 / 点遮罩 / 节点详情 tab 切换 / 审批按钮 / Escape 需接线。`#pcRunDetail` 点击委托切 Output/Prompt
（重渲染当前选中节点），`#pcRunApprovals` 点击委托读 `data-action/data-node` 调 `runApproval`；Escape 把 pcRun 放**最前**，
先关查看器再关 analyze/detail，互不抢占。

```js
// Run Viewer 生命周期（pcRunOverlay）：关闭按钮 / 点遮罩 / 节点详情 tab 切换 / 审批按钮 / Escape
var pcRunClose = getEl('pcRunClose');
if (pcRunClose) pcRunClose.addEventListener('click', closeProblemRun);
var pcRunOverlay = getEl('pcRunOverlay');
if (pcRunOverlay) pcRunOverlay.addEventListener('click', function (e) {
    if (e.target === this) closeProblemRun();
});
var pcRunDetailEl = getEl('pcRunDetail');
if (pcRunDetailEl) pcRunDetailEl.addEventListener('click', function (e) {
    var tab = e.target && e.target.getAttribute ? e.target.getAttribute('data-tab') : null;
    if (tab) { pcRunTab = tab; renderRunDetail(pcRunSel); }
});
var pcRunApprovalsEl = getEl('pcRunApprovals');
if (pcRunApprovalsEl) pcRunApprovalsEl.addEventListener('click', function (e) {
    var btn = e.target && e.target.getAttribute ? e.target : null;
    var action = btn && btn.getAttribute ? btn.getAttribute('data-action') : null;
    if (!action) return;
    var nodeId = btn.getAttribute('data-node');
    runApproval(action, nodeId);
});
document.addEventListener('keydown', function (e) {
    if (e.key !== 'Escape') return;
    if (getEl('pcRunOverlay') && getEl('pcRunOverlay').classList.contains('open')) closeProblemRun();
    else if (getEl('pcAnalyzeOverlay') && getEl('pcAnalyzeOverlay').classList.contains('open')) closeAnalyze();
    else if (getEl('pcDetailOverlay') && getEl('pcDetailOverlay').classList.contains('open')) closeProblemDetail();
});
```

## 影响范围

| 场景 | 预期 | 实际 | 状态 |
|------|------|------|------|
| in_progress 问题行 | 出现 View analysis 按钮（pending 不出现） | `renderTable` in_progress 分支渲染 | OK |
| 点 View analysis | 宽弹框：run id + status；DAG 节点实时着色 | `.open` 后 `GET {agentflow}/runs/{run_id}` 2s 轮询，`applyRunView` 落图 | OK |
| run 跑到 waiting_approval | 审批卡片出现，Approve/Reject | `renderRunApprovals(data.pending_approvals)`；approve/reject 后 `POST /runs/{id}/approve|/reject` → 节点继续 | OK |
| 点任意节点 | 下方 detail 看 Output/Prompt | `renderRunDetail(nid)`；tab 切换重渲染 | OK |
| run 终态 success/failed/cancelled | 轮询停止，状态定格 | `applyRunView` 清 timer | OK |
| 关弹框（Escape / × / 点遮罩） | 轮询停止（Network 无新请求）、再开恢复 | `closeProblemRun()` 清 timer + 置空 | OK |
| 行 evidence 无 agent_run 记录 | 不显示按钮 / 点了 toast 提示 | 有 run 才渲染按钮；`openProblemRun` 兜底 toast | OK |
| Detail 弹框 evidence | agent_run 条目仍为 JSON 文本，不受影响 | 未改动 buildDetailHtml | OK |
| Bug Solve 页 | 仍用 `bs-*` 正常（第三份 canvas 无 id 冲突） | createGraphCanvas id 全参数化，pcRun* 唯一 | OK |

- 静态校验：`node --check js/app.js` 通过；index.html 里 `pcRun*` id 与 app.js `getEl`/opts 引用一一对应（脚本核对无缺失）。
- 后端/agentflow 零改动（run_id 取自 evidence，过程详情直连 agentflow `GET/POST /runs`，与 Bug Solve 页同源）。
- 边界注意：canvas DOM 常驻只实例化一次（open/close 只切 `.open`）；先 `.open` 再拉数据避免 display:none 时 fit 取 0；
  关弹框必清 timer；弹框文案英文，与 Problem Center 其余 UI 一致。
- **浏览器 E2E 未跑**（遵循用户「改好了和我说就行」惯例）。建议走查：agentflow :8000 + anomaly-detector :7070 + SIP
  静态服务，DB 种子一条 pending → Analyze → in_progress → 行出现 View analysis → 点开弹框看 DAG 实时执行；
  bug-fix-with-approval 流程跑到 waiting_approval → Approve → 节点继续 → success 停轮询；关弹框后 Network 无新 run 请求。
