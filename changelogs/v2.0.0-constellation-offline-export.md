# v2.0.0 — Constellation 离线副本 + 数据导出（dev 工具）

**日期**: 2026-09-14

**需求背景**: 把部署站 `https://sip-platform.web.app/` 上 **Constellation** 菜单的内容
弄到本地，离线和线上看到的一样。

**先说清楚这不是什么**：部署站**不是本仓库的产物** —— 它是另一套 **Next.js** 应用
（`/_next/` + Turbopack + RSC），而本仓是 Vue + legacy IIFE。两者是同一产品的不同世代：
导航域完全一致，部署站搜索框占位符写着 `Search 893 apps · 22 portfolios · 6 journeys…`，
与本仓 `src/router/nav.js:60` 对得上（那套数据就在本工具导出的 `data-sicg.json` 里）。

所以本次改动**只新增 `tools/` 下一个自包含目录，不碰 `src/`、`js/app.js`、`css/styles.css`**，
双世界结构与「同一棵 DOM 子树只能有一个所有者」的不变式不受影响。

---

## 方案演进：试了两条路都不通，第三条才对

记下来，因为每一条的失败原因都不明显。

### 方案 1：Chrome 扩展驱动 UI —— **废弃并删除**

写了个 MV3 扩展，跑在已解锁的标签页里，按人类节奏点节点、读 inspector。
代码完整（content / background / offscreen / popup / 查看器，含断点续传、React 受控输入
处理、按需注入），语法与交叉引用全部验证通过 —— **但实际不 work**。

更要紧的是：**它解决的是一堆本来不存在的问题。** 见方案 2。

### 方案 2：直接从公开 JS chunk 抽数据 —— **采用**

回头看才发现：那个站的内容**根本不是从接口取的**，整份 estate 快照以对象字面量打包在
客户端 JS 里随页面下发。于是密码门、点击策略、枚举缺口、限流、断点续传**全都不必要**：

| | 方案 1（驱动 UI） | 方案 2（抽 chunk） |
|---|---|---|
| 需要密码 | 要手动解锁 | **不要**（只挡渲染，chunk 是公开静态资源） |
| 完整性 | 受枚举策略限制，可能漏 | **全量**，一次拿到 10 个租户 |
| 耗时 | 近千实体约 20–60 分钟 | **几秒** |
| 对站点 | 近千次真实交互 | **只读几个静态文件** |
| 字段 | 从 DOM 反推，可能抽歪 | **原始 JSON，零损失** |

**教训：先确认数据从哪来，再决定怎么抓。**

### 方案 3：本地渲染原应用 —— **采用**

方案 2 拿到的是数据，用户要的是「和网站上一模一样」。于是做离线副本。
这条路上踩了本次最大的一个坑，见下。

## 改动明细

### 1. `tools/constellation-export/extract.py` — 新增

从首页 HTML 现读 chunk 列表再下载。**不硬编码 chunk 文件名** —— Next.js 的 chunk 名带
内容哈希，站点一重新部署就全变，硬编码的脚本活不过一次发布。

产出 `data/*.json`：10 个租户，含 apps（每个 282~1800 条，带 `position` 坐标）/
portfolios / journeys / `portfolioEdges`（技术重叠·变更级联·事件共现）/ `valuePool` /
`topStorm` / `scenarios` 等。

两个解析要点：

```python
# 1) 括号配对必须跳过字符串字面量，否则内容里带 { } 的字符串会让配对跑飞
# 2) JS 的 \' 在 JSON 里是非法转义，json.loads 直接抛 Invalid \escape
if nxt in '"\\/bfnrtu':
    out.append(raw[i:i+2])      # 合法转义，原样保留
else:
    out.append(nxt)             # \' → '  ，降级成字面量
```

### 3. `tools/tenant_data.py` — 新增（数据可编辑）

让节点数据可以改、可以加租户。

**数据是一个 JSON 字符串**，包在 bundle（`0wuztp2.9oz~8.js`）的模块 89784 里：

```js
89784,(e,t,o)=>{ t.exports = JSON.parse('{"banking":{…},"retail":{…},…}') }
```

所以改数据**不需要解析/重写 JS** —— 取出字符串、解码、改 JSON、编码、写回。
`read_bundle()` / `write_bundle()` 只替换那一段字符串，文件其余字节原样保留。

三个要点：

```python
# 1) JS 字符串字面量解码。顺序要紧：\\ 必须最先处理，
#    否则 \\' 会被误读成 \\ + ' 而提前结束字符串
# 2) 校验照着页面里的 zod schema 做（见 validate_tenant）——
#    页面是 f.parse(t) 硬校验，不过就抛异常整页白屏
# 3) 覆盖写进**输出目录那份**，源文件不动。改源文件的话重建不可重复
```

## 踩坑记录

### 坑 1（最隐蔽）：Chrome「网页，完整」保存的 HTML 启动不了 Next.js 应用

保存下来的是**运行时渲染完的 DOM 快照**，含 `.scene-container`、一个 `<canvas>`、
以及 three.js 运行时注入的 `<style>`。拿它当页面打开的表现极具误导性：

- 整页**看起来完全正确** —— 顶栏、搜索框、FILTER 面板、LEGEND、状态栏、甚至
  `TOTAL NODES 352` 全都显示
- 但 **React 从未启动**
- 于是**「点不动」**（没有任何事件处理器）
- 图永远是空的：那个 canvas 是保存下来的**死元素**，尺寸位置都对，从没被绘制过
- **console 里没有任何报错**

定位靠的是往页面里注入探针，实测 `document.body` 上的 `__reactFiber$` 键数量：

```
服务器原始 HTML    → bodyFiberKeys 2   React 正常启动，WebGL 创建成功
Chrome 保存的 HTML → bodyFiberKeys 0   React 从未启动
```

**同样的资源、同样的本地服务器**，差别只在 HTML 本身。两边的 RSC 载荷逐字节相同
（7736 字符），脚本集合相同。

> **判断一个页面「是不是活着」不能靠看。** 看事件处理器在不在、看 fiber 键、
> 看 WebGL 上下文有没有被创建 —— 静态快照可以把外观复刻到看不出破绽。

### 坑 2：turbopack 硬编码 `/_next/`，所以必须起 HTTP

```js
function N(e){ return `${t}${e.split("/").map(encodeURIComponent).join("/")}${r}` }
//                            t = "/_next/"  ← 硬编码，不随页面位置变
```

懒加载 chunk 一律拼成从根算起的 `/_next/static/chunks/…`。
`file://` 下这会落到**文件系统根**，必然 404。只有 HTTP、且**服务根目录就是输出目录**
时才对得上。所以双击 html 打不开是必然的，不是配置问题。

### 坑 3：Next.js 客户端运行时的 `/_next/` invariant

```js
let { pathname: t } = new URL(e.src);
let n = t.indexOf("/_next/");
if (-1 === n) throw new InvariantError(`Expected document.currentScript src to contain '/_next/'…`);
```

Chrome 保存时把脚本路径改写成 `./<页面名>_files/xxx.js`，`/_next/` 没了 → **直接抛异常**
→ 客户端运行时崩溃。即使解决了坑 1，不改路径也跑不起来。

### 坑 4：PasswordGate 的解锁状态不随保存带走

它读 `localStorage["sip-platform-unlocked"] === "1"`，而「网页，完整」不保存 localStorage。
离线打开会重新卡在密码框。构建时在 `<head>` 最前注入解锁标记，早于任何 Next.js 脚本。

### 坑 5：字体只匹配绝对 URL 会漏

Chrome 保存的版本把字体写成绝对 URL，**服务器原始版用的是根相对路径
`/_next/static/media/…`**。第一版正则只匹配绝对 URL，结果 `media/` 是空的。
两种写法都要认。

### 坑 6：`journeyId` 可以是字符串 `"journey:null"` —— **会静默吞掉 100+ 个应用**

有些 portfolio 是**企业级支撑组合**（Data/AI、基础设施、安全、财务、战略架构），
本来就不挂任何客户旅程。bunnings 有 5 个、qantas 4 个、data-sicg 1 个。

查看器第一版按 `journeyId` 过滤渲染树，这些 portfolio **一个都不显示，也不报错**。
bunnings 那是 144 个 app、qantas 115 个凭空消失。

修法是收进「Enterprise services（未归属 journey）」组，并加覆盖率测试：

```
10 个租户：树中 app 数 == 总数，重复 0，失败 0
```

**教训：查看器最糟的失败模式不是报错，是少显示东西还不说。**

### 坑 7：`facts.portfolios` ≠ `portfolios` 列表长度

retail 是 9 vs 10 —— `portfolio:real-estate` 有 **0 个 app**。`facts` 数的是「有应用的组合」，
列表含空组合。两者都对，是口径差异，查看器里显式说明。

### 坑 8：本机工具链的两个坑

- **`grep` 静默失败**：`grep -n "function" file.js` 返回空、`grep -c` 连计数都不打印。
  差点误判成编辑把代码吃掉了。后续一律用 `python3` 做文本检索。
- **没装 node**：`node --check` 用不了。改用 macOS 自带的 JavaScriptCore：
  ```bash
  osascript -l JavaScript -e 'ObjC.import("Foundation"); …
    const s = $.NSString.stringWithContentsOfFileEncodingError(p, $.NSUTF8StringEncoding, null).js;
    new Function(s)   // 只编译不执行，抛 SyntaxError 即失败'
  ```

### 坑 9：headless 截图会骗人

无头 Chrome 里这个 3D 图**渲染不出来**（`CVDisplayLinkCreateWithCGDisplay failed`，
没有显示链路），但**线上站在同样是 headless 的环境里渲染正常**。所以不能用
「headless 截图空白」推断本地副本有问题 —— 必须两边对照。

最终靠装一个 **Chrome DevTools Protocol 客户端**（`WebSocket` 手写，只用标准库）
拿到真实数据：console、任意 JS 求值、网络请求、截图。本机无 node、无自动化浏览器，
这是唯一能自证的手段。

## 用法

```bash
cd tools

# 1) 起离线副本 —— 或者直接在 Finder 里双击「启动 Constellation.command」
./start-offline.sh                       # → http://localhost:8777/

# 2) 重新构建（默认离线，只读 vendor/）
python3 make-offline-page.py
python3 make-offline-page.py --refresh   # 站点更新后刷新 vendor/ 用

# 3) 重新导数据
python3 constellation-export/extract.py
```

> **不能双击 html。** 两个独立原因叠加：`file://` 下 turbopack 会去找文件系统根的
> `/_next/`；而 Chrome 保存的那份 html 是 DOM 快照，React 根本不会启动。
> 必须是「HTTP 服务 + 正确的服务根目录」。
