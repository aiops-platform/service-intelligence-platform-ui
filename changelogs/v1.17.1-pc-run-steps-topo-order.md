# v1.17.1 — fix: Execution Flow 步骤列表按 YAML 定义顺序导致与流程图不一致，改按拓扑执行顺序

**日期**: 2026-09-07

**问题/背景**: v1.17.0 主弹框左栏 Execution Flow 步骤列表看着"乱"，与 Flow Diagram 流程图（及实际执行顺序）对不上。
根因：`renderRunSteps()` 直接用 run 返回 `graph.nodes` 的**数组原样顺序**排步骤，而该数组是 **YAML 定义顺序**，并非依赖/执行顺序。
例：run_4c9a4dc444 返回 `nodes order = ['app-log','approve-root','git-search','remediation-plan','root-cause']`，
依赖链却是 `app-log→git-search→root-cause→approve-root→remediation-plan` → approve-root 被排到它依赖的节点前面，列表与图对不上。
（Flow Diagram 画布内部用 Kahn 拓扑分层排布，故不受影响。）

**方案**: 左栏步骤排序改为与画布同一套 **Kahn 拓扑分层**（新辅助 `pcRunTopoOrder`，BFS 按层出队），
保证列表与流程图一致；无可达依赖的环节点按原顺序兜底追加。纯前端 SIP `js/app.js` + changelog，后端/agentflow 零改动。

---

## 改动明细

### `js/app.js`（initProblems 内 run viewer 块）
- 新增 `pcRunTopoOrder(graph)`：从 `graph.nodes`/`graph.edges` 算入度 → 初始入度 0 层入队 → 逐层出队并减子节点入度，
  产出**拓扑执行顺序**（与 `createGraphCanvas` renderGraph 的分层算法一致）；防环兜底。
- `renderRunSteps()`：`ordered` 由 `nodes.map(n => n.id)`（YAML 定义顺序）改为 `pcRunTopoOrder(graph)`。
