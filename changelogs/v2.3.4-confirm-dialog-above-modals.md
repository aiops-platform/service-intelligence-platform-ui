# v2.3.4 — 通用确认弹窗盖在诊断弹框之上：修「忽略 / 升级」二次确认看不见、且点了没反应

**日期**: 2026-09-21

**需求/背景**: 「你帮我看下为什么我点击升级 · 生成工单 或者是忽略按钮，弹出框看不到他在当前弹出框
的后面，让他在这个弹出框的上面，然后我点击确认后，没反应」

**这不是两个 bug，是一个**：确认框被诊断弹框整个盖住，于是

1. 看不见（视觉）；
2. 「确认」按钮**收不到点击**——点上去落在诊断弹框的内容区（`#pcDiagnoseBody`）上，所以"没反应"。

---

## 根因

`#confirmModalOverlay`（`src/legacy/legacy-panels.html:1714`）与 `#pcDiagnoseOverlay`（同文件 `:1764`）
**共用同一个类** `.ap-modal-overlay`，而它写死了 `z-index: 10000`（`css/styles.css:1548`）。

`#confirmModalOverlay` 在 DOM 里排在 `pcDetail(1753)` / `pcDiagnose(1764)` / `pcRun(1775)`
**之前**，四个又都是 `<body>` 直属兄弟（同一个层叠上下文）——**同 z-index 时，后出现的赢**，
所以确认框永远在诊断弹框下面。

> 确认框自身**没有任何 CSS 规则**（全文件零命中），它的一切外观与层级都来自那个共用的类。
> 也就是说：这不是"某个 z-index 写小了"，而是"两个弹层共用一个值、靠 DOM 顺序决胜"。

**触发面不止「忽略」与「升级」**：凡是从**已打开的弹框内部**调起 `confirmDialog` 的地方都中招
（诊断弹框里的忽略 / 升级，以及任何弹框内的删除类二次确认）。从列表行直接点「Ignore」不受影响
（那时没有第二个弹层）。

---

## 改动明细

### 1. `css/styles.css:4686` — 给确认弹窗单独提一层（唯一改动，一行）

```css
/* 通用确认弹窗必须能盖在**任何**已打开的 `.ap-modal-overlay` 之上。
   它会被从别的弹框**内部**调起——诊断弹框里的「忽略」与「升级 · 生成工单」都走它做二次确认。
   两者共用 `.ap-modal-overlay` 的 `z-index: 10000`，而 `#confirmModalOverlay` 在
   legacy-panels.html 里排在 pcDetail(1753) / pcDiagnose(1764) / pcRun(1775) **之前**，
   四个又都是 `<body>` 直属兄弟（同一个层叠上下文）→ **同值时后出现的赢** →
   确认框被整个盖住，连「确认」按钮的点击都落在上层遮罩上（表现就是"弹框看不见 + 点了没反应"）。

   取 11000：高于所有 `.ap-modal-overlay`，仍**低于** `.toast-container` 的 99999——toast 永远最上。 */
#confirmModalOverlay { z-index: 11000; }
```

**为什么选 id 选择器**：`#confirmModalOverlay` 这个 id 在原文件里从未被样式消费过
（`styles.css` 零命中），所以这条规则不会与既有声明打架，也不依赖书写顺序（id 权重本就高于 class）。

**为什么不动 DOM 顺序**（把 `#confirmModalOverlay` 挪到最后也能解决）：`legacy-panels.html` 是
legacy 世界的 DOM 快照，挪动会改变源码顺序（tab 序、以及将来做 class 差集比对时的基线）；
而 z-index 只表达"谁在上面"这一件事，更贴意图。

**为什么是 11000 而不是 10001**：留一段空档。将来再加全域弹层时 10001 会和"第二个弹层"撞上，
而这次踩的正是"两个层共用一个值、靠 DOM 顺序决胜"的坑——**不要在同一个数值上再挤。**
