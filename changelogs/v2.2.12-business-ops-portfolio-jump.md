# v2.2.12 — Business Ops 组合名 → 跳到 Service Ops（并按该组合过滤）

**日期**: 2026-09-20

**需求**: Business Ops 里点 journey 筛选后，列表出现该 journey 的**组合**（portfolio）信息；
点**组合名字**要跳到 Service Ops，且那边的列表数据就是**这个组合**的数据。

`otr` 租户实测：点「Sales Customer Journey」→ 组合表出现 6 行 → 点行首的 **Lead** →
落到 Service Ops，筛选条上 `Sales Customer Journey` 与 `Lead` 均为选中态，
匹配数 `7 of 50 apps match`（= Lead 这个组合的 7 个 app）。

## 改动明细

### 0. 链路（四段，各管一件事）

```
① Business Ops chunk（编译产物）  点组合名 → postMessage 给父窗口
        ↓              {type:'sip:open-service-ops', portfolio:'portfolio:lead'}
② 外壳 src/composables/useEmbedBridge.js   校验后 router.push('/service-ops?portfolio=…')
        ↓
③ src/views/service-ops/ServiceOpsView.vue  把 query 拼进 iframe src
        ↓              /service-ops/?portfolio=portfolio%3Alead
④ Service Ops chunk（编译产物）     读自己的 query → 预置「所属 journey + 该组合」两项筛选
```

★ 全仓此前**没有任何 iframe ↔ 外壳的通信通道**（`postMessage` 零命中），这是第一条。

### 1. 新增 `src/composables/useEmbedBridge.js` —— 外壳侧的监听

**原因**: 内嵌页说「我要去某页」，外壳负责翻成一次路由。放在 composable 里由 `App.vue`
装一次，与 `useAlertDetail` 同一套写法。

```js
export const OPEN_SERVICE_OPS = 'sip:open-service-ops'
const PORTFOLIO_ID = /^portfolio:[A-Za-z0-9._~:@+-]{1,200}$/

function onMessage(event) {
  if (event.origin !== window.location.origin) return          // 三样都得对，
  if (!msg || msg.type !== OPEN_SERVICE_OPS) return            // 否则**静默忽略** ——
  if (!PORTFOLIO_ID.test(msg.portfolio)) return                // 不该因别人发消息就把用户跳走
  router.push({ path: '/service-ops', query: { portfolio: msg.portfolio } })
}
```

**为什么不让 iframe 直接改 `parent.location`**: 那要整页刷新 —— Vue 应用重启、
legacy 世界（`js/app.js` 的 17 个 init）重跑、其它视图的 KeepAlive 缓存全丢。
走路由只重载目标那一个 iframe。

### 2. `src/App.vue:19,29` — 装上桥

App 全生命周期只挂载一次（`main.js`），所以全局唯一那个 `message` 监听就在这里。

### 3. `src/views/service-ops/ServiceOpsView.vue:44-88` — 把 query 拼进 iframe 的 src

```js
const portfolio = computed(() => typeof route.query.portfolio === 'string' ? route.query.portfolio : '')
const src = computed(() => portfolio.value
  ? `/service-ops/?portfolio=${encodeURIComponent(portfolio.value)}`
  : '/service-ops/')
```

⚠️ **路径本身不变**（仍是 `/service-ops/`），只多一个查询串 —— 这是这个页面最容易踩的坑
（`panelByRoute` 只剥尾斜杠、对不上就静默把 h1 变成 "SIP"），所以动手前先实测过：
带查询串时 h1 仍解析成 `Service Ops`。

**另加一个 remount 计数器**（`:key="embedKey"`，只在**带 portfolio 落到本页**时自增）：

- 目标组合与上次**相同**时 `src` 不变 → Vue 不会重设 iframe 的 src → iframe 不重载 →
  用户看到的是自己上次手动改过的筛选（比如点过 All），**像是跳转没生效**；
- 自增 → 重挂载 → 必定重新加载并落到该组合；
- **不带 portfolio 的普通导航不自增**，保持改造前的行为（KeepAlive 缓存着视图，
  来回切页内层状态原样保留）。

## 踩坑记录

### 1. 组合 label 里带**零宽空格**（U+200B），锚点不能手打

那条 `e.label.replace(/​/g,"")` 里的字符在编辑器里**看不出来**（所以页面源码里特意把 `​`
显示成 `[ZWSP]` 一样的东西）。锚点里少一个字符就永远匹配不上，而失败方式是**静默跳过**
（功能不见了、页面不坏）。所以常量用 `BPJ_ZW = "​"` 拼出来，注释里写明原因。

### 2. 跨补丁的**前置依赖**必须显式挡住

SDL ② 引用 SPF 装上的 `pfToggle`。如果哪天 SPF 因为站点改版被跳过、SDL 却照打，
页面会在运行时 `pfToggle is not defined` → **整页白屏** —— 比"功能不见了"严重得多。
所以 SDL 第一件事就是检查 `pfToggle` 在不在文本里，不在就整组跳过（已实测：只有 SDL 时返回
「前置补丁未打（portfolio 筛选）→ 整组跳过」且文件未被改动），构建顺序也写死 SPF 在前。

### 3. 目标相同 → `src` 不变 → iframe 不重载 → 看起来"跳转没生效"

第一次实现没有 remount 计数器时：用户落地后手动点过 `All`，回 Business Ops 再点同一个组合，
URL 与上次完全相同 → Vue Router 认为是重复导航/`src` 无变化 → iframe 保持清空后的状态。
这正好是最容易发生的演示路径。解决见改动明细 3。

### 4. 验证时的一个假象：兜底跳转会让求值返回 `undefined`

测【C】时 `Runtime.evaluate` 返回 `undefined` —— 因为 `location.assign` 正在卸载页面、
求值上下文被销毁。**这不是失败信号**，但也不能当成通过：必须等跳转完成后**另开一次求值**
去读落点（地址 + h1 + 筛选状态）。事后确认落点与筛选都对。

### 5. 默认租户 `otr` 又被重建冲回 `retail`（**第三次**）

同 v2.2.10 / v2.2.11 的踩坑 1：`cf01394` 手改的兜底默认值没做成补丁，
每次 `make-offline-page.py` 都会冲掉（构建输出一切正常、不报错）。本次照旧把
`0wuztp2.9oz~8.js` 与 `business-ops/index.html` 回退到 HEAD，让 diff 只含该改的东西。
根治仍未做（先前已确认"先不用"）。
