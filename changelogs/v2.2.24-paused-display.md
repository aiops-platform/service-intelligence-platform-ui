# v2.2.24 — `paused` 显示成「已暂停」而不是"进行中"

**日期**: 2026-09-21

**需求/背景**: 用户提议「paused 如果没有用就删除相关状态和代码」。
盘点后发现**它不是死代码**，于是改为「保留后端，只补前端展示」。

---

## 盘点结论：`paused` 不能删

| 层 | 内容 |
|---|---|
| API | `POST /runs/{run_id}/pause`（`api/app.py:1257`） |
| Service | `pause_run()` —— queue 模式发 `run.command.{tenant}`；inline 模式直接 `request_pause()` |
| Worker | `_cmd_pause()`（`worker.py:189`） |
| Executor | `request_pause()` / 主循环 `return "paused"`（`dag_executor.py:237/733`） |
| 状态机 | `ACTIVE_RUN_STATUSES` 含 `paused` → **占用租户的 active-run 配额**（sqlite/postgres/memory 三处都在用） |
| 接单 CAS | Worker resume 允许 `from_status ∈ (paused, waiting_approval)` |
| 测试 | **3 个在跑且通过**：`test_worker_pause_then_resume`、`test_executor_pause_returns_paused_then_checkpoint_resume`、`test_executor_pause_mid_wave_stops_scheduling` |
| 设计 | design-v5.0 有 `POST /runs/{id}/pause` 与 `run.command` 的 pause 处理；**design-v5.7 §3.6 的「原地暂停」方案明确要复用它**（"平台已有全部底层能力…"） |

**唯一"没用"的是 UI 入口** —— 前端没有任何按钮调用它，`grep pause src/` 只命中
`usePolling` 的注释。

删除的代价：删一个设计内的 API 端点 + 让 design-v5.7 §3.6 的计划失去底层能力 +
**删掉 3 个通过的测试**（这最不该做 —— 为了让删除"看起来干净"而删测试，
等于把覆盖也一起扔了）。所以保留。

---

## 改动明细（只动前端展示）

### 1. `useTickets.js` — `paused` 单独一档

```js
if (r.status === WAITING_APPROVAL) return WAITING_APPROVAL
if (r.status === PAUSED) return PAUSED        // ← 新增
if (RUN_ACTIVE.has(r.status)) return 'running'
```

**不改的话会显示成"进行中"**：`paused` 不在 `RUN_ACTIVE` 里，会掉进最后一行兜底
`t?.status`，而**工单自己的状态是 `running`**（后端只在发起时写一次，见 v2.2.19）。

### 2. `useBugSolveRun.js` — `stepLabel` 认 `paused`

```js
if (runStatus.value === 'paused') return '已暂停'   // 否则落到"排队中…"
```

`paused` 不在 `TERMINAL` 里，不单列会显示成「排队中…」—— 它没在排队。

### 3. 文案

`STATUS_LABELS.paused = '已暂停'` 上一版已有，本次直接复用。

**没有**加筛选 chip 和 KPI 卡片：这个状态从 UI 不可达，加一个恒为 0 的卡片是噪音。
真出现时列表徽章会如实显示「已暂停」。

## 影响范围

| 场景 | 预期 | 实际 | 状态 |
|------|------|------|------|
| `paused` 的 run | 「已暂停」，不是"进行中" | 已暂停 | OK |
| `running` / `waiting_approval` | 不受影响 | 进行中 / 待审批 | OK |
| 后端 | 一行不改 | 未触碰 | OK |
| 3 个 pause 测试 | 继续通过 | 3 passed | OK |
| 生产构建 | 通过 | `npm run build` ✓ | OK |

**注**：这一档是**防御性**的 —— 前端没有暂停入口，所以正常操作下遇不到；
真由 API 触发时不会再被谎报成"进行中"。

## 未处理

- **暂停/恢复按钮**没有加。要不要在 Run 详情页加，是产品决定 —— 加了两颗按钮，
  演示动线上就多两个会改变流程状态的入口。
