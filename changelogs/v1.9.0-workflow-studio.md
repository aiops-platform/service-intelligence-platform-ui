# v1.9.0 — Workflow Studio 流程配置页面

**日期**: 2026-09-01

**问题/背景**: 需要「流程配置」能力——粘贴 workflow YAML → 预览节点图 → 保存/编辑/删除/复用已存流程。因 SIP 为纯静态 ES5（无 js-yaml、无构建工具），图预览必须由后端解析 YAML 返回 graph 结构（`POST /workflows/preview`），不能前端本地解析。配套后端为 `multi-agent-workflow`（本改动为后端新增 workflow CRUD + preview 接口，见「后端配套」章节）。

### 4. `js/app.js` — 新增 `initWorkflowStudio()` 模块 (app.js:5174)

**原因**: 实现流程配置页全部交互，仿 `initAgentRegistry()` 模式（ES5、局部 `getEl`/`setText`、`localStorage` 可覆盖后端地址）。

`initWorkflowStudio()` 内部：
- `WS_API_BASE = localStorage.getItem('workflowBaseUrl') || 'http://localhost:8000'` — 后端地址可配置
- `loadWorkflows()` → `GET /workflows` → `renderList()`（名称 + 创建时间 + Edit/Delete 按钮，事件委托）
- `preview()` → `POST /workflows/preview {yaml}` → `renderGraph(data.graph)`；后端 400 时展示 `detail`
- `renderGraph(graph)` → **SVG 拓扑分层布局**：Kahn 入度剥层（层为行 y、层内节点横排 x），环兜底追加末层；节点 `rect + text`（`kind === 'approval'` 高亮为紫色），边为 `line + #wsArrow` marker；每次渲染连同 `<defs>` 一起写入 `svg.innerHTML`（innerHTML 整段替换会清掉静态 defs）
- `save()` → 有 `editingId` 走 `PUT /workflows/{id}`，否则 `POST /workflows`；保存成功回填 `editingId` 并刷新列表 + 重绘 graph
- `edit(wid)` → `GET /workflows/{id}` 回填 name/yaml，按钮文案变「Update Workflow」，自动 preview
- `remove(wid)` → `confirm` 确认后 `DELETE /workflows/{id}`，删除编辑中对象时 reset 表单
- `resetForm()` → 清空表单 + 清画布 + 恢复 hint
- 注册 `_pageRefreshers['page-workflow-studio'] = loadWorkflows`（切回本页自动刷新）

## 后端配套（multi-agent-workflow 仓库）

本页面调用的 workflow CRUD / preview 接口在 `multi-agent-workflow` 中新增（跨仓库配套改动）：

- `agentflow/api/workflow_store.py`（新建）— `WorkflowStore`（aiosqlite 惰性连接，`workflows` 表：id/name/yaml/created_at）
- `agentflow/api/app.py` — 新增 `_workflow_graph()` 助手 + 6 个端点：`POST /workflows/preview`（解析不落库）、`POST/GET/PUT/DELETE /workflows[/{wid}]`；YAML 解析/DAG 校验失败返回 400 中文错误；`preview` 注册在 `{wid}` 之前避免被捕获
- `tests/test_workflow_api.py`（新建）— 10 个 httpx+ASGITransport 测试，全绿
