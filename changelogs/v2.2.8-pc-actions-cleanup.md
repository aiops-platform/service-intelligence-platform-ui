# v2.2.8 — Problem Center Actions 列清理：下线 Analyze 按钮 + 清理 view-analysis 死代码

**日期**: 2026-09-20

> 本文所有行号均指**改动前（HEAD）**的文件，可用 `git show HEAD:js/app.js` 核对。

**问题/背景**: 两件事一起做，都是 Problem Center 列表 Actions 列的清理：

1. **下线 Analyze 按钮**。问题处于 `pending` 时 Actions 列渲染 4 个按钮
   （Detail / 分析new / Analyze / Ignore）。其中 **Analyze** 是早期「选一个 workflow 再发起分析」的入口，
   与后来接入的 **「分析new」**（固定走 `problem-log-diagnose` 流程）**功能重叠**——
   两个入口做同一件事，且 Analyze 需要人工选流程，实际已无人走。
2. **清理 `view-analysis` 死代码**。`v2.2.3-pc-diagnose-view-revert` 那轮把列表行的
   **View analysis** 按钮换成了 **View diagnosis**，但只删了按钮，**事件分支和 CSS 留在原地**，
   成为永远走不到的死代码。

> ⚠️ **与「分析new」的区分**：`分析new` 走 `POST /v1/problems/{id}/analyze`
> （`body: { workflow_id, rerun: true }`，见 `startDiagnose`），**保留不动**。
> 本次只删「选流程弹框」那条路径（`confirmAnalyze`，`body: { workflow_id }`）。

不是「看着像没人用」，逐条查过：

| 检查 | 方法 | 结果 |
|------|------|------|

| 是否动态拼 action 名（grep 单词的漏检风险） | grep `'view-' +` / `"view-" +` 等拼接写法 | 无命中 |
| `.pc-viewrun-btn` 是否有消费方 | 全仓 grep（排除 node_modules/dist/changelogs） | 仅 CSS 定义处命中，无 JS/HTML 引用 |
| 是否跨世界引用（Vue 侧） | grep `src/` | 无命中 |
| 删分支后是否留下孤立 | 比对「监听器分支」与「data-act 全集」 | detail/ignore/diagnose/view-diagnosis 四个分支**均有按钮发出** |

## 踩坑记录

1. **`pcWorkflows` 是同名共享变量，差点误删**。它同时被 Analyze 弹框和「分析new」的
   `resolveLogDiagnoseWorkflowId()` 使用。若按「Analyze 相关」整块删除，
   「分析new」会在运行时抛 `pcWorkflows is not defined`——而**这个错误只在点「分析new」时才出现**，
   构建和静态检查都不会报。处理方式：保留变量语义但降级为函数内局部变量。

2. **`openProblemRun` 差点跟着 `view-analysis` 分支一起删**。那个分支从名字上看最像它的
   「专属调用点」，但它同时被「分析new」(`startDiagnose`) 和诊断弹窗重跑回调调用——
   删了会让发起分析后**不再自动打开运行视图**，且只在真发起分析时才暴露。删分支前先确认了函数的全部调用方。

3. **两个 `/analyze` 调用点，只该动一个**。`js/app.js` 里有两处 POST `/v1/problems/{id}/analyze`：
   - `confirmAnalyze()`（本次删除，`body: { workflow_id }`，人工选流程）
   - `startDiagnose()`（**保留**，`body: { workflow_id, rerun: true }`，「分析new」用）

   仅凭「删除 Analyze 相关」去 grep `/analyze` 会连带删掉「分析new」的整个发起逻辑。

4. **`data-act` 全集比对比 grep 单词更可靠**。只 grep `view-analysis` 只能证明「没有同名字符串」，
   证明不了「没有别的写法发出这个 action」。把全文件的 `data-act="…"` 取值去重，才能确认按钮侧
   真的不存在该 action；同时顺带覆盖了「动态拼 action 名」这个漏检风险点。
