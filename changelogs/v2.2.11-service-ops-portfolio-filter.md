# v2.2.11 — Service Ops：journey 筛选之后新增 Portfolio 筛选

**日期**: 2026-09-20

> 本文行号指**本次改动后**的当前文件。`public/` 下是压缩产物（整个文件一行、无换行），
> 只能给字符串锚点，给不了行号。

**需求**: Service Ops 概览页顶部筛选条里，journey 那组 chip **后面**再加一组 portfolio chip，
只列出**当前选中 journey 名下的** portfolio，点它就在该 journey 内再按 portfolio 过滤。

三条产品口径（已确认）：

1. **没选任何 journey 时不渲染这组 chip**（严格「由 journey 决定有哪些 portfolio」）；
2. **切换 journey 时清空已选 portfolio**（否则会出现「chip 看不见、却仍在筛」的幽灵筛选）；
3. 组前只加一根现有分隔符，**不加组标签**。

`otr` 租户实测的改前 / 改后：

```
改前  Filter │ All·50 │ T1 T2 T3 │ PS·21  Bot<50%·0 │ Sales…·28  Customer…·22
                                                       └─ 点 Sales… 之后 ↓
改后  Filter │ All·50 │ T1 T2 T3 │ PS·21  Bot<50%·0 │ Sales…·28 │ ─── Lead·7
             Offer&Order·5  Campaign·4  Handover·5  Consulation·4  Used Car·3
```

## 改动明细

### 1. `tools/tenant_copy.py:398-541` — 新增 `patch_service_ops_portfolio_filter()`

**原因**: 页面源码不在本仓（内嵌的 Next.js 应用），但本仓已在维护它的编译产物。
本次是第 7 个补丁，也是**第一个多点补丁**。

筛选条的 chip 渲染在组件 `T` 里，状态与过滤在 `ServiceOps` 里，所以 `pfSel` 这个新状态要穿过
**9 个位置**：

| # | 位置 | 改什么 |
|---|---|---|
| ① | `ServiceOps` 状态区 | `[pfSel,pfToggle]=(0,o.useState)(new Set)` |
| ② | 过滤谓词（`if($.size>0){…}` 内） | 选中 journey 内再按 portfolio 过滤 |
| ③ | 该 `useMemo` 的依赖数组 | `[w,F,I,$]` → `[w,F,I,$,pfSel]` |
| ④ | `W`（anyActive） | 加 `\|\|pfSel.size>0`，否则「All」徽标与匹配数不跟着变 |
| ⑤ | `onReset` | 加 `pfToggle(new Set)`，否则「All」清不掉 portfolio 筛选 |
| ⑥ | `onToggleJourney` | 一并 `pfToggle(new Set)` |
| ⑦ | `T` 的调用处 | 传 `portfolioFilter` / `onTogglePortfolio` |
| ⑧ | `T` 的解构 | 接这两个 prop |
| ⑨ | journey chips 之后 | 渲染 portfolio chip 组（前带一根现有分隔符 `w`） |

渲染那段（关键部分）—— 数据与控件全部复用，没有新造：

```js
i.size>0 && <>                       // i = journeyFilter，没选 journey 就不渲染
  {w()}                              // 现有分隔符
  {JOURNEY_DOMAINS.filter(d => i.has(d.id)).flatMap(d => d.portfolios)
     .map(p => chip({label: p.label, active: pfP.has(p.id), count: p.appCount,
                     onClick: () => pfT(p.id)}))}
</>
```

- **数据**：模块级 `JOURNEY_DOMAINS[].portfolios[]`（域构造函数里从 `snapshot.portfolios` 现算的），
  每项自带 `id` / `label` / `appCount`，且已按 `incidentsTotal` 降序 —— 与 journey chip 同口径；
- **控件**：chip 用本文件里现成的 `h`，分隔符用现成的 `w`；
- **计数**：静态的「该 portfolio 有几个 app」，与 `k`（journey chip 的计数源）同性质。

**为什么必须 9 处一起改（原子性）**：只打一半的后果不一样 ——

| 少打 | 后果 |
|---|---|
| ① | `pfSel is not defined` → **整页白屏** |
| ③ | 筛选生效但列表不重算（要等别的状态变化才刷新） |
| ⑤ | **幽灵筛选**：UI 看着已清空，列表却还被 portfolio 卡着 |

所以本函数**先全量校验 9 个锚点、全部命中才落笔**，任一缺失整组跳过并返回原因。
这与单点补丁「不唯一就静默跳过」的约定**相反** —— 那里是「功能不见了」，这里是「页面坏了」，
所以构建脚本对非 `already` 的情况会打 `!` 警告，不允许静默失效。

## 踩坑记录

### 1. ★★ `useState` 的 setter 不能直接喂 id —— 静态检查发现不了，只有真点才炸

⑦ 最初写成 `onTogglePortfolio:pfToggle`（直接把 setter 传下去），chip 里 `pfT(e.id)` 于是调用
`pfToggle("portfolio:lead")`。**setter 收到非函数值就整体替换 state**，`pfSel` 从 Set 变成字符串
`"portfolio:lead"`，下一次渲染 `pfP.has(...)` 立刻：

```
TypeError: pfP.has is not a function    at 0t1fyt7wcotiz.js:1:28754
```

既有那几个 toggle **全都在父组件里包一层**，正是这个原因：

```js
onToggleJourney:e=>E(t=>{let r=new Set(t);return r.has(e)?r.delete(e):r.add(e),r})
//                ↑ id 进，Set 的增删在 updater 里做，setter 永远只收到函数
```

修法就是照抄这个形状（见 ⑦）。**这个坑值得记的原因**：补丁过了 `node --check`、过了幂等检查、
过了锚点唯一性检查，甚至**第一屏渲染还是对的**（不选 journey 时那段代码根本不执行）——
它在「点下第一个 portfolio chip」那一刻才爆。

定位过程也有教训：第一版探针把「筛选条还在不在」当作判据，结果只看到
`Cannot read properties of undefined (reading 'querySelectorAll')`（**我自己脚本的错**），
真实异常被淹没。改成监听 `Runtime.exceptionThrown` 才看到 React 那条 TypeError；
再用「不抛异常、把坏值记进 `window.__badPfP`」的探针，才拿到 `"portfolio:lead"` 这个字符串。

### 2. journey chip 是**多选** toggle —— 决策 2 的真实后果

需求里说「切换 journey」，但 journey chip 本身就是多选：点第二个是**累加**而不是替换。
所以「切换时清空 portfolio」的实际含义是：**点任何一个 journey chip 都会清空已选 portfolio**，
包括「往已选里再加一个」的情况。实测（⑥）：

    选 Sales + Lead（7 of 50）→ 再点 Customer Server
    → 选中变成 Sales + Customer Server（50 of 50，两个都在）
    → Lead 的选择被清空，chip 组变成 11 个（两个 journey 的并集）

这是决策 2 的直接推论、行为自洽；写在这里是因为它比「切换」这个词听起来更容易触发。

### 3. 已知边界：0 个 portfolio 的 journey 会多出一根孤立分隔符

12 个租户实测都没有这种 journey（每个 journey 至少 1 个 portfolio），但数据是手改的，
将来可能出现。选中它时会渲染「分隔符 + 空列表」。**没有加守卫** —— 在压缩代码里加守卫要么引入
一个 IIFE，要么重复一遍域名过滤表达式，不划算，而后果只是外观。已写在函数 docstring 里。

### 4. 默认租户 `otr` 又被重建冲回 `retail`（**第二次**撞上）

同 `changelogs/v2.2.10` 踩坑 1：`cf01394` 把兜底 `return"retail"` 手改成 `return"otr"`，没做成补丁，
所以每次 `make-offline-page.py` 都会把它冲掉（构建输出一切正常、不报错）。
本次同样把 `0wuztp2.9oz~8.js` 与 `service-ops/index.html` 两个产物**回退到 HEAD**，
让本次 diff 只含该改的那个 chunk。根治办法（做成补丁或加 `--default-tenant`）仍未做 —— 上一轮已确认"先不用"。

### 5. 探针正则要锚定，否则会把相邻 chip 的数字吃进来

第一版读匹配数用 `/ ([\d,]+) of ([\d,]+) apps match/`，未锚定，于是
`…Used Car· 3` + `28 of 50 apps match` 被读成 **"328 of 50"**。改成在**单个 span** 上匹配
`^([\d,]+) of ([\d,]+)` 才对。
