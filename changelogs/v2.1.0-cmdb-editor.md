# v2.1.0 — CMDB 实体图谱编辑器

**日期**: 2026-09-16

**需求背景**: CMDB 的载体是 `aiops-datasource-mcp-server` 的实体文件
（`data/cmdb-entities.json`），此前只能改 JSON + 跑脚本。后端已开出 `/admin/cmdb/**`
写端点（同批改动，见该仓 CHANGELOG），本步给它配一个页面。

**这是本仓第一个会写数据的页面** —— 其余视图都是查询。

## 改动明细

### 1. `src/api/cmdb.js` — 新增：CMDB 管理端点客户端

第三个后端（前两个是 sip-aiops `:8080`、agentflow `:8000`）。base 走
`src/api/config.js` 的 `cmdb` 项，默认 `/api/cmdb`，dev proxy rewrite 成 `/admin/cmdb`。

`describeError()` 把后端的原话取出来给界面——**4xx 不是"网络抽风"，是这次编辑真的没生效**，
且 `message` 里带着具体原因（哪个节点、哪个字段）。吞成"保存失败"等于把唯一有用的信息丢掉。

### 2. `src/router/index.js` — 路由挪进 `EXTRA_ROUTES`，不进任何域

`/cmdb`，与 `/runs/:runId` 同栏（那栏的注释本来就写着"不在侧边栏里的 Vue 原生页"）。

**刻意不属于任何域**：它是一张给少数人用的运维工具表，不是产品叙事的一部分。
放进某个域（最初试过挂在空壳域 `architecture` 上）会让它出现在演示动线的导航里。

### 3. `src/components/shell/AppHeader.vue` — 新增：右上角用户菜单

入口在**点姓名**（`san.zhang`）。那个位置原本是一个静态 `div.status-pill`，
现在改成真 `<button>`，点开一个下拉，一项「编辑 CMDB」→ `/cmdb`。

菜单项写成数组 `MENU`：加第二项只改那一处，关闭/焦点那套不用跟着动。

几个不显眼但必要的点：

- **点外部关闭**挂 `document`，且用 `click` 而非 `mousedown`——拖选文字到菜单外不会误关
- **Esc 关闭并把焦点还给触发按钮**：菜单消失而焦点悬在 body 上，键盘用户会失去位置
- **路由一变就收**，否则从菜单跳走后它会挂在目标页上
- CSS 用限定选择器 `.user-menu-trigger`，**没动 `.status-pill` 本身**

### 4. `src/views/cmdb/` — 新增：编辑器

`CmdbView.vue` + `useCmdb.js`（状态就近放，**不用 Pinia**，与既有视图一致）。

**左清单 + 右 Inspector**，与 Agent 目录同构，但 Inspector 是**表单**不是只读详情。

三条来自后端的事实决定了它长什么样：

1. **写前整份过校验，不过就整个不生效。** 合法性依赖整张图（边端点是否存在、端点类型
   是否被允许、id 前缀是否与 type 一致、tags 是否在封闭词表内），不是单条记录能判的。
   所以前端**不复刻**校验规则（两份规则一定会漂移），而是把后端的原话显示出来。
2. **`id` / `type` 不可改**——它们是节点的身份与分桶依据，后端明确拒绝，界面也就只读。
3. **删节点默认拒绝被引用的节点**（409 并列出挡路的边）。所以「相关边」直接摆在表单旁边，
   删之前就该看见有什么连着它。

#### 表单字段从哪来

**不是** `docs/cmdb-entities.schema.json`。那份由 `EntityDocument` 生成，而
`Node.attributes` 声明成 `dict[str, Any]`——每种节点类型真正的属性模型
（`NODE_ATTR_MODELS`）是**旁表**，pydantic 在模型图上看不到它。所以字段只能来自
`GET /admin/cmdb/schema` 的 `attribute_models`；没登记模型的类型（agent / codebase /
incident …）退回自由 JSON 编辑。

同一份 schema 还给 `conditional_required`：**条件必填**（`app` 看 `source`——
`kubernetes` 要 6 个运行时字段、`otr-inventory` 要 `business_tier`）。JSON Schema
表达不了这种约束（`required` 里只有 `kind`），不并进来的话用户看不到"必填"标记，
填完一保存才被拒。

#### 建边：候选按 ontology 过滤

「+ 新建边（从本节点出发）」→ 选边类型 → 选另一端的节点。

按 `edge_types` 的 `from_types` / `to_types` 推导三件事：

- 当前节点在这个边类型的**哪一端**（`from` / `to` / `either`），提交时据此摆正方向
- 另一端**只能是哪些类型**——选中 app 时 `app_codebase` 只给 10 个 codebase 候选，
  而不是 102 个节点里挑；且**选不出非法组合**
- 有向边反着连是不可能的，界面直接不给这个选项

每条相关边上有 `×` 直接删。**这条是必须的**：后端的"一个 app 一个仓库"约束报错里写着
"请在编辑页删掉多余的那条"，页面删不掉就等于把人堵死。

### 5. `vite.config.js` / `src/api/config.js` — 第三条后端

`'/api/cmdb'` → `http://localhost:8300`（datasource MCP server），rewrite 剥掉
`/api/cmdb` 换回 `/admin/cmdb`。`server` 与 `preview` 各配一次——**Vite 的 preview
不继承 server.proxy**，只配一边会让 `npm run preview` 连不上。

## 已知取舍

- 建边只能**从当前选中节点出发**。跨两个不相干节点建边要先选中其一——覆盖了实际用法，
  且免掉两个 102 项的下拉。
- 边**不能改**，只能删了重建。边的属性目前只有 `calls.relation`，改动频率极低。
- `attributes` 是**整体替换**而非按字段合并（`attributes` 形状由类型决定，
  合并会让"删掉一个属性"无法表达）。后端同理。
