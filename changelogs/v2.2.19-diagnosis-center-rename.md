# v2.2.19 — Problem Center 改名为 Diagnosis Center（只改文案层，URL 仍是 /problems）

**日期**: 2026-09-21

**需求/背景**: 「Problem Center 这个菜单名想改一下 —— 它的功能是监控日志和指标产生的问题才会
到这儿来，然后分析完形成 ticket。能不能叫『告警中心』？」（用户提议 `告警中心`）

**结论：没有采用「告警中心」，改叫 `Diagnosis Center`。** 下面是为什么。

---

## 为什么不是「告警中心」

调研后发现 **`Alert`（告警）在本仓已经是一个别的实体，而且来自另一台后端**：

| | **Alert**（告警） | **Problem**（这页的东西） |
|---|---|---|
| 后端 | sip-aiops **`:8080`** `/api/sip-aiops/app-alert` | APM **`:7070`** `/v1/problems` |
| 字段 | `title` / `type` / `severity` / `status` / `summary` | `record_id` / `occurrence_count` / `state` / `symptom` |
| 动作 | Acknowledge（`PUT /app-alert/{id}/acknowledge`） | Analyze → 起 agentflow run 诊断 / Ignore 判误报 |
| 语义 | **单条原始告警** | **聚合记录**：多次触发算一条（`occurrence_count`） |

即：**告警是输入，problem 是聚合+分析的产物** —— 正好是 `监控 → 问题 → 分析 → ticket`
流水线里中间那一环。叫「告警中心」会指向前半段，并与 `app-alert` 那套撞名。

**两条旁证**：

1. **代码已经自己在往 `Problem` 收敛**：Smart Inspection 服务抽屉里的字段早就从 `Alerts:`
   改成了 `Metric Problems` / `Log Problems`（`js/app.js:1868` 附近的注释记录了这次改名），
   理由是那两列数字来自 Diagnosis Center 的数据源，不是 `app-alert`。
2. **`Problem` 在这个领域有出处**：Dynatrace 等 APM 产品的 "Problems" 就是这个语义
   （原始异常关联聚合成带 occurrences / 状态 / 根因的记录）。后端库文件也是 `router/problems.py`。

> ⚠️ 但要说清楚风险有多大，免得讲过头：**这些 `Alert` 界面目前全都够不到** ——
> metrics-analysis 与 log-analysis 两个面板 2026-09-18 就从导航摘掉了，
> 告警列表弹框（`openAlertModal`）现在只剩它自己的翻页回调在调，没有任何入口。
> 所以那次撞名**暂时不会表现为「两个告警」**，但等那两个页面恢复（`nav.js` 里留着恢复步骤）
> 就会撞。

**为什么最后选 `Diagnosis Center`**：用户从四个候选里选的。它强调这页独有的那一步 ——
`Analyze` 按钮 → 起 agentflow run 做诊断 → 出结论 → 形成 ticket。代价是弱化了
「它同时是个列表页」这层（带筛选、分页、误报处理）。

---

## 改名规则（本次实际执行的）

> **改的是页面名，不是实体名。**

- **`Problem Center`（页面名）→ `Diagnosis Center`** —— 全部改掉；
- **`problem(s)`（实体名）保持不变** —— 后端仍是 `/v1/problems`、`router/problems.py`，
  所以页面副标题 `Detected Problems`、KPI `Total Problems` / `problems resolved`、
  表头 `Problem`、`Loading problems...` 都**原样保留**（页面叫 Diagnosis Center、列表里装的是
  problems，同 "Ticket Inbox 里装的是 tickets"）。

## 改动明细

### 1. `src/router/nav.js` — 侧边栏菜单标签 (197)

```js
// before
{ slug: 'problems', label: 'Problem Center' },
// after
{ slug: 'problems', label: 'Diagnosis Center' },
```

**`slug` 刻意不动**（URL 仍是 `/problems`）。上方新增 15 行注释说明这一点（183-196），
因为「标签与 slug 不一致」正是下一个读代码的人会停下来问的地方。改 slug 会牵动
`PANEL_ID`、`initSmartInspection` 的 `navigateToPage('problems')`、`applyQueryFilters`
消费的三个 query，以及所有已分享的 `/problems?service=…` 链接。

### 2. `src/legacy/legacy-panels.html` — 面包屑与 H1 (972、975)

```html
<!-- 972 -->
... Smart Inspection <span class="breadcrumb-sep">&rsaquo;</span> <strong>Diagnosis Center</strong>
<!-- 975 -->
<h1 class="page-title">Diagnosis Center <span ...>Detected Problems</span></h1>
```

注意副标题 `Detected Problems` **没动** —— 按上面的规则，它描述的是实体。

### 3. `src/legacy/legacy-panels.html` — 两个模态的段落注释 (1760、1771)

```
<!-- 诊断模态（Diagnosis Center 的 Analyze）：... -->
<!-- Diagnosis Center Run Viewer Modal：... -->
```

**踩坑**：批量替换后第一处变成 `<!-- Diagnosis Center Diagnosis Modal ... -->` ——
"Diagnosis Center Diagnosis Modal" 读起来是重复的。已手工改成「诊断模态（Diagnosis Center 的
Analyze）」。

### 4. `js/app.js` — 一处**运行时字符串** (5805)

```js
comment: action === 'reject' ? 'rejected from Problem Center' : ''   // before
comment: action === 'reject' ? 'rejected from Diagnosis Center' : '' // after
```

**这条不是注释**，是 `runApproval()` 拒绝审批时写进 agentflow 的 `comment` 字段，
会出现在 run 历史里 —— 属于用户可见文案，必须跟着改。

### 5. `js/app.js` — 其余 14 处注释 (37、38、46、81、1417、1422、1602、1667、1727、1769、2356、2357、2482、3955)

其中 `1667` 是 `console.info('[sip] Smart Inspection × … 服务名对照：')`，**也是运行时字符串**
（dev 控制台可见）。其余为纯注释。

### 6. `README.md` — 改名 + 修上一版遗留的失效描述

`Problem Center` → `Diagnosis Center` 共 7 处（220、226、233、239、246、260 等）。

**另外修了 v2.2.18 遗留的失效描述**（那版没同步 README）：

| 行 | 原文 | 问题 |
|---|---|---|
| 168 | `## Observability — Metrics Analysis / Log Analysis（已隐藏）` | 分组已改名 APM |
| 171 | 「该分组现只剩 `Smart Inspection` 与 `Problem Center`」 | 改版后该分组只剩 `Smart Inspection` 子分组 |
