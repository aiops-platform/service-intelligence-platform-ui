# v1.7.0 — 新增 Problem Center（问题中心）页面

**日期**: 2026-08-28

**问题/背景**: Observability 下需要一级菜单集中展示 APM 后端 `problem_record` 表检测出的**全部问题**——不再按日志 / 指标 / 内存分类（原「Error Log Anomalies / Metrics / Memory」都是按信号类型拆开的单类视图）。数据源即后端已具备的 `/v1/problems` 列表 / 详情 / resolve 能力，**后端零改动**。页面风格对齐现有「Log Analysis / Error Log Anomalies」页面，并带操作按钮（**Detail / Ignore**）。

## 改动明细

### 1. `index.html` — 侧栏 Observability 新增 Problem Center 菜单 (index.html:106-108)

**原因**: 一级菜单入口，挂 Observability 下与 Smart Inspection / Metrics Analysis / Log Analysis 平级。

```html
<div class="sidebar-item" data-page="problems">
    <span class="sidebar-label">Problem Center</span>
</div>
```

### 2. `index.html` — 新增 `#page-problems` 面板 (index.html:1166-~1300)

**原因**: 页面样板完全镜像 `#page-log-analysis`：面包屑、页头（Refresh + 服务过滤标签）、5 张 KPI 卡、工具栏（服务下拉 + Severity 芯片 + State 芯片）、`reflow-table` 表格（Problem / Service / Domain / Severity / State / Occurrences / First Seen / Actions）、客户端分页。复用现有样式类（`.reflow-stats` / `.kpi-card` / `.reflow-filter-bar` / `.filter-chip` / `.reflow-table` / `.pagination` / `.alert-tag` / `.si-refresh-btn` / `.ap-modal-overlay`），复用 `confirmModalOverlay` / `alertDetailOverlay` 弹窗。操作列表头补上 `Actions`（原 `<th></th>` 留空）。

### 3. `js/app.js` — 侧栏导航映射 `problems → showPage('page-problems')` (app.js:101)

**原因**: `initSidebar` 的 if/else 分支需要把新 `data-page="problems"` 转发到新面板，与 `log-analysis` 等已有分支一致。


### 4. `js/app.js` — 新增 `initProblems()` 模块 (app.js:3581-~3945)

**原因**: 页面全部数据逻辑。复用 `initMonitorTargets` 里的 `apmApi()` 连接模式（`APM_BASE_URL` = `localStorage.apmBaseUrl || 'http://localhost:7070'`，`X-Tenant-Id` 头，可选 Bearer），一次 `GET /v1/problems?limit=500` 拉全量后客户端聚合：

- `renderKpi()`：Total Problems / Unique Services / Critical / Open(pending+in_progress) / Resolved（后端无 summary 端点，故客户端聚合）。
- `filteredProblems()`：服务下拉 + Severity 芯片（all/warning/high/critical）+ State 芯片（all/open/in-progress/resolved/closed，`open` = pending|in_progress，`closed` = closed|archived）。
- `renderTable()`：客户端 10/页分页，行内 Severity/State 标签（`.severity-{sev}` / `.status-{st}`）、Occurrences 徽标、`formatTime(detected_at || first_seen_at)`、**Detail / Ignore** 操作按钮。
- `openProblemDetail()`：展示完整记录（symptom 摘要、Meta、Metric/Log Anomalies 表、Correlation、Verification、Evidence、trace_id）——v1.7.0 迭代后改走专用宽模态 `pcDetailOverlay`（见 #8）。
- `confirmIgnore()`：复用共享 `confirmModalOverlay` → `POST /v1/problems/{id}/resolve` body `{"false_positive": true}` → toast + 刷新。
- 注册 `_pageRefreshers['page-problems']`，切回该页自动刷新；后端不可用时 toast 报错 + 渲染空态，不白屏。

### 5. `js/app.js` — `init()` 注册 `initProblems()` (app.js:4920)

**原因**: 主初始化入口调用新模块，与 `initLogAnalysis()` 相邻。

### 6. `css/styles.css` — 新增 Problem Center 样式块 (styles.css:4860-~4970)

**原因**: 复用现有类的基础上，仅补齐缺失的标签/状态颜色（`.alert-tag.severity-high`、`.status-pending`/`.status-in_progress`/`.status-closed`/`.status-archived`）与详情弹窗排版（`.pd-header`/`.pd-summary`/`.pd-section`/`.pd-meta`/`.pd-anoms`/`.pd-evidence`）、操作按钮（`.pc-ignore-btn`）及筛选空态提示（`.pc-empty-state`）。

### 7. `js/app.js` — 列表标题改为展示报错 message（不展示堆栈签名）(app.js:~3708-3722)

**原因**: 原 Problem 列标题直接用 `symptom.summary`（后端模板拼的是 `{service} {signature} x{count}`，signature 含 `|` 分隔的堆栈帧），显示一长串代码且被 48 字符截断。改为新增 `problemTitle()` 辅助函数，按异常类型取可读标题，列表不再代码化；详情弹窗（`openProblemDetail`）仍展示完整记录，不丢信息。

```js
// before：直接用 symptom.summary（日志问题是整条堆栈签名）
var title = (p.symptom && p.symptom.summary) ? p.symptom.summary : (p.record_id || 'Untitled');
// after：problemTitle 提取
//   日志问题 → log_anomalies[0].signature 冒号后的 message（| 前的异常首行，去掉 ExceptionType: 前缀）
//   指标问题 → metric_anomalies[0].metric + ' = ' + value（如 cpu_usage = 0.98）
//   兜底     → symptom.summary / record_id
var title = problemTitle(p);
```

同时把标题截断从 48 放宽到 90 字符（`truncateText(title, 90)`）——message 是给人读的句子，48 会把 `Required request parameter 'serviceName' for method parameter type String is not present` 这类常见 message 截掉一半；90 以内完整显示，超长仍走 `title` tooltip + 省略号。

### 8. `index.html` + `css/styles.css` + `js/app.js` — 操作按钮 Analyze → Detail，详情改走专用宽模态 (index.html:~1558-1567, styles.css:~4894-4902, app.js)

**原因**: 用户要求列表里放「Detail」按钮，点击弹出框按标准排版展示问题内容，且弹出框大小参考 Monitor Targets 的 **Test/net 按钮弹窗**（`#apmModalOverlay`：1200px 宽、`height: calc(100vh - 120px)`）。原「Analyze」按钮本身就是详情弹窗，故直接改名 **Detail**，并弃用共享的 `alertDetailOverlay`（960px，仍被 Log Analysis / Error Log Anomalies 使用），新建专用宽模态 `#pcDetailOverlay`：

- `index.html`：在 `#alertDetailOverlay` 后新增 `#pcDetailOverlay`（标题 `#pcDetailTitle` + 关闭 `#pcDetailClose` + 内容 `#pcDetailContent`），`#pcDetailContent` 复用 `buildDetailHtml()` 的标准排版（symptom 摘要 / Meta / Metric·Log Anomalies / Correlation / Verification / Evidence）。
- `css/styles.css`：`#pcDetailOverlay .ap-modal { max-width: 1200px; height: calc(100vh - 120px); max-height: calc(100vh - 120px); }`、`#pcDetailOverlay { align-items: center; padding: 60px 24px; }`——与 `#apmModalOverlay` 同款尺寸，内容区 `.ap-modal-body` 已有 `overflow-y: auto`，长内容在弹窗内滚动。
- `js/app.js`：`renderTable()` 操作按钮 `Analyze` → `Detail`（`data-act="detail"`），点击分支改判 `detail`；`openProblemDetail()` 从 `alertDetailOverlay` 改指向 `pcDetailOverlay/pcDetailContent/pcDetailTitle`，并新增 `closeProblemDetail()` + 关闭按钮 / 遮罩点击 / Escape 三个关闭路径。Log Anomalies 的 signature **完整展开不截断**：新增 `logSignatureHtml()`，按 `|` 拆成「异常/消息首行（`.pd-msg`，加粗）+ 每帧堆栈（`.pd-frame`，次要色）」各自独占一行，替代原 `truncateText(..., 90)`。

### 9. `js/app.js` + `css/styles.css` — Evidence 改为结构化卡片展示 round_id / target_ids (app.js, styles.css)

**原因**: 后端 `emit` 每条 evidence 现在携带 `round_id`（= 该轮 `trace_id`）与该轮 `detection_round.target_ids`，跨轮 append 后仍可追溯 evidence → round → target。前端把 Evidence 从原始 JSON blob 改为**逐条结构化卡片**，把 round_id 直接可见：

- `js/app.js`：`buildDetailHtml()` 的 Evidence 段不再 `JSON.stringify` 整段，改为逐条渲染 `.pd-ev-item` 卡片：`type` 徽标（`.pd-ev-type`）+ `round {round_id}`（`.pd-ev-round`，title 注明「detection round id (= trace_id)」）+ `count N`（`.pd-ev-count`）+ `targets` / `traces` 两个等宽 id 列表（`.pd-ev-label` + `.pd-ev-ids`）。未知字段兜底展示原始 JSON，不丢信息。
- `css/styles.css`：`.pd-evidence` 改为滚动容器（`max-height: 320px; overflow: auto`），新增 `.pd-ev-item` / `.pd-ev-head` / `.pd-ev-type` / `.pd-ev-round` / `.pd-ev-count` / `.pd-ev-line` / `.pd-ev-label` / `.pd-ev-ids` 卡片样式。

## 踩坑记录

- **不新增 `apmApi` 全局**: `initProblems` 内部定义局部 `apmApi`（app.js:3597），与 `initMonitorTargets`（app.js:4048）、`initDomainConfig`（app.js:4437）各自私有，互不干扰——保持既有「每个 init 模块自带连接层」模式。
- **State 归类**: 后端 state 枚举是 `pending/in_progress/resolved/closed/archived`；UI 筛选把 `pending|in_progress` 并成 **Open**、`closed|archived` 并成 **Closed**，避免芯片过多。
- **KPI 聚合**: 后端无 summary 端点，5 个 KPI 全部由单次 `limit=500` 拉取在客户端计算；超出 500 的问题暂不聚合（与 Log Analysis 同款限制）。
- **筛选空态补全**: `renderTable` 最初在筛选无结果时只渲染 `&nbsp;` 空行（无提示），端到端验证中发现后补了「No problems match the current filters.」提示行（`colspan=8` + `.pc-empty-state` 居中样式），后端不可用时同一分支也复用该空态 + 错误 toast，不白屏。
- **标题提取的边界**: 日志 message 取 `signature.split('|')[0]` 再截冒号后内容——无堆栈时 signature 就是 `log.message[:120]`（无冒号），此时整行展示；异常类型只作为前缀丢弃（`ExceptionType: message` → `message`），异常类型本身可从详情弹窗的 LOG ANOMALIES 里看。指标问题没有 message，统一展示 `metric = value`，Service 列已单独显示服务名，标题不重复拼服务。混合问题（log+metric）时日志 message 优先。
- **不直接改 `alertDetailOverlay` 尺寸**: 该弹窗被 Log Analysis / Error Log Anomalies 共用（`openAlertDetailGeneric` 等），若全局放宽到 1200px 会影响其他页面。故 Problem Center 新建专用 `pcDetailOverlay`，复用同样的 `.ap-modal` 骨架与 `buildDetailHtml()` 内容，仅尺寸对齐 Monitor Target 的 Test/net 弹窗；三个关闭路径（关闭按钮 / 遮罩点击 / Escape）与 Confirm 弹窗一致补齐。
- **`node --check js/app.js`** 通过，无语法错误。
