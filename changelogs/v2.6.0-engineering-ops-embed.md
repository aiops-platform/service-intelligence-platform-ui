Engineering Ops 的页面，请根据 skill 帮我构建到我们的前端服务中」，

### 7. `tools/tenant_copy.py` — ★ 三处页内跳转改道给外壳 (line 1108-1200)

**原因（实测，不是推演）**: 内层是另一套 Next 应用，`router.push()` 推的是**它自己的**
路由。本仓没把 `/agents/` 导出成内层页，于是落进宿主 SPA 兜底 ——
**iframe 里渲染出整个 Vue 应用自己**。实测点「SDLC Agents Live」：

```
iframe URL  → /agents?group=sl
iframe 内容 → 完整 SIP 外壳 + AGENTS 页        ← 自己套自己
```

**⚠️ 而且这一例连 `NextEmbed` 的第二道闸都躲过了**：`inSameOriginFrame()` 只在
**目标路由本身是内嵌页**时才拦得住 —— `/agent-registry` 不是内嵌页，所以那次
**没有任何拦截**，整个应用就套进来了。

三处（已穷尽核过 chunk 里所有以 `/` 开头的字面量）：

| 触发 | 原目标 | 现在 |
|---|---|---|
| MTTR 卡片 | `r.push("/service-ops/")` | `postMessage {type:"sip:open-service-ops"}` |
| SDLC Agents Live 卡片 | `r.push("/agents/?group=sl")` | `postMessage {type:"sip:open-agents"}` |
| 打开某个 agent | `r.push(\`/agents/?agent=${…}\`)` | 同上 |

未嵌入时（`window.parent===window`）**保持原来的 `push`** —— 单独打开离线副本时内层
shell 是自洽的，改了反而坏（Business Ops 那条补丁给的是另一个落点，因为那边原路径会
404；这里不会）。

### 10. `.claude/skills/sip-embed-page/` — 三处工具与文档修复

**a. 扫描器的两个盲区（★ 本次靠它才没漏）**

- `ESTATE_NOUN` 缺 `changes` → 「`86,994 changes`」**一条都不报**；
- 引号配对正则 `"([^"\\\n]{10,300})"` 在**模板字面量**面前整片错位 ——
  反引号里的 `"` 被当成边界，从某处起后面的文案**一条都扫不到**，而报告仍是 ✓。

第一个盲区让这条真问题没被发现；第二个盲区**连修了第一个之后仍然漏**（局部能匹配、

**b. `EMBED_PAGES` 的校验从「同名域」放宽到「所有目录索引页」**

原先只在同名分支里查，于是 business-ops / engineering-ops 这类**不同名**的页漏了也没人报。

## 踩坑记录

### A. ★ 「不加 `EMBED_PAGES` 就去看页面」会渲染出**别的页面**（上一轮记的，这轮又中）

接完前四步、还没做 Vue 接线的中间态，打开 `/eng-ops` 看到的是 **Service Ops 的内容**，
但 **h1 显示「Engineering Ops」** —— 因为 `/eng-ops` 那时还不是路由，落进 catch-all
→ `emptyDomainRoutes` 的**空壳语义**：渲染 service-ops 概览 + 接缝 S9 改写标题。

**h1 是对的，内容是别人的。** 比白屏更容易误判成「接上了」。

### B. ★ 自检报告的 ✓ 可能是假的

见改动 10a。这一页的 `eng_desc` 是**两个盲区叠加**才漏掉的：名词表没有 `changes`，
且模板字面量让扫描器整片错位。如果只信脚本，这一页会以「✓ 接线完整」交付，
而 description 里 best-buy 的数字与租户的 KPI 并排显示。

### C. 内层跳转的后果**必须实测，读代码会推错**

我原先推断 `/service-ops/` 会「套出一层 Service Ops 内嵌页」，实测是
**iframe 里跑起整个 Vue 应用**（URL 被规范成 `/service-ops`，**没有尾斜杠**，
于是 dev 插件不拦、落进 SPA 兜底）。推断与事实差了一层 —— 所以这三处都是点出来的。
