# v2.2.16 — 修复：轮询刷新后流程图滚回顶部

**日期**: 2026-09-20

**问题**: Run Detail 的流程图往下滑动后，**后台一刷新就弹回顶部**，停不住。

**根因**: `renderGraph` 里这行尺寸处理：

```js
svgEl.removeAttribute('width')
svgEl.removeAttribute('height')
```

删掉 `height` 会让 SVG **塌成 0 高**（实测 `scrollHeight` 1205 → 358），
父容器 `.bs-zoom` 的 `scrollTop` 随之被浏览器**夹成 0**；
之后 `applyScale` 把尺寸设回来，**滚动位置不会自己回来**。

宿主是**轮询驱动**的（`watch(runData.nodes, {deep:true})` → `render()`），
所以每几秒就把用户滑下去看的位置清一次。

**逐步骤实测**（把候选操作一个个单独跑）：

```
设 300 ｜ 清空 innerHTML:300 ｜ 写回:300 ｜ 改 height 属性:300
｜ removeAttribute('height'):0 (scrollHeight 1205→358)
｜ 设回 height:0    ← 尺寸恢复了，滚动位置**没有**
```

---

## 改动明细

### 1. `src/components/graph/useGraphCanvas.js` — 删掉 `removeAttribute` (约 190)

**原因**: 这行**没必要**——`applyScale` 每次都会重设 `width`/`height`，
不需要"先删再设"。删掉之后连塌陷都不会发生。

### 2. `src/components/graph/useGraphCanvas.js` — 捕获提到函数最开头 (106)

```js
function renderGraph(graph, statusMap) {
  if (!svgEl) return
  // ⚠️ 必须在动 DOM **之前**捕获
  const keepScrollTop = zoomEl ? zoomEl.scrollTop : 0
  ...
```

**为什么位置这么讲究**：第一版我把捕获放在 `innerHTML = html` 之前，看着没问题——
但 `removeAttribute('height')` 在**函数开头**就已经把 scrollTop 夹成 0 了，
捕获到的是 **0**，恢复等于没做。**恢复对了，捕获晚了。**

恢复仍在末尾 `fitGraph()` 之后（尺寸定下来才设得进去）。

## 踩坑记录

### 探针两次写到了 `/tmp`

Python heredoc 继承了上一条 Chrome 命令留下的 `cwd=/tmp`，
"写入成功"但写的是 `/tmp/__graph-harness.html`，页面加载的还是旧文件——
表现为"改了代码但行为没变"。**改用绝对路径**后才定位到真因。

### "改对了但没用"要先怀疑测的不是同一份

中间一度以为是"布局未刷新导致 scrollTop 被夹"，加了 `void zoomEl.scrollHeight`
强制布局——**那是对的，但没解决问题**，因为**捕获就晚了**。
强制布局只保证"设得进去"，不保证"抓到的是真值"。
