# v2.6.5 — 建单表单默认选中 `order-service-quotation-print-fail`

**日期**: 2026-09-22

**需求**: 「将 `order-service-quotation-print-fail` 流程作为手动创建 ticket 的默认选中流程」。

---

## 改了什么

`useTickets.js` 新增常量 `DEFAULT_TICKET_WORKFLOW = 'order-service-quotation-print-fail'`，
并在 `loadWorkflows()` 拉完列表后**预选**它（列表按 `created_at DESC`，但这里**按名字找**）。

合成一条：

```js
if (!draft.value.workflowId) {
  const hit = workflows.value.find((w) => w.name === DEFAULT_TICKET_WORKFLOW)
  if (hit) draft.value.workflowId = hit.id
}
```

## 三个刻意的选择

### 1. 按**名字**找，不写死 id

id 每个租户库都不同（种子 `seed-*` vs 新建 12 位 hex）。写死 id 等于把某台机器的库状态
钉进代码 —— 换个租户就静默失效。名字是库与库之间可移植的键，与工单钉 workflow 时
**存名字**是同一个理由（见 v2.6.4 的后端改动）。

### 2. 预选放在 `loadWorkflows()`，不放在 `emptyDraft()`

`emptyDraft()` 在 composable 初始化时就跑了，**那一刻列表还没加载**，拿不到 id。
放在拉完列表之后既拿得到 id，又保证**每次开模态都重选一次**，不会因上一次的编辑残留而漂。

### 3. 找不到就**保持空**（= 不指定），不退回别的

该流程被删/改名的租户上：既不该因此建不出单（不钉是合法的），
**也不该退而选一条别的** —— 那是在替人做决定，而选错流程的后果是整条 run 跑错图。

## ⚠️ 「默认选中」≠「兜底」，两个东西别混

- **默认选中**（本次）：表单替你**预选**一个好用的值，人随时能改成「不指定」。
- **兜底**（后端 `_workflow_for_ticket` 的第三档）：未钉 workflow 的工单发起诊断时
  取 `saved[0]` = 库里**最新**一条，**随推新流程而变**。

所以空选项上那句文案说的是**兜底**会跑哪条（现在是 `problem-diagnose-fix`），
与新加的默认选中**不是一回事** —— 截图里两者同时可见、指向不同的流程。
