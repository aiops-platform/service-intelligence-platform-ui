# v2.6.9 — 工单列表的「新建 / 进行中 / 已暂停」补上徽标样式

**日期**: 2026-09-22

**问题**: 「ticket inbox 的列表中，新建和已暂停跟其它状态样式不一样，统一下」。

---

## 症状

Ticket Inbox 的 STATUS 列里，同一列有的带底色、有的是纯黑文本：

| 显示 | 类名 | 改前 |
|---|---|---|
| 已解决 | `status-resolved` | 绿底 |
| 失败 / 审批超时 / 审批不通过 | `status-failed` / `status-rejected` | 红底 |
| 缺少必要信息 | `status-needs_info` | 琥珀底 |
| **新建** | `status-new` | **纯黑文本** |
| **已暂停** | `status-paused` | **纯黑文本** |

## 根因：和 severity 那次是**同一族**——类名裸拼 + 规则缺失

`TicketsView.vue` 的类名是 `'status-' + ticketDisplayStatus(t)`，而 `css/styles.css` 里
**没有** `status-new` / `status-running` / `status-paused` 三条规则。

**关键在于 `.alert-tag` 基类里既没有 `background` 也没有 `color`** —— 所以没命中的值
不是"被设计成中性"，而是**一点样式都没有**，呈现为继承色的普通文本。
（同一族的前一次见 `v2.6.6`：severity 的 `medium`/`low`/未知档。）

**实际是三个不是两个**：截图里只露了 `新建` 与 `已暂停`，而 `进行中`（`status-running`）
同样缺规则 —— 只是当时库里恰好 0 条 running 的工单，看不见。

## 改动：`css/styles.css` 补三条（只增不改）

```css
.alert-tag.status-new     { background: #f3f4f6; color: #6b7280; }   /* 灰：未开始/中性 */
.alert-tag.status-running { background: #eff6ff; color: #2563eb; }   /* 蓝：进行中，与 status-in_progress 同义同色 */
.alert-tag.status-paused  { background: #fffbeb; color: #d97706; }   /* 琥珀：停住了、等人恢复 */
```

配色不是新发明，是沿用本文件**既有的语义映射**：蓝=进行中、灰=中性/未活跃、
琥珀=等人（`acknowledged` / `needs_info` 用的就是它）。

⚠️ **双世界共享**：legacy `js/app.js` 也拼 `'status-' + st`，那边若有这三个值的行会一并变色。
本机 `sip-aiops:8080` 未运行、枚举不了实际取值，**未验证** —— 与 severity 那次同一个未验证项。

## 验证（CDP 对真实页面；本仓无前端测试框架）

改后逐条量 STATUS 列的签名（文案 \| 类名 \| 计算背景），**七种状态全部非透明**：

```
已解决(×7)     | status-resolved  | rgb(236, 253, 245)   绿
失败(×5)       | status-failed    | rgb(254, 242, 242)   红
已暂停(×1)     | status-paused    | rgb(255, 251, 235)   琥珀   ← 改前透明
新建(×2)       | status-new       | rgb(243, 244, 246)   灰     ← 改前透明
审批超时(×10)  | status-rejected  | rgb(254, 242, 242)   红
缺少必要信息(×6)| status-needs_info| rgb(255, 251, 235)  琥珀
审批不通过(×2) | status-rejected  | rgb(254, 242, 242)   红
```

**`进行中` 当前库里没有数据**，用**只改浏览器**的方式注入了一条 `running` 工单
（拦 `fetch` 给 `/tickets` 塞一行，后端零改动）：`status-running` → `rgb(239, 246, 255)` 蓝。

### 证明「新规则确实是起作用的那一条」

只量出"现在不透明"是不够的 —— 那可能来自别处的样式。所以**在页面上把这三条规则关掉**
（同特异度、后写的胜出）再量一次：

| 状态 | 有规则 | **关掉这三条之后** |
|---|---|---|
| 新建 | `rgb(243, 244, 246)` | **`rgba(0, 0, 0, 0)` 全透明** |
| 进行中 | `rgb(239, 246, 255)` | **`rgba(0, 0, 0, 0)`** |
| 已暂停 | `rgb(255, 251, 235)` | **`rgba(0, 0, 0, 0)`** |

关掉即变透明 —— 既证明这三条是承重的，也**复现了改前的样子**（与截图里那两格的黑字一致）。

`npm run build` 通过。
