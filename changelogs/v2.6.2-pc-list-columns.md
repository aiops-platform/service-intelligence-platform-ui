## 改动明细

### 1. `src/legacy/legacy-panels.html:1052` — 表头：Service 后插 Ticket，删 Occurrences 与 Domain

**原因**: 需求即此。Diagnosis Center（slug 仍是 `problems`）是**未迁移的 legacy 面板**，
表头住在这个文件里（`index.html` 里没有这段标记，它只有 12 行）。

```html
<!-- before -->
<th class="col-problem">Problem</th> <th>Service</th> <th>Domain</th>
<th>Severity</th> <th>State</th> <th>Occurrences</th> <th>First Seen</th> <th>Actions</th>

<!-- after -->
<th class="col-problem">Problem</th> <th>Service</th> <th>Ticket</th>
<th>Severity</th> <th>State</th> <th>First Seen</th> <th>Actions</th>
```

### 2. `js/app.js:4327` — 新增 `problemTicketNumber(rec)`

**原因**: 单号要从问题记录里**推**出来，而记录里有**两个**可能写着它的地方，判据必须与后端的
`storage/records.py::_holds_ticket` 对齐：

```js
function problemTicketNumber(p) {
    var ev = (p && p.evidence) || [];
    for (var i = ev.length - 1; i >= 0; i--) {         // 真源：evidence 里的升级裁定
        var e = ev[i];
        if (e && e.type === 'diagnose_decision' && e.decision === 'escalate' && e.ticket_number) {
            return String(e.ticket_number);
        }
    }
    var reason = String((p && p.resolve_reason) || '');  // 兜底：给人看的副本
    if (reason.indexOf('escalated:') === 0) return reason.slice('escalated:'.length).trim();
    return '';
}
```

- **evidence 优先**：升级那一步写的 `{type:"diagnose_decision", decision:"escalate", ticket_number}`
  是**结构化真源**（后端 `records.py` 的注释就是这么定的）。
- **`resolve_reason` 只作兜底**：它是 `mark_escalated` 顺手写下的 `escalated:<号>`，
  只给「Detail 弹窗不展开 evidence 就能看到号」用；**单号为空时它退化成裸的 `"escalated"`**，
  拿它当唯一判据会静默漏掉一批（早期记录还可能根本没有 evidence 条目）。两处都看才不漏。
- 取**最后一条**升级裁定：一条记录理论上只会升级一次（`escalated` 是终态），但 evidence 是追加的，
  倒序取语义更稳。
- **没有单号就返回空串**，由调用方渲染成 `-`（需求点名的空值写法）。

### 3. `js/app.js:4364` — 行模板：Service 后插 Ticket 格，删 Occurrences 与 Domain 格

**原因**: 与表头**成对**。少删/多删一个 `<td>` 会让整行**错位**，而且不报错——这是本表增删列
最容易踩的一处。

```js
// before
'<td>' + escapeHtml(p.service || '-') + '</td>' +
'<td>' + escapeHtml(p.domain || '-') + '</td>' +
'<td><span class="alert-tag severity-…' +
'<td><span class="alert-tag status-…' +
'<td>' + (p.occurrence_count || 1) + '</td>' +        // ← 删（Occurrences 列）
'<td class="col-time">' + formatTime(...) + '</td>' +

// after
'<td>' + escapeHtml(p.service || '-') + '</td>' +
'<td>' + (ticket ? escapeHtml(ticket) : '-') + '</td>' +   // ← 新（Ticket 列）
'<td><span class="alert-tag severity-…' +
'<td><span class="alert-tag status-…' +
'<td class="col-time">' + formatTime(...) + '</td>' +
```

**样式选择**：纯文本、不加 class、不上色，空值 `-`。与 Ticket Inbox（`TicketsView.vue` 的
`Number` 列 `<td class="col-title">{{ t.number || t.id }}</td>`）和本表的 Service 格一致；
单号是数据，走 `escapeHtml`。

### 4. `js/app.js:4351`、`js/app.js:4380` — 两处占位行 `colspan` 8 → 7

**原因**: 列少了一列，占位行（筛选无结果的空态、以及"凑满一页"的补白行）必须跟着改，
否则那行比表头宽一格。**这两处是 `#pcTableContainer` 专属的**——本文件里另有
`colspan="8"`（2040、3741 行）属于别的表，未动。

## 踩坑记录

1. **单号有两个来源，只认一个会静默出 `-`**。`evidence`（真源）与 `resolve_reason`（副本）会在
   「单号为空」「记录早于该字段」两种情况下各漏一批，而失败长相是**一个安静的 `-`**，
   不报错、不留痕。判据直接照抄后端 `_holds_ticket` 的「两处都看」。

2. **增删列必须表头与行模板成对改，且 `colspan` 要跟着列数走**。本次先撤 Occurrences（8→8，
   因同时加了 Ticket，colspan 不用动）、再撤 Domain（8→7，两处 colspan 必须改）。
   `<td>` 的增删是**位置敏感**的：漏一处就是整行错位，页面照常渲染、控制台照常干净。
   验证办法是数 DOM 里每行的 `<td>` 个数（不是看截图"差不多对"）。

3. **Detail 弹窗的 Occurrences 与 Domain 有意保留**。本次只按要求撤列表列；弹窗头部的
   `Occurrences: N` 与 Meta 表里的 `Domain` 行（`buildDetailHtml`）仍在，两个字段也照旧由后端返回。

4. **列表排序那点事单独一个 changelog**：`changelogs/v2.6.3-pc-table-sort-fix.md`
   （点表头原本会抛异常、排序整体失效；改列时顺带修的，两件事分开记）。
