# v2.2.26 — 点击节点：入边也动起来，且与出边**不同色**

**日期**: 2026-09-21

**需求/背景**: 「在流程节点的展示上，点击某个节点，将进入这个节点的所有线条也动态展示，
跟出的线条用不同的颜色。」

原来只高亮**出边**（蓝），入边不动，看不出"这个节点的输入是从哪来的"。

---

## 改动明细

### 1. `src/components/graph/useGraphCanvas.js`

**新增入向色与类名**：

```js
const FLOW_IN_COLOR = '#f59e0b'      // --accent-orange
const FLOW_IN_CLS = 'bs-edge-flow-in'
```

**新增箭头 marker** `#${markerId}In`（琥珀）。只有节点的**入主干**带箭头，
所以只有它用得上。

**抽出 `paintFlow(paths, cls, markerSuffix)`**：原来"加类 + 换箭头"这段是内联写的，
现在出入两向共用。箭头必须一起换 —— 只改线色不改箭头会得到"蓝色的线 + 灰色的箭头"。

**`highlightFlow(nid)` 扩成双向**，入向是出向的**镜像三段**：

| 段 | 出（蓝） | 入（琥珀） |
|---|---|---|
| 分支 | `data-from = nid` | `data-to = nid` |
| 自己的主干 | `data-out = nid` | `data-in = nid` |
| 对端主干 | 各目标 `data-in` | 各来源 `data-out` |

第三段两边都不能少：分支只画到"节点上方/下方"，
最后一截竖线是对端的入主干（或来源的出主干），漏了流动就断在半路。

**`clearFlow()` 同时清两种类**，并按 `data-flow-marker` 还原箭头。

### 2. `css/styles.css` — `.bs-edge-flow-in`（琥珀）

与 `.bs-edge-flow` 共用同一套 `stroke-dasharray: 6 6` 与 `bsEdgeFlow` keyframes ——
**本仓的边一律自上而下**，所以"虚线向下跑"对入向而言就是"流进这个节点"，
不需要额外的反向动画。`prefers-reduced-motion` 那条也一并覆盖新的类。

---

## 为什么必须换色而不是同色

中间节点同时有进有出（`rca` 有 **6 条入、2 条出**）。同色的话两个方向糊成一片，
分不出"哪条是喂给我的、哪条是我喂出去的" —— 而那恰好是点击节点最想看清的一件事。
