# v2.2.4 — 修复诊断视图「耗时」显示 NaN、「更新」整块消失

**日期**: 2026-09-18

**问题/背景**: Problem Center 诊断弹窗的状态头里，「耗时」渲染成 `耗时 NaNm NaNs`，
紧跟其后的「更新 …」整块不见。两个症状同源：**时间戳类型对不上**。

「分析new」改走 agentflow 工作流（v2.2.2）后，诊断快照的时间字段由 **epoch 秒（数字）**
变成了 **ISO 字符串**：

| 后端路径 | `created_at` 形状 | 出处 |
|---|---|---|
| spike（旧） | `float` epoch 秒 | `aiops-agent-orchestration-spike/aidiag/diag/session.py:58` `created_at: float = Field(default_factory=time.time)` |
| agentflow（新） | ISO 字符串 | `aiops-apm-anomaly-detector/src/aiops_apm/diagnosis/from_agentflow.py:472` `_iso(run.get("created_at"))` |

而 UI 这两个 helper 是照 spike 的数字形状写的，没跟着改：

- `dgxElapsed(a, b)` 直接做 `b - a` → 字符串相减得 `NaN` → 返回真值串 `"NaNm NaNs"`，
  外层的 `(dgxElapsed(...) ? … : '')` 判真通过，于是**渲染出垃圾而不是不渲染**；
- `dgxClock(ts)` 做 `new Date(ts * 1000)` → `NaN` → 返回 `''`，外层判假 → 「更新」被**静默丢弃**。

`viewmodel.py:16` 的契约定的是 `"created_at": ISO8601 | None` —— 即**后端没错，是 UI 的
两个 helper 停留在旧形状上**。本版让它们两种都吃，不再依赖上游用哪种形状。

---

## 改动明细

### 1. `js/app.js` — 新增 `dgxTsMs()`，`dgxElapsed` 改用它 (line 4363, 4377)

**原因**: 归一化时间戳，消除对上游形状的隐含假设。

```js
// 新增：时间戳归一 → epoch 毫秒
function dgxTsMs(v) {
    if (v === null || v === undefined || v === '') return NaN;
    if (typeof v === 'number' || /^\d+(\.\d+)?$/.test(String(v).trim())) {
        var n = Number(v);
        // epoch 秒 vs 毫秒：1e11 秒 ≈ 公元 5138 年，真实时间戳到不了，可安全区分
        return n < 1e11 ? Math.round(n * 1000) : Math.round(n);
    }
    // 后端给的是无时区 UTC 串（实测 '2026-09-18 06:58:06' 对应本地 14:58）。
    // 空格分隔 Safari 不认 → 换 T；无时区后缀则补 Z，与 formatTime 口径一致。
    var s = String(v).trim().replace(' ', 'T');
    if (!/([Zz]|[+-]\d{2}:?\d{2})$/.test(s)) s += 'Z';
    var t = Date.parse(s);
    return isNaN(t) ? NaN : t;
}

// dgxElapsed
-   if (!a || !b || b < a) return '';
-   var s = Math.round(b - a);
+   var ta = dgxTsMs(a), tb = dgxTsMs(b);
+   if (isNaN(ta) || isNaN(tb) || tb < ta) return '';
+   var s = Math.round((tb - ta) / 1000);
```

### 2. `js/app.js` — `dgxClock` 改用它，并对齐 `formatTime` 的时区口径 (line 4351)

**原因**: 原实现 `ts * 1000` 只认 epoch 秒，且用本地时区显示。

```js
-   var d = new Date(ts * 1000);
-   if (isNaN(d.getTime())) return '';
-   return d.toLocaleTimeString('zh-CN', { hour12: false });
+   var t = dgxTsMs(ts);
+   if (isNaN(t)) return '';
+   // 与 formatTime 同口径：按 UTC 解析、以 Asia/Shanghai 显示
+   return new Date(t).toLocaleTimeString('zh-CN', { hour12: false, timeZone: 'Asia/Shanghai' });
```

## 踩坑记录

**这类 bug 不会报错，只会「显示垃圾」或「静默少一块」**，是本次两个症状形态不同的原因：
`dgxElapsed` 返回了 `"NaNm NaNs"`（**真值** → 渲染垃圾），`dgxClock` 返回 `''`（**假值**
→ 外层 `? :` 直接不渲染）。同一个根因，两种表现。

排查手法：把渲染函数**原样抽出来**喂真实快照在 node 里跑（不复制副本），一眼就能看到
返回的是 `"NaNm NaNs"` 而不是空：

```js
dgxElapsed("2026-09-18 06:58:06", "2026-09-18 06:59:19")  // 修前 → "NaNm NaNs"
```

**时区口径**：后端给的是无时区的 UTC 串（实测 `06:58:06` 对应本地 14:58）。按 UTC 解析、
以 Asia/Shanghai 显示，与既有的 `formatTime()` 一致；不补 `Z` 会被当本地时间，差 8 小时。

**未动的地方**：`from_agentflow.py` 的时间戳输出（契约就是 ISO8601，不该改），
以及 `viewmodel.py` 的 `created_at: ISO8601 | None` 契约声明。
