# v2.2.18 — Service Ops 侧边栏重组：一级 Observability 改名 APM，二级 APM 摘除，四页收进 Smart Inspection

**日期**: 2026-09-21

**需求/背景**: Service Ops 域侧边栏的结构调整，四条要求：

1. 一级分组 `Observability` 改名 `APM`；
2. `Smart Inspection` 位置不动；
3. `Problem Center` / `Monitor Targets` / `Domain Rules` 收到 `Smart Inspection` 下一级；
4. 二级分组 `APM` 去掉。

**改动前**：

```
▾ Ticket Workspace
    Ticket Inbox
▾ Observability            ← 一级
    Smart Inspection       ← 叶子（真实页面 /smart-inspection）
    Problem Center         ← 叶子
  ▾ APM                    ← 二级分组（本次摘除）
      Monitor Targets
      Domain Rules
```

**改动后**：

```
▾ Ticket Workspace
    Ticket Inbox
▾ APM                      ← 由 Observability 改名（键同步改）
  ▾ Smart Inspection       ← 可导航的分组头：点标签进页面，点箭头展开
      Problem Center
      Monitor Targets
      Domain Rules
```

`Smart Inspection` 是**真实页面**（`/smart-inspection`，Services 健康表 + 两个问题数徽标，
徽标下钻 Problem Center），不是纯分组标题。所以它不能简单降级成 `groups` 里的一个分组
——那样它会从路由表里消失（见下面「踩坑」第 2 条）。本次给它加了「**可导航的分组头**」
这一新语义：`slug` 让它自身仍是一条路由，`items` 是它下一级的三个页面。

## 改动明细

### 1. `src/router/nav.js` — 侧边栏数据结构重组 (165-190)

**原因**: 导航结构的唯一真源。

```js
// before
{
  key: 'observability',
  label: 'Observability',
  items: [
    { slug: 'smart-inspection', label: 'Smart Inspection' },
    { slug: 'problems', label: 'Problem Center' },
  ],
  groups: [
    { key: 'apm', label: 'APM', items: [ monitor-targets, domain-config ] },
  ],
}

// after
{
  key: 'apm',            // ← 由 observability 改名
  label: 'APM',
  groups: [
    {
      key: 'smart-inspection',
      label: 'Smart Inspection',
      slug: 'smart-inspection',   // ← 新增：分组头同时是叶子
      items: [ problems, monitor-targets, domain-config ],
    },
  ],
}
```

**键名为什么跟着改**：分组键就是 DOM id（` :id="group.key"`）与 `data-toggle`。
标签叫 APM 而键还叫 `observability`，下一个读代码的人必然要停下来确认这两者是不是一回事。
二级 APM 摘掉后 `apm` 这个键正好空出来，就用它。消费方只有 `App.vue` 的默认展开集合，已同步。

**原 `Observability` 分组的整段历史注释保留**（Metrics Analysis / Log Analysis 于 2026-09-18
被摘掉的那段），只把「要恢复就把这两行放回来」改成「在本分组上**新增** items」——
本分组现在只剩子分组、已经没有 `items` 键了，照旧说法去塞会塞进一个不存在的数组。

### 2. `src/router/nav.js` — `flattenItems()` 支持可导航分组头 + `items` 可选 (318-325)

```js
const walkGroup = (g) => {
  if (g.slug) out.push({ slug: g.slug, label: g.label })   // ← 新增
  for (const it of g.items || []) if (it.slug) out.push(it) // ← 原来没有 `|| []`
  for (const sub of g.groups || []) walkGroup(sub)
}
```

**两处都必需**，各自对应一个会静默出错的场景：

- `if (g.slug)`：`flattenItems()` 是**路由表的唯一来源**。分组头不产出，`/smart-inspection`
  这条路由就不生成 —— 侧边栏上它看着好好的，点下去却落进 catch-all 回到 `/service-ops`。
  （`navKeyOf()` 也走本函数，所以这一条同时决定「点进该页时顶栏高亮哪个域」。）
- `|| []`：新的 APM 分组只有子分组、没有 `items`。原写法 `for (const it of g.items)`
  会抛 `TypeError: g.items is not iterable` —— **整个路由表构造失败**。
  在此之前所有分组都带 `items`，所以这个隐患一直没暴露。

### 3. `src/components/shell/SidebarGroup.vue` — 可导航的分组头 (29-54)

```js
const isPage = computed(() => !!props.group.slug)
const isActive = computed(() => isPage.value && props.group.slug === props.activeSlug)

function toggle() { expandedGroups.toggle(props.group.key) }
function onHeaderClick() { isPage.value ? navigate(props.group.slug) : toggle() }
```

```html
<div class="sidebar-item has-children" :class="{ expanded: isExpanded, active: isActive }"
     :data-toggle="group.key" @click.stop="onHeaderClick">
  <span class="sidebar-arrow" @click.stop="toggle"></span>
  <span class="sidebar-label">{{ group.label }}</span>
</div>
```

点击分区是必然的，不是口味问题：整行都导航就没法收起子项，整行都只展开就丢了页面。
**箭头上的 `@click.stop` 必需** —— 否则那一下会继续冒泡到整行处理器，变成「又展开又跳页」。
没有 `slug` 的分组保持改造前行为：整行点击都是展开/收起。

### 4. `src/App.vue` — 默认展开集合同步 (120)

```js
// before
new Set(['knowledge-studio', 'ticket-workspace', 'ticket-workspace-svc', 'observability', 'apm', 'agent-fleet'])
// after
new Set(['knowledge-studio', 'ticket-workspace-svc', 'apm', 'smart-inspection', 'agent-fleet'])
```

`smart-inspection` 必须默认展开，否则改版的全部意义（让那三个页面看得见）当场作废。
顺带清掉 `'ticket-workspace'` —— 该分组的键一直是 `ticket-workspace-svc`，
这条从写下来就没生效过。

| 同上 | 887 | Service Ops › APM › **Metrics Analysis** |

两件事：`Observability` → `APM`（六处统一），以及**收进 Smart Inspection 下的那三个页面
补上中间那级**，让面包屑与新导航一致。

**为什么另外三处不补**（初版六处只改名、不补级，补级是复核时追加的）：

- **Smart Inspection 自己**（785）就是当前页，补了会变成 `APM › Smart Inspection › Smart Inspection`；
- **Metrics Analysis**（887）与 **Log Analysis** 是 2026-09-18 从导航摘掉的两个叶子，
  **本来就不在 Smart Inspection 之下** —— 按本次的新导航它们仍直接挂在 APM 上，

**Monitor Targets / Domain Rules 中间那级 APM 同时消失**：改版前它们是
`Observability › APM › Monitor Targets`（二级分组 APM 是它们的父级）；一级改名成 APM 之后
那一级就重复了，留着会是 `APM › APM › Monitor Targets`。现在替换成 Smart Inspection。

**补的这级是纯文本，不是链接** —— 与同一条面包屑里其它中间级一致（只有当前页是 `<strong>`，
其余都是裸文本）。如果以后要让中间级可点，六个面板要一起改，别只改一处。

`legacy-panels.html` **五处都是行内改字、不增删行**（`git diff --numstat` 为 `5 5`），
所以行号全部不变 —— 这一点是有意维持的：`nav.js` 的注释里引用了
`legacy-panels.html:885`（Metrics Analysis 面板位置），一旦行号漂移那条引用就失效了。

## 踩坑记录

**第 1 版漏了 `|| []`**：把 `items` 从 APM 分组上拿掉之后，`flattenItems()` 里
`for (const it of g.items)` 直接抛 `TypeError`。这个写法在改动前是**对的**
（所有分组都带 `items`），所以是个纯粹的「新数据形态踩到旧假设」。
已在 `nav.js` 文件头注释里写明 `items` / `groups` **都是可选的**，两处消费方（`SidebarGroup.vue`
的两处 `v-for`、`flattenItems`）都按可选处理。

**「位置不动」不能只靠分组名**：`Smart Inspection` 的缩进由 CSS 层数决定，
不是由代码指定。核对过 `styles.css` 的规则后确认视觉深度确实没变：

| 节点 | 选择器 | 缩进 | 改前 | 改后 |
|------|--------|------|------|------|
| 一级分组（APM） | `.sidebar-item`（基础） | 16px | 16px（Observability） | 16px ✓ |
| Smart Inspection | `.sidebar-children .sidebar-item` | 38px | 38px（叶子） | 38px ✓ |
| 三个子项 | `.sidebar-children .sidebar-children .sidebar-item` | 56px | 56px（原二级 APM 的两个叶子） | 56px ✓ |

即：**层级多了一层，但最深的叶子仍在 56px** —— 因为摘掉的二级 APM 恰好腾出了这一层。
样式表一字未改。

## 未动的东西

- `css/styles.css` **一字未改**（缩进复用既有三层规则，见上表）。
- `js/app.js` 与 `PANEL_ID` 未动：`smart-inspection` / `problems` / `monitor-targets` /
  `domain-config` 四条映射原样，legacy 面板与 `initSmartInspection` / `initProblems` 都不受影响。
- `js/app.js` 的 `initSidebar` / `initNavigation` 里那份侧边栏实现**没有同步**
  （`initSidebar` 里 `querySelectorAll('.has-children')` 的整行展开语义、
  `initNavigation` 里按 `textContent` 比域名的分支）—— 那是独立的一份实现，
  只服务单独打开旧 `index.html` 的场景，与 Vue 外壳不共用 DOM。两边不会自动同步，
  但本次改的是 Vue 侧，那边保持原样即可。
