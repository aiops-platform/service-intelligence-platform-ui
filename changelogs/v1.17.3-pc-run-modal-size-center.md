# v1.17.3 — fix: View analysis 一级弹框下移至菜单栏之下收小；Flow Diagram 画布加舞台层居中，DAG 完整展示不偏右/裁切

**日期**: 2026-09-07

**问题/背景**: 三个问题叠加：
1. 一级弹框若做到贴顶/近满屏，顶部会被顶部菜单栏遮挡，观感过大；
2. Flow Diagram 弹框打开后，DAG **偏到画布右侧、未居中，且展示不全/被裁**。

问题 2 根因（非尺寸）：`createGraphCanvas`（`js/app.js`）把 `translate/scale` transform 施加在 **被撑满整宽的 `.zoom` 容器**上，
而 pan 按「内容尺寸居中」计算 → 当图比画布窄/高时，是把**整块容器**推走而不是把内容居中，导致内容整体右移并超出容器被 `overflow:hidden` 裁掉。
Bug Solve / Workflow Studio 共用同一工厂，图窄于画布时同样潜在偏移，只是此前多为宽图未暴露。

**方案**:
- 一级弹框改为**置于菜单栏之下、大小适中**（CSS）。
- 画布**新增内层「舞台层」**：把 svg 包进 `.bs-stage`，`translate/scale` 只施加在舞台上，`.zoom` 容器保持固定作视口/裁剪面 →
  内容严格按视口居中、整体可见。工厂自动给三个画布（ws-zoom / bs-zoom / pcRunZoom）套舞台；异常 DOM（svg 非 zoom 直接子级）回退旧逻辑，零回归面。

---

## 改动明细

### `css/styles.css`
- 一级 `#pcRunOverlay`：`.ap-modal` 高 `calc(100vh - 24px)`（贴顶）→ `calc(100vh - 120px)`；
  遮罩 `flex-start + padding:12px` → `center + padding:60px 28px` → 整框位于 52px 菜单栏之下、不被遮挡、不过大。
- 二级 `#pcRunGraphOverlay`：`.ap-modal` `max-width:min(1180px, calc(100vw - 96px))`（>960 更宽）、`height:calc(100vh - 200px)`、
  `max-height:none`（去 680 硬顶）→ 仍明显小于一级、给整图更大可视区。
- 新增 `.bs-stage { width: max-content; transform-origin: 0 0; }`：舞台层收缩贴合 SVG 内容宽，作为精确的变换目标。

### `js/app.js`（`createGraphCanvas`，三处画布共用）
- 初始化时若 `svg` 是 `.zoom` 的直接子元素，自动插入舞台层并把 svg 移入（`stageEl.className='bs-stage'`）。
- `applyTransform()`：变换目标改为舞台层；舞台模式下清掉容器上残留 transform，避免叠加；无舞台时回退旧逻辑。
- `fitGraph`/`zoomBy`/滚轮/拖拽测量不变（仍以 `.zoom` 视口为基准），居中与缩放自然归位。
