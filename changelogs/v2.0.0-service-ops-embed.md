# v2.0.0 — Service Ops 域改内嵌部署站页面（第三次复用内嵌流水线）

**日期**: 2026-09-16

**需求背景**: 本仓自研的 Service Ops 概览页（legacy `page-service-ops` 面板）**点 Applications
表格的行没有反应**，而线上部署站 `https://sip-platform.web.app/service-ops/` 同一页点行会
弹出右侧详情面板（340px INSPECTOR，带 INSPECTOR / ACTIVITY / EVIDENCE 三个页签与
CROSS-SOURCE INSIGHTS 卡片）。要求把线上这版 1:1 搬到前端，**挂在 Service Ops 域**。

**「本地实现」的含义**：不是挂一个指向 `sip-platform.web.app` 的 iframe。
`--refresh` 一次性把线上静态产物**拷贝进本仓库**，之后完全离线 ——
iframe 的 `src` 是同源相对路径 `/service-ops/`，由本仓自己的服务器伺服。
佐证：现有 `public/business-ops/index.html` 里指向线上的绝对 URL **零命中**。

---

## 结论先说

照搬已经跑通过两次的流水线（Constellation、Business Ops），本次是第三次。
**只缺一个 chunk**（`0t1fyt7wcotiz.js`，53KB），其余 10 个 chunk、CSS、3 个字体仓库里全都有。

但 Service Ops 和那两个域有**两处本质不同**，都不是照抄能解决的：

1. **路径与 Vue 路由同名**。Business Ops 的 Vue 路由叫 `/biz-ops`、内嵌页在 `/business-ops/`，
   两边不同名所以从不打架。Service Ops 两边都叫 `/service-ops` —— 目录索引插件剥掉尾斜杠后
   会把 `/service-ops` 也拦下来，**硬刷新会返回裸的内嵌页**（没有导航，Vue 应用不启动）。
2. **这个域有侧边栏**。那两个域都是 `sidebar: null`，而 `.cs-embed` 当时是
   `position: fixed; left: 0` 相对**视口**定位 —— 会盖住侧边栏和那个 12px 折叠把手。
   而侧边栏**默认收起**，把手是打开该域 9 条导航的唯一入口，盖住等于导航全废。

## 改动明细

### 1. `tools/make-offline-page.py` — 注册第三页 + 三处加固

**(a) `PAGES` 加 `service-ops`（line 148-155）**。`--page` 用的是 `choices=sorted(PAGES)`，
加了 key 就自动支持，不用动 argparse。

**(b) `refresh_vendor` 的抓取正则补上 `.css`（line 215）**

```python
- r"/_next/static/chunks/([A-Za-z0-9._~\-]+\.js)"
+ r"/_next/static/chunks/([A-Za-z0-9._~\-]+\.(?:js|css))"
```

本仓已有**按路由拆分的样式表**（`0yiy_grop9liv.css` 是 constellation 独有的），
而正则原来只抓 `.js`。今天 `/service-ops/` 用的 CSS 恰好是共用的所以能跑，
但下一个带自己样式表的页面会**静默漏掉它**：构建正常、不报错，打开才发现内嵌页没样式。

**(c) 「已知 chunk」集合补上其它页面的 vendor 目录（line 200-206）**

原实现只把 Chrome 保存的分享池当作已知，于是被两个页面共用的 chunk 会被下载两遍。
实测 `100pim9o6kpoy.js`（161KB）就这样在 `vendor/business-ops/` 与 `vendor/service-ops/`
各存了一份 —— 输出目录没问题（并集拷贝按文件名去重），但仓库白白多背 161KB。

**(d) `build()` 末尾加产出校验（line 357-359）+ `main()` 里非零退出（line 462-471）**

每次构建都先 `rmtree` 掉 `<out>/_next` 再从 vendor 重铺，所以 vendor 少一个文件的表现是
**内嵌页静默 404、白屏、零报错**，看着像后端问题。现在会扫产出 HTML 里所有 `/_next/…`
引用逐个断言存在，缺失就列出并 `return 1`。与 `load_vendor` 自己的原则一致
（「缺东西就报清楚缺什么，而不是默默去联网」）。

### 2. 产物 — `public/service-ops/index.html` + `tools/vendor/service-ops/`

```bash
python3 tools/make-offline-page.py --page service-ops --refresh   # 唯一一次联网
python3 tools/make-offline-page.py --page service-ops             # 之后纯离线
```

产出 `public/service-ops/index.html`（33,547 字节）、
`tools/vendor/service-ops/server.html`（9,746 字节）、`tools/vendor/service-ops/chunks/0t1fyt7wcotiz.js`
（53,322 字节）。**都已入库** —— 与既有两个页面同理，这是「克隆下来 `npm run dev` 就能用」的关键。

### 3. `src/views/service-ops/ServiceOpsView.vue` — 新增

薄壳一行 `<NextEmbed src="/service-ops/" … />`。文件头记了路径约束与同名冲突的原委。

### 4. `src/router/index.js` — 让 `/service-ops` 渲染真实组件 (line 35-58, 71-96)

`/service-ops` 由 `STANDALONE_PAGES` 产出，给条目加可选 `component`，`routeFor()` 认它：

```js
- component: VIEW_COMPONENTS[item.slug] || LegacyPanelHost,
- legacy: !MIGRATED.has(item.slug),
+ component: item.component || VIEW_COMPONENTS[item.slug] || LegacyPanelHost,
+ legacy: item.component ? false : !MIGRATED.has(item.slug),
```

**为什么不用「加进 `MIGRATED` + `VIEW_COMPONENTS`」那条路**：`MIGRATED` 的语义是
「已迁 Vue 的侧边栏叶子」，而这里既没迁 Vue（是内嵌）、也不是侧边栏叶子。硬塞进去会破坏
`CLAUDE.md` 记的「两处必须同时改」不变式，也会误导后人以为 `page-service-ops` 可以删（它不能）。

`DOMAIN_COMPONENTS` **没动** —— 那条路只服务 `EMPTY_DOMAINS`，而 `service-ops` 有侧边栏。

### 5. `vite.config.js` — 插件只拦带尾斜杠的请求 (line 69, 75-77)

```js
- const EMBED_PAGES = ['/business-ops']
+ const EMBED_PAGES = ['/business-ops', '/service-ops']

- const path = (req.url || '/').split('?')[0].replace(/\/+$/, '') || '/'
+ const raw = (req.url || '/').split('?')[0]
+ if (!raw.endsWith('/')) return next()          // ← 关键
+ const path = raw.replace(/\/+$/, '') || '/'
```

`/service-ops/` → 内嵌页（iframe 打的就是它）；`/service-ops` → 落到 SPA 兜底，Vue 应用正常启动。

**生产端必须同步**（`README.md:59`，已加）：
```nginx
location = /service-ops { try_files /index.html =404; }
```
否则通用 `try_files $uri $uri/ /index.html` 会把 `/service-ops` 经 `$uri/` 解成目录索引，
同样吐内嵌页。README 里「不需要额外配置」的措辞已相应修改。

### 6. `css/styles.css` — `.cs-embed` 从 `fixed` 改回 `absolute` (line 7475-7483)

```css
- position: fixed;  top: 52px; right: 0; bottom: 40px; left: 0;
+ position: absolute; top: 0;   right: 0; bottom: 40px; left: 0;
```

**当年为什么是 `fixed`**：整条高度链是断的（`#app` 没有任何规则、`main` 只有 60px 高且
`overflow-y:auto`），绝对定位会被 main 裁掉，只露出顶部一小条。`fixed` 能跳出发明的高度链。

**为什么现在能收回来**：上次的 `#app` 修复（`changelogs/v2.0.0-vue-sidebar-collapse.md`）
已经补上那条规则，`main` 拿到了确定高度（实测断言过 `main.clientHeight === innerHeight - 52`），
绝对定位子元素不再溢出、不再被裁。

**为什么必须跟着 main 而不是视口**：`.sidebar`（220px）和 `.sidebar-grip`（12px）都是
**未定位**元素，而 `main` 是 `position:relative; z-index:1` —— main 的子树盖在它们之上。
跟着 main 之后，main 的左边缘天然在侧边栏右侧，iframe 自动让位，
**不需要把 220px 抄进样式表**（宽度真源仍只有 `.sidebar` 一处）。
没有侧边栏的域 main 左边缘就是 0，行为与改动前逐像素一致。
原地重写了那段注释块（line 7442-7474），因为它的标题「为什么是 position: fixed」已过期。

## 踩坑记录

| 坑 | 现象 | 根因 | 处置 |
|---|---|---|---|
| **同名冲突**（本次核心） | 把 `/service-ops` 加进 `EMBED_PAGES` 后，硬刷新/书签/外链拿到的是**裸内嵌页** —— 没有 AppHeader / footer / 侧边栏，Vue 应用根本不启动，用户卡在没有导航的页面 | 目录索引插件剥尾斜杠后匹配，`/service-ops` 与 `/service-ops/` 都被拦 | 插件只拦带尾斜杠的请求 + nginx 补一条精确匹配。**两处必须成对**，只改一处等于没改 |
| **`.cs-embed` 盖住侧边栏** | 展开侧边栏后 iframe 压在它上面，连 12px 折叠把手都点不到；而侧边栏默认收起，**把手是打开 9 条导航的唯一入口**，等于导航全废 | `.cs-embed` 当时是相对**视口**的 `fixed`，无视 `.app-body` 的 flex 布局；`main` 有层叠上下文，子树盖过未定位的侧边栏 | 改回相对 main 的 `absolute`。**这是上次修好 `#app` 高度链才解锁的** —— 当年被迫用 `fixed` 的前提已消失 |
| **`panelByRoute` 只剥一个尾斜杠** | 路径写成 `/service-ops/index.html` 时内层 h1 **静默**变成 "SIP"（不报错、不白屏） | 从 `0wuztp2.9oz~8.js` 取到真实实现：`e.endsWith("/") ? e.slice(0,-1) : e`，且该 chunk 里 `index.html` **零命中** | 产出必须叫 `service-ops/index.html`，iframe 必须打 `/service-ops/` |
| **共用 chunk 被下两遍** | `100pim9o6kpoy.js`（161KB）在 `vendor/business-ops/` 与 `vendor/service-ops/` 各存一份 | `refresh_vendor` 的「已知」集合只查 Chrome 分享池，没查其它页面的 vendor 目录 | 「已知」集合补上 `vendor/*/chunks/`；输出目录一直是对的（并集拷贝按名去重），只是仓库白背 161KB |
| **`--refresh` 不抓 CSS** | 若某页有独有样式表会静默 404、产出无样式页面 | 正则只匹配 `\.js` | 改成 `\.(?:js\|css)` |
| **构建缺资源无提示** | 内嵌页白屏、零报错，像后端问题 | `build()` 写完就返回，不校验引用 | 加产出校验 + 非零退出 |

> - 用 `table tbody tr` 找表格行 → 找不到。内层那「表格」其实是 **div 网格**，根本没有 `<table>`。
> - 在非 async 的箭头函数里用 `await` → `SyntaxError`；`(()=>{…})()` 必须写成 `(async()=>{…})()`。

### 已知代价 / 不在本次范围

- **`/domain-config` 与 `/monitor-targets` 两条侧边栏叶子没有路由**（**既有 bug，非本次引入**）。
  点它们会经 catch-all 跳回 `/service-ops`。根因：`nav.js` 的 `flattenItems()` 调用的是
  `walk(g.items)`，而 `apm` 这个嵌套分组挂在**分组对象** `observability` 的 `groups` 上、
  不是挂在某个 item 的 `groups` 上 —— `walk` 里的 `if (it.groups)` 永远碰不到它。
  而 `SidebarGroup.vue` 却正确递归渲染了 `group.groups`，两边不一致。
  **本次未修**（超出范围），已上报待定。
- **应用内同时存在两份 Service Ops 概览实现**：Service Ops 域是内嵌的新版，
  4 个空壳域（`/architecture`、`/finops`、`/security-ops`、`/value-pool`）仍是 legacy 旧版。
  这是既有设计（空壳域本就是占位），外观会不一致。
- **内层页的跨域导航链接被 build 中和成 `href="#…"`**，页内导航不会跳出 iframe。
  与既有两个内嵌页一致。
- **外层 footer 用的是 Constellation 的固定数字**（`AppFooter.vue` 写死 `SCOPE 282A · …`），
  内嵌的 Service Ops 页下方也显示它。**既有问题**（`/biz-ops` 同样），本次未动。
- **顶栏 SIP 图标与 `__SIP_NAVIGATE('page-service-ops')` 现在落到内嵌页**（前者 `AppHeader.vue`
  写死 `NAV[2]`，后者经 `PANEL_ID` 反查）。符合预期。
- `CLAUDE.md:36` 与 `package.json` 的「已迁移视图 = 2 个」是过期描述（实际 `MIGRATED` 有 4 个）。
  本次未顺手改，避免混杂。

## 怎么用

```bash
npm run dev                                    # 顶栏点 Service Ops

# 重建（默认不联网）
python3 tools/make-offline-page.py --page service-ops
# 部署站更新后（唯一联网操作）
python3 tools/make-offline-page.py --page service-ops --refresh
```

> ⚠️ 三个页面**共用 `public/_next/`**：每次构建先清空、再把**所有页面**的资源铺满，
> 所以重建哪一个都不会拆掉另一个。现在还会校验引用完整性。
