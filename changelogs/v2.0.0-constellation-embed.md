# v2.0.0 — Constellation 域接入星座图

**日期**: 2026-09-15

**需求背景**: 本仓的 **Constellation** 域一直是「空壳」—— 点进去落到 service-ops 概览、
只把标题改成域名，没有自己的页面。现在接上企业架构星座图，整个前端能在一处看全。

---

## 结论先说：内嵌，不用 Vue 重写

图上跑的是 **three.js 的 3D 力导向图**（951 节点 / 1504 边，布局由物理模拟现场算出来），
整个页面是**另一套 Next.js 应用**。用 Vue 重写它等于重写整个应用 + 重新实现布局。

**这条路我走过一遍，做出来不像，已废弃。** 记下来免得重走：

| 尝试 | 结果 |
|---|---|
| 用数据自带的 `position` 布点 | 十片放射状的「羽毛」——每个组合一个扇面 |
| 卫星节点绕父节点黄金角散开 | 「烟花」——每个组合一个辐条 |
| 自写力导向（FR 变体 + 网格近邻） | 量级失衡，又调了一轮，仍未收敛到原站观感 |

后来才想明白：**原站的构建器根本不把 `position` 拷进节点**，布局完全由
3d-force-graph 跑出来，所以呈有机的团簇。要像它，最省事的就是**用它本身**。

> 教训：先把「有没有现成的能跑」问清楚，再决定要不要重写。重写前先量一量目标有多复杂
> —— 951 节点、13 种节点类型、1000+ 连线，这个量级本来就该先怀疑"重写值不值"。

## 改动明细

### 1. `public/` — 新增（入库，6.5 MB）

星座图应用的产物，由 `tools/make-offline-page.py` 构建：

```
public/
├── constellation-app.html          ← 入口
└── _next/static/{chunks,media}/    ← 14 个 chunk + 3 个字体
```

**为什么放 `public/`**：内层的 chunk 路径 `/_next/…` 是 turbopack **硬编码的根绝对路径**
（`function N(e){ return \`${t}${…}\` }`，`t = "/_next/"`）。Vite 的 `public/` 正好**按根
伺服**，于是 dev 和 build 都对得上，**不需要任何 Vite 插件**。

**为什么这份要入库**：它是「克隆下来 `npm run dev` 就能用」的关键，不是可弃的中间产物。
（对比：`tools/constellation-export/data/` 是纯生成物，仍然 gitignore。）

### 2. `src/views/constellation/ConstellationView.vue` — 新增

iframe 包一层，`src="/constellation-app.html"`（同源相对路径，符合
「`src/` 下不出现 `http://localhost:*`」）。带加载遮罩。

### 3. `src/router/index.js` — 空壳域可挂真实组件

新增 `DOMAIN_COMPONENTS`，`emptyDomainRoutes` 按它选组件：

```js
const DOMAIN_COMPONENTS = {
  constellation: () => import('@/views/constellation/ConstellationView.vue'),
}

const emptyDomainRoutes = EMPTY_DOMAINS.map((d) => {
  const own = DOMAIN_COMPONENTS[d.key]
  return {
    path: `/${d.key}`, name: `domain-${d.key}`,
    component: own || LegacyPanelHost,
    meta: { label: d.label, domainKey: d.key,
            panelId: PANEL_ID[DEFAULT_SLUG], legacy: !own },   // ← 关键
  }
})
```

> **`meta.legacy` 必须跟组件一致。** 它为 `true` 时 `App.vue` 会继续显示 `LegacyPanels`，
> 同一位置出现两套内容。这跟 `nav.js` 里「MIGRATED 与 VIEW_COMPONENTS 两处必须同时改」
> 是同一个坑的不同入口。
>
> ⚠️ 那条「两处同时改」**不适用**于这里：它针对的是**侧边栏叶子**（经 `flattenItems()`
> 产路由）。空壳域不在任何侧边栏里，走的是 `emptyDomainRoutes` 这条独立分支，
> 只需在 `DOMAIN_COMPONENTS` 登记一次。

其余 4 个空壳域（architecture / finops / security-ops / value-pool）行为不变。

### 4. `css/styles.css` — 追加 77 行（**纯追加，0 删除**）

新增 `/* Constellation Embed */` 一节，4 个 class。

```css
.cs-embed {
    position: fixed;          /* ← 见坑 2 */
    top: 52px; right: 0; bottom: 40px; left: 0;
    z-index: 1;
    background: var(--bg-white);
}
```

**必须是 `position: fixed`** —— 整条高度链是断的（`#app` 没有规则），而中间那层
`main` 又有 `overflow-y: auto` 会把溢出裁掉。只有相对**视口**定位能同时跳开这两样。
详见面两个坑，那是本次返工最久的地方。

> 保留的那条 `estate-status-bar` 覆盖在内层底部（`position:absolute`，高 49px），
> 位于外层 footer 之上、不重叠（帧底 873 / 页脚顶 880）。

> 符合本仓约定：**组件不带 `<style>` 块，样式一律走全局样式表**。
> 核对了 `src/` 下原有 14 个组件，无一带 `<style>`；本次新增的这个也没有。

### 5. `tools/make-offline-page.py` — 输出改到 `public/`，新增剥壳

- 默认输出目录 `tools/constellation-offline/` → **`public/`**
- 产出文件名 `index.html` → **`constellation-app.html`**
- 新增 `STRIP_CSS` 注入（见坑 1）
- 新增 `--standalone`：保留内层顶栏/底栏（单独打开时用）

### 6. `tools/start-offline.sh`、`tools/启动 Constellation.command`、`tools/tenant_data.py`

路径跟着改到 `public/`。

### 7. 已删除

`tools/constellation-offline/` —— 产物搬到 `public/` 后不再需要。

## 踩坑记录

### 坑 1：内层的三条外壳，藏着两条、留一条

内层页面自带顶栏（9 个域）和**两条**底栏。外层 Vue 已有 AppHeader / AppFooter，
不管的话底部会堆三条。

逐条比对内容后（**不能只看名字像不像**）：

| 内层元素 | 内容 | 处理 |
|---|---|---|
| `header.fixed.top-0` | 9 个域的导航 | 剥 —— 与宿主 AppHeader 完全重复（同一份 NAV） |
| `footer.fixed.bottom-0` | `Live · SNAPSHOT · SCOPE · TOTAL NODES · PANEL 1/9` | 剥 —— 宿主 AppFooter 就是**照它逐字做的** |
| `footer.estate-status-bar` | `LIVE · Snapshot · 282 apps… · 0 agents online · 2 in queue · ⌘K` | **保留** —— 内容不同，宿主没有 agents online / queue |

> **教训**：第一版把三条一起剥了，理由是"看着都是外壳"。用户直接问「为什么原来页面中的
> 这个内容没有展示」—— 那条底栏的信息宿主根本没有。
>
> 判别标准应该是**逐字比内容**，不是看元素名字/位置像不像。名字叫 `status-bar`、
> 位置也在底部，不等于内容重复。

**解法**：构建时往内层注入 `<style id="sip-embed-shell-strip">`，只 `display:none` 掉
上面那两条，并把面板高度从 `calc(100vh - 92px)` 还原成 `100vh`（那 92px 本来就是给顶栏让的位）。

选择器对着 Next 那边的 class 写，站点改版后要跟着改 —— **剥错了不会报错，只是少了点东西**，
所以改完要看一眼。

### 坑 2：高度链断在 `#app`，而且 `main` 的 overflow 会把内容裁掉

**这是本次返工最久的一个，两个坑叠在一起，而且症状具有误导性。**

**第一层**：`#app`（index.html 的挂载点）在 `styles.css` 里**没有任何规则** ——
它是 `display:block` + 自动高度，作为 `body` 的 flex 子项也不会被拉伸。实测只有 **112px**。
于是 `body(100vh, flex) → .app-body(flex:1) → main(flex:1)` 这条链全塌。

> 旧视图没暴露这个问题，是因为它们是**在流内的真实内容**，把 `#app` 撑开了。
> 而 iframe 外层是绝对/固定定位、不贡献高度，链一断就露馅。**这个隐患一直在，只是没人踩到。**

**第二层（第一次修的时候栽在这）**：给 `.cs-embed` 补一个 `height: calc(100vh - 92px)`
看起来解决了 —— 实测它确实有 821px。但 **`main` 仍然只有 60px，而它带
`overflow-y: auto`**，会把超出的部分**裁掉**。于是内层只露出顶部约 60px（标题那两行），
下面一片白 —— 用户看到的正是「一层白布遮住了页面」。

**用 `elementFromPoint` 才定位到**：修之前 `document.elementFromPoint(800, 450)` 返回
`BODY`，修之后返回 `IFRAME.cs-embed__frame`。**这个探针比截图有用得多** —— 截图只能看到
"白的"，说不出被裁的是谁。

**解法**：`position: fixed`，相对**视口**定位，一次跳开断掉的高度链和 `main` 的裁剪。
`top: 52px` / `bottom: 40px` 分别对应 header 高度和 `main` 给 fixed footer 让的位。

**另一个被否掉的方案**：给 `#app` 补 `flex: 1; min-height: 0` —— 能修好整条链，但会影响
**全部 15 个 legacy 视图**的布局，风险不可控，不做。

### 坑 2b：外壳的 footer 会盖住内层底部 31px

外壳的 `header`/`footer` 都是 `position: fixed`（`header` z-index 100、`footer` 30），
`footer` 会盖住视口底部约 31px —— 内层右下角的缩放按钮和左下角的 LEGEND 会被压掉。
`main` 自己的 `padding-bottom: 40px` 就是为此留的。
`.cs-embed` 的 `bottom: 40px` 跟着它。实测：帧底 873 / 页脚顶 880 → 不重叠。

### 坑 3：`public/` 与 Vite 的根部伺服

一开始想用 Vite 插件 + `--directory` 中间件伺服副本，写了一百多行。其实**不需要**：
Vite 的 `public/` 就是「按根伺服静态资源」，而内层要的正是根绝对路径 `/_next/…`。
把产物放进去就完事，dev 和 build 都自动适用。

**能用现成机制就别写插件。**

### 坑 4：`file://` 与 Chrome 保存版的 DOM 快照

这两条在 `v2.0.0-constellation-offline-export.md` 里已详细记录，此处不重复。
一句话：必须 HTTP + 服务根目录正确；且**必须用服务器原始 HTML 作外壳**，
Chrome 保存的那份 DOM 快照会让 React 根本不启动。

## 怎么用

```bash
npm install
npm run dev          # → http://localhost:5173，点顶栏 Constellation
```

单独看那一页（不经过 Vue）：

```bash
./tools/start-offline.sh    # → http://localhost:8777/constellation-app.html
```

> `public/` 里那份是入库的，**克隆下来直接就能用**。
> 要重建（改了数据、或站点更新了）：

```bash
python3 tools/make-offline-page.py                # 离线，只读 vendor/
python3 tools/make-offline-page.py --refresh      # 站点更新后刷新缓存（唯一联网操作）
```

改节点数据 / 加租户见 `tools/如何修改数据.md`。
