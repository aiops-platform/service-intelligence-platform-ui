# v1.4.0 — APM 分组导航重构：Observability › APM › Monitor Targets

**日期**: 2026-08-27

**问题/背景**: v1.3.0 中 APM Monitors 是 Observability 下的一个叶子菜单项，页面同时充当「分组名 + 页面名」。本次把该叶子拆分为**分组 `APM` + 子页 `Monitor Targets`**，仍嵌套在 Observability 下（`Service Ops › Observability › APM › Monitor Targets`），为后续平级挂入 Detection Rules / Alerts 等子页预留结构。**明确不做提级**：APM 在整体 AIOps 链路中是「检测模块」，属于观测/检测伞下的组成部分，不应与 Observability 平级。分组命名用缩写 `APM`（避免与子页 Monitor Targets 的 "Monitor(s)" 字样在面包屑里重复），子页保留语义最准的 `Monitor Targets`（对齐后端 `monitor_target` 表 / `/v1/monitors` API）。

---

## 改动明细

### 1. `index.html` — 侧边栏：APM Monitors 叶子 → APM 分组 + Monitor Targets 子页 (line 106-114)

**原因**: Observability 下新增分组（沿用 `has-children` + `data-toggle` + `sidebar-children` 既有嵌套模式），原叶子 `data-page="apm-monitors"` 改为分组头 `data-toggle="apm"`，子页 `data-page="monitor-targets"`。

```html
<!-- before -->
<div class="sidebar-item" data-page="apm-monitors">
    <span class="sidebar-label">APM Monitors</span>
</div>

<!-- after -->
<div class="sidebar-item has-children expanded" data-toggle="apm">
    <span class="sidebar-arrow"></span>
    <span class="sidebar-label">APM</span>
</div>
<div class="sidebar-children" id="apm">
    <div class="sidebar-item" data-page="monitor-targets">
        <span class="sidebar-label">Monitor Targets</span>
    </div>
</div>
```

### 2. `index.html` — 页面区块改名 + 面包屑 + 标题 (line 1160-1166、1303)

**原因**: 页面 div 由 `page-apm-monitors` 改为 `page-monitor-targets`，面包屑补上 APM 一级，h1 由「APM Monitors」改为「Monitor Targets」，副标题去掉重复的 "Monitor Targets ·"。

```html
<!-- 面包屑 -->
Service Ops › Observability › APM › <strong>Monitor Targets</strong>
<!-- 标题 -->
<h1 class="page-title">Monitor Targets <span ...>configure once, auto-scheduled</span></h1>
```

### 3. `js/app.js` — 路由 key 与函数改名 (line 94-95、574、3657、4010、4028)

**原因**: 侧边栏叶子点击、顶栏 Service Ops 导航、`_pageRefreshers` 键、`initApmMonitors()` → `initMonitorTargets()`（含 `init()` 调用点）全部跟随页面改名。

```js
// before
} else if (page === 'apm-monitors') { showPage('page-apm-monitors'); }
_pageRefreshers['page-apm-monitors'] = function () { refreshList(); };
function initApmMonitors() { ... }
// after
} else if (page === 'monitor-targets') { showPage('page-monitor-targets'); }
_pageRefreshers['page-monitor-targets'] = function () { refreshList(); };
function initMonitorTargets() { ... }
```

### 4. `css/styles.css` — 嵌套分组子项加深缩进 (line 341-343)

**原因**: `.sidebar-children .sidebar-item` 统一 `padding-left: 38px`，嵌套分组的子页与分组头缩进相同，视觉上无法区分层级；补一条规则让 Monitor Targets 再深一级（56px）。

```css
.sidebar-children .sidebar-children .sidebar-item {
    padding-left: 56px;
}
```

## 踩坑记录

- **提级与否的讨论**：曾评估把 APM 提升为与 Observability 平级的二级菜单，但确认 APM 实为整体 AIOps 链路中的「检测模块」，属观测/检测伞下的组成部分，若提级会语义放大 → 结论保持嵌套，不做提级。
- **面包屑命名冗余**：分组「APM Monitors」+ 子页「Monitor Targets」都含 "Monitor(s)"，视觉重复。权衡后分组用缩写 `APM`，保住子页信息量（子页若改 "Targets" 会丢 "Monitor" 语义，不划算）。
- **旧引用逐一核对**：`grep apm-monitors|page-apm-monitors|initApmMonitors` 全项目扫描，代码引用已清零；`changelogs/v1.3.0-apm-monitors.md` 为历史记录，按约定不修改。
