# v2.6.14 — View diagnosis 弹框整块英文化

**日期**: 2026-09-24

**问题**: `Diagnosis Center` 页面的按钮（Analyze / Ignore / Escalate / View diagnosis）与列表列
全是英文，点开的 View diagnosis 弹框里却整块中文 —— `已完成`、`来源 problem-log-diagnose`、
`耗时 11m 43s`、`根因 · ROOT CAUSE`、`拒绝 · 重新分析`… 同一个功能两种语言。

---

## 症状

用户指出的那条状态行：

```
已完成 | 来源 problem-log-diagnose | run_acf50619ad | 耗时 11m 43s | 更新 17:51:36
```

弹框内约 **60 处**中文界面文案，分布在 6 个状态映射表、7 个区间渲染函数、3 条
`confirmDialog` 与 8 条 `_showToast` 里。下游数据（根因正文、步骤正文、工具参数）本就是
模型产出的内容，不动。

**「半中半英」不是风格问题而是内部矛盾**：同一个 `completed` 在**两处**渲染 ——
页头状态胶囊（`DGX_STATUS_LABEL`）与下方「历次执行」列表（`DGX_EXEC_STATE`）。
只改一处就会出现「页头写 Completed、下面同一轮写已完成」。

## 踩坑记录

### 坑 1：`.dgx-k` 是 68px 定宽，英文标签会折行（**实测踩到**）

`css/styles.css:7096` 是 `.dgx-k { flex: none; width: 68px; }` —— 中文四字（48px）
天然放得下，英文一上来就折：

| 标签 | 文本宽（12px Inter） | 68px 下 |
|---|---|---|
| Why recommended | 109.73px | 折 2 行 |
| Rejection reason | 94.20px | 折 2 行 |
| Expected effect | 89.66px | 折 2 行 |
| Applies when | 75.47px | 折 2 行 |

症状是**同一张卡里行高参差**：`Verification` 一行、`Outcome` 两行（截图确认过）。

**选择缩短标签而不是加宽列**：`.dgx-k` 变宽会把整个弹框所有 KV 行的值列起点右移 44px
（1086px 的卡宽里没必要的度量变更）；且这是「为英文让路而改既有布局」。改成
`Rationale` / `Reason` / `Outcome` / `Applies to` / `Status`，**12 个字段名全部 ≤66.5px**，
一个不多。

> 判「某标签会不会折行」**不能用量元素高度**：`.dgx-k` 是 flex 子项、会被拉伸到行高，
> 它的 `height` 等于**值**的高度（长值能算出 11 行）。判据只能是「文本宽 ≤ 68px」。

### 坑 2：新增的 `.dgx-k` 字段名没有既有中文可对照

`Outcome`（预期效果）比 `Expected effect` 短但语义略泛；`Rationale`（推荐理由）是产品
英文里的标准词。两处取舍按「先满足度量、再保语义」定，已在代码里留注释说明这个约束。

### 坑 3：CDP 验历史快照时预检把 GET 顶掉了

`dgxHistSnapshot`（历史条目里的整轮渲染）在**本机所有记录上都没有数据** —— 16 条记录的
decision 快照**全是空的**（会话过期，只走降级分支）。用 `Fetch.fulfillRequest` 合成了一份
才验到。第一次跑失败：`X-Tenant-Id` 是自定义头 → 跨源 GET 先发 `OPTIONS`，它**同 URL、
同样被模式命中**，假回一个没有 `Access-Control-Allow-Headers` 的响应 → 浏览器判预检失败 →
真正的 GET 根本没发出去，表现为「拦到了但页面没数据」。**预检必须 continue**。
