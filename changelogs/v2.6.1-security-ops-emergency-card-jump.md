# v2.6.1 — 修 Security Ops「Emergency change risk」卡片的跳转：内层 push 被抹掉尾斜杠 → iframe 里套出 Vue 应用

**日期**: 2026-09-22

**问题**: 「Security Ops 页面中点击 Emergency change risk 这个卡片后跳转有问题，
请参考 https://sip-platform.web.app/security-ops/ 的跳转逻辑」。

原站上点这个卡片是**整页切到 Engineering Ops 面板**（卡片自己的 `sub` 里就写着
`· /engineering-ops`）。我们这边点下去，iframe 里换成了 Service Ops，而且换成的是
**Vue 应用自己**，外壳却仍以为在 Security Ops 上。

**原站行为已实测确认**（用 CDP 在线上点了一次，不是读代码推断）：

```
点击前  url = https://sip-platform.web.app/security-ops/
点击后  url = https://sip-platform.web.app/engineering-ops/
        h1  = "Engineering Ops"
```

修复后的本仓行为与之**完全等价**：顶层 `/eng-ops` + iframe `/engineering-ops/` +
h1 `Engineering Ops` + 页脚 `PANEL 4/8 · ENGINEERING OPS`。

---

## 症状（实测，不是推演）

```
                  点击前                          点击后
iframe            /security-ops/          →      /service-ops      ← 跑起整个 Vue 应用
顶层路由          /security-ops                   /security-ops     不动
页脚              PANEL 7/8 · SECURITY OPS       PANEL 7/8 · SECURITY OPS   不动
导航高亮          Security Ops                    Security Ops      不动
iframe 里有 #app  false                     →      true
```

**内容与导航彻底脱节**：iframe 里已经是别的东西了，外壳还以为自己在 Security Ops。

---

## 根因：Next 的 `trailingSlash: false` 会抹掉尾斜杠

卡片是这么写的（`15zvtls0y9kdc.js`）：

```js
{ label:"Emergency change risk", value:`${s.REAL.emergencyVsStandardMultiplier.toFixed(0)}×`,
  sub:"emergency backout · canonical security signal · /engineering-ops",
  provenance:"real",
  onClick:()=>e.push("/engineering-ops/") }      // ← 内层 Next 应用自己的 router
```

`e` 是**内层 Next 应用的 router**，不是外壳的。这条链条是：

```
内层 push "/engineering-ops/"（带尾斜杠）
  → Next 默认 trailingSlash:false，导航前规范化掉尾斜杠
  → 浏览器实际请求 "/engineering-ops"（无斜杠）
  → vite.config.js 的目录索引插件**只拦带尾斜杠的请求**（那正是它与同名 Vue 路由分流的手段）→ 不接
  → 落进 SPA 兜底 → 返回 Vue 应用的 index.html
  → vue-router 里没有 "/engineering-ops"（本仓的 key 是 "/eng-ops"）
  → 被 catch-all 重定向到 "/service-ops"
  → iframe 里跑起完整的 Vue 应用
```

### ★ 这条最值得记：**「本仓有这个页面」不等于这个链接是安全的**

`/engineering-ops/` 是本仓**确实导出**了的目录索引（v2.6.0 刚接的）。
按「目标路径存不存在」来判断，这个链接看着完全没问题 —— 但实际上它照样落进兜底。

判据不是「目标路径存不存在」，而是**它过没过内层路由** —— 过了就可能被规范化。
**必须实测点击**。我读代码时先推断成「会套出一层 Service Ops 内嵌页」，
实测是「跑起整个 Vue 应用」，差了一层。

> 与 v2.6.0 修的 Engineering Ops 那三处**不是同一个成因**：那三处推的是本仓**没有**
> 的路径（`/agents/`），这个是推了**有**的路径、但被 Next 规范化掉了。

## 改动明细

### 1. `tools/tenant_copy.py` — 新增 `patch_security_ops_links()` (line 1203-1272)

```python
SS_SITE = (
    "Emergency change risk 卡片 → /engineering-ops/",
    'onClick:()=>e.push("/engineering-ops/")',
    'onClick:()=>{window.parent!==window'
    '?window.parent.postMessage({type:"sip:open-engineering-ops"},location.origin)'
    ':e.push("/engineering-ops/")}',
)
```

未嵌入时（`window.parent===window`）**保持原来的 push** —— 单独打开离线副本时
内层 shell 是自洽的。锚点 `onClick:()=>e.push("/engineering-ops/")` 在 chunk 里唯一（已核）。

⚠️ 这一段是 JSX **属性位**，替换成块语句后原来紧跟的 `,drillLabel:…` 必须还在属性位上 ——
注释里写明了「除了尾部那个 `,`，一个字符都不能动」。

### 2. `src/composables/useEmbedBridge.js` — 加第三种消息

```javascript
export const OPEN_ENGINEERING_OPS = 'sip:open-engineering-ops'
…
if (msg.type === OPEN_ENGINEERING_OPS) { router.push('/eng-ops') }
```

外壳在**顶层**路由到 `/eng-ops` —— 与原站行为一致。

注释里同时记了一条**给未来的判据**：三种消息长得几乎一样（都只是「去某个顶层路由」），
**再多一种就该换成白名单表**（`{type: path}` 映射），而不是继续加常量。

### 3. `tools/make-offline-page.py` — 接线新补丁 (line 419)

```python
             ss = tenant_copy.patch_security_ops_links(chunks_dir)
             if ss == "applied":
                 print("  Security Ops：Emergency change risk 卡片 → postMessage 给外壳")
```
