# Vue 化改造：外壳 + 2 个代表视图（分支 `vue`）

## Context

本仓是 16 天内迭代了 51 个版本（**其中 32 个是补丁版，占 63%**）的纯静态站点，当前架构已经跟不上迭代节奏：

| 现状 | 问题 |
|---|---|
| `js/app.js` 8777 行单个 IIFE，23 个 `init*()` 闭包 | 每次改动都落在同一个巨型文件里；返工率 63% |
| `index.html` 2210 行含 **17 个** `.page-panel`，全部同时挂在 DOM | 无视图边界，`showPage()` 切 `display` |
| 渲染 = 手拼 HTML 字符串塞 `innerHTML`（**100 处**），`escapeHtml` 的使用远少于拼接点 | 存在 XSS 面 |
| base URL 硬编码 **12 处**，无统一 fetch 封装；`apmApi` 被复制粘贴 3 份 | 换环境要改十几处 |
| 前端硬编码 `http://localhost:8080` / `:8000` 调后端 | 跨域靠后端开 CORS，无 proxy/同源方案 |
| 无 `package.json` / 无 CI / 无 lint / `.idea/` 5 个文件已入库 | 无工具链 |

目标：用 Vue 3 重写外壳（header / 侧边栏 / main / footer）+ **2 个代表视图**（各打通一条后端链路），并把跨域从「硬编码绝对 URL」改为「相对路径 + proxy」。

**其余 15 个视图本次不动，继续由旧 `app.js` 驱动** —— 这是本方案最核心的约束，决定了整体设计（见「二、双世界共存」）。

已确认的三个 scope：
- **范围** = 外壳 + `page-log-analysis`（接 sip-aiops `:8080`）+ `page-bug-solve`（接 agentflow `:8000`）；其余 15 个视图保留旧实现；
- **样式** = `css/styles.css`（7099 行）**原样全局 import，一字不改**，组件模板逐字沿用现有 class；
- **技术栈** = Vue 3 + Vite + **JavaScript（非 TS）** + Vue Router，**不用 Pinia**（现 8777 行里几乎无跨模块共享状态，各视图状态都是局部的，用 colocated composable 即可）。

不在范围：**APM（`:7070`）与 KB** —— 相关视图（`page-problems` / `page-monitor-targets` / `page-domain-config` / `page-reflow-log` / `page-knowledge-search`）本次不迁。分支 `vue`，`master` 不动（回滚 = 切回 master）。

## 一、双世界共存（本方案的关键设计）

单文档内 Vue 与旧 `app.js` 并存，唯一不变式是 **同一棵 DOM 子树只能有一个所有者**。

### 1.1 已核实的硬冲突（不是理论风险）

`app.js` 的四个全局初始化器用**全文档**查询，且**只在 `init()` 时绑定一次**：

| 函数 | 行号 | 查询 |
|---|---|---|
| `initFilterChips` | 2140 | `document.querySelectorAll('.filter-chip')` |
| `initTableSorting` | 2172 | `document.querySelectorAll('th')` |
| `initButtonGroup` | 2218 | `document.querySelectorAll('.btn-group .btn')` |
| `initRowClick` | 2229 | `document.querySelectorAll('tbody tr')` —— 实为 `console.log` 空壳，风险低 |

`showPage`（app.js:42）同样全文档查 `.page-panel`。

而 Vue 的 `log-analysis` 视图**必须沿用同样的 class 名**（才能复用 `styles.css`）。若 Vue 先于 `init()` 挂载，旧 handler 会绑到 Vue 的 DOM 上 —— 点表头时旧代码直接 `appendChild` 重排 `tbody`，点筛选 chip 时旧代码直接改 class，**vdom 与真实 DOM 失步**。症状随机、难复现，必须优先拆掉。

### 1.2 解法：`legacyRoot()` 作用域根 + 8 处接缝

IIFE 顶部加零成本 helper：`function legacyRoot() { return window.__SIP_LEGACY_ROOT || document; }`

| # | 位置（app.js 行号） | 改动 | 目的 |
|---|---|---|---|
| S1 | 42 `showPage` | `document.` → `legacyRoot().` | 旧页切换只动自己的树 |
| S2 | 2140 / 2172 / 2218 / 2229 | 同上（**共存地基，不可漏**） | 消灭 1.1 的冲突 |
| S3 | 22 `navigateToPage` | 首行 `if (window.__SIP_NAVIGATE) return window.__SIP_NAVIGATE(pageId, context)` | 旧页跨页下钻改走 Vue Router |
| S4 | 2255 `openAlertDetailGeneric` | **首行**（须早于 `!overlay` 守卫）`if (window.__SIP_OPEN_ALERT_DETAIL) return ...` | 未迁移页也能用 Vue 的详情模态 |
| S5 | 8746 `init()` | 嵌入模式下跳过 `initSidebar()` / `initNavigation()` | shell 归 Vue，避免抢绑 |
| S6 | 8746 `init()` | 嵌入模式下跳过 `initLogAnalysis()` / `initBugSolve()` | 两视图 DOM 已迁走，不跳会在 `getElementById(...).addEventListener` 上抛错 |
| S7 | 8774 自启动块 | `if (window.__SIP_DEFER_LEGACY_INIT) { window.__SIP_LEGACY_INIT = init } else { …原逻辑 }` | 让 Vue 注入完 legacy DOM 后再启动旧世界 |
| S8 | `showPage` 定义后 | `window.__SIP_SHOW_PAGE = showPage` | 路由守卫触发旧页切换（旧 `_pageRefreshers` 原样保留生效） |

全部走 `window.__SIP_*` 特性检测、**保持 ES5 风格**（该文件 0 处箭头函数、0 处 `?.`）。不引入构建期分支 —— 直接打开旧 `index.html` 时这些分支全不生效，行为与今天一致。

### 1.3 防重入

`src/legacy/bridge.js` 的 `ensureLegacyBooted()` 是幂等 memoized promise，整个生命周期只装载一次；`v-html` 绑定**模块级冻结常量**（不是 ref），Vue 永不重写它。容器用 `v-if="booted" v-show="isLegacyRoute"` —— `booted` 一旦置 true 就不再回退，所以 legacy 树永不卸载，app.js 的监听器与 `setInterval` 不会重复绑定。

## 三、跨域方案

**不变式：`src/` 下永不出现 `http://localhost:*`，只出现 `/` 开头的相对路径。**

- **开发**：`vite.config.js` 的 `server.proxy` —— `/api/sip-aiops` → `:8080`（真路径同名，不 rewrite）、`/agentflow` → `:8000`（`rewrite` 剥前缀，因 agentflow 路由挂在根路径）。浏览器视角同源，**无 CORS、无 preflight**。
- **生产**：dist 静态托管 + 同源 nginx 反代（片段写入 README）。若部署环境不给配 nginx，把 `createWebHistory` 换 `createWebHashHistory`（一行）。
- **已知且接受的不对称**：未迁移的 15 个视图仍打硬编码绝对 URL、依赖后端已有 CORS 头，**不走 proxy**。本次不为它们改那 12 处 base —— 等逐个迁移时自然收敛。

### API 层

修掉「12 处硬编码 base + 3 份复制粘贴的 `apmApi` + 全文件无 `localStorage.setItem`」：

- `api/config.js`：`resolveBase(name)` 三级回退 **localStorage > `VITE_*` > 相对路径默认**；**保留旧 key 名**（`bugSolveBaseUrl` / `workflowBaseUrl` 等），console 里设过的值继续生效；补 `setBase()`（旧版缺失的写入口）。
- `api/http.js`：唯一 `createClient({ base })` 封装 —— query 拼接（跳过空值，对齐旧版条件拼接）、`AbortController` 超时、`ApiError`（带 status/url/method）、**`unwrap` 剥一层 `{success,data}` 信封**（不剥第二层：analysis 接口需要 `.data.data`，与 app.js:2269 一致）。
- 视图私有状态放视图目录的 colocated composable（`views/*/use*.js`）—— 没有 Pinia 时的替代：**每视图一个微型 store，随组件生命周期创建销毁**。

## 四、路由与导航

不做嵌套（shell 只渲染一次，视图都是叶子）。path 用 slug，`panelId` 进 `meta`。

`router/nav.js` 是唯一真源 —— 把 `app.js:61-124` 那串 slug↔panelId 的 if-else 变成 `PANEL_ID` 映射表（**只有两处真不一致**：`knowledge-reflow-log`→`page-reflow-log`、`agent-registry`→`page-agents`）。

未迁移视图共用**一个持久 `LegacyPanels` 容器**，不给每个路由建一个 —— 否则切页会重挂整棵 legacy 树、重跑 17 个 init 的 fetch 与 8 个 interval。

**`_pageRefreshers` → 路由守卫**：`router.afterEach` 对 legacy 路由调 `ensureLegacyBooted().then(() => window.__SIP_SHOW_PAGE(meta.panelId))` —— 1:1 替换，那 10 处注册原样不动。已迁移视图改用 `onActivated`。

**跨页下钻**：`navigateToPage('log-analysis', {serviceName})` → `router.push({ path, query })`，替代 `sessionStorage.navContext`，URL 可分享可刷新。

**轮询 → `usePolling(fn, { interval, enabled })`**：内建 `onDeactivated` 停 / `onActivated` 恢复 + `document.hidden` 暂停，替掉旧版 8 处 `setInterval` + `page.style.display !== 'none'` 守卫，顺带修掉「标签页在后台仍 2 秒一轮」。

## 五、两个视图的迁移要点

### 5.1 `page-log-analysis`（app.js:3415-3601，189 行）

拆 `LogAnalysisView.vue` + 4 个子组件（KPI / 过滤器 / 表格）+ `useLogAnalysis.js`。

- **表格恒定 10 行**（旧版 `for (var i=0;i<10;i++)`，不足则渲染空行占位）—— 保持表格高度稳定，**重写极易丢**。
- `formatTime`（app.js:3487）的时区处理（先正则剥时区后缀再拼 `Z`，再 `toLocaleString('zh-CN', {timeZone:'Asia/Shanghai'})`）**逐字移植，不要顺手简化**。
- 旧版**无轮询**，靠 `_pageRefreshers` 切页刷新 + Refresh 按钮 → 重写保持无轮询。
- `currentPage` 旧版恒为 0（无翻页 UI 绑定）→ 保留字段、先不接 UI，避免"看起来能翻页其实没接"的假象。

### 5.2 `page-bug-solve`（app.js:7270-7707，437 行）

拆 `BugSolveView.vue` + 4 个子组件 + `useBugSolveRun.js`（原闭包局部变量原样升为 `ref`）。

**`createGraphCanvas`（app.js:6845-7053，209 行）→ 命令式引擎 + 薄 Vue 壳**：
- `useGraphCanvas.js` 逐字保留引擎逻辑（Kahn 入度剥层 + 防环兜底 + 层内居中、`NODE_W=150` 等常量、`.bs-stage` 中间层技巧 —— 它是"按视口居中而不是把容器推偏"的关键，**不能省**）；
- `GraphCanvas.vue` 里 `<svg ref>` **绝不能有 Vue 插值子节点**，否则与引擎的 `innerHTML` 互相覆盖；marker 也由引擎管，模板里不放；
- 旧的那份**原地不动**（未迁移的 Workflow Studio 仍在用），本步是"复制一份适配"，接受暂时重复。

### 5.3 `alertDetailOverlay` 双向复用

它被 log-analysis 与**未迁移的** metrics-analysis 共用。Vue 侧做全局单例 `AlertDetailModal.vue`，经 S4 接缝把 `open()` 暴露给旧代码；`#alertDetailOverlay` 从 legacy 树删除避免重复 id。

**`renderAlertAnalysisContent`（app.js:2287-2690，403 行）是本方案最大的单块工作量，排期不要按"小模态"估**。且**不能整段 `v-html`** —— 内含 3 处 `onclick="window._showToast(...)"`（2421/2423/2425），`v-html` 注入的 HTML 不会被 Vue 编译，内联 `onclick` 失效 → 推荐操作按钮全废。必须拆成 8 个子组件转模板（`HeroBanner` / `AiSummaryCard` / `CodeAnalysisCard` / `ImpactAssessmentCard` / `Recommendations` / `DiagnosisChain` / `ErrorSnapshot` / `InvocationMeta`）。
