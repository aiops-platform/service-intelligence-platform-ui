# AgentSpec 平台化：DB 驱动 agent 配置 + SIP 配置页 + agent→MCP server 绑定（server 粒度）

## Context
现在 15 个 agent 的 AgentSpec 全部硬编码（`agents/registry.py` + `agents/prompts.py` + `agents/tools.py`），
运行时每节点只认 `SYSTEM_PROMPTS[name]` 与 `tools_for_agent(name)`。用户希望：
1. 通过**前端页面**配置 AgentSpec 内容（覆盖 system_prompt / 输出 schema / role / stage / description / enabled）；
2. AgentSpec 能**选择调用的 MCP server**（此前已把 MCP server 记录的 `agents` 字段移除、改为「agent 为主表」方向）；
3. 内置 15 个可编辑，另支持**新增自定义 agent**（可被 workflow 节点引用、出现在 agent 舰队）。

跨两仓库：后端 `multi-agent-workflow`（新增配置表 + 运行时装配读取 + CRUD 端点），前端 SIP
`service-intelligence-platform-ui`（新增 Monitor-style 配置页 + 弹窗编辑）。**沿用「改完查验再提交」惯例，全程不 git commit。**

已确认的三个 scope：
- 可编辑字段 = **含 system_prompt 与输出 schema**（DB 存覆盖，NULL→回退内置）；
- MCP 绑定粒度 = **server 粒度**（勾选绑定的 server → 运行时挂载该 server 的全部 enabled 工具；enable/disable_tools 仍由 server 记录自己管）；
- 范围 = **内置 15 可编辑 + 可新增/删除自定义 agent**（内置行禁止删除，提供“清空覆盖=回退内置”）。

---

## 一、语义与默认决策（先定，避免实现期摇摆）

- **覆盖即存值、NULL 即回退内置**：DB 行对内置 15 的 `description/system_prompt/schema_json` 存 NULL 时，
  运行时合并回退到静态 `AGENT_DESCRIPTIONS / SYSTEM_PROMPTS / AGENT_SCHEMAS`；写入非空即覆盖。
  **schema 覆盖仅为元数据/详情展示层生效**（对齐现状：`extract_json` 不做强校验，prompt 内联 JSON 模板不自动重写）——
  计划里如实注明，避免高估。
- **`mcp_server_ids` 三态**：
  - `NULL`（未配置）= 全量 enabled server（**保持现状**：不破坏现有 demo/E2E 对“每 agent 可见全部 enabled server”的依赖）；
  - `[]` = 明确不绑定任何 server（无 MCP 工具）；
  - `[mid,…]` = 精确子集。
  UI 用「radio：全部(默认/未绑定) vs 指定 server」表达，勾选指定后存具体数组；**全勾 ≠ 改存 NULL**。
- **origin 语义**：`origin='builtin'`（代码内置 seed）行禁止 DELETE（返回 400），前端 Delete 置灰并提示
  「内置 agent，只能编辑/清空覆盖」；`origin='custom'` 行可增删。清空覆盖的“重置”= 编辑时清空文本（端点把 `""` 映射为 `NULL`）、
  绑定切回 radio「全部」。
- **enabled=0**：运行时该 agent 节点短路返回占位（`{"node":…,"ok":True,"disabled":True}`），不调 LLM。
- **seed 幂等**：init 时若 `agent_configs` 表为空 → 从静态 registry seed 15 条 builtin；非空则不动（不 clobber 用户编辑）。
- **name 约束**：`^[a-zA-Z0-9_-]+$`（agent 名同时是 workflow `node.agent` 引用键 + AgentScope `Agent.name`）；name 全库唯一
  （与内置并集不冲突，撞内置名即 PK 冲突 → 400）。custom 必须提供 role + stage + 非空 system_prompt。

## 二、后端改动（`multi-agent-workflow`）

### 1) 新配置存储 `agentflow/api/agent_store.py`（照抄 mcp_store.py 骨架）
复制 `MCPStore`/`PgMCPStore`/`build_mcp_store` 结构为 `AgentConfigStore`/`PgAgentConfigStore`/`build_agent_config_store(settings)`。
- sqlite `_SCHEMA` + PG `_PG_SCHEMA`（两表结构一致，JSON 存 TEXT、bool 存 INTEGER、时间戳 ISO TEXT），表 `agent_configs`：
  ```sql
  name            TEXT PRIMARY KEY,          -- agent 名（= node.agent / SYSTEM_PROMPTS key）
  origin          TEXT NOT NULL DEFAULT 'builtin',   -- 'builtin' | 'custom'
  role            TEXT NOT NULL,             -- diagnose | fix
  stage           TEXT NOT NULL DEFAULT 'other',     -- detect/diagnose/fix/verify/deliver/learn
  description     TEXT,                      -- NULL→回退 AGENT_DESCRIPTIONS
  system_prompt   TEXT,                      -- NULL→回退 SYSTEM_PROMPTS
  schema_json     TEXT,                      -- NULL→回退 AGENT_SCHEMAS（仅元数据/详情）
  mcp_server_ids  TEXT,                      -- JSON list[str] | NULL；NULL=全量 enabled（见“语义决策”）
  enabled         INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL
  ```
- 复用 `_to_row/_from_row` 风格：JSON 列读写；`save/update/delete/list/get`（list 按 created_at DESC）。
  - `save` name 冲突 → `sqlite3.IntegrityError`（PG `UniqueViolation`→`sqlite3.IntegrityError`，对齐 mcp_store 做法，供 400 映射）。
- agent_configs 是新表，**不需要** mcp_servers 那段「ADD tools/DROP agents」迁移钩子（可留空 `_MIGRATION_COLUMNS`）。

### 2) 运行时解析器 `agentflow/agents/agent_config.py`（新）
不 import `api/*`（避免 agents→api 反向依赖）；构造时喂 store 行，启动/CRUD 后重建。
```python
@dataclass
class ResolvedAgent:
    name, origin, role, stage, description, system_prompt, schema: dict, enabled: bool,
    mcp_server_ids: set[str] | None   # None=未配置(全量) / set=精确(可空)

class AgentConfigResolver:
    def __init__(self, rows: list[dict])            # 建 name→row 索引
    def resolve(self, name) -> ResolvedAgent | None # 合并静态回退（registry/prompts）
    def server_ids_for(self, name) -> set[str] | None
    def all(self) -> list[ResolvedAgent]            # DB 行 ∪ 未落库的内置（顺序=DIAGNOSE+FIX→custom）
```
静态合并来源：`agents/registry.py` 的 `AGENT_DESCRIPTIONS/AGENT_STAGES/DIAGNOSE_AGENTS/FIX_AGENTS`、`agents/prompts.py` 的 `SYSTEM_PROMPTS/AGENT_SCHEMAS`。

### 3) `agents/scopes.py::build_agent`（改签名）
加 `system_prompt: str | None = None`（keyword-only），内部改：
`system_prompt = system_prompt or SYSTEM_PROMPTS.get(name, "你是 AI 运维平台智能体。")`。其余不变。

### 4) `agents/runner.py::AgentNodeRunner`（改）
- `__init__` 增 `agent_config: AgentConfigResolver | None = None`。
- `__call__`（现 L114-155）开头：
  - `cfg = self.agent_config.resolve(agent) if self.agent_config else None`
  - `if cfg is not None and not cfg.enabled:` → 短路返回 `{"node": node.id, "ok": True, "disabled": True}`。
  - 把 `cfg.system_prompt`（合并后的有效值，可能=静态回退）作为 `system_prompt=` 传 `build_agent`（cfg 为 None 时不传 → 走静态）。
- 其余（mcp clients 取法、build_toolkit/permission、run_agent、usage 计量）不动。

### 5) `agents/mcp_manager.py`（改，server 粒度过滤）
- `__init__` 增 `self.server_ids_for: Callable[[str], set[str] | None] | None = None`（默认 None = 现行为）。
- `clients_for_agent(agent_name)`：在现有 enabled+connected 遍历前，若 `server_ids_for` 存在 → `allowed = self.server_ids_for(agent_name)`；
  `allowed is None` → 返回全部 enabled（现状兼容）；否则**只返回 `mid in allowed` 的 enabled client**（docstring 更新：agent 主表绑定落地，按所选 server 过滤）。
- `allow_names_for_agent` 复用 `clients_for_agent`，自动一致（非只读工具的 allow 只对真正下发的 client 生成）。
- 不改 client 缓存/热刷新；**read_only 工具自动 ALLOW** 已由「只下发绑定 server」天然约束（server 粒度下 agent 只见所选 server 的 enabled 工具）。

### 6) `api/app.py`（改）
- import `AgentConfigResolver`、`agent_store` builder；新增模块全局 `agent_config_store = build_agent_config_store(settings)`。
- `init()`：`await agent_config_store.connect()`；空表 → seed 15 条 builtin（role/stage/desc 取静态默认，runtime 字段全 NULL，
  mcp_server_ids NULL，enabled=1）；建 `resolver = AgentConfigResolver(await agent_config_store.list())`，并接线：
  `mcp_manager.server_ids_for = resolver.server_ids_for`；把 resolver 注入 `AgentNodeRunner(..., agent_config=resolver)`。
- `_migrate_sqlite_config_to_pg()`：新增 `_copy_agent_configs()`（PG 目标表非空即跳过；源 sqlite `agent_config_store` 整行搬 PG——整行含 name 直接 INSERT，id 即 name）。
- 新 Pydantic `AgentConfigCreate/Update` + CRUD 端点：
  - `GET /agent-configs` → `list[dict]`：每行 + `bound_servers:[{id,name,transport}]`（按 `mcp_server_ids` join `mcp_store.get`；NULL → `[{id:'*', name:'全部 enabled'}]` 或前端自行处理）+ 合并后 `effective_description`。
  - `POST /agent-configs`(201) → 只建 **custom**（origin='custom'）；校验 name 正则 / role∈{diagnose,fix} / custom 必填非空 system_prompt；`""`→NULL 归整；重复 name → 400 中文。成功后重建 resolver 并重接 `mcp_manager.server_ids_for`，返回 `{name}`。
  - `GET /agent-configs/{name}` → 单条 + **合并有效值**（description/system_prompt/schema 已回退内置，供编辑弹窗回填）+ `bound_servers`；404 中文。
  - `PUT /agent-configs/{name}` → 完整对象覆盖式更新（custom 仍校验必填；`""`→NULL）；builtin/custom 都允许。成功后重建 resolver + 重接，返回 `{ok:true,name}`。
  - `DELETE /agent-configs/{name}` → `origin='builtin'` → 400「内置 agent 不可删除，请用编辑清空覆盖」；custom 删除；404 兜底。成功后重建 + 重接。
- `GET /agents`（现 L600-612）改读合并视图：`resolver.all()`（DB 覆盖/新增 + 静态回退）→ 形状 `{name,description,tools,stage}` 不变
  （tools 仍 `tools_for_agent(name)` 静态函数工具；custom → `[]`）。**store 为空（未 init）时 == 原 15 条静态** → 既有 `tests/test_agents_api.py` 不破。

### 7) `docker/init/01_schema.sql`
末尾加 `agent_configs` 的 `CREATE TABLE IF NOT EXISTS`（与应用 `_PG_SCHEMA` 一致）。

## 七、风险 / 备注
- `build_agent` 签名改动 → 同步所有调用方（runner、相关测试）。
- 存了 system_prompt 覆盖后，代码里 prompt 的后续修改对该 agent 不再生效（需清空覆盖）——UI hint 说明。
- schema 覆盖仅为元数据，不做 `extract_json` 强校验（对齐现状，如实注明）。
- `mcp_server_ids` 三态里 NULL=全量是为保持现状兼容；一旦某 agent 在 UI 上「指定 server」保存，即变为精确子集（不再跟随新增 enabled server）。
- 既有绑定过 agent 的 MCP server 记录不受影响（绑定在 agent 侧）。PG/sqlite 双后端 + compose 迁移都需验证。
