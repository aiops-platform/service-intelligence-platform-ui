# 如何修改 Constellation 的数据

> 这份文档是独立可用的 —— 明天打开照着做就行，不需要回忆之前的上下文。
>
> 配套：`README.md`（整个 tools 目录的说明）、`tenant_data.py`（干活的脚本）

---

## 30 秒版

```bash
cd tools

# 1) 把某个租户的数据导出成可编辑的 JSON
python3 tenant_data.py extract retail

# 2) 编辑 tools/tenant-data/retail.json

# 3) 校验（很重要，见「坑 1」）
python3 tenant_data.py check

# 4) 重建 → 刷新页面
python3 make-offline-page.py
```

**改完是可逆的**：删掉 `tools/tenant-data/retail.json` 再重建，就回到原样。

## 数据在哪

整份数据是一个 **JSON 字符串**，包在 bundle 里
（`public/_next/static/chunks/0wuztp2.9oz~8.js`）：

```js
89784,(e,t,o)=>{ t.exports = JSON.parse('{"banking":{…},"retail":{…},…}') }
```

10 个租户，每个长这样：

```
{
  "tenant":   { … }   ← 租户元信息（公司名、品牌色、业务叙述…）
  "snapshot": { … }   ← ★ 节点数据全在这里
}
```

**改数据不用碰 JS** —— `tenant_data.py` 负责取出字符串、解码、改 JSON、编码、写回。

### 别直接改源文件

数据在两个地方各有一份：

| 位置 | 说明 |
|---|---|
| `SIP … Acme Retail_files/0wuztp2.9oz~8.js` | **源文件，别动** |
| `public/_next/static/chunks/0wuztp2.9oz~8.js` | 生成物，覆盖只写这里 |

改源文件的话**重建不可重复** —— 改一次叠一次，回不去。`make-offline-page.py`
会自动把 `tenant-data/*.json` 注入到**输出目录那份**。

## 四个命令

```bash
python3 tenant_data.py list                 # 看有哪些租户、哪些有覆盖文件
python3 tenant_data.py extract retail       # 导出到 tenant-data/retail.json
python3 tenant_data.py extract --all        # 全部导出（约 4.5 MB，一般不需要）
```

## 数据结构参考

### `snapshot` 顶层

| 键 | 类型 | 说明 |
|---|---|---|
| `apps` | list | **节点主体**。每条一个应用 |
| `portfolios` | list | 组合（应用的上级） |
| `journeys` | list | 客户旅程（组合的上级） |
| `enterprise` | dict | 图中心的那个节点 |
| `facts` | dict | 底部状态栏的数字（**独立字段，见坑 2**） |
| `portfolioEdges` | dict | 组合之间的关系边（技术重叠／变更级联／事件共现） |
| `appTechnologies` | list | 每个应用的技术栈 |
| `topTechnologies` | list | 技术分布前 5（注意只有前 5） |
| `valuePool` | dict | FinOps 价值池 |
| `topStorm` | dict | 最大的一次告警风暴 |
| `scenarios` | dict | 演示场景 |
| `agents` | dict | Agent 舰队（retail 里是空的） |
| `sparkline90d` | list | 90 天曲线 |

### `snapshot.apps[]` —— 你最常改的

```jsonc
{
  "id": "app:pos",                    // 必须有 "app:" 前缀，全局唯一
  "appKey": "pos",                    // 短标识，技术栈映射用它
  "label": "POS",                     // ★ 图上显示的名字
  "portfolioId": "portfolio:stores",  // ★ 必须对得上 portfolios[] 里的某个 id
  "tier": 1,                          // 1 | 2 | 3
  "holidayCritical": true,            // 图上给高亮色
  "financeFreeze": false,
  "operationalStatus": "ok",          // ok | degraded | down
  "incidentsTotal": 317,              // >100 会自动生成 incident-cluster 节点
  "changeCount": 68,                  // >50 会自动生成 change-cluster 节点
  "riskScore": 86,
  "botResolutionRate": 0.62,          // 0~1
  "botMttrMin": 49.7,
  "humanMttrMin": 1824.4,
  "position": { "x": 19.4, "y": -479.6, "angle": -1.53 }
}
```

> **派生节点不用你管。** team / codebase / wiki / incident-cluster / change-cluster
> 都是页面按规则从 apps 算出来的。加一个 app，会自动多出它对应的 codebase、
> 可能还有 wiki、以及（看阈值）cluster 节点。

### `snapshot.portfolios[]`

```jsonc
{ "id": "portfolio:stores", "label": "Stores", "tier": 1,
  "journeyId": "journey:1", "journey": null,
  "position": { "x": 0, "y": -360, "angle": -1.57 } }
```

### `snapshot.journeys[]`

```jsonc
{ "id": "journey:1", "label": "Browse", "capability": "Browse",
  "position": { "x": 0, "y": -180, "angle": -1.57 } }
```

### 坐标怎么摆的

分层同心圆，半径从中心往外：

```
enterprise   r = 0
journeys     r = 180
portfolios   r = 360
apps         r = 480 ~ 810
```

`angle` 是弧度。手写坐标的话，照这个半径挑一个角度即可：

```python
import math
r, deg = 560, 137
pos = {"x": r*math.cos(math.radians(deg)),
       "y": r*math.sin(math.radians(deg)),
       "angle": math.radians(deg)}
```

> 页面用的是 3D 力导向图（three.js），会在此基础上做微调，
> 所以坐标不用精确 —— 大致位置对就行。

## 例子 2：加几个节点

在 `snapshot.apps` 数组里追加一条就行（字段照抄现有的，保证 `portfolioId` 存在）：

```python
import json, math, pathlib

p = pathlib.Path("tenant-data/retail.json")
d = json.loads(p.read_text(encoding="utf-8"))

r, deg = 600, 210
d["snapshot"]["apps"].append({
    "id": "app:my-new-app", "appKey": "my-new-app",
    "label": "我的新应用",
    "portfolioId": "portfolio:stores",     # 必须已存在
    "tier": 1, "holidayCritical": True, "financeFreeze": False,
    "operationalStatus": "degraded",
    "incidentsTotal": 500, "changeCount": 80, "riskScore": 90,
    "botResolutionRate": 0.5,
    "botMttrMin": 30.0, "humanMttrMin": 1200.0,
    "position": {"x": r*math.cos(math.radians(deg)),
                 "y": r*math.sin(math.radians(deg)),
                 "angle": math.radians(deg)},
})

# ★ 别忘了同步 facts（见坑 2）
d["snapshot"]["facts"]["apps"] = len(d["snapshot"]["apps"])

p.write_text(json.dumps(d, ensure_ascii=False, indent=2), encoding="utf-8")
```

## 例子 3：加一个租户

### 步骤

1. **复制一个现有租户**（这样能保证过 zod 校验）：

   ```bash
   python3 tenant_data.py extract retail
   cp tenant-data/retail.json tenant-data/myco.json
   ```

2. **改两处必改的**：

   ```python
   import json, pathlib
   p = pathlib.Path("tenant-data/myco.json")
   d = json.loads(p.read_text(encoding="utf-8"))

   d["tenant"]["id"] = "myco"                       # ★ 必须 kebab-case，且和文件名一致
   d["tenant"]["name"] = "My Company"
   d["tenant"]["industry"] = "Retail"               # 随便
   d["tenant"]["demoTitle"] = "Service Intelligence Platform · MyCo"
   d["tenant"]["client"]["displayName"] = "My Company Ltd"   # ★ 图上中心节点的名字
   d["snapshot"]["source"]["db"] = "synthetic:myco@1"

   p.write_text(json.dumps(d, ensure_ascii=False, indent=2), encoding="utf-8")
   ```

3. **校验 + 构建**：

   ```bash
   python3 tenant_data.py check      # 会逐条告诉你缺什么
   python3 make-offline-page.py      # 输出里会提示「新增租户：myco」
   ```

4. **打开**：

   ```
   http://localhost:8777/constellation-app.html?tenant=myco
   ```

### 完整清单

| 要改的地方 | 要求 |
|---|---|
| 文件名 | `tenant-data/<id>.json`，`<id>` 要和 `tenant.id` **完全一致** |
| `tenant.id` | kebab-case：`^[a-z][a-z0-9-]*$`。`myco` ✓、`MyCo` ✗、`my_co` ✗ |
| `tenant.client.displayName` | 图上中心节点的名字取这个字段 |
| `snapshot.source.db` | 任意标识字符串，用于在附录里显示 |
| 其余 | 从现成租户复制过来即可 |

---

## 校验规则（不过就白屏）

`tenant` 部分被页面用 **zod 硬校验**（`f.parse(t)`），不过会抛异常，**整页白屏**，
而且报错在压缩过的代码里很难看懂。所以改完**一定先跑 `check`**。

| 字段 | 要求 |
|---|---|
| `id` | kebab-case，`^[a-z][a-z0-9-]*$` |
| `name` / `industry` / `demoTitle` | 非空字符串 |
| `client.displayName` | 非空字符串 |
| `brand.accentHex` / `accentInkHex` | `#RRGGBB` 格式，如 `#8b5cf6` |
| `taxonomy.portfolios[]` | 至少 1 条；每条有 `id`、`name`、`tier`(整数 1~3) |
| `taxonomy.appArchetypes[]` | 至少 1 条；`tier` 是 `"T1"`/`"T2"`/`"T3"` |
| `businessCase.*` | `baselineUsdM`、`opportunityUsdM`、`roiMultiplier` 都必须是**正数**，加 `splitNarrative` |
| `talkTrack.*` | **9 个全部必填**：constellation / serviceOps / engOps / businessOps / architecture / finops / securityOps / agents / valuePool |
| `highlightEntities.*` | stormIncident / anchorApp / anchorChange |
| `labels.*` | 可选；一旦给了就要 6 个全给 |
| `nameFanout.*` | 可选，字段都可选 |
| `journeys` | 可选，字符串数组 |

`snapshot` 部分没有 zod 校验，但缺 `apps` / `portfolios` / `journeys` / `facts`
会画不出东西 —— `check` 也会报。

## 切换租户

**不用改代码**，站点自带机制：

```
?tenant=<id>  →  localStorage["sip-active-tenant"]  →  兜底 "retail"
```

所以：

```
http://localhost:8777/constellation-app.html                     # 默认 retail
http://localhost:8777/constellation-app.html?tenant=qantas       # 切到 Qantas
http://localhost:8777/constellation-app.html?tenant=myco         # 你自己加的
```

也可以按 `Shift+S`（或三击顶栏的 accenture 标记）打开租户切换面板。

### ⚠️ 它会被记住，这是个坑

URL 参数一旦生效就会被写进 `localStorage`，**之后访问不带参数的 `/` 也会继续用它**：

```
访问 /?tenant=qantas   → 记住 qantas
访问 /                 → 还是 qantas，不是 retail！
```

想回到默认：

```
http://localhost:8777/constellation-app.html?tenant=retail
```

或者在 F12 console 里：

```js
localStorage.removeItem('sip-active-tenant')
```

### 怎么确认切换成功了

看底部状态栏那行数字。每个租户的 apps 数都不一样，一眼能认出来：

| URL | 状态栏应显示 |
|---|---|
| `/` | 282 apps · 9 portfolios · 54 teams |
| `/?tenant=qantas` | 340 apps · 10 portfolios · 65 teams |
| `/?tenant=life-sciences` | 1800 apps · 9 portfolios · 346 teams |

如果带了 `?tenant=` 但数字没变，说明那个租户**没有真的进到 bundle 里** ——
跑 `python3 tenant_data.py list` 确认它出现在列表里。

> 自己新加的租户，记得把 `facts` 里的数字也改得和原租户不同，
> 否则你没法一眼看出切换成没成功（这是我踩过的：复制了 retail 加租户，
> 两边数据一样，测了半天以为没生效）。

## 坑

### 坑 1：zod 校验不过 → 整页白屏

见上面「校验规则」。**改完一定先 `check`。**
白屏时按 F12 看 console，会有一条 zod 的报错告诉你哪个字段不对。

### 坑 2：`facts` 是独立的数字，不会自动跟着变

底部状态栏那行 `Snapshot · 282 apps · 9 portfolios · 6 journeys · 54 teams`
**读的是 `snapshot.facts` 里的数字，不是数组长度**。

所以你加了 3 个 app 之后，状态栏还是会显示 282 —— 得手动改：

```python
d["snapshot"]["facts"]["apps"] = len(d["snapshot"]["apps"])
d["snapshot"]["facts"]["portfolios"] = len([p for p in d["snapshot"]["portfolios"] if p["id"]])
```

> 顺带一提：`facts.portfolios` 的**原值 9 和数组长度 10 本来就不一致**
> （`portfolio:real-estate` 里 0 个 app）。这是数据源自己的口径，不是你改坏了。

`facts` 还有这些字段（都只是展示用，改不影响图形）：

```
apps, portfolios, journeys, teams, incidents, changes, problems,
infraIncidents, monthsCovered, mttrBotMin, mttrHumanMin, mttrGapMultiplier,
topAlertStormId, topAlertStormChildren, emergencyBackoutRate,
standardBackoutRate, emergencyBackoutMultiplier, mondayNormalBackoutRate,
sundayNormalBackoutRate, mondayNormalMultiplier, issueGenericPct, changeUnlinkedPct
```

### 坑 3：改完没反应？多半是缓存

硬刷新：**Cmd+Shift+R**。或者确认真的跑了 `make-offline-page.py`。

还要注意：**重建会清空输出目录**，所以别把东西放在 `public/` 里。

### 坑 4：`app.id` 和 `appKey` 的区别

- `id`：`app:pos`，带前缀，图形内部用它
- `appKey`：`pos`，不带前缀，`appTechnologies` 用它做映射

两个都要唯一，都要改的话**一起改**，否则技术栈会丢。

### 坑 5：副标题是写死的，不是数据

标题下面那句
`The Acme Retail operational fabric · 282 apps across 9 portfolios + 6 journeys…`
**写死在 `public/constellation-app.html` 里**，不在数据里。
要改它得直接编辑那个 HTML（或者改 `vendor/server.html` 后重建）。

### 坑 6：中心节点的名字来自 `tenant.client.displayName`

图中心那个节点，页面代码读的是 `b.tenant.client.displayName`。
`snapshot.enterprise.label` 是另一份，**建议两个保持一致**，避免不同位置显示不一样的名称。

## 怎么回退

```bash
rm tools/tenant-data/retail.json    # 删掉覆盖文件
python3 make-offline-page.py        # 重建 → 回到原始数据
```

**永远不用怕改坏。** 源文件（`_files/` 里的那份）从头到尾没被碰过。

想保留改动但暂时不生效？把文件改名成 `retail.json.bak` 就行 —— 脚本只认 `.json`。

## 排查

| 现象 | 原因 / 怎么办 |
|---|---|
| 整页白屏，console 报 zod | `tenant_data.py check` 看缺什么 |
| 改完没变化 | 没重建（`make-offline-page.py`），或没硬刷新（Cmd+Shift+R） |
| 新加的 app 不在图上 | `portfolioId` 指向了不存在的 portfolio —— `check` 会报 |
| 状态栏数字不对 | `facts` 没同步（坑 2） |
| 技术栈丢了 | `appKey` 和 `appTechnologies` 里的对不上了（坑 4） |
| `✗ 找不到数据模块的锚点` | 站点换了构建版本。跑 `make-offline-page.py --refresh` 刷新，必要时改 `tenant_data.py` 里的 `ANCHOR` 正则 |
| 端口 8777 被占 | `start-offline.sh` 会自动换到 8778 |
